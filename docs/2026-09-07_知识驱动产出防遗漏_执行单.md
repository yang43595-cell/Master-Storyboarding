## 0. 一句话目标
把"**每阶段必须先跑 `prepare` 拿到知识包 → 产出前核对命中的规范 → 缺规范就停/补齐，绝不自由发挥**"变成**跨所有生产 skill 的强制流程**，杜绝"有的环节查知识库、有的环节自己写"。

## 1. 诊断（为什么之前没做到）
- **机制存在**：`stage_context_cli.py prepare` → `knowledge_selector` → 把该 skill 的**知识包嵌进 `stage_startup.md`**；`_shared/knowledge-access.md` 规定"只读选中的知识包，不扫整个 Vault"。这是"知识驱动、不扫库"的架构。
- **没做到的根因**：
  1. **资产阶段漏跑 `prepare`**：给 asset-image-assistant 出图时**没先 `prepare`**，该阶段没有自己的 `stage_startup` 知识包（当时的 stage_startup 是上一个 skill 的）。→ 无知识输入。
  2. `knowledge-access.md` 规定"**不扫整个 Vault**"，所以没包可读又不许自己扫 → **无回退** → 只能自由发挥（比"停下来报缺口"更糟）。
  3. 部分 skill 方法把"读规范"标成**条件性/可选**（如"涉风险才读"），不是强制。
  4. **每类产出的"必须命中的规范"没有在知识库/方法里写死、可查**，导致不同产出不一致。
- **结论**：不是机制坏，是**没把"先 prepare + 必须命中规范"变成强制的、可查的门禁**。

## 2. 修复清单（四步）

### 步骤一：把"每阶段必须先 prepare"设为硬门槛（核心）
- 在 `scripts/stage_context_cli.py`（或新增一个产前校验函数/钩子）加一道**门**：生产某 stage 的产物前，校验该项目的 `00_项目管理/执行上下文/stage_startup.md` **存在且 `kind=startup`、`Skill` 为当前 skill**；若缺失或 skill 不符，**阻止并提示先 `prepare`**。
- 在 `PROJECT_RULES.md`（或共享红线 `_shared/knowledge-access.md`）加一句：**"任何生产 stage 必须先 `prepare` 拿到本 skill 的知识包；未 prepare 不得产出。"**
- 位置参照：`scripts/audit-knowledge-entrypoints.py`（已有可开关审计）——可把这道门**作为它的一个 check** 扩展进去，或单独加 `scripts/ensure_stage_prepared.py`。

### 步骤二：给每类产出写"必须命中的规范"清单 + 强化"缺规格即停"
- 在 `skills/_shared/` 新增/强化一条**红线**（可并入 `knowledge-access.md`）：
  > **产出任何项目产物/提示词/镜头/分镜/脚本前，必须先读取并命中对应的知识库规范（Obsidian Vault wiki + repo references）；对应规范缺失或不在当前知识包时，先补齐/重新 `prepare` 或停下来报告缺口，绝不凭空写。**
- 在**每个生产 skill**（creative-director / storyboard-planner / asset-image-assistant / storyboard-director / voiceover-to-video-script / blender-previs）的 `modules/<方法>.md` 开头加**"本 Skill 产出须命中的规范"清单**，例如：
  | Skill | 产出 | 必须命中 |
  |---|---|---|
  | asset-image-assistant | 人物/场景/道具/产品图 | `色卡统一风格` + `图片连续性规则`（背景母版/四图） + repo `01-04-master-guide` + `prompt-language-hard-rules` |
  | storyboard-director | 分镜图 | 分镜方法 + `景别理论` + `连续性剪辑` + `image-continuity-hard-rules` + `prompt-language-hard-rules` |
  | creative-director / storyboard-planner | 编导/分镜方案 | `PROJECT_RULES` + 知识包 + `景别理论/连续性剪辑`（如相关） + 各 skill 方法 |
  | voiceover-to-video-script | 视频提示词/脚本 | `prompt-language-hard-rules` + `seedance提示词结构` + `产品展示与使用过程边界`（涉产品时） |
  | blender-previs | 预演配方 | `CLI与配方契约` + `prompt-language-hard-rules` |

### 步骤三：补全知识 profile / selector 覆盖（让该规范的"知识块"真被 select 进来）
- 核对并补全会产出图的 skill 的 `knowledge-profile.json` topics，确保**色卡统一风格 / 图片连续性（背景母版+四图）/ 空间连续性 / 景别理论** 等 Vault 概念**能被选进 `stage_startup`**。asset-image-assistant 现有 topics：`character-consistency, image-continuity, spatial-continuity, product-reference, asset-driven-video` —— 确认这些 topic 在 `knowledge_blocks` 里真的映射到 `色卡统一风格` 与 `图片连续性规则`；缺就补 topic 或改 selector 映射。
- 跑一次 `python scripts/stage_context_cli.py prepare --project <项目> --skill asset-image-assistant --objective ... --vault <vault>`，确认`stage_startup.md` 里出现色卡/连续性相关规则块。

### 步骤四：review-profile 加 `KB-COMPLIANCE` 检查（审查兜底）
- 在会产出"图/提示词/分镜"的 skill 的 `review-profile.json` 的 `production_artifact_checks` 加：
  ```
  {"id":"KB-COMPLIANCE","text":"产物命中对应知识库规范：资产图须遵循色卡统一风格+图片连续性+对应master-guide；提示词须遵循prompt-language-hard-rules；分镜须遵循分镜方法/景别理论/连续性。产出前已读取这些规范，非自行发挥。"}
  ```
- 保持 JSON 合法；用 `review-pack` 验证可读出、检查数 +1。
