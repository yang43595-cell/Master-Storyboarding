# 执行分工与自查

本文件是项目规则的职责细则；适用范围及默认流程以 [项目总规则](../../PROJECT_RULES.md) 为准。只在本轮职责或明确选用的分支内读取。

## Skill 执行分工

### 创作执行开始前：干净上下文

- 新一轮编导生产或实质重跑，必须由全新、专属的生产 agent 执行，不继承长主会话。导演稿、视频提示词等创作阶段的新轮同理；多案例分别执行，不把其他案例的草稿或推测带入本轮。主对话负责范围协调、澄清和结果检查，不边聊边直接写完整生产稿。
- 只交接当前有效项目规则与目标 Skill 入口、可实际读取的原始素材、适用于本轮的用户约束与已确认决定（保留准确依据）、现行版本与未决事项，以及本轮目标、范围和停止点。排除废弃候选、失效推测及无关讨论；干净上下文不等于丢弃有效决定，也不能只传摘要替代原片、原文或真实参考。
- 专属 agent 是本轮生产执行者，负责必要资料与方法阅读、来源核对、适用的准备流程、候选写作和自查；不因新开 agent 跳过现行 Skill、对白核对、来源或确认门禁。同一轮的逐段推进、局部返修和工具调用可继续原执行者，不为每段或每次调用重新开 agent；目标、来源或执行基线发生重大变化时重新开一轮。
- 普通查问、只读检索、纯错字/排版维护不因此要求新 agent。此规则只用宿主已有委派能力，不新增多 agent 运行时、审批层或交接格式，也不构成创建本地 Codex、切换电脑或突破用户指定执行环境的授权。无法实际创建干净上下文 agent 时如实说明限制，暂停该轮生产，不用当前主会话续写冒充独立执行。

### 图片生产批次

- 需要界面操作的资产图或分镜图批次，由承接任务的主对话按[项目专用界面分工](#画布执行与交接的宿主边界)直接完成。其他图片批次由协调方直接委派给干净上下文的专属图片子 agent。每批由实际执行者读本批输入、方法和参考，写词、自查、生成、实看并在授权内修正，独占落盘并记录准确用途和结论。受派执行者不递归派发生图子 agent。
- **每批最多 8 张目标图**，无需凑满。主对话逐批处理界面制作，受派的图片子 agent 只承接一批。同批同目标的返修沿用原执行者和目标身份，生成新文件版本；不得追加第 9 张目标或把换一个任务名当成清空上下文。批次上限不改变单请求 `max_images`、单状态候选数、四格／四视图的生产规范、工具并发限制或费用授权，也不表示无限返修许可。工具失败或结果未知不自动重提；视觉问题可在本轮已有授权与既定目标内修正，需改上游、增加目标或扩展授权时退回阶段负责人。
- 阶段负责人按角色、场景、服装、状态和实际参考依赖分组并固定准确来源。基础母图或共同设计须先确定，依赖它的后续批次再启动；仅已具备各自有效参考且互不等待的批次可并行。关联状态图、机位图及跨镜不变量沿现有方法一起核对，不按张数机械打断连续性，也不拿失败图串联垫图。
- 每批使用自己的真实执行者／任务身份和本批输入证据，不能继承阶段负责人或其他批次的阅读声明。普通对话按[图片批次的隔离准备](../../skills/_shared/knowledge-access.md#图片批次的隔离准备)隔离准备目录，资产 Web 继续使用本次 task-package 的受限读取流程，不叠加普通 prepare。网页已经一图一独立会话的制作项可继续保持，不为批量上限合并上下文。
- 阶段负责人先分配互不覆盖的目标身份和候选路径。图片执行者只写独占分配的本批候选、提示词及现有制作／请求记录，不并发改整份 manifest、当前资产清单、阶段状态或其他批次记录；多个批次共用一个记录文件时，由阶段负责人接收准确内容与定位后统一写入。共享登记、正式采用、网站送审及最终阶段状态由阶段负责人核对后统一更新；已确认文件始终保留，返修另存新版本。
- 普通对话制作资产图时，按[资产 Skill 的批次回执](../../skills/asset-image-assistant/SKILL.md#本轮执行-sop)固定结果路径。主对话直接核本批回执；委派批次收到终态通知后按批次 ID 接收。
- 图片执行者交回文件夹绝对路径、准确文件名、AST/output 或 artifact/请求与镜号身份、revision/字节依据、实际参考及用途、自查可见事实、修正结果和未满足项。证据沿现有候选、制作／审核备注、请求、`quality_evidence` 与采用记录保存，不新增平行 QA 账本。后续从登记身份定位目录中的准确文件，不能按“最新图”或整个文件夹猜选。
- 本批实看与自查由图片执行者负责；跨批相关图由能读取准确原图和来源的执行者合看，记录实际范围。协调方核覆盖、依赖和回执，下游实看当前用途所需的图。**资产图沿项目已定通道接受人审，分镜图按本轮流程验收。** 批次自查后继续办理适用的审核和采用。

### 本轮执行与自查

- 上述创作轮由专属生产 agent 直接完成本 Skill 工作；图片生产按图片批次规则决定执行者。其他任务默认由当前执行者完成，只有用户明确要求或独立子任务有清楚的并行收益时才委派。生产执行者不递归为同一轮再派生产 agent；确需委派的图片批次由协调方直接分派。
- 除上述创作轮与图片批次的生产委派外，可委派范围仍限于只读检索与整理、隔离组件开发、不写真源的有界候选分析、对已完成结果的独立检查。生产 agent 按已交接的目标与整体创意方向写本轮候选，主对话检查结果；候选分析只交建议、依据与影响，由生产执行者选择并写回。**不得把目标解释或整体创意方向的最终决定、同一份核心稿的并发改写、费用与账户授权、用户最终审批或发布委派出去**；阶段负责人保留阶段依赖、完整验收与正式采用责任，不各自持有互相冲突的当前状态。
- 确定性步骤不再套一层模型：能由脚本或现有 CLI 完成的校验、转换、下载、转写、渲染、打包、巡检直接执行，不把子 agent 当调度器。除上述干净上下文生产轮与图片批次外，只为真正需要独立判断的边界任务增加 agent，不为了看起来更工程化而扩编制。
- 本项目的生产、维护及子任务协调均执行[等待与工具回传](#等待与工具回传)：不人为过早返回制造二次等待，不在无新问题时叠加进度查询；先筛选再回传，不依赖截断处理大结果。首次必读原文、必要视觉核验与及时沟通仍按各自要求执行。
- 本轮生产执行者完成创作、自查、修改和复核；新开生产 agent 不使其成为独立审核者。只有用户明确要求独立审核时才启动独立审核，不因初稿、重要修改或提交前检查自动另派审核 agent。
- 整稿交付、重大改动或反复出错时，可向用户建议独立审核；建议不是授权，不据此自动派发或阻塞阶段。日常小改仍在当前生产对话自查。
- 自查对照当前原始证据和既定验收要求，检查正文、镜头/对白承载、时长与素材决定的一致性；不能只看程序通过。发现问题由当前执行者修改候选，再检查改动及直接影响；已确认产物仍须新版本，不原地覆盖。来源或授权缺口仍报告并暂停相关执行，不自行补造事实。
- 自查复用本执行者仍有效的材料；图片批次在图片执行者中自查，不为模拟两个角色另建 review-pack、reviewer 身份、producer-response 或重复交接文件。必要的问题与修复证据记在现有任务记录，明确结论为“自查”，不冒充独立审核。技术检查、用户确认和付费授权边界不变。
- 用户明确要求独立审核时，按[阶段审核入口](../../skills/stage-reviewer/SKILL.md#执行-sop)向独立审核者交当前候选、准确来源和验收范围。返修仍由当前执行者完成，必要复审回原审核者。交接只传路径、未决 ID、实际改动及直接影响。
- 用户确认、付费或提交的明确授权，以及不覆盖已确认产物的边界仍然生效；兼容人工流程需用户确认并明确要求继续；默认统一入口按网站准确通过回执及既有自主执行授权流转，不要求重复确认。
- 修复或新增检查后，须在正式完整入口（如正式采用的完整校验）复现问题并验证修复，不能只凭局部函数或局部测试通过就报已覆盖：本项目曾有缺陷在局部测试全过后、由复审在完整入口才复现。局部绿灯只证明局部路径，不证明完整链路。



## 逐场创作与全片复核

以下创作安排适用于默认统一入口及兼容人工流程；确认方式仍按项目总规则选择，不把创作段落等同于停等用户的节点。

导演稿与视频提示词默认按创作段落逐段写作、自查；用户明确要求整稿交付时可整稿完成。创作段落按场景、时空转换或完整剧情阶段划分，短且完整的戏可整段完成；不按固定秒数或镜头数切割，不截断连续动作。同一场景可含多个创作段落，但不新增或改写上游场景、故事、对白编号。创作段落不同于生成片段，生成分段仍按视频 Skill 的模型承载能力与现行优先级。

顺序为：全片统筹 → 逐段完善导演稿并按所选流程验收 → 全片导演稿复核及结构化 → 按需检查分镜素材 → 逐段完善视频提示词并按所选流程验收 → 全片提示词复核。导演全片未完成并正式交接前，不进入正式提示词阶段。统一入口逐段自查后继续，不停等逐段人审；兼容人工流程才按准确段落确认后继续。

- 全片统筹写在现有导演 JSON 内，记录各创作段落的作用、情绪走向、来源范围及前后衔接；统筹不代表各段拍法已经完成或确认。
- 每轮完成当前完整创作段落，说明本轮范围、已完成与待完成部分，核当前段及跨段依赖；尚未细写的后段不宣称已检查。
- 全部段落完成且按所选流程验收后，核全片对白、镜头覆盖、节奏及衔接，再校验完整 JSON 并按现有合同登记。视频提示词同样做全片复核，不能以逐段自查替代。
- 追加内容不改变已确认范围；需改动已确认内容时另作修订，重查直接影响并重新取得相应范围依据。不默认新增逐段副本、任务表或局部导演包；结构化与正式交接要求全片完整。

人工确认的准确范围及机器字段见 [确认范围](artifacts.md#确认范围)，兼容停等步骤只在明确选用时读取 [兼容流程](legacy-review.md#逐场创作与确认)。

## 画布执行与交接的宿主边界

本项目及其工作树的电脑、浏览器和画布界面操作由承接任务的主对话直接执行。本条覆盖通用电脑操控规则、工具说明中对本项目固定模型或派界面子 agent 的要求。浏览器仍用每任务独立的后台 Edge，按站点规则核会话与实际权限，用户本人完成需要人工处理的登录。主对话开工前核准确目标、当前输入、授权和停止点，同一目标续用有效操作记录。

阶段交接继续用 `stage_context_cli.py handoff` 的现有交接卡，可传 `--objective` 和 `--stop-at` 固定本轮目标与收口条件。卡内列当前有效产物的 ID、修订、路径和实际 SHA-256，指向现有来源、需求、确认、流程授权与未决记录。接收者实读所需原件，缺证保持未决。新卡消费时重查字节，历史无 hash 的正式卡仍按旧身份检查，不替历史补证。

并行委派普通编导或导演时，按[普通编导和导演的任务隔离](../../skills/_shared/knowledge-access.md#普通编导和导演的任务隔离)绑定实际接收者和任务 ID，并交回该任务的 `context_id`。

长任务交接同时约定有界等待渠道、总等待期限和完成回执路径。执行者在现有制作、请求或交付记录写结果，完成通知只回目标身份、完成范围、检查结论、差异、未完成项和证据路径。过程日志、原生回读与大图留在原处。协调方收到完成通知后验收一次。继续按[等待与工具回传](#等待与工具回传)处理。

### 工具报错与原处续作

- 来源、确认、稿件或素材确有缺口时，沿本职入口处理受影响项。程序异常、依赖不可用或入口加载错误交阶段负责人处理工具问题。发布、采用、保存等操作结果未知时，先沿原发布版本、事务、任务或节点只读核验已有结果。确定性报错在相关条件未变时停止重试。暂态故障沿原工具的重试边界，同因连续失败两次暂停受影响范围。独立且已有授权的工作可继续。
- 在现有制作、请求或交付记录留下失败步骤、准确目标和输入修订、可用的产物路径及哈希、退出码和首条可定位错误的证据位置。注明最后已核实的结果与下一未完成步骤。交接只带这些定位信息，完整日志留原处。工具排障交回具体改变及针对同一失败步骤的验证结果。
- 原执行者按[恢复入口](../../skills/_shared/knowledge-access.md#恢复后的实际执行)重核原阶段、输入和已落盘结果。确认原操作已完成时直接从下一步继续。条件确有变化且原操作仍未完成时，先用已有只读检查验证原失败范围，再沿同一入口完成该步。受影响输入有新版本时按既有版本与采用规则处理。

## 等待与工具回传

生产、维护和已授权的子任务协调沿本节等待及回传。这里限制协调方的重复唤醒和取进度，不删去工具内部为原操作所需的有界只读等待、目标身份、保存及结果核验。

- **一次有界等待**：使用宿主完成通知；无须更早处理输入时，在宿主上限和本轮沟通间隔内优先用 60 秒有界等待，不以 10 秒或 30 秒固定短间隔反复唤醒模型。嵌套等待的外层覆盖内层，不人为提前 yield；返回运行中只续接原调用，不另起同一等待，也不用无限循环阻塞代替模型调用。
- **落实到宿主参数**：Codex `wait_agent` 用 `timeout_ms: 60000`；终端任务首次 `exec_command` 用 `yield_time_ms: 30000`（当前单次上限），返回 `session_id` 后用 `write_stdin` 对同一 ID 续等，`yield_time_ms: 60000`。`functions.exec` 外层显式给不短于本次内层等待的 `yield_time_ms`，返回 cell ID 后只用 `functions.wait` 续接该 cell，不能同时另查其终端 session。已有完成通知时不另起状态轮询。参数以当前宿主 schema 为准；确需提前处理用户输入或独立工作时可提前返回，不能把 1000 ms 当后台任务默认值。
- **无变化不重复取进度**：等待超时只表示本次没有新通知，不据此叠加 `read_thread`、`list_agents`、日志、目录或提前读取批次回执；沿同一等待渠道及游标续等（若支持）。用户问进度、子任务报告阻塞、收到可接续且需核验的新结果、出现真实异常，或超过本轮已约定的总等待期限而仍无终态时，才按原任务身份做一次定向只读回查。旧交接未约定总期限时，首次只读核原任务一次并明确接续期限，不因后续超时反复回查。超时或通知缺失均不触发重新提交。收到终态后验收准确回执一次；缺项只交原执行者补核，已验同版回执不再重复获取。必要沟通说明已知状态，不为凑更新重新取数。
- **返回前筛选**：历史恢复先取当前结果和准确来源，缺失决定再回查对应轮次；默认不附历史工具输出。脚本可完整校验本地文件，但向模型只回本轮对象、结果、差异位置和必要原文；不整体序列化工具返回对象、完整资产历史或全工作树列表。所选工具的安全和接口要求优先。
- **图片批次回传**：按[图片生产批次](#图片生产批次)回传准确目录／文件身份、用途、实际观察和缺口，不回传图片载荷或整批历史；跨批视觉问题交能读相关图的图片执行者定向检查，主协调方不为收回执再次加载全图。普通准备使用[本批 context-id](../../skills/_shared/knowledge-access.md#图片批次的隔离准备)，不能多批共写旧准备目录；磁盘隔离不等于宿主上下文清空。
- **验收按争议取原件**：资产批次优先用 `handoff --receive-batch` 的逐项目标、原图路径、字节、实看摘要和 `issue`；完整观察留在返回的 `receipt_path`。分镜及其他阶段沿现有请求／交付记录，只提取本轮 ID、修订、结论、差异与证据路径，不整体打印 JSON 或日志。原图由实际执行者实看；协调方有具体争议时才按准确文件定向查看，执行者已看且本轮仍可用的同图不紧接着重复加载。下游新增用途或字节变化仍按实际需要看图，紧凑摘要不能替代应做的视觉检查。
- **对齐输出上限**：按外层总额度分配各内层输出，多个结果先汇总再返回。首次必须阅读的长文按章节连续读完；发生截断只补缺失范围，不重打整批。失败先回失败列表和一个代表性异常，完整日志留本地，需要时再定位读取。
