# 按需选用的兼容审核流程

本文件是项目规则的职责细则；适用范围及默认流程以 [项目总规则](../../PROJECT_RULES.md) 为准。只在本轮职责或明确选用的分支内读取。

仅在本轮明确选用兼容人工流程或处理历史产物时适用；默认统一入口不加载本文件，不恢复旧审核要求。

## 逐场创作与确认

仅在本轮明确选用兼容人工逐段模式时，当前完整段落自查交付后等待用户确认及继续授权，再细写下一段。一段通过不批准其他段落或整稿；需要改已确认内容时保留旧版，另作修订并重审受影响范围。

通用的创作段落划分、全片统筹、导演到提示词顺序及整稿复核，统一读取 [逐场创作与全片复核](execution.md#逐场创作与全片复核)；确认记录与局部范围的门禁读取 [确认范围](artifacts.md#确认范围)。兼容分支全部导演段落确认且整稿复核完成后，校验完整导演 JSON 并按原合同登记；视频提示词同理。发现需改已确认段落时重新确认受影响修订。

默认统一入口按 [项目总规则](../../PROJECT_RULES.md#网站审核到画布的统一入口)自主逐段检查，不因本文件存在而恢复逐段停等。

## 导演 JSON 与网页审查（本次修正）

以下是未选用统一入口时的兼容路径；统一入口的导演稿只做本职自查，不进入审核网站。

本节只修正 storyboard-planner 导演阶段的交付顺序，不改编导稿内容，不给其他阶段新增网页或导出门禁。[JSON 业务权威、历史兼容和导出规则](artifacts.md#json-交付与按需导出)保持不变；导演阶段按本节更明确的要求执行。

正常顺序为候选导演 JSON → 自查校验 → 现有审核网页审查 → 用户确认准确 JSON 版本及范围。网页阅读视图绑定同一 JSON 修订；JSON 变化后重新校验并送审新版本，不沿用旧版本意见。仅用户明确要求 Markdown 检查稿时，才从同一已校验导演 JSON 版本按 [JSON 导出命令](artifacts.md#json-交付与按需导出)导出；不作为 JSON 生成、自查或网页审查的前置，不新建业务权威、不反向覆盖 JSON、不登记为新依赖。历史 human_readable_path 的双文件只读兼容、用户确认范围及正式交接授权不变。旧导演操作说明和压力场景的 Markdown 先行顺序只供历史路径参考，不作为新导演交付要求；保留历史记录不代表继续采用该旧顺序。

网页交付复用 [既有网页适配说明](../../docs/development/web-content-adapter.md) 和原有审核入口；scripts/core/web_content.py 只做同一业务 JSON 的离线编译与固定契约校验，不执行发布、部署或用户确认。实际入口、部署版本和发布回读流程未核实时，保留缺口并暂停对应网页操作，不虚构页面或 URL，不把离线通过说成已线上集成；sourceScriptVersion、expectedVersion 和准确版本确认边界保留。
