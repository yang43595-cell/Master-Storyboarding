# 视觉生产与资产调整

本文件是项目规则的职责细则；适用范围及默认流程以 [项目总规则](../../PROJECT_RULES.md) 为准。只在本轮职责或明确选用的分支内读取。

## 导演稿之后的生产顺序

声音参考是可选能力，仅在用户明确提出或选用时启用。用户未提出时，交付中省略声音参考，不主动询问、推荐、创建声音清单或列“未提供／待确认”占位，也不因缺少声音参考或声音目录阻挡后续流程；对白、环境声和既定配音安排按原稿处理。

导演稿采用后，`storyboard-director` 按镜号核对并登记视觉依据。已有所需确认图的镜段先查，具体缺图只影响依赖该图的镜段。`voiceover-to-video-script` 开写前须确认本轮拟写镜号均已完成视觉检查且依赖就绪。

分镜图默认使用竖屏 **9:16**，生成与交付时核对实际画幅；用户另有明确指定时按指定执行。此默认不改变人物板、产品资料板或原始参考的画幅；它们转作分镜画面时须按 9:16 重新核对构图，不能把横图直接标为竖屏分镜。

编导稿采用后，资产 Skill 直接按人物、场景和道具需求核对现有图，先复用合用的已确认图，缺的按已有授权制作。导演规划与 1:1 复刻分段各自可与资产制作并行启动。导演线按实际镜号核所需确认图，复刻线按段号及实际出镜对象核所需确认图。登记缺失或待确认的图片及用途，只暂停实际依赖它的镜段，其余就绪范围继续交接。补图沿本轮已有授权制作，执行者实看、自查并按准确镜号和用途采用，兼容人工流程沿原规则确认。动作过程由视频提示词承载。

**关键人物位置关系要有实际图像约束。** 通读整剧，按连续场景和位置状态核对关键人物的前后、相邻、遮挡、站坐、视线和可达范围。凡这些关系决定对白归属、反差、互动或跨镜连续性，先选一张能看清人物与门、座位、桌边等固定锚点的关系图，缺合用图就按需补做。同一关系可跨镜复用，换场或关系实质改变时重核适用范围。单人身份板与空场图各自继续承担身份和环境参考。按[场景关系参考的交付约定](../../skills/storyboard-director/modules/storyboard-method.md#场景关系参考的交付约定)记入现有分镜选择记录。

### 导演到视频的视觉交接

分镜执行者实看本轮镜号所需的确认图，并按以下步骤登记结论。协调方沿同版记录核镜号覆盖、用户改动和就绪范围，直接派发已就绪的镜段。

> 读本轮已采用的导演稿、用户最新确认的改动和当前可用素材。沿准备交给视频的镜头，找出位置猜错就会影响动作、对白对象或前后连续性的地方。
>
> 对这些镜头，先用门、窗、桌、椅等固定物说清人物的位置和朝向，再实看哪张现有图能交代这个关系。换机位时，画面左右可随拍法改变，人物在场景里的实际位置要接得上。同时核对本镜需要的场景母图与指定动作参考。
>
> 导演的位置没定清就退回导演。位置已定且现有图能看清，记下镜号和那张图，直接复用。位置已定但图交代不清，写明缺哪个关系，只暂停相关镜段。普通镜头可以成组记结论。
>
协调方派发前再核两项交付记录。

> **核用户改动进了哪份稿。** 对照用户原话、受影响镜号和实际交给视频的已采用导演稿，指出必须由导演落实的剧情或拍法改动写在正文哪里。采用稿仍是旧写法时，写明差异，退回导演修订，只暂停受影响镜段。视频候选已改时也照此核对。
> 把同一事件的场景、角色与说话人、动作和反应的先后，对照采用稿的视听流程、逐镜字段和对白。比如拥抱前后说哪句、纸件是口头交代还是递出、出门后谁留在屋里。各处说法冲突时，由导演按本轮决定收口后再交接该段。
>
> **核素材状态是否一致。** 对照本镜段的素材清单、自查结论和未决项。同一素材出现「已用」和「待定」时，核准确文件、镜号及用途，再按证据在现有记录结清。稿件已列入素材和画布已实挂分别记，画布实挂以准确版本的回读为准。状态未核清时，只暂停受影响镜段。

在现有视觉补充请求 JSON 记录结果，分镜选择记录引用该请求。用 `source_shot_ids` 列实际核过的镜号，用 `visual_review.storyboard_sha256` 绑定已采用导演稿，用 `visual_review.observation` 写本轮结论和依据。按实际情况登记：

| 决定 | 登记依据 |
| --- | --- |
| `no_supplement` | 当前镜头没有独立静态控制需求。仅将依据相同的普通镜头成组登记，在 `observation` 写清本组的具体画面事实、现有常规素材覆盖的内容，或为什么无需单独锁定静态状态。例如「同一已确立位置继续普通对白，人物未换座、无交接，原环境与人物参考足以维持」。状态为 `not_needed`，`max_images: 0`。 |
| `reuse_existing` | 已实看具体参考，能承担本请求的静态状态。在 `existing_references` 写准确来源与 `coverage`。指定承担关键位置关系的图按下文锁定身份及用途。`max_images: 0`。 |
| `request_supplement` | 导演已定且基础参考有效，现有素材仍缺一个关键可见状态。写出看到的缺口、参考不足的原因和对下游的影响，再按[补图范围与计数](#补图范围与计数)确定目标。 |
| `return_upstream` | 剧情、拍法或连续性未定／冲突，或缺当前要求的资产母图、实拍等必要上游来源。写明原件位置、受影响镜号、退回对象及原因。`max_images: 0`，受影响镜段待处理。 |

「已检查」「无需补图」是结论，须补上上述依据。未核、缺图、冲突和待确认的镜号保持待处理。已有请求可补记本版有效结论。已登记退回的镜号由相应上游解决。图片已正式采用但视频稿漏挂时，由视频执行者沿现有修订入口补齐准确图片和用途；相应画布交接继续等待。

写词前用现有分段 CLI 只读核检查范围、必保画面声明和视觉依赖。每个要写的镜号传一次 `--shot-id`。漏查、导演稿换版或同镜登记多个最低时长时，定位受影响镜号并退回补齐。

```sh
python -m scripts.core.generation_boundaries --project <项目> --storyboard <已采用导演包> --shot-id S01-001 --shot-id S01-002
```

当前请求放在 `05_分镜/` 下的 `*视觉补充请求*.json` 或沿已有位置登记为 `visual-supplement-request`。补图采用使用的图片观察引用实际核对的请求文件。复用既有关系图沿用 `reuse_existing`，在 `relationship_reference` 用 `ref_id` 和 `sha256` 锁定 `existing_references` 中的一张图。以准确 `AST@输出` 或已采用分镜图的 ART-ID 标识，其他参考可以照常列明各自职责。视频稿和画布预检按相关镜号核同一图的字节、身份及 `layout` 或 `state_reference` 用途。明确取消或上游问题已解决后，保留该镜号的实际检查结论，再退役旧请求。历史普通请求仍可用于依赖排查。开始新的写词范围时按本入口记录实际检查。

剧情使场景出现后续仍需保留的可见变化（如空桌摆满菜、礼盒打开或移走、布置或损坏）时，先按[剧情后的场景状态参考](../../skills/storyboard-director/references/reference-asset-contract.md#剧情后的场景状态参考)建立并审查对应状态图，再供后续镜头实际引用；基础环境图不能继续作为与新态冲突的活动全景参考。沿现有导演、补图与视频 JSON 记录，不新增平行状态台账；缺图可写待制作／待审候选，不能提交生成。用户明确选择取消补图、由提示词生成的准确范围，沿[场景状态交付核对](../development/delivery-snapshot-checks.md#剧情场景状态的交付核对)复用现有接受决定，不机械重开补图；生成效果仍待验证，真实产品和冲突引用检查保留。角度、对白或普通走位而场景未改变，不触发每镜补图。

### 补图范围与计数

1. **先列确需控制的状态，再查参考。** 优先检查会影响剧情或衔接的空间关系、持续场景后态，以及确需锁定的动作接触、准确表情、身份、产品状态和相对尺度。已有生成证据显示某状态难以维持时，同样以实际目标和参考覆盖判断。关键是缺图会影响哪个可见结果。普通对白、反打、走位和动作阶段数量本身无需补图。
2. **按去重后的缺口计新图。** 同一物理状态和兼容用途可共用一张已核图，并列全适用镜号。换座、离场、持物归属或持续后态实质变化时重核原图。只有原图覆盖不到而且会影响下游的状态或指定机位才另计一个目标。每个确需新制的目标先从一张开始。确需多个备选时，在同一请求说明理由并设 `max_images`（1–4 张候选）。每批至多 8 个不同目标，候选、批次和实际采用张数分别核对。
3. **真实跨段切点定了再补查。** 视频阶段确定同一连续事件确因模型时长或承载需拆分时，回传两侧镜号、准确切点和未覆盖的静态相位。按[切点参考](../../skills/storyboard-director/references/reference-asset-contract.md#连续事件因时长拆段时的实际衔接参考)优先复用，同机位优先共用一张，两侧确需不同构图时才分别计图。查完该切点并落实两侧实际引用，再完成受影响镜段的正式提示词。


## 资产图需求判断

故事登记不等于出图任务。简单一次性配角可完全无需资产图，用明确提示词描述即可；身份、服装与连续性确需控制时再选单图或完整人物板。环境优先保一致并留充分覆盖余量，四图默认合理；可按实际覆盖少补，但不追求临界最少。新资产表和实质修订按 [资产图需求判断与检查](../../skills/creative-director/references/asset-image-necessity.md) 填写处理结论及判断依据；只有“需要制作”进入新制清单。交付前只检查有无跳过这一步，不增加重复审核。历史确认包兼容读取，不批量改写。


## 用户调整资产图需求

普通剧情物品（PROP）允许没有参考图时按名称、剧情用途及用户生成方向直接生成候选，有品牌名也不自动归为广告产品。外观由用户审图决定，不声称已核对实物。此规则是普通物品对真实参考要求的例外；广告产品 REAL_PRODUCT 仍以真实参考为准。

用户可以确认删除、恢复或新增资产需求。通过本地资产接口 `/api/project` 的 `asset-choice` 操作登记。删除表示本项目不需要该资产图，保留原故事和素材文件，不作为待补缺口；恢复重新进入制作清单。新增必须核对有效故事段落和具体出现方式，用户确认即为该范围的新需求，不伪称原片已包含该物件。接口将决定保存到 `04_资产/资产需求调整.json`，同步生成 `当前资产需求表.md`，保留修订与原选图记录；不修改已确认编导正文。

制作规格不符时，先核现有资产调整，不为工具标签回改已确认编导。`asset-choice` 的 `production-spec` 操作只接受明确的 `wardrobe_name_map`（原 `wardrobe_states` 旧名到同一造型槽位的新名，须明确 `unchanged_appearance: true`）或 `scene_state_coverage`（主状态到所覆盖的原 `required_states` 数组），并记录真实 `quote`、`decision_ref`、原需求摘要和来源修订。同一静态空间多次到访可用一张母图覆盖，须明确 `unchanged_static_space: true`；实际场景或物品持续变化不适用。标签对应保留原图片、输出 ID 与准确人审回执，不冒称用户重新审过新图；改服装实物、人物身份、故事出现位置或动作链仍走相应新需求／修订。原需求变化后旧规格失效，不能自动套用。

当前图片制作白名单由已确认叙事包和用户明确的资产调整共同决定。编导修订和下游资产引用按本轮涉及的条目核对有效决定。导出清单的 `asset_requirement_decisions` 和交接说明携带取消项、新增出现位置及拆分关系。新增只确认需求，不批准图片、生成费用或新的整段剧情；出现位置未核对时不能加入。上游变动使引用失效时停止相关项并核对。多个独立物品不得因用途相同合并成一个选图对象。

资产状态、在场区间与可用图以已采用叙事包、已登记的用户调整及有效的资产 manifest 为准。`04_资产/当前资产清单.json` 是可重建的盘点快照。下游按本次涉及的条目核对已登记输出和实际文件。素材必须引用具体 `confirmed_outputs`：有多个版本时写明 output ID，不能按文件名猜服装、状态或用途。取消资产图不删除故事物件：**已取消出图或被拆分的资产仍可作为故事事实保留引用，但不得作为素材或出图引用——素材清单只放状态为“要出图”且有已确认母版图片的资产，已拆分的改用子项，没有图的人物或物件只写在镜内过程或动作文字里。** 资产被取消、恢复或新增后，用 `python -m scripts.core.asset_refs --project <项目> --scan <AST-ID> --write` 产出受影响位置清单（只报告、不自动改稿），再按清单改当前候选；提交素材前用 `--require-final-image AST-ID@OUTPUT-ID` 核对实际选择，状态、确认输出或文件不符都直接阻塞。已登记最终人物板的造型还须通过最终规格检查。导演 Markdown 阶段用 `python -m scripts.core.story_sources --project <项目> --shot-plan <导演稿>` 核对引用可追溯性（已取消／已拆分告警，未知编号报错）。
