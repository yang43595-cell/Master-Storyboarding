# 视觉生产与资产调整

本文件是项目规则的职责细则；适用范围及默认流程以 [项目总规则](../../PROJECT_RULES.md) 为准。只在本轮职责或明确选用的分支内读取。

## 导演稿之后的生产顺序

声音参考是可选能力，仅在用户明确提出或选用时启用。用户未提出时，交付中省略声音参考，不主动询问、推荐、创建声音清单或列“未提供／待确认”占位，也不因缺少声音参考或声音目录阻挡后续流程；对白、环境声和既定配音安排按原稿处理。

导演稿确认后，可由用户按需选择本机 `blender-previs` 白模步骤，默认关闭；关闭时沿用下面的原流程。开启时先按确认镜号提取场景、人物站位与动作状态、机位运镜，再复用同一场景的权威模型/布局版本做逐镜调整。默认本机 Blender 5.2 渲染；仅本轮已明确授权云执行时可显式选用真实云端 Blender（按所需功能的原生证据验收，不按版本号一刀切），按项目接入的运行位置与原生字节证据登记，不按镜头重搭房间；固定家具、建筑与尺度保持，剧情状态覆盖只写逐镜副本。白模检查通过并经用户确认后，按准确镜号交给 `storyboard-director` 作为空间构图参考，人物、服装与场景外观仍取已确认母图。白模技术通过、用户通过空间参考、生图授权和成图确认分别记录，不自动流转。入口与登记用法见 [白模项目接入](../../skills/blender-previs/references/项目接入.md)。

导演稿与资产图确认后，先由 `storyboard-director` 按导演稿检查并按需补分镜图，再进入 `voiceover-to-video-script` 编写视频提示词。重点检查复杂动作的关键姿态、需要精准控制的表情，以及人物与物品的空间关系；不等视频提示词写完或生成失败才检查。

分镜图默认使用竖屏 **9:16**，生成与交付时核对实际画幅；用户另有明确指定时按指定执行。此默认不改变人物板、产品资料板或原始参考的画幅；它们转作分镜画面时须按 9:16 重新核对构图，不能把横图直接标为竖屏分镜。

检查覆盖本轮导演镜头，实际出图按需。素材足够就记录复用；确需补图时沿用开工授权，统一入口由执行者实看、自查并按准确镜号和用途采用，再连同资产图交给视频阶段。兼容人工流程才按原规则请用户确认补图。补图继承导演拍法，动作时间过程仍由视频提示词承载。

剧情使场景出现后续仍需保留的可见变化（如空桌摆满菜、礼盒打开或移走、布置或损坏）时，先按[剧情后的场景状态参考](../../skills/storyboard-director/references/image-continuity-hard-rules.md#剧情后的场景状态参考)建立并审查对应状态图，再供后续镜头实际引用；基础环境图不能继续作为与新态冲突的活动全景参考。沿现有导演、补图与视频 JSON 记录，不新增平行状态台账；缺图可写待制作／待审候选，不能提交生成。角度、对白或普通走位而场景未改变，不触发每镜补图。


## 资产图需求判断

故事登记不等于出图任务。简单一次性配角可完全无需资产图，用明确提示词描述即可；身份、服装与连续性确需控制时再选单图或完整人物板。环境优先保一致并留充分覆盖余量，四图默认合理；可按实际覆盖少补，但不追求临界最少。新资产表和实质修订按 [资产图需求判断与检查](../../skills/creative-director/references/asset-image-necessity.md) 填写处理结论及判断依据；只有“需要制作”进入新制清单。交付前只检查有无跳过这一步，不增加重复审核。历史确认包兼容读取，不批量改写。


## 用户调整资产图需求

普通剧情物品（PROP）允许没有参考图时按名称、剧情用途及用户生成方向直接生成候选，有品牌名也不自动归为广告产品。外观由用户审图决定，不声称已核对实物。此规则是普通物品对真实参考要求的例外；广告产品 REAL_PRODUCT 仍以真实参考为准。

用户可在项目资产网页删除、恢复或新增资产需求。删除表示本项目不需要该资产图，保留原故事和素材文件，不作为待补缺口；恢复重新进入制作清单。新增必须核对有效故事段落和具体出现方式，用户确认即为该范围的新需求，不伪称原片已包含该物件。网页将决定持久化到 `04_资产/资产需求调整.json`，同步生成 `当前资产需求表.md`，保留修订与原选图记录；不修改已确认编导正文。

当前图片制作白名单由已确认叙事包和用户明确的资产调整共同决定。后续编导、导演、分镜和视频准备必须读取这份现行资产表；导出清单的 `asset_requirement_decisions` 和交接说明携带取消项、新增出现位置及拆分关系。新增只确认需求，不批准图片、生成费用或新的整段剧情；出现位置未核对时不能加入。上游变动使引用失效时停止相关项并核对。多个独立物品不得因用途相同合并成一个选图对象。

当前资产清单 `04_资产/当前资产清单.json` 是下游唯一入口：状态（要出图／无需独立图／待定／用户不需要／已拆分）、在场区间和图片有无都从这里读。它是可重建的方便快照；读取和门禁以当前已确认叙事包及资产 manifest 重新派生的有效条目为准，不能让旧快照继续携带候选或已替换图片。素材必须引用具体 `confirmed_outputs`：有多个版本时写明 output ID，不能按文件名猜服装、状态或用途。取消资产图不删除故事物件：**已取消出图或被拆分的资产仍可作为故事事实保留引用，但不得作为素材或出图引用——素材清单只放状态为“要出图”且有已确认母版图片的资产，已拆分的改用子项，没有图的人物或物件只写在镜内过程或动作文字里。** 资产被取消、恢复或新增后，用 `python -m scripts.core.asset_refs --project <项目> --scan <AST-ID> --write` 产出受影响位置清单（只报告、不自动改稿），再按清单改当前候选；提交素材前用 `--require-final-image AST-ID@OUTPUT-ID` 核对实际选择，状态、确认输出或文件不符都直接阻塞。已登记最终人物板的造型还须通过最终规格检查。导演 Markdown 阶段用 `python -m scripts.core.story_sources --project <项目> --shot-plan <导演稿>` 核对引用可追溯性（已取消／已拆分告警，未知编号报错）。
