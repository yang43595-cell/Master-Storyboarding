## 问题与修正留档

项目遇到可复现、可能反复发生或影响出片的问题时，执行者在本轮收尾前主动留档。已授权的修复、优化和规则调整随改动一起记录，无需单独请用户确认。留档只描述本轮处理和证据，专业方法晋升或扩大改动范围仍按原授权。仅影响单个业务项目的故障或返修记在该项目现有任务或回执文件里，交接时给出准确路径。涉及仓库共同流程、校验、跨阶段交接、历史兼容或取舍的决定记在本文件。普通错字、排版和能从差异直接看明白的小修沿用现有任务记录或 Git 提交说明。

动到已有行为前，以待改文件名、入口、函数名、字段或具体报错在本文件定向检索。业务项目续作时同时查该项目现有任务记录或回执。只读相关条目，核对现行规则、代码和测试。查不到时，沿目标文件的 Git 历史核对已有依据。若新方案与旧决定冲突，先查原问题是否还存在，再说明要保留、替换或废止什么。新的决定链接旧条目，旧条目追加状态注并指向新的现行出处。

### 记法约定

- **背景与原因**：具体症状、触发条件和已证实的根因。未查明时注明待核。
- **决定与边界**：采用的做法、原因、影响范围，以及必须保留的检查或兼容行为。若否掉了容易被重新提出的方案，简记后果。
- **验证与依据**：写实际复现或回归结果，以及当前规则、代码、测试、任务或提交的准确定位。未实施或未验证的部分如实标注，后续有结果再补。

同一问题沿已有条目补充，正文写上可用于后续检索的文件名及准确入口、函数或字段。现行规则仍写在原规则文档，这里只留背景、取舍和证据。交接只带相关条目的链接和本轮差异。发布或提交对应改动时，记录随改动进入同一分支或工作树，供新会话查阅。

依据引用的文件若日后佚失，就地把链接降为纯文字并标注「原记录已佚」与核对日期，保留原文件名，不猜测、不改指其他文件。

决定被后续规则或实践取代时，不改写原条目，只在条目末尾追加一条「现行状态注（日期）」，写明哪部分已被取代、现行出处在哪；未被注明的部分继续有效。

### 隔离运行依赖只能由当前解释器持有（2026-09-21）

- **背景**：仓库同时被两个解释器使用——项目 Python 3.13（测试与确定性工具）和 Codex 内置 Python 3.12（视觉资产库服务）。

  一次全量测试从 363 通过变成 97 失败/258 通过，资产 schema 校验统一报"运行结构化合同校验需要 jsonschema"。

  依赖清单哈希）且全部匹配才使用；带 stamp 但不匹配一律弃用（绝不试探性加载）；没有 stamp 时才用当前解释器起隔离子进程
  逐个 import 目录里的顶层包，要求解析结果确实落在该目录内。新增 `scripts/install_runtime_deps.py` 作为唯一安装/登记入口：

- **为什么**：两个解释器共用一个绝对路径时，"可用性"是运行时的属性而不是目录的属性；只有让每次使用都按当前解释器验证，
