# 制作优化台账

本表跟踪用户反馈、已采用的修改、待优化建议和实际验证。开工先定位本项目相关阶段和待验证项，执行细节沿各行链接回现行规则。做项目优化时再读对应证据和 [决策记录](decisions.md)。相同问题更新原行，新增问题才加行，保留原证据及历次验证结果。待优化建议供排期，具体改动按本轮任务范围执行。

## 审计发现的待优化方案

| 优先级 | 触发问题 | 最小改法与验收 | 状态 |
| --- | --- | --- | --- |
| 高 | 引用转换、文件和本地命令校验在平台操作之后才报错 | 把能确定的本地失败放到创建、上传或提交之前。用历史错误输入验证无外部写入。 | 待实施 |
| 高 | 媒体转写和探测反复查解释器、依赖与 PATH | 交接复用本轮已核的解释器、ffmpeg/ffprobe 与 PATH。以同机后续步骤是否一次起跑验证。 | 待实施 |
| 高 | 准备包装入局部任务未用依赖，旁路变更也使它失效 | 将范围收窄到准确镜号、输出和传递依赖。用相关变化应拦、无关变化继续做对照。 | 待实施 |
| 中 | 长时间持有整画布快照，与异步更新冲突 | 短化读写窗口，保存前只核相关变化，保留并发冲突保护。 | 待实施 |
| 中 | 用唯一控件判断所有页面是否就绪，遇变化整页重开 | 用已验证的真实就绪条件核原目标，保留同一任务身份与有界恢复。 | 待实施 |
| 中 | 试读和接缝问题到出片才发现 | 沿 C02/C05/C06 的现有自查提前挑高风险段实测，验证发现时点与同因返工次数。 | 先随现有检查复测 |
| 中低 | 同一媒体可能反复跑转写和取证 | 先核是否同源同配置再复用既有完成回执，保留新音轨或新范围复核。 | 待实测触发频率 |
| 低 | 选用单个知识文件时仍重复全包散列 | 已知单次约 9 毫秒。先量累计调用规模，出现实际影响再处理。 | 暂缓 |
