# 编导 Skill 提示词优化方案与执行记录

日期：2026-11-05。

授权依据：用户在当前对话收到六项优化建议后要求“出一个详细的修改方案，然后执行”。本轮只修改编导方法、入口与直接依赖；不写业务稿、不操作审核站、不生成媒体、不修改外部 Vault。

## 修改目标

让执行者先理解本轮创作任务，再按适用条件核对来源、设计故事及产品接入。保留故事因果、人物反应、情绪变化、动作交互、产品真实用途、来源追溯、版本与人工确认边界；减少任务分支混用、个案泛化和重复操作说明。

这些修改依据现行文字的歧义诊断，尚无新旧提示词的真实成稿对照；不承诺质量或 token 节省比例。

## 逐项修改

| 项目 | 当前问题 | 具体修改 | 完成判断 |
| --- | --- | --- | --- |
| 1. 任务类型 | 通用入口以“有对白就核音频、字幕、画面”开头，原创条件在后文 | 在 Skill 入口前置原创、授权改编、原样复现的判定；混合任务按具体内容分别处理。原创依据需求和锁定事实设计，原片声画核对仅覆盖涉及原片还原的部分 | 无原视频不阻止原创；保真范围不因允许原创而被重写；不新增必填字段或固定结构 |
| 2. 对白修改范围 | “已核台词不得润色”可能把核对来源等同锁定 | 对齐 Skill、最低方法、对白合同与检查项：原样任务及明确锁定/已确认对白按其范围保留；本轮获准修改时保留原版与来源，在新修订改动 | 来源准确、是否允许修改与是否确认分别判断；不自动授权改写或伪造来源/确认 |
| 3. 个案范围 | 整理前发、护理等待、正向用后效果、去膜等经验可能跨产品套用 | 改成通用的使用前提、真实耗时与关键过程条件；护理动作仅作有条件示例；效果描述须由本产品资料支持；只展示的剧情不自动补完整演示 | 保留真实用法与连续性；不继承其他产品时长/效果；不新增产品宣称许可 |
| 4. 创作自由 | “最小充分改写”与可选植入路径的检查可能笼罩原创 | 区分局部返修、保留原戏的植入和原创/获准重构；最小改动只约束对应任务，完整创作仍围绕目标、阻力、选择、后果；可选植入检查限定在选用该路径时 | 可设计必要铺垫、事件和反应；保留原样任务与确认内容边界；不固定购买/赠送/露出结构 |
| 5. 正文密度 | “像详细小说”可能诱导修辞和无效动作扩写 | 改为可连续阅读、可理解和表演的故事正文；保留影响行动者、因果、持物、先后与情绪转折的必要细节 | 不增加字数、动作或情绪配额；不把剧情压成梗概，也不越界设计镜头 |
| 6. 渐进读取 | 创作主干含长篇候选治理、旧 Markdown 与飞书分支，确认/交付说明多处重复 | 主干保留条件导航和必要约束；候选/案例细节移到按需参考，旧对白交付/飞书步骤移到兼容参考；保持原有主合同入口与适用锚点 | 正常新稿不被要求执行旧分支；条件能力仍可定位，来源/确认/候选隔离保护保留 |

1. 先保存本方案，核对当前工作区和依赖；保留已有未跟踪文件。
2. 修改入口、最低方法及对白合同，并迁出条件细节。
3. 同步检查清单、压力场景和内置专业方法。
4. 固定新方法版本与 hash；仅更新该文件的 manifest 项，保留原上游采集时间、修订与历史批准基准。
5. 运行结构、引用、方法加载与相关现有回归；失败按具体原因修复，不降低校验或伪造批准。
6. 连读最终差异，核对六项目标与保留约束，将实际结果补在本文末尾。
