# 生成分段流程修复与验证

## 已核根因

基于 `main` 的 `6fdad89479a588802259550735377f0dc6c9c9c4` 独立修复，不修改独立仓库整理 PR 的分支。

业务工作区临时脚本 `build_generation_segments.py` 使用固定 5–15 秒窗口、约 11 秒代价函数，并含场景编号特判。输出同时将模型标为未核实。它没有按现行方法先核当前模型承载能力和真实连续边界；脚本对段长的通过检查只验证自身设定，不能证明符合用户流程。该项目专用脚本和私人素材不属于源码仓库，本次没有上传或覆盖它们。

现行项目规则和视频方法已经明确连续事件先合并、普通切镜不自动拆段、连续拆段须有实际共用切点参考。仓库退役 `production_plan` 的同场景检查不能覆盖现行 JSON；现行正式采用只检查源版本、镜号与续跑对账，未检查新生成段为何在同场景拆开。这是技术入口的缺口，不是规范缺失。脚本与入口缺口说明流程失守，不能单凭它们断言某次模型画面跳变的唯一原因；具体成片仍须核提交时实际输入与结果。

## 修复范围

- `generation_boundaries` 只读检查现行 JSON，不自动分段、不固定上限、不重写导演、不产生新图片。
- 同场景边界绑定准确导演字段原文；模型超限须有当前选择、真实能力取证字节、内容估时和实际段参数。具体执行限制也须有证据。
- 连续拆段的源材料及实际交付必须引用两侧正确状态/字节/用途，并覆盖实际尾镜和首镜。基础环境图不自动算切点，合法共用图、不同机位同状态组和经核实的首尾帧路径保留。
- 同批实际交付的前驱节点与事件关系不能推翻源连续边界；部分交付不会机械要求重传未包含的前段。
- 接入正式采用与画布源核对；旧只读历史比较不变，候选仍可保存真实未决项但不能冒充检查通过。保留已有复合源快照入口。
- 合成旧测试补足来源场景/镜号，不以修改真实素材或伪造用户确认满足检查。

## 独立审查修复

1. 合法前段 `end_frame` / 后段 `start_frame` 被误拦：改为按侧接收，逆侧仍拒绝。
2. 同镜长对白完整句末不能定位：允许承载限制下的准确 `audio.dialogue.<index>.text`，不把句末自动当新事件。
3. 桥图用途缩窄到非切点镜头：源与实际输入均核首/尾镜覆盖。
4. 将后段重新标作新事件绕过原生切点核验：绑定源前驱、实际节点、事件与顺序。
5. 完整 `validate_submission` 原先只核源能力，未绑定实际交付参数：现在逐段核模型、参考模式与生成时长；支持既有参数别名，但别名不得冲突。自填 `duration_bounds` 不能覆盖源已核上限或改写源时长。
6. 完整入口原先把未同批上传的真实前驱当未知节点，删掉前驱另起事件反而可通过：现在只读加载已登记且字节可核的准确历史节点，核同项目、同目标、同模式、同源修订、参数与出边参考。保留当前 `drafts`，不重传前段、不生成确认。只核所需历史节点及当前已加载节点间的循环，不递归重跑整条历史或无关旧段。

第 5、6 项由第二轮独立复审在完整入口复现；此前局部测试通过不能代表完整路径已覆盖。新增 `test_generation_submission.py` 同时通过正式与私有候选入口测试合法别名、合法部分交付、参数替换、删前驱、错节点/事件、过期字节、错项目/目标/模式/源修订、循环及无关历史。

以上均有合成正反例。声明一致性不等于看图、真实平台能力、批准或成片验收；原有图片证据、原生输入、用途确认与参考组门禁继续执行。

## 验证与边界

运行 `python -m pytest -q -rs -c config/pytest.ini` 和 `node --test scripts/tests/*.cjs`。准确最终结果在本 PR 说明记录。使用 Python 3.12 的既有隔离依赖和 Node 24 / Zod 3.25.76；没有为测试新增生产依赖。

本修复没有重生成视频、修改项目确认、变动素材权限、覆盖历史稿、发布审核站点或自动合并。已存在的错误分段不会被程序静默合并。实际项目下一步应依据准确导演、真实节奏、当前平台能力和已确认参考另出受影响修订，再按原流程送审。
