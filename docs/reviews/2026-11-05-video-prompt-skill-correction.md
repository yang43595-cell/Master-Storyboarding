## 目标与范围

让写稿、画布交付、生成、查询／下载各走适用流程；统一开场状态、素材职责、时长与自查的口径；把产品个案从通用方法移出；修复剧情内实体屏幕文字被当作画外叠字的已复现误报。

保留以下现行要求：JSON 是唯一业务稿；来源与对白可追溯；导演决定不得在视频阶段暗改；已确认稿另建修订；产品使用真实参考；逐段完成后仍做全片检查；统一入口在指定画布草稿保存和刷新核对后停止；上传、生成、费用和重试遵守既有授权。

每个独立生成段仍须自包含，分别保留必要身份、光线、声音与不生成叠加文字的约束。精简只减少执行说明和同段同义复述，不删除这些控制。

不修改真实业务项目、原始媒体、历史批准、外部 Vault、全局规则或其他任务的资产工具修改；不操作网页、不生成媒体、不部署或提交 Git。

## 十项具体修正

| 编号 | 当前问题 | 具体修改 | 完成判断 |
| --- | --- | --- | --- |
| V01 产品个案范围 | 通用视频方法残留持碗开封、落碟、0.933／2.933 秒等特定案例细节 | 通用方法只保留动作前后态、接触承托、阶段重复和实际参考片段检查；原案例细节迁至本 Skill 的按需产品参考，并从产品使用分支定位 | 普通产品不加载该案例；对应产品也先核本轮来源、实际素材和授权，历史秒数不成为平台能力或通用步骤 |
| V02 屏幕与叠字 | 内容规则允许剧情内 UI，有限检查却拦截具有具体实体设备的屏内显示 | 在既有检查函数中区分有实体设备锚点的屏内显示与画外文字；同步现有参数化回归和内容压力样例 | “手机屏幕显示：‘通话中’”不误报；泛称屏幕显示、明确字幕／字卡、合法 UI 同时夹带画外叠字仍会阻断；保留时间文字检查 |
| V03 公共条件 | “真实开场”和“真正不变项”口径不同 | 统一为持续条件与真实开场；明确稍后变化写入正文的对应时刻 | “开头站着，随后坐下”允许表达；稍后才拿起的物品不能提前写成已持有 |
| V04 素材职责 | 一个主职责、多项相容职责与额外解释要求不一致 | 统一为一个主要职责，可以有相容附加用途；只有存在串用风险或继承边界不清时补充说明；同步内置素材方法的准确版本与绑定 | 同一张图可同时管身份和已有站位，不为形式强拆图或补解释；身份／年龄／动作相位冲突仍阻塞 |
| V05 正向改写 | “不要夸张表情”示例引入闭嘴、放松等额外表演 | 改为缩小原有表情幅度，并明确保留原定情绪、对白和动作；无法等义转述时保留必要否定 | 正在讲话或紧张的角色不因改写被要求闭嘴、变放松；不新增微表情或导演决定 |
| V06 分段时长 | “两侧生成时长须一致”容易被理解为等长 | 明确两侧模型与模式匹配已选能力；每段各自时长字段相符并各自不超上限，不要求两段等长 | 合理的 8 秒与 12 秒可相邻；同段参数冲突和超限仍失败；不改变分段程序 |
| V07 操作分支 | 查询／下载与写完整创作段串在同一顺序内 | 入口前置四路任务表；创作步骤只适用于写／改稿；画布与生成消费准确现稿；查询／下载按任务身份和结果执行 | 仅下载已有任务不触发重写、重新选模型或全稿内容审查；未保存结果仍不能报交付完成 |
| V08 自查与采用 | 普通写稿“不要求机器报告”，正式采用又需要结构化凭据 | 明确写稿结论在业务稿简记；正式采用按既有入口形成唯一自查报告，稿内不重复抄全表；平台回读仍另记实际事实 | 报告不被省略，也不新增报告体系；报告不在被绑定正文内填自身 hash；不伪造逐稿人审 |
| V09 上传事实 | 候选阶段统一称“实际上传顺序” | 候选称拟上传顺序和准确选中文件；平台操作后核实际上传与原生绑定，复用同一素材映射 | 只写稿不会被描述成已上传；没有真实原生绑定时不得声明引用已验证 |
| V10 重复说明 | 叠字、焦段、自查在多文档反复展开，开场有重复填写位置 | 方法保留详细判断，入口和交付说明保留触发条件与链接，模板保留可直接使用的短提示；公共条件写过的状态不在正文同义复述 | 不新增固定标题、字数或检查层；必要动态、状态和每段约束完整；旧兼容路径仍可定位但不反复穿插主线 |
