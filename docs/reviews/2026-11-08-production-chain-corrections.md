# Master-Storyboarding 制作链路修正报告

审查对象是仓库的制作流程和执行入口。《爱花钱的老婆》R08 是验证案例，定稿保留。报告不把案例未执行的动作列成当前交付任务。

## 项目问题与修正

| 项目问题 | 根因与证据 | 修正及验收 |
|---|---|---|
| 平台能力发现得晚 | 开工记录主要说明交哪个平台和用什么参数。现有红帧代表段在首次写入或批量排版时执行。两处之间没有明确的早期通路验证，可能先完成整批素材才发现原生引用不可回读。R08 的文字卡和图片存活，未证明生成器绑定。 | **本轮已调整** [开工入口](../development/review-to-canvas-entry.md#开工确认单)。先查同平台、模型及引用方式的实际回读依据，缺依据时在批量投入依赖项前试接一次。已验证的写法复用，未授权或没有样段时继续独立工作。下一次用一段原生保存并重开证明通路，正式代表段另核正文和布局。 |
| 分段检查通过，状态问题却到画布才暴露 | `generation_boundaries` 和画布的 `validate_scene_state_references` 校验不同合同。案例 13 段、6 个边界通过前者；四段在后者的真实输入投影被拦。靠末端拦截仍会返工提示词和图。 | **本轮已调整** [视频 Skill 步骤 2](../../skills/voiceover-to-video-script/SKILL.md#执行顺序与停止点)。分段时查三类冲突：段内跨状态、用旧态底图、参考只覆盖部分镜号。再决定补图、重分段或保留审阅用途。保留两个检查的不同结论。下一步可复用现有验证器做写前诊断，先用这三类负例验收，再决定是否接入命令；正式门禁仍保留。 |
| 上游决定未登记时，下游容易各自理解 | 集中确认入口和漂移检查已接通。历史项目可没有 `kickoff`，候选测试也保留独立路线。复测中 R08 项目缺该记录，这是兼容边界，不证明新流程已经执行或校验器失效。 | 新任务协调方先登记现有决定，并列出少量仍待决定项；首次交接检查已登记的准确版本、产品用途和目标。候选允许独立推进，未知的关键身份、产品版本或用途只阻塞受影响的正式步骤。不把旧项目一律迁移，也不新增确认系统。 |
| 人物与视觉质量的问题大多靠观察，结构通过容易被误读 | 当前编导方法已要求原片角色与改编出镜分开，资产链可对明确登记的最终 1×4 拒绝单图，分镜观察已要求生活状态和人/物尺度。它们不能从哈希判断说话人、比例或道具归属。案例中沙发样图的尺度可用，完整首态道具缺失。 | **保留现有窄范围门禁**。首次源片基线在编导处核身份和发声归属；资产计划先登记明确要求的最终输出；首个难镜按完整用途实看，合格范围写进现有观察。下游只引用已核用途。验收例子分别是串绑角色回到编导、旧单图拒入最终板、比例通过但道具缺失的图只供尺度。 |
| 并行批次易被上游规则变化打断，且全景不能代表好用 | 最后三张人物板遇到规则文件变动，既有复核入口保住了成图；R08 全景有图文距离及正常缩放验收缺口。 | **已有机制，重在执行**。冻结每批实际方法，变化时只复核受影响结果；不再建台账。画布沿现有代表段先试排，重开看正常缩放的局部，再铺全片。布局、绑定和用户定稿各自保留证据。 |

## 验证范围

上轮在同一仓库和案例字节上运行 337 项相关用例及 17 个子测试，复核了 13 套最终人物板、34 个引用文件和四段状态负例。本轮回看对应生产入口，修订两处执行顺序，不改程序和业务定稿。红帧实际写入及回读能力仍需在下一次获授权的代表段上验证；离线用例和访问失败均不能推断平台能力。没有为本报告重新打开或制作案例画布。

后续已实现写前诊断。现有 `generation_boundaries` CLI 输出 `scene_state_plan`，与画布消费端共用状态覆盖逻辑；源分段结果和原生验收维持各自原有含义。实际 R08 在源分段通过的同时报出 V06、V07、V10、V11 四个需复核段。126 项分段、状态和画布相关测试通过，其中新增用例覆盖正常计划、同段多状态、旧底图、参考覆盖不足及状态从段中开始。
