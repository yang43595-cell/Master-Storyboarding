# 导演稿模板评审（2026-11-21）

## 结论

现有导演稿模板的骨架是扎实的**执行分镜表**，但还不是一份完整的**导演阅读稿**。主要问题是阅读层与执行层混在一起：视听流（给人读）和逐镜卡片（给拍摄/AI 执行）并列展开，信息重复，且容易漂移。

建议保留现有 JSON 作为业务权威，把 Markdown 导出拆成两层：

1. **导演阅读稿**（2–5 页）：场景头、共用设定、look/tone、连续视听流、关键切点、时间预算、表演与声音提示。
2. **执行附录**（JSON 或按需表格）：逐镜卡、参考 ID、AI 参数、coverage 分级、continuity 表。

## 现有模板实际结构

- 文件头：项目、修订、来源、只读声明。
- 每场：戏核、起/变/落、空间规则（轴线/方向/站位/物件/锚点/光/声底）、视听流、逐镜卡（目的、景别/构图、运动、焦点、起幅/过程/落幅、对白、音效、剪、节奏）。
- 逐镜卡与视听流重复表达同一场戏。

## 优点

- 戏核 + 起/变/落 + 空间规则 + 视听流 + 剪点/信息交接，是一条专业的分镜脊梁。
- 每镜有“目的 → 动作 → 切点 → 下一镜接什么”，不是镜头堆叠。
- 台词和声画切点写在准确位置，镜号可追。
- 共用空间条件只写一次，不逐镜复述。

## 缺口（按优先级）

### P0：影响阅读和执行的基本层

1. **阅读/执行未分层**：视听流和逐镜卡并列，重复且会漂移；阅读稿只留视听流和关键切点，卡片进执行附录/JSON。
2. **没有场景头**：缺 INT/EXT、地点、日/夜、场号、段号（W01–W15）、cast、props、预估时长、累计 runtime。
3. **没有时间预算**：每镜“约 X 秒，估计”，但没有场景/段落总时长、累计 runtime、handles、转场类型，无法管理全片节奏。
4. **没有 continuity 表**：服装、道具、肤质、屏幕方向、时间状态没有一张总表；红裙顺序、门位、左右关系这类漂移就是缺这张表。

### P1：影响导演判断的创作层

5. **没有 look/tone**：缺视觉概念、参考片/摄影、色彩、画幅、镜头倾向、光比、材质；light_source 只是局部光源，不是 lookbook。
6. **没有 coverage/priority**：没有 hero / connective / insert / alternate / safety 的分级；哪些必须拍、哪些可省、哪些是保险，表里看不出来。
7. **没有表演层**：动作写得很细，但 subtext、eye line、pace、情绪转折没有独立位置；purpose 是理性的，不是可演的。
8. **没有声音设计**：只有对白和 sfx，没有 ambience、music、silence、声音转场；scene 级 sound_base 太薄。

### P2：执行与下游衔接

9. **没有 AI 执行字段**：逐镜参考 ID、首尾帧、运动约束、模型/时长档缺失；但这些应进执行附录，不塞进阅读稿。
10. **景别是散文，不是标准 code**：阅读可以，但排序、估时、给 AI 不稳定。
11. **没有转场类型**：只有剪点语义（入/出/触发/信息交接），缺硬切/匹配切/跳切/声音转场等选择。
12. **没有参考/版本层**：lookbook、场景母图、人物板、产品参考与修订号没有在场景头集中列出。

## 建议的模板骨架

### 1. 封面/总则

- 项目、修订、状态（候选/确认）、来源 narrative/asset 版本、总时长预算。
- 一句话视觉概念：类型、基调、参考、画幅、色彩、镜头语法。
- 本片 do / don't：例如“不用对标演员脸”“产品包装按实拍”“不拍正脸的孩子”等。

### 2. 场景头（每场一次）

| 字段 | 内容 |
| --- | --- |
| 场号/段号 | S07 / W09–W11 |
| INT/EXT | INT |
| 地点 | 奢华大平层客厅 |
| 时间 | 日/夜 |
| cast | 林晓、陈默、小宝 |
| props | 合同、离婚协议、红裙、黑色小包 |
| 预估时长 | 本场 36 秒；累计 145 秒 |
| 空间母图 | 客厅正面/反打/夜晚 R01 |

### 3. 共用设定

- 谁在哪、相互朝向、门位、窗位、沙发位。
- 主光方向与明暗、实用光源。
- 环境声底、音乐进入/退出点。
- 摄影机保持哪一侧、轴线、屏幕方向。

### 4. look / tone

- 参考片/摄影/画家（只作视觉方向，不借用身份）。
- 色彩与材质：石材、深木、金属、织物。
- 镜头：焦段倾向、景深、机位高度、运动语法。
- 光：主光/辅光/轮廓/实用光，日/夜差异。
- 后期：颗粒、对比、色彩空间、字幕/水印策略。

### 5. 视听流（阅读稿主体）

- 直接写谁正在做什么，按观众顺序。
- 台词随过程出现一次；在准确词句/动作处写“切向谁/什么景别，看见什么反应”。
- 一句可跨多镜；不为一句一切。
- 关键停留、运镜触发、落幅写在发生的位置。
- 不重复逐镜字段；不写“按原文说完”这类摘要。

### 6. 时间与节奏

- 每段估时 + 本场总时长 + 累计 runtime。
- 节奏曲线：哪一拍快、哪一拍留白。
- 转场类型与理由：硬切/匹配切/跳切/声音先入。
- 给剪辑的 handles：入/出点余量。

### 7. 表演与声音 notes

- 表演：subtext、eye line、pace、情绪转折、身体状态（肤质/疲态/呼吸）。
- 声音：ambience、music、silence、画外音、声画错位、转场声音。

### 8. 执行附录（逐镜卡）

- 镜号、景别 code（WS/MS/CU/OTS/INSERT）、机位/运动/焦点、起幅/过程/落幅、对白/音效、剪点、时长。
- 参考 ID：人物板/场景母图/产品/分镜图，标明“定什么/不定什么”。
- AI 参数：模型、画幅、时长档、首尾帧、运动约束、生成风险。
- coverage/priority：hero/connective/insert/alternate/safety。
- continuity：wardrobe/props/skin/screen direction/time。

### 9. 一致性检查

- 视听流 ↔ 逐镜卡 ↔ 时长表 三方 diff。
- 场景头 cast/props 与逐镜卡一致。
- 门位/左右/屏幕方向跨场一致。
- 参考文件版本/hash 与场景头一致。

## 与现有 skill 的衔接建议

- 不新增业务权威：JSON 仍是唯一权威，Markdown 只读导出；阅读稿和执行附录都从同版 JSON 导出。
- 不恢复 V3 manifest/gate/orchestrator；只在现有 v4 字段上做“阅读稿/执行附录”两种投影。
- 现有 v4 字段可复用：scene.audiovisual_flow、space_rules、shots[].camera/take/cut/audio/rhythm。
- 新增字段要克制：优先用现有字段承载；确需新增时只加“场景头/look/coverage/continuity”这几类，不铺全套制片系统。
- 阅读稿控制在 2–5 页；短项目不为页数删对白/动作/切点；长片按场分页。
- 自动检查放进现有 validate/自查入口，不新建平行 QA 账本。

## 验收清单

- [ ] 阅读稿能在 5 分钟内读完，知道每场戏怎么发生。
- [ ] 场景头能直接回答：哪场、哪里、日/夜、谁、什么道具、多长时间。
- [ ] look/tone 能让摄影/美术/AI 执行者知道“要什么质感”。
- [ ] 视听流的每个“切”都能在逐镜卡找到对应镜号。
- [ ] 时长表能加出全片总时长，和视频分段一致。
- [ ] continuity 表能查出服装/道具/肤质/左右方向的漂移。
- [ ] 执行附录能直接交给 AI 或摄影组，不需要再猜参考和参数。
