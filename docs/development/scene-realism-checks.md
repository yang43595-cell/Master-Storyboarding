# 场景真实感的候选检查

本项是项目内的待验证检查能力，不是已验证的创作知识。没有修改 `knowledge/`、知识 manifest 或动态规则；也不改正式稿、采用记录、网站或画布。程序不播放视频、不听声音、不调用模型、不批准生成。

## 先查内容，再用小工具核声明

沿既有导演稿、视频稿及自查记录核四件事，不另建生产计划：

1. **事件影响到谁。** 核附近的人原来在做什么、能否看见/听见触发、察觉后怎样回应。近处面对冲突却完全不受影响，和所有人提前、整齐复制反应，都是要查的反例。远处背向且听不见的人可继续活动；克制、僵住与有依据的齐声回应也可成立，不强制所有人错峰。
2. **物件怎样到这里。** 核数量、位置、持有人及来源，追踪取得、接触、承托、交接和最终落点。出画不等于消失，切镜不重置。能成立的画外取物不必强行补镜，关键取得过程须让观众理解。
3. **现场听起来怎样。** 核可听声源、远近/遮挡及事件前后的持续或变化。冲突不自动等于全场静音或集体尖叫；有意静音说明拍法依据。文字环境声安排不是实际听核结果。
4. **前后镜能否接上。** 核入态/尾态、动作相位、人物自身左右、持物、衣饰和空间锚点。区分反打投影与实体换边、真实时间省略与无依据瞬移；检查接物等动作是否被重演。

## 可选的有限声明检查

在同一候选 JSON 的制作信息中，可用顶层 `scene_realism` 数组临时记录高风险段的结构化核对。它不是模型正文，也不是第二份权威剧情。使用时须覆盖本文件被识别的所有段、同序、段号唯一。只检查所选局部文件时不能冒充整片；真实前驱不在文件时保留未验证，不改成 start。

```sh
python scripts/check_video_prompt_focal_intent.py <当前候选.json> --check-scene-realism
```

不加开关保持原有焦段与正文污染检查范围。加开关后，缺记录/错误格式/旧正文指纹为 `unverified`；明确声明矛盾为 `needs_revision`；没有发现声明矛盾只为 `consistent`。CLI 分别用退出码 2、1、0。混合缺口时保留全部发现，矛盾优先返回 1。结果永远不声明视频或声音已验证。它不是新的采用、上传或生成门禁。

### 记录字段

每条对应一个已存在的 `segment_id`：

- `prompt_sha256`：现行检查器取得的提交正文，仅去掉首尾空白后，以 UTF-8 计算 SHA256。可调用 `scripts.core.scene_realism.prompt_digest`。不能用旁注、参考说明或另一个版本计算。内部空白保留；沿用原正文 alias 冲突检查。
- `events`：每个来源事件的 `event_id`、`description`、本段内计划秒数 `at`；角色靠听觉察觉时另写 `audible_source`。秒数只是计划，不是假称测得的时码。
- `reactions`：每人一次本段重点触发的 `person_id`、`event_id`、`prior_activity`、`perception_basis`、`perception`（seen/heard/not_perceived）、`perceived_at`、`response`、`response_at`。未感知时后三项均为 null；已感知但没有可见反应时，后两项为 null，并写 `no_visible_response_reason`。多人同刻同动作须逐人给出 `coordination_reason`，不自动改为错峰。同人多次触发仍在自然语言自查核，不虚造身份来满足此工具。
- `objects`：每件关键物的 `object_id`，`before`/`after` 中的 `count`（非负整数）、`place`、`holder`（无人持有时 null）。状态改变时写 `change.event_id`、`count_delta`；位置/归属改变写 `path`，不同持有人交接另写 `contact`。这些都是对真实正文的核对声明，不是脚本推断出的动作。
- 上述三组无适用项时仍写空数组，并写对应 `events_not_applicable`、`reactions_not_applicable` 或 `objects_not_applicable` 的实际原因。未知或漏盘点不算不适用。
- `environment_sound`：mode 为 present 时，用 `sources` 数组逐项写 `source` 与 `behavior`（事件前后保持或变化）；mode 为 intentional_silence 时写 `reason`。
- `boundary.kind`：start 只用于当前完整范围的真实开头；后续为 continuous、time_jump 或 new_scene，写 `from_segment_id`。后两者须有 `basis`，不能只改标签解释错误。`entry_state`、`exit_state` 是同一坐标下的非空键值对象，如 `{"left_wrist":"bracelet","cup_action":"held"}`；前后持续项用同一键名。连续段比较相邻两侧状态及物件；时间跳切/换场放开跨边界相等比较，仍保留段内因果核对。

可运行的完整合成正例和修改负例见 `scripts/tests/test_scene_realism.py` 的 `fixture` / `two_segments`。测试夹具不作生产素材、不作用户批准。字段可写错、可漏掉人物、可与自然语言不符，所以声明通过仍须回正文逐项核实，不能用它自动发现全部语义问题。支持的物件属性只有数量、位置、持有人；其他细节由内容自查承担。

## 实片复审和进入知识库的条件

有已获准检查的实际片段后，沿既有视频质检记录绑定准确文件/hash、镜号、时间范围，正常速度连放并听核；手物交接、遮挡与切点再密帧检查。记录应该怎样、实际看见/听见怎样、补法及修后复核。只抽帧不判动态通过，只读文字不判声音通过。

先用一段明确事件及旁人、一段取物/交接、两段相邻镜头做有针对性的复核。没有适用媒体就留未验证，不为完成检查自动收费生成。保留通过、需修、未验证、不适用及具体原因，不能只汇总测试数量。

只有实际案例证明有效、反例与合理例外都被核过，并且适用范围可复查，才在另一次获准维护中考虑写入 **Master-Storyboarding 项目自身知识库**。本轮合成测试只证明程序在声明事实上的行为，不满足知识晋升或真实成片通过条件。
