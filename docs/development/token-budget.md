# 生产读取、计量与停止

执行者操作说明。`prepare` 只写本地输入文件，宿主对话仍保留原有上下文；不能把文件字节上限当作模型输入上限。

## 视频提示词直接执行

当前视频 Skill 直接读取原始资料、编写完整分段提示词并自行检查；不使用旧局部准备包或逐块索引、编码、登记和导出流程。旧命令及候选格式已退役，历史证据保留但不作为当前执行说明。见 [Skill 入口](../../skills/voiceover-to-video-script/SKILL.md)。

## 等待与工具回传

本节适用于本项目生产、维护和已授权的子任务协调，不依赖 `prepare`。这是执行者的工具使用约定，不是宿主强制拦截或硬 token 上限。

- **一次有界等待**：使用当前宿主已提供的等待/完成通知机制。嵌套等待时，外层允许执行时间应覆盖内层的有界等待；例如内层等待最多60秒时，不设置外层1秒提前yield。遵守宿主等待上限和沟通间隔，不用无限等待或持续循环阻塞来规避模型调用。确实返回运行中时，只续接该调用，不另起同一等待。
- **无变化不重复取进度**：等待超时不等于出现新问题。不因超时就叠加 `read_thread`、列全部agent、重复读取日志或中间产物；需要继续时沿用同一等待渠道及其游标（若支持）。已有完成通知即可恢复验收。用户问进度、子任务报告阻塞、出现需核验的新结果或真实异常时，才定向查询。必要沟通说明当前已知状态，不为凑更新内容重新取数。
- **返回前筛选**：历史恢复先取当前结果和准确来源，缺失决定再回查对应轮次；默认不附历史工具输出。脚本可完整校验本地文件，但向模型只回本轮对象、结果、差异位置和必要原文；不整体序列化工具返回对象、完整资产历史或全工作树列表。所选工具的安全和接口要求优先。
- **对齐输出上限**：按外层总额度分配各内层输出，多个结果先汇总再返回。首次必须阅读的长文按章节连续读完；发生截断只补缺失范围，不重打整批。失败先回失败列表和一个代表性异常，完整日志留本地，需要时再定位读取。

验收分开记录：本地检查能证明入口与用法已改，不能证明宿主已执行或节省了多少费用；下一次真实委派再按逐response日志核对等待/查询次数及累计输入，保留必要反馈和独立验收。不为验证等待方式额外启动付费子任务。

## 计量

`scripts/session_usage.py` 仅提取原始日志中的逐 response 用量，通过 `(thread_id, response_id)` 去重。读取 `compacted.latest_token_usage_record` 可补入压缩调用，但不读取/输出压缩正文。忽略 UI 的 `token_count` 快照与累计计数，避免跨轮归零、重复播报、窗口分片和压缩导致误算。

```powershell
py -3.13 scripts/session_usage.py --log '<原始日志>' --turn-id '<准确turn_id>' --output '<用量明细.json>'
```

同一 turn 跨多个日志窗口时重复 `--log`；用 `--through-ordinal` 固定截止，用 `--after-response` 只计算指定起点之后的已落盘记录。保存这些边界才能复算。结束前记账必然遗漏尚未完成的当前答复，报告须写清截止；必要时在结束后补读原始日志。旧日志没有逐 response 记录、字段缺失或尾行未落盘时保留未知，不回退成 0 或把上下文估计充当费用。

- input 包含 cached input；未缓存输入 = input − cached input。
- output 已包含 reasoning output；不能再次相加。
- 累计 token、单次输入、文本编码计数、账单费用是不同指标。
- 订阅额度换算与实际费用缺少证据时输出 `cost=null`。
- 宿主系统提示、工具定义、历史/缓存、文本与图像的准确拆分若日志没有提供，保持未知。原始日志本身不保证记录所有后台请求。

## 受控试跑与停止

开始前声明交付范围、准确输入、测量起点、最大单次输入、累计 token 和模型调用次数。下面 **80,000 / 600,000 / 8** 仅为一次小范围试跑可采用的预算示例，并非模型上限或长期默认值。预算按任务需要在启动前选定；达到阈值不再开启下一批工作。

```powershell
py -3.13 scripts/stage_context_cli.py prepare ... --usage-log '<本轮日志>' --usage-turn-id '<本轮turn_id>' --max-input 80000 --max-total 600000 --max-requests 8
py -3.13 scripts/stage_context_cli.py ensure-prepared ... --usage-log '<本轮日志>' --usage-turn-id '<本轮turn_id>' --max-input 80000 --max-total 600000 --max-requests 8
```

门禁检查本轮任一次已观测输入、累计 token 和请求数；超过/达到阈值，或必需计量未知，即失败退出。生产开始前、下一次读取/产出批次前检查；同一原因连续失败两次也停止。停止时报告产物、源缺口、用量、失败原因和未完成步骤；不自动提高预算或循环重试。

这仍是**检查点门禁**：项目脚本不能取消宿主正在进行的模型请求，也无法强制宿主在每个工具调用前执行检查；可能有一个在途请求的超额。首次检查只能在宿主已有用量记录后进行。若要求精确硬预算，需要宿主原生支持，不能在本仓库伪造保证。

生产只进行“输入读取 → 写一个候选 → 直接检查/必要修正 → 交付”；仓库审计、GitHub 调研和计量工具开发属于维护任务，不混入生产计量。独立任务可使用已有宿主空白上下文能力；同一候选返修优先保留有效证据，遇到预算停止再报告。不要以盲目压缩替代准确源文件。

## 审查交接增量化（2026-09-10）

默认当前对话自查、修改和复核，不建立审核交接包或模拟双角色。视频提示词获明确独审授权时直接交准确候选与来源，不创建本节的准备包或审核包；按审核方法的直接审核分支执行。以下包化文件交接仅用于仍采用准备包的阶段且用户明确要求独立审核时，合同与文件格式统一见 [审核方法](../../skills/stage-reviewer/modules/review-method.md)；禁止用重复转发聊天维持连续性。

使用准备包的生产入口（不含已改为直接执行的视频提示词 Skill）先输出本轮唯一 `task_basis.json`（含准确来源版本、交付对象筛出的冻结验收集、本地规范/Profile 指纹及方法清单）。独立审核默认只维护当前 `review_packet.md` / `review_scope.json`；轻复审给 `--previous-review` 的四项发现，候选变化时用 `--change-summary` 说明实际改动和直接影响，不要求基线、生产者回复、编号或版本目录。没有旧正文就不假称计算了 diff；原审核者按当前稿和准确来源复核。未决发现必须逐条回应，遗漏不能当作解决。

仅用户要求正式留档时启用 `--formal-archive`，使用 `review_rounds/<内容指纹>/`，正式复审仍要求 `--previous-review`、按序的 `--baseline`、`--producer-response`，输出真实 diff 和未决 ID 回复。旧完整调用兼容，缺失旧保护的输入不能静默降级。两种模式的 `production` / `skill_contract` 都使用本轮对应冻结清单；实际来源、范围、方法或标准改变须重新准备/首审。新包的实质审核身份不含阅读缓存 key、执行者阅读声明和候选目录；旧仅文件哈希的记录仍保守按旧哈希比对，不补造历史身份。详细格式和边界见上列审核方法。
包仍受 12 KiB 上限，增量 JSON 受 64 KiB 上限；超限停止，不截断。当前候选和显式外部证据属于额外读取，不能把这两个文件大小称为总上下文上限。正式留档时的目录版本化便于准确引用与追溯，不意味着每轮读取整个目录。文本 diff 暂不支持二进制媒体；这类复审需另定直接对比方案。

这限制的是项目构造的交接输入，不是宿主的历史保存或模型请求本身；`followup_task` 不等于清空原 agent。未进行新的视频提示词生产或模型用量 A/B 试验，不据此宣称 token 节省比例或创作质量改善。

`review-pack` 可沿用同一用量计量参数，并用 `--usage-phase production|self_check|initial_review|revision_review` 标记已观测阶段；它只报告日志中已有的请求，不能清空宿主上下文、取消在途请求或保证每次调用前都被拦截。

官方依据核对：[OpenAI 实用指南](https://openai.com/business/guides-and-resources/a-practical-guide-to-building-ai-agents/) 建议先充分使用单 agent，再按复杂度拆分；其中传递最新会话状态的 handoff 指 Agents SDK 模式，并非本仓库的文件交接命令或 Codex 的工作目录迁移工具。

## 显式受控候选运行：防止省略计量参数

当用户明确要求计量试跑时，由协调方在创建该隔离运行时，把任务选定的要求登记进已有 `candidate_test`，再交给执行者；不能把是否登记再次变成执行者的可选步骤。普通未要求计量的项目仍沿用原行为。

`candidate-test --usage-contract-json <本轮合同.json>` 的合同为：

```json
{"required": true, "turn_id": null, "limits": {"max_input": 80000, "max_total": 600000, "max_requests": 8}}
```

这些数字仍只是示例，必须按本轮任务确定。未知准确 turn 可先登记 `null`：这表示要求已启用但缺证，`prepare` / `ensure-prepared` 会拒绝，不表示免计量。合法宿主证据到位后，可在同运行、同授权下把未知 turn 补成准确值。已确定 turn 不可换；重复配置省略合同会保留原要求，预算只能收紧，不能抬高；不能在同项目更换 run ID 绕过旧要求。

执行入口仍传准确 `--usage-turn-id` 和合法 `--usage-log`；预算省略时使用已登记值，传入值只能更严。缺日志、未知用量、错 turn、达到预算均拒绝。此单 turn 合同不接受换成任意多轮边界文件；原有未启用该合同的边界集合计量方式不变。不要访问被禁止的宿主路径、用合成测试日志冒真实计量，或将检查点说成宿主硬预算。

专业方法阅读凭据仍为执行者声明，不是程序认知证明：必须先让全文工具结果实际返回、阅读后，再单独登记；同一 shell 把输出与登记连在一起不能证明阅读已经发生。自然执行轨迹必须另核这一时序，不能靠文件 hash 覆盖该缺口。


## 计量试验与工作流合规测试分开

协调方先按用户的具体目标区分：验证 token/成本/预算控制，还是验证来源、方法、创作、交接与质量流程。只有明确要求前者，或已有需要控制的异常消耗，才为对应运行初始化必需计量合同；“实测”“盲测”“循环修复”本身不构成每案必须先计量的依据。无法导出宿主用量时仍记未知，不能报告成本节省或计量通过。

错误扩大范围形成的旧受控运行保持原合同、失败和未测记录，不删字段续跑、不改失败成通过。经任务范围核实后，另建明确工作流合规范围的独立候选运行，保新 run/目录身份，不继承原批准或方法阅读声明；这不是用新 ID 绕过仍适用的预算、明确成本要求或异常消耗停止条件。原计量验证单独保留未完成，工作流分支结果不能替它结案。

工作流分支仍核准确来源、实际阅读、产品/素材用途、真实声画事实、QA与批准边界。只有内容确实含声画来源时才要求对应声画核对，ASR安装不是唯一合法核对方法；机器转写不等于听核。离线候选可检内容与依赖，但缺实际平台绑定不得称已可提交生成。Windows专项、旧私有回归样本、特定平台能力等仅限制各自的覆盖，不自动成为每个不依赖它们的编导/导演检查前置。记录可做/未测/明确豁免，不能用“可独立检查”放宽真实制作标准。

测试清单若有目标耦合，应保留旧冻结清单和回执，另建带明确适用范围与原因的新分支；不得直接删原失败项或把未测挪成全局通过。流程、计量、平台提交三类结果分开报告，总范围未全部验证时仍不得宣称全部完成。
