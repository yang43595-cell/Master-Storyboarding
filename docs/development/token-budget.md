## 计量

`scripts/session_usage.py` 仅提取原始日志中的逐 response 用量，通过 `(thread_id, response_id)` 去重。读取 `compacted.latest_token_usage_record` 可补入压缩调用，但不读取/输出压缩正文。忽略 UI 的 `token_count` 快照与累计计数，避免跨轮归零、重复播报、窗口分片和压缩导致误算。

```powershell
py -3.13 scripts/session_usage.py --log '<原始日志>' --turn-id '<准确turn_id>' --output '<用量明细.json>'
```

同一 turn 跨多个日志窗口时重复 `--log`；用 `--through-ordinal` 固定截止，用 `--after-response` 只计算指定起点之后的已落盘记录。保存这些边界才能复算。结束前记账必然遗漏尚未完成的当前答复，报告须写清截止；必要时在结束后补读原始日志。旧日志没有逐 response 记录、字段缺失或尾行未落盘时保留未知，不回退成 0 或把上下文估计充当费用。

- input 包含 cached input；未缓存输入 = input − cached input。
- output 已包含 reasoning output；不能再次相加。
- 累计 token、单次输入、文本编码计数、账单费用是不同指标。
- 订阅额度换算与实际费用缺少证据时输出 `cost=null`。
- 宿主系统提示、工具定义、历史/缓存、文本与图像的准确拆分若日志没有提供，保持未知。原始日志本身不保证记录所有后台请求。

## 检查点与停止条件

用户要求用量、成本或预算实测，或确有异常消耗需要控制时，先固定准确输入、原始日志、轮次、计量起点和本轮预算。预算分峰值输入、累计 token 和调用数。工作流合规测试沿[试验目标与证据范围](../rules/experiments.md#计量试验与工作流合规测试分开)确定适用检查。

首个已落盘可计量请求后检查，在下一批读取、产出、写入或恢复前重查。达到任一阈值、必需用量未知，或同一原因连续失败两次时，停止受影响范围并报告已完成产物、最后可用证据、源缺口、用量、失败原因和未完成步骤。不自动提高预算、换模型、重开执行者、反复 `prepare` 或循环重试。宿主不可见时记用量未知，缺证只阻塞适用的计量运行及该计量结论，独立流程检查仍按本职证据判断。已登记的合同、停止条件和预算保护继续适用。

项目检查点只能检查宿主已经记录的请求，可能有一个在途请求超额。精确硬预算需宿主原生支持。宿主日志完整性、干净上下文、实际等待和用量下降沿执行轨迹核验。合成用量只验证算法和停止行为。将生产、维护、返工和复盘分开计量。同一候选返修复用仍有效的证据，必要原文有缺失时补读准确来源。

## 普通准备的计量检查点

先读[检查点与停止条件](#检查点与停止条件)。已有受控候选合同同时沿[该运行的持久计量合同](../rules/experiments.md#受控候选的计量合同)。

开始前声明交付范围、准确输入、测量起点、最大单次输入、累计 token 和模型调用次数。下面 **80,000 / 600,000 / 8** 仅为一次小范围试跑可采用的预算示例，并非模型上限或长期默认值。预算按任务需要在启动前选定；达到阈值不再开启下一批工作。

```powershell
py -3.13 scripts/stage_context_cli.py prepare ... --usage-log '<本轮日志>' --usage-turn-id '<本轮turn_id>' --max-input 80000 --max-total 600000 --max-requests 8
py -3.13 scripts/stage_context_cli.py ensure-prepared ... --usage-log '<本轮日志>' --usage-turn-id '<本轮turn_id>' --max-input 80000 --max-total 600000 --max-requests 8
```

已启用计量的普通生产在 `prepare` 与 `ensure-prepared` 使用同一日志、准确轮次和预算。首个已落盘请求后检查，下一批读取或产出前重查。

## 直接读取和画布的同一计量检查点

本轮要求计量或确有异常消耗需要控制时，先定准确项目、原始日志、轮次、起点和预算。视频直读、画布批次或恢复沿下列入口复用 `session_usage.checkpoint`，省去准备包和阅读登记。数值是示例，预算由本轮预先选定。

```sh
python scripts/stage_context_cli.py usage-check --project '<项目>' \
  --usage-log '<本轮逐response日志>' --usage-turn-id '<准确turn>' \
  --max-input 80000 --max-total 600000 --max-requests 8
```

首个已落盘请求后检查，下一批读取、产出、写入或恢复前重查。跨轮或主协调与执行者累计用 `--usage-boundaries-json` 明列日志、turn、`after_response`、`through_ordinal`，按实质范围区分生产、返工和复盘。已有[受控候选合同](../rules/experiments.md#受控候选的计量合同)继续限制准确 turn 与预算，不能用多边界替换。

`canvas_readback.py --delivery` 的预检和回读接受同名参数并返回 `run_usage`。正式交付和私有预览继续核各自来源、授权及采用；无必需合同的常规项目仍可省略计量，直接 `usage-check` 缺边界或预算则拒绝。

成功摘要给 scope、首末边界、峰值输入、缓存与未缓存输入、输出、累计量及调用数。逐响应明细用[日志计量](#计量)的 `--output` 写文件。缺字段、损坏尾行或选定轮次无记录时记用量未知，已知小计不能当总量。输入输出与 total 冲突或推理输出超过 output 的记录拒绝。

达到任一阈值、必需用量未知或同因连续失败两次时停止受影响范围，留已完成产物、最后可信回读、失败原因与未完成位置。失败 `stop_reasons` 含实际限值或 `usage_unknown`。不抬预算、换模型、重开执行者或反复准备。检查点仅查已落盘请求，宿主在途请求及实际用量仍需实际日志证明。

## 正常生产的测量窗口

启用计量验证时，下一次有真实生产任务按[逐响应日志](#计量)记录对应窗口。离线检查只验证现有入口和用法，实际用量须有真实日志。不为验证等待方式额外启动付费子任务。

### 资产批次协调

启用计量验证时，下一次正常资产生产顺带记录一个完整的主聊天协调窗口。以首次委派的实际工具调用为起点，到协调方核完准确回执或明确未完成原因的响应为止。按[逐响应记录](#计量)计算未缓存输入，同时记录墙钟耗时、批次数、目标数、通过和未解决数。重复查询按同一个目录、同一个批次回执或同一个原任务身份归组，同一观察范围内业务状态投影没有变化的重复读取计一次，忽略命令耗时、工具外壳和行号变化。等待超时、真实状态变化及一次性完成回执验收分别记录。并行导致的混合工作在窗口里注明。用正在做的业务任务采集，沿用《摇钱树》的已有日志作历史基线。

### 视频提示词局部返修

启用计量验证时，下一次正常的视频提示词局部返修顺带计量。从首次实际读取该返修目标起，到交回本段及受影响接缝的自查结果或明确未完成原因止。记录实际改动及邻接范围、重复读取次数、逐响应未缓存输入 token 和墙钟耗时。同一执行者在该窗口内再次收到仍有效且只为机械核对而取回的同版原文或等价全量工具结果，按重复读取计数。程序内部读取全文只回结论、首次适用原文、新依赖、原上下文已丢失时的必要补读及收尾全片复核单独注明。多个执行者各按真实日志列范围，主聊天和执行者用量可分别记录。混入工具开发或平台另项验收的窗口须注明。用正常生产采集，不为取得对照重跑历史稿。

### 工具失败与恢复

启用计量验证时，下一次正常生产遇到工具报错时，按[原处续作](../rules/execution.md#工具报错与原处续作)顺带计量。从首次失败返回到同一步核实恢复或交回明确未解决为止，记录墙钟耗时、逐响应未缓存输入 token 和重复重试次数。同一操作、目标、相关输入及故障条件都未变，再次执行并证实同因失败时计一次。只读确认原操作结果、条件有实质变化后的复查、不同原因的失败及测试用的反例单列。若维护和制作分属不同执行者，按实际日志窗口合计或分别列出用量，标明后续正常制作的起点。

### 其他已有观察项

启用计量验证时，以下项目用下次正常生产采数。每项各自记录准确对象、起止事件、未缓存输入 token 和墙钟耗时。并行的日志窗口重叠时按响应去重，等待外部决定的时间另记。沿用已有《摇钱树》记录作历史参考。

- **产品演示时长**。从首次核固定演示窗口到已记录可沿用的决定或明确证据缺口。记首次发现冲突的阶段、约定秒数和有依据的估算。若定稿后仍改窗，另记实际重排镜数、仅顺延时码的镜数和返工轮数。
- **资产局部变更**。从收到准确输出的换图或同版退回决定到核完受影响下游。记实际影响范围、被误纳入复查的镜段数及不受影响的已确认输出是否继续可用。
- **并行阶段开工**。每个任务从首次 `prepare` 到该任务的 `ensure-prepared` 通过。记因开工包被覆盖或找错而重建的次数，输入或确认确有变化后的重建另记。
- **原片和字幕复用**。下次正常修订观察同一原片字节、同一字幕证据和同一已核范围是否再次批量提取，记录重复页数。新范围、证据冲突和导演必要的对白落镜核对分别记录。
