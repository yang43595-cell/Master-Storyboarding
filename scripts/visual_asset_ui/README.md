# 拾景视觉资产库：执行说明

入口：`scripts/打开视觉资产库.cmd`。默认地址 `http://127.0.0.1:8766`，仅本机访问。

运行环境使用 Codex 内置 Python / Pillow；启动脚本只启动本次本地服务，不安装依赖、不设置开机启动。
网页缓存和制作记录默认位于执行仓库 `.master-storyboarding/visual-library/`；收藏资产的原文件、索引和说明以知识库 `资产库/` 为准。新上传制作参考保存在本地库 `assets/<ID>/`，项目参考保存在项目内，均不进入 Git。
可通过 `visual_asset_library.py --library <路径> serve` 指定其他数据目录；代码不绑定某部短剧。

## 入库与项目选用

项目页的“白模预览”只读显示 `export-preview` 产出的 Blender 同源模型。支持导演机位、自由观察、俯视、播放/时间轴和起止跳转，辅助路径默认关闭。需要先由白模 Skill 为所选镜头导出预览；来源或配方变化时显示过期。依赖为本地 Three.js 0.180.0（MIT），不连接 CDN。用法见 [白模项目接入](../../skills/blender-previs/references/项目接入.md#同源网页快速预览)，依赖来源见 [Third-party notice](vendor/three/NOTICE.md)。

- 项目“上传参考图”只保存生成输入，原像素与电脑原文件保留；文件和来源记录位于项目 `04_资产/项目参考/<ID>/`，不加入资产收藏。参考图不会成为制作结果或计入交付，制作步骤仍能查看和引用。上传成品及生成结果沿用资产入库与逐项确认流程。
- 新上传的项目参考与成品分开展示。历史图片仅在核对原用途与制作引用后迁移，不按“参考”用途、名字或是否未确认自动移出收藏。

- 外部文件夹导入保留源文件；网页只留缩略图和操作缓存，原图写入知识库 `资产库/`。已连接的项目目录与知识库目录不能反向导入网页。
- 同一来源路径、大小和修改时间未变化时跳过；源文件变化则新增版本，不覆盖已保存副本。不做跨文件内容哈希去重。
- 文件夹导入的分类与用途由路径提供初始建议；上传文件由 6 Luna 看图建议类别。所有历史图默认待核对，不能按目录名自动断言用户已确认。
- 顶部“上传文件”统一接收图片和 MP4、MOV、WEBM 视频。原始输入只存为 `upload_reference`，不进入收藏与知识库资产索引，不能作为成品确认或导出。电脑源文件始终保留；重复选择同一未变化来源不会重复建立相同主体与类型的制作记录。
- 视频取 15%、50%、85% 三个代表画面（最多1600边长）共同识别和制作；短视频末尾无帧时回取首帧，记录采样位置。原视频与抽帧均只作参考。采样不等于完整视频转写，也不保证已看到所有角色或服装；多个不同主体、低置信度或无法判定类型时要求指定主体与类别。
- 自动分类后复用资产图 Skill 的现有任务与提示词准备：人物生成3:4无衣服大头照，服装生成16:9无头无脸人台三视图；可指定其他已有类别。人物1×4仍要求已确认脸部与服装。提示词完成后沿用原有提示词核对、工具/模型与额度授权，再生成并自动回填。准备失败可从制作记录重试，生图不自动重试。
- 此入口的生成结果先按类别规范尺寸并核对实际文件比例，再入库作为候选；补边保留完整主体，不拉伸、不裁掉三视图。大头照与产品为3:4，其余为16:9，不强制放大至固定像素尺寸。生成原图、上传源文件与参考均保留，只有用户确认具体结果才能升级确认状态。
- 项目“上传成品（保留原文件）”仍用于已有规范成品：完全相同字节的图片不重复入库；看图分类与项目位置不符、识别失败或低把握时不入库；可安全裁剪或补边后核对尺寸。处理时只清理本次暂存副本，成功、重复、拒绝和失败都不删除电脑源文件。此成品入口仍保护已被资产记录引用或位于管理目录的文件，已确认资产不追溯清理。

### 视频参考、手动整理与命名（2026-09-30）

- 文件夹导入及历史“视频参考”仍可预览、归组和作为视频参考导出；顶部上传视频改为抽帧制作资产，不把上传原视频直接放进收藏。视频上限2 GB、2小时；图片上限64 MB。
- 图片和视频都可放入通用文件夹；默认直接拖动资产到另一项资产或文件夹归组，拖动文件夹改变显示顺序。需要划过多选时可关闭“拖动归组”。文件夹关系及顺序保存在资产记录中，不改变项目 AST 资产组。
- 同一人物的不同服装 1×4 图按明确的项目人物需求编号自动归组；独立资产库制作的 1×4 图按共用的已确认大头照归组。第二张同人物图片出现时显示文件夹。手动分组或手动移出不会被自动归组覆盖；缺少可靠身份记录的旧图不按名称猜测合并。
- “产品”总类下可按需建立、改名、删除手动分类，单项或批量归类；分类有资产时不能删除。新上传的图片由 Codex CLI `gpt-6-luna` 看图识别类别并直接命名，用户可在详情修改名称，原名留在记录中。拖动、归类与清理不调用模型。
- 垃圾桶可“永久清理选中”或“清空垃圾桶”。清理同时移除知识库原文件及索引记录、网页封面；已确认或被项目引用的资产不能清理。清空时自动排除这些受保护项。项目中已复制的参考副本不受网页垃圾桶影响。
- 新入库原图和选用包使用类别前缀、稳定编号、可读名称、视角或用途、版本组成文件名；旧文件路径保持原样。名称建议只是输入框候选，不会自动重命名已确认文件。视频选用包条目带 `media_type=video`，只作为参考，不作为已确认图片资产。
- 原确认清单仍以来源项目为准。库内用户确认仅表示这张图片可接受，不等于已确认适用于新的剧情、服装状态、风格和资产需求。
- 选用包包含图片副本和 `selection.json`。资产助理读取选用包，再匹配当前叙事包 `AST-*`、适用范围及真实参考；保持原 `visual-asset-manifest.json` 的候选 / 确认流程。
- 项目选用知识库资产时，先从知识库复制到该项目 `04_资产/知识库参考/`，核对文件一致后供任务使用；正式交接时再从知识库复制到项目母版目录。项目自有图片可用于需求盘点，但不自动进入网页资产库。
- 支持 PNG/JPEG/WEBP/BMP/TIFF。DNG 等未支持原始格式仍保留于来源目录，不谎报入库成功。

## 照片转资产

网页执行 `skills/asset-image-assistant/SKILL.md` 的独立资产库入口，方法在 `modules/library-mode.md`，类别和比例在 `library-profile.json`。

选择真实参考与继承边界 → 资产 Skill 的 Web 受限读取入口组装完整资料 → Codex 看图写词并自查 → 用户编辑或确认 → 工具生成 → 技术检查 → 用户视觉确认。

- 生成要求统一填写在“提示词框”，包括需要保留、去掉或调整的内容；不再分开填写继承项。
- 每次在独立请求目录记录 task-package.json、skill-evidence.json；缺少适用专业方法全文、动态语言规则、模板或本地规范即停止。资料完整不等于执行者已读，不生成阅读声明。PROMPT-LANG、分类/连续性/引用/输出格式等七项不得漏审；程序额外阻断已知画质大词。旧审查记录不能继续批准生成。
- 新增人物1×4、道具/物品、广告产品、风格母版及色卡；1×4须按服装、脸部顺序选两张已确认图。生成比例从Skill配置读取，实际比例不符时禁止确认。

- 大头照：单张3:4头顶至锁骨特写，画面内无衣服；服装：单张16:9正面、左侧、背面三格服装图，使用无头无脸人台。
- 环境：45°母图 → 正面 → 反面 → 90°俯瞰，按顺序确认；后续步骤附带前面全部已确认图片，45°作为文件夹封面。
- Codex桥接位于 `scripts/visual_asset_codex.py`，调用本机已登录的 `codex exec`，只读沙箱、临时会话、图片附件和结构化结果。模型沿用用户CLI配置，不修改全局配置；使用Codex账号额度。撰写、自查和修正在同一次调用内完成；重新检查当前编辑稿也只调用一次。检查通过后仍须用户确认具体提示词才可生成。`drafting` / `reviewing` 分别表示这两个网页动作，不再自动串行启动两个模型会话。
- 网页显示看图记录、具体审查结论、不确定项和问题。只有当前提示词审查通过并由用户确认才能生成；修改提示词撤销审查通过与用户确认。Codex自审不等于用户终审。
- 每次调用的草稿、审查结果和日志保存在 `requests/<组ID>/<视图序号>/codex/<运行ID>/`。处理超时、失败或重启中断均显式报错，不自动重试模型请求。提示词任务最多并行 3 项，同一制作项不能重复提交。
- 照片转资产可选收藏图片与新上传的图片参考，参考预览同时显示库外的输入记录。电脑源文件与库内参考始终保留。照片未显示部分记录为推测补全；不能作为真实产品或真实地点的背面证据。
- 图片识别与提示词准备共用现有的文件结果接收方式，避免 Windows 下工具已经写出结果、输出管道仍不结束而卡住。已保存的识别结果在同一主体与类别选项下复用；修改选项会重新识别。中断的上传参考在“照片转资产”显示“继续处理这份参考”，不需要重新上传；上传期间表单持续显示处理说明。
- ImageGen：网页确认提示词和本次1张生成授权后，`/api/imagegen`启动本机Codex CLI，调用内置 `image_gen.imagegen`；无需API密钥或手动复制请求。输入参考副本、结构化结果与日志保存在 `requests/<组ID>/<视图序号>/imagegen/<运行ID>/`。工具先保存原图到Codex默认 `generated_images`，服务器验证文件位置、新建时间及图片可读性后自动导入当前资产组，页面轮询显示结果，仍需用户确认图片。具体ImageGen模型由宿主管理，不伪造可选模型。
- ImageGen不自动重试，也不自动切换到API。失败、超时或重启中断标为结果待核实，重复点击不会再提交；日志用于核对实际生成状态，已有结果可从“导入生成结果”恢复。旧的 `交给Codex.txt` 仍作为手动恢复资料保留。
- Windows大文件读取兼容：超过3MB的不透明参考图准备为同分辨率JPEG副本（质量95/90/85中首个达标值），原图不变；仍超限或大透明图则明确停止。每次保存参考副本清单。异常任务可点“重新准备（不生图）”，保留失败记录并清除旧确认；再次生成必须重新由用户确认。
- 即梦 CLI：本机 `dreamina image2image`，界面显式选择模型；每次一张2K，比例按Skill当前分类配置。用户确认审查后的提示词并勾选本次上传及额度授权后才提交。异步查询使用 `query_result --download_dir`，图片入库后用户确认。
- 本轮接入依据 2026-09-07 本机 `dreamina image2image --help` / `query_result --help`；版本 `a857341-dirty`。未实际进行付费生成，CLI 提交与下载结果需用用户批准的一次真实生成验证。
- 提交不自动重试。未取得 `submit_id`、超时或进程中断均标为未知，保留日志，先核对服务任务再决定后续。查询不再次提交生成任务。
- 查询命令非零退出或无法执行时暂停自动查询，保留原 `submit_id` 和日志；超时/连接异常累计三次后暂停。可手动查询原任务，不能据此重新提交生成。正常尚未下载到结果时继续间隔查询，批处理保留原有 30 分钟总等待上限；状态检查不再固定睡满 8 秒才发现已完成。
- 网页状态刷新由统一调度负责，活动区域共用一次请求；慢请求不重叠，页面隐藏或无活动任务时暂停自动刷新。已有手动刷新入口保留，提示词编辑和授权表单不被进度刷新替换。
- 这是资产图Skill的独立资产库模式。具体短剧生产仍由同一Skill的项目模式按已确认 AST、准备包和授权执行；独立模式不伪造叙事或AST，不推进下游阶段。

## 项目资产工作台（2026-09-08）

左侧“项目资产”接收桌面项目目录，按产物登记定位唯一已确认的 `narrative.package`，核对确认凭据和正文版本后展示完整 AST 表。输入路径是项目文件夹，不是仓库或任意图片目录。已连接项目保存在本地工作台列表。

使用顺序：选择参考 → Codex 盘点必要制作项 → 选用已有图片，或多选网格批量写词 → 修改、保存并重新审查 → 核对批量工具/模型/提示词后授权生成 → 逐格看图确认 → 整表导出。没有独立模板的输出会标注分类指南来源。场景依赖按项目网页入口的 45°、正面、反面、俯视顺序；参考不足先补充实际事实，不猜外观。

网页调用同一资产 Skill 的项目模式，按 [Web 受限读取合同](../../skills/asset-image-assistant/modules/web-input-contract.md) 加载当前 AST 与必要叙事事实、专业方法全文和 production_artifact_checks；不改写真实项目执行上下文。独立照片转资产继续使用 library 模式。库内确认不替代项目确认，原项目状态的 current_stage、next_stage 不由资产网页重写。

`/api/project` 支持 bind/detail/sync/references/plan/select/clear-references/resolve/confirm/reopen/batch/export/continue。任务关联项目本地 ID、AST 和制作格；批次保留每项输入快照、工具、授权和结果。排队输入变化会停止该项，失败不会自动再次生成。重启标记中断；即梦批次只自动查询已提交任务，不重复提交。

正式交接位于项目 `04_资产/母版/<revision>_<交接ID>/`（未迁移旧项目保留原导出目录），包含图片、1.1 资产清单和用户确认记录。产物登记的 `visual.asset.manifest` 路径是当前版本入口，不覆盖旧确认清单。清单保留 confirmed_asset 主图并新增 confirmed_outputs 图片组。导出可从中断处恢复，同一交接不重复登记。需求变化或返工会使旧交接及其下游依赖过期；旧文件保留。

成功生成的图片先暂存，写入知识库并校验后才登记为网页资产；网页仅保存封面与任务记录。图片、资产索引和说明只保存在知识库磁盘，不进入 Git；资产库使用独立的文件写锁。命名沿用类别前缀、六位编号、名称、视图、版本。未确认图不额外建“候选”子目录。后续分类、命名和确认等索引更新由队列同步，失败时显示原因并可手动重试；不借重试触发生图。整表导出从知识库原图复制到项目。

运行环境：复用 `config/requirements.txt` 的 jsonschema/referencing。Codex 内置 Python 缺少时，用**同一个**解释器运行 `python scripts/install_runtime_deps.py` 安装到 `.master-storyboarding/visual-library-deps` 并写入 stamp；不修改宿主 Python 全局包，也不手写 pip --target。

隔离目录**一个解释器一份**：`core/runtime_deps.py` 是唯一解析出口，只在该目录的 stamp 与当前解释器、平台、依赖清单一致（或未登记但当前解释器能真正导入）时才加入 `sys.path`；不匹配就跳过，回落到当前环境已有依赖。`python scripts/install_runtime_deps.py --check` 只报告，`--force` 才会清空重建。

验收命令：`<内置Python> -m unittest discover -s scripts/tests -p "test_visual_asset_*.py"`，及 `node --test scripts/tests/test_visual_asset_ui.cjs scripts/tests/test_visual_asset_scenes.cjs`。2026-09-08 在隔离目录跑通真实 Codex 项目盘点、写词及八项独立审查；浏览器验证复用选图、逐项确认和下一视角解锁。生图提交用受控替身验证逐项执行与失败不重试，没有代用户发起真实付费图片生成。

## 移动与垃圾桶

勾选图片后选择“移动到…”切换分类，或“移入垃圾桶”。垃圾桶内可批量恢复，也可打开单张图片恢复；恢复回到原分类。移动同步库内文件和已关联的知识库归档目录，不改来源项目。

删除后保留 30 天，期限从每次移入时重新计算。服务启动时及运行期间每小时清理到期副本；服务关闭时暂停，下次启动补做。资产库文件写锁被占用时暂停操作并显示原因；其他知识库任务的 Git 状态不影响图片管理。中断操作会保留 management-pending.json 及现场，需核对后修复，不会盲目继续删除。此前手动删除的 10 项记录已同步，不自动重建。

## 角色类型与资产路线

CHARACTER 为叙事角色，character_type 分为 HUMAN 人类、HUMANOID 人形角色、ANIMAL 动物和 NON_HUMANOID 非人形角色。类型字段由上游明确登记；历史包默认保留原人物路线，已确认的类型更正保存到资产需求调整.json，不改已确认剧情。

后端共用 core/character_assets.py 决定是否读取服装及可用制作类型。动物、非人形角色与PET幻想伙伴选用或制作完整角色的正侧背三视图，库存分类为宠物；人体身份与服装依赖不适用。提示词资料加载、上传类别、项目选图、确认导出、当前资产清单与分镜素材读取沿用同一类型。动作状态仍保留在原剧情中，不机械为每个动作生成外观图。

### 宠物与幻想伙伴三视图

宠物层包含动物、非人形角色及用户指定的幻想伙伴（PET）。小精灵可为人形但走完整角色路线；不拆大头照、服装与人物1×4。统一一张16:9正面、左侧、背面三格完整角色图，固定服饰和配件一并保留。上传单张外观参考不等于三视图已完成，视觉完成由用户核对。旧角色外观库存归入宠物层，原图和确认记录不覆盖。

## 外部已生成候选的接入（不替换原生生成）

原 Codex CLI 不可用时，不能假造审查通过或自动切换生成服务。用户已另行授权外部工具产生的真实文件，可用现有 `/api/import → /api/update → /api/project(select)`；这只验证成品接入，不能报告为 `/api/imagegen` 或 `codex_bridge` 已接通。未获得新增生成授权时，只能重用已有文件检查这条链。

给 `/api/import` 的 `source` 指定**单张实际图片**，可选附上 `external_generation`：

```json
{
  "source": "<本次真实输出文件绝对路径>",
  "external_generation": {
    "tool": "<真实外部工具；不要冒充CLI>",
    "model": "<实际已知模型；未披露就明确未披露>",
    "user_authorization_ref": "<本次已有真实授权引用>",
    "prompt": "<本次实际提交全文>",
    "reference_paths": ["<实际使用的参考图片路径；纯文生图可为空数组>"],
    "image_sha256": "<本次工具结果文件的SHA256>"
  }
}
```

这是来源记载，不是未来生成授权或用户成图确认。服务核对结果hash、读取实际参考并记指纹，复用资产 `provenance`、知识库来源记录和正式导出凭据；不创建 CLI run_id、prompt_approval 或 generation authorization。同一路径已入库且来源记录不同会明确报错并保留原记录，不能静默改历史；需要改来源时另存候选。不能给整目录套同一生成记录。

之后将资产设为相应分类、role=候选，并通过 `/api/project` 的 `action=select` 指定 project_id/job_id/index/asset_id。它验证现行需求、前置依赖和文件后进入 awaiting_review；原审查失败继续保留。没有具体图片的用户确认，不调用 `confirm`，整表导出仍会阻塞。获准后沿原项目逐项确认、整表导出与下游 `asset_refs --require-image`；导出记录保留外部工具身份，不借任务默认provider填成CLI。

返工用原 `action=reopen`：保存旧图/确认/审查来源，撤下受影响选用，连带前置依赖失效，重新核对后才可再消费。公共 `/api/attach` 不允许在生成或审查中手工覆盖，也不能写入旧版需求；原 worker 的已提交任务回填仍保留。仅粘贴路径的手工回填不能证明生成工具，来源记为 manual_result_import，不沿用任务默认模型或生成授权；有实际外部记录的图走上文 import 入口。
