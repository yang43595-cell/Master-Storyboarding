# 按需分镜图（视觉补充）

开始本职任务前读取[共用三层规范](../_shared/skill-layers.md)。本 Skill 适用边界：承接确认导演稿与资产，先检查动作、表情、空间及连续性；实际补图按缺口，不强制每镜生成，不改导演决定。

由当前执行者按 [PROJECT_RULES.md 的 Skill 执行分工](../../PROJECT_RULES.md#skill-执行分工) 执行本阶段；默认由主 agent 直接执行和自检，已明确委派时由受派执行者完成。

读取 `PROJECT_RULES.md`、`../_shared/knowledge-access.md`、当前 `stage_startup.md`、`../_shared/draft-lifecycle.md` 等六项共享红线（含 `../_shared/prompt-language.md`）、`modules/storyboard-method.md`、`references/reference-asset-contract.md`、`references/storyboard-production-checklist.md`、`references/image-continuity-hard-rules.md`、`templates/storyboard-image-template.md` 与 `../../schemas/visual-supplement-request.schema.json`。涉及灯光风险时才读取 `../storyboard-planner/references/lighting-prompt-standard.md` 的对应小节；写本 Skill 提示词时必读 `../voiceover-to-video-script/references/prompt-language-hard-rules.md` 并以其为准。这些引用不授予修改导演镜头或视频提示词的权力。

缺口判断与产出前，完整读取 knowledge-profile 绑定的 `VISUAL-SUPPLEMENT-METHOD`（缺口证据、参考覆盖与状态继承）和 `IMAGE-CONTINUITY-METHOD`（共用图片连续性）方法快照，按原流程登记实际阅读并通过 ensure-prepared；方法缺失不得退回旧本地正文。经验层不自动加载，模板与请求合同继续从本地读取。

本轮明确制作、返修或核对造物者抛光面膜的真人上脸状态时，在当前请求设 `creator_mask_face_effect: true`，按 knowledge-profile 加载 `VGEN-CREATOR-POLISHING-MASK-USE`，并将其指定的真人上脸模板实际路径加入当前 `source_paths` 后阅读。只有碗内搅拌、产品展示或其他产品时不设置此条件。参考职责和局部补涂的专业标准以该方法为准，不从产品名称泛化到所有任务。

## 触发与输入

- 在导演稿及资产图确认后、视频提示词之前，先检查已确认 `storyboard.package` v4（旧 v1/v2/v3 只读）的本轮镜头及对应素材。检查可以发现缺口，不要求启动前已经证明缺口或视频生成失败；实际补图必须绑定具体 `source_shot_ids` 和现有素材无法充分表达的目标状态。
- 先以本轮镜头关联的 AST 和明确 output ID 取得最小参考集合；同一有效上下文且同一用途可复用已完成的视觉结论。新执行者、新 Web 调用或结论未覆盖当前状态时没有可复用的“已看图”，必须实际查看需要判断的确认输出；登记与路径核对不代替此步骤。
- 检查输入至少包含：确认导演包 revision、本轮镜头及对应确认资产、动作参考和产品实拍。检查后登记目标状态、出现/禁止/保留项、参考覆盖和决策；只有 request_supplement 必须填写缺口证据及最大生成数量。reuse_existing 用 existing_references.coverage 说明覆盖依据，return_upstream 用 return_upstream.reason 说明上游问题，不虚构缺口。
- 用 `visual-supplement-request.json` 按 schema 登记判断。现有材料足够时记录 `reuse_existing`，最大图片数为 0，并直接复用；真正缺图时才记录 `request_supplement`。
- 独立候选试跑仅按 PROJECT_RULES 的现有测试授权例外执行。补图请求调用 `scripts.core.schema_contracts.validate_visual_supplement_request(value, project_root=项目路径, candidate_test=True)`，须有有效隔离项目状态；默认不传测试参数或直接校验原 schema 仍要求已确认导演。测试来源如实写 `source_storyboard.status: candidate`，不伪写 confirmed。请求登记 `type: visual-supplement-request`，manifest 的采用身份继续 candidate/unreviewed；正文保留实际业务结果：补图草案 candidate、复用 not_needed、退回 blocked。不能为消费者改成假 candidate；return_upstream 仍须有真实原因且 max_images=0。候选消费者复核此合同及准确来源，交接卡带业务状态和退回原因。schema_valid 只证明结构，不说明已确认、已解决或可生成；blocked 应返回指定上游处理。其他合同不获得此状态例外，不生成、不采用、不发布。

- 用户为本镜选择白模时，读取 `blender-previs handoff-reference` 产出的 `reference-handoff.json`，核对确切镜号、目标状态、覆盖、局限与确认记录；失效则返回白模步骤，不自行重建。未选择白模不新增门禁。白模只约束空间构图、承托、站位及相机路径，身份/服装/场景外观仍使用其列明的确认母图，不继承代理颜色材质或精细姿态；静态起幅图不当作完整运镜或表演证据。本 Skill 不运行 Blender。

剧情带来后续沿用的持续可见场景变化时，按[剧情后的场景状态参考](references/image-continuity-hard-rules.md#剧情后的场景状态参考)先查新态覆盖，再复用或补一个对应状态图；基础环境母图不是后续所有状态的替代。沿同一请求保留旧态、事件、新态、不变量及准确镜号范围，缺图待制作、未核待审，不把静帧当动态过程或每微动作补图。

## 对话选图

涉及产品使用时，先读取当前资产清单的 `product_usage` 与产品条目的 `action_references`，按 [产品使用参考对接](../_shared/product-usage-contract.md) 取对应动作和质地。幻想使用画面属于本阶段分镜；真实敷脸效果参考不替代该画面。

先按场景检查需要跨镜头、跨视频段保持的位置关系，再讨论单镜动作或表情。对涉及连续动作的候选图，按导演稿核对上一状态、本图要固定的瞬间和后续状态：人物从哪里开始、站坐与持物如何变化、本图处于动作前／关键瞬间／动作后哪一处。核对动作能否从上一状态到达本图、再从本图继续；来源未规定的动作或位置不自行补造。复用与补图的专业判断仍按绑定方法执行；复杂动作本身不触发补图。

逐项向用户说明来源场景／镜头、现有参考覆盖、建议补图的具体作用和局限，并给出“复用、补图、暂缓、返回上游”的建议。用户可以改选、合并同一关系状态的需求或指定控制重点；建议不自动成为用户决定。已确认的选择持续有效，不重复提问。

将本轮决定汇总到项目 `05_分镜/分镜图选择记录.md`（旧项目沿用现有分镜目录），保留来源 revision、适用镜头、共用状态；连续动作另记画面职责及前后状态的衔接依据，并保留用户理由及未决项。暂缓仅是讨论状态，不伪填成 schema 中的最终决策。确认选择不等于批准具体图片或触发生图；生成和成图确认沿用既有授权。

已有请求 JSON 的条目，在选择记录中只引用请求 ID、准确路径及版本，额外记录用户理由、暂缓/未决事项和请求尚未表达的适用或失效边界；不再抄写目标状态、保留项、参考覆盖等已在请求中的完整内容。暂缓且尚无请求的条目仍完整记录必要信息。用户改变目标或适用镜头时先修订对应请求，再更新引用；不能留下两套冲突决定。下游仍同时读取两者，不把链接当成已读。旧记录不自动删除或迁移。

场景关系图按一个共用位置状态组织，允许同一请求的 `source_shot_ids` 关联多个镜头。执行时按本地方法模块的空间参考交付约定注明适用范围；不要求每镜一图，也不把原场景关系图延用到已经改变的位置状态。

## 缺口判断标准

合格缺口限于：身份难以锁定、空间关系难以锁定、真实产品外观难以锁定、单一关键状态缺少静态依据，或已有证据表明当前生成路径无法可靠保持该状态。先执行复用检查，再决定是否补图。

重点检查复杂动作中的接触、交接、掉落或拾取姿态，需要精准控制的情绪表情，以及站位、遮挡、视线关系。以导演指定的动作和情绪目标为依据，说明现有图缺少什么，不把“动作复杂”或“有情绪”本身当作必须出图的理由。关键姿态和表情沿用 `critical_state`，空间关系沿用 `space`。一张图固定一个关键瞬间，不把连续动作硬塞进单图，也不声称静态图能保证动态表现。

下列不是视觉补充缺口：剧情因果不成立、对白或事件错误、镜头目的/景别/机位/调度/切点不成立、导演连续性合同自相矛盾、资产需求表外缺失。发现这些问题时记录证据并分别返回 `creative-director`、`storyboard-planner` 或 `asset-image-assistant`，不得用漂亮图片掩盖。

## 返工入口

图被退回后，先按[返工分流](references/reference-asset-contract.md#返工先定位原因再选择是否回白模)核对整体来源链，判断回导演、回资产、调整白模、复用有效白模再生图，或无需白模。空间错误不能只加排除词，外观问题也不强制重建空间。连续事件因时长拆段缺实际桥接图时，按[跨段参考](references/image-continuity-hard-rules.md#连续事件因时长拆段时的实际衔接参考)检查具体切点状态，不只承诺提示词连续。

## 执行与输出

按“来源镜头与证据 → 复用盘点 → 唯一目标状态 → 最小参考集合 → 候选生成 → 技术与引用检查 → 用户视觉终审”执行。

新边界分镜图的生图输入按[独立基础参考规则](references/image-continuity-hard-rules.md#新边界分镜图独立取基础参考)执行；不得把前一边界图递归作为下一边界图的生图输入。相邻视频复用同一切点图的规则保持不变。

- 每个请求只解决一个目标状态；生成数量不得超过 `max_images`，也不得顺带重做相邻镜头。动作前图必须停在本段首个新增动作发生前；关键瞬间或结果图不能冒充动作前图。目标图与相邻状态无法自然衔接且导演稿没有相应调度时，记录矛盾并返回上游，不靠增加排除词或补画中间动作掩盖。
- 必须继承导演包的镜头契约和已确认资产状态，不重新决定景别、机位、构图目的、调度、运镜或切点（景别与基础连续性剪辑属模型通用能力或导演已定，不靠知识包供给）。具体镜头的静态构图只把其指定状态可视化；场景关系图的展示视角按模块约定处理，不成为新的导演拍法。
- 产品实拍、确认母版或动作参考足以承担控制时直接引用，不重复生成。参考冲突与连续性核对按本 Skill 的直接参考执行。
- 生成或编辑前，工具和具体模型分别取得用户明确授权；付费或额度动作遵守项目授权门槛。输出只包含请求记录、复用引用或候选图片及其技术记录，不写视频模型、视频分段或视频提示词。
- 成图实际观察及新活动引用按[观察证据准入](references/image-evidence-admission.md)执行；同一原图登记保存准确字节、源版本、用途和可见事实，失败/未核不因用途文字而放行。程序仅查证据一致性，不替代看图。
- Agent 核对文件存在、格式、尺寸、命名、来源镜头、参考链和明显产品事实。候选保持待确认；用户明确确认具体文件后才能登记为确认视觉补充。
- 检查结果标明需要补图的镜头、目标动作或表情、原因与复用素材；无须为每个普通镜头另建请求。全部无需补图时简记复用结论；需要补图时先完成这些图片的用户确认，再供视频提示词阶段按镜头引用。不得带着未确认候选当正式输入交接。
- 交用户审核时只提供文件夹绝对路径、准确文件名、来源镜头和需要判断的视觉事项，不嵌入图片载荷。视觉质量由用户终审。

## 硬禁区

- 不是固定分镜出图阶段，不要求每镜、每段或每个 Panel 出图。
- 不新建或修改 `AST-*`，不替代资产阶段建立角色、场景、道具或产品母版。
- 不改剧情、对白、事件、导演镜头和连续性合同；上游错误必须返回对应 Skill。
- 不把联系表、缩略图、技术检查或 Agent 观感当作用户视觉确认。
- 不决定下一阶段、不调用其他 Skill，也不恢复 V3 manifest、gate、orchestrator 或任务图协议。
