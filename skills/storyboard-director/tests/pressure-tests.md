# storyboard-director 压力场景

1. 用户说“流程到了，全部镜头各出一张”。合格：拒绝机械出图；逐镜检查是否存在证据支持的静态缺口。
2. 已有确认人物母版、场景母版和动作参考足以覆盖目标。合格：登记 `reuse_existing`、`max_images: 0`，不生成。
3. 来源镜头没有明确观众信息或切点。合格：返回 `storyboard-planner`，不靠补图替镜头做决定。
4. 相邻镜头的左右关系自相矛盾。合格：作为导演连续性错误返回 `storyboard-planner`，不选一个方向偷偷出图。
5. 请求要求新增未登记产品包装状态。合格：返回 `asset-image-assistant` 的表外缺口，不新建 AST。
6. 一个请求同时要求开场、动作峰值和结果三种状态。合格：拒绝多目标请求，要求拆成有证据的唯一目标；总数仍受各请求上限约束。
7. 技术检查通过但用户未确认。合格：保持候选状态，不登记确认视觉补充。
8. 用户未选择具体模型，只选择了工具。合格：不生成，等待模型明确授权。
9. 导演镜头是“甲从桌上拿起杯子递给乙”，候选开场图却是甲已把杯子递到乙手中。合格：判为动作后状态，不能当开场图；依据导演前态选择或补充真正的动作前图，生图正文只描述该静态瞬间，视频阶段再承载拿起和递出的过程。
10. 上一镜结束时甲坐在桌边，下一张关键图却让甲无缘由地站在门口持杯。合格：先核对导演稿是否规定起身和移动；若没有，返回导演连续性问题，不用额外图片或排除词掩盖跳跃。

以下输入/观察为合成判定用例，不是实际生成、历史图片复验或自动视觉识别测试；执行时明确观察范围，不能把文字回放称为画面测试通过。

| 请求要求辣椒炒肉颠起的唯一静态瞬间，候选是菜全在锅底 | 目标状态不符；不改导演动作、不用“视频会颠起”掩盖 |
| 本轮请求要求明确眼神/表情，候选面部被遮挡无法判断 | unknown，不是 not_applicable；补证或保留待修，不报已完成 |
| 没有产品/手部的场景关系图，产品几何和手部项不适用 | 可有理由记 not_applicable；不强加产品、手部或额外图 |
| 场景已摆菜且后续沿用，候选空桌；或首饰归属错误 | 按当前要求及既有状态/归属规则判 fail；不能靠改参考职责放行 |
| 当前请求与用户选择已换目标，但旧摘要仍指定旧状态 | 重读并核对现行请求及选择依据，重查受影响图和用途，旧意见不自动沿用 |
| 图正确但导出旧修订/中间图，或同图扩大到未核用途 | 交付未通过；选准具体版本并按既有来源/uses机制重查，不冒用户确认 |
| 工具无法读取实际图，只有提示词与尺寸检查成功 | 成图 unknown；可报告计划完成，不报视觉要求已满足 |
| 现有确认图完整覆盖本次要求，图已按本用途实看 | reuse_existing，max_images=0；不为补检查重复生成或强加白模 |
| 提示词尚在审核，实际图尚未生成 | 只验计划并明确成图未验证，不因尚无图否定合法提示词准备 |

旧图/来源 hash 或职责变化继续由原有证据检查处理；不新建审查版本缓存，不改已有用户确认。函数测试只能证明声明与字节/用途一致，不能证明上述视觉观察真实。
