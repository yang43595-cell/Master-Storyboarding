# 图片连续性项目硬规则

本文件保留图片连续性的本地触发、引用与输出合同；背景固定层的专业判断按图片生产 Skill 的 knowledge-profile 绑定的图片连续性方法读取。视频阶段只消费适用的参考职责、状态与衔接合同，不因此承担图片生产或恢复 prepare；若确需判断背景固定层与派生制作，则返回相应图片阶段，按下文准确方法路径读取。Wiki 原主题保留来源、论证和生产反馈。

## 剧情后的场景状态参考

基础环境图只说明建筑、固定布局及其已核状态，是派生来源，不自动等于视频剧情初态，也不是整场永久有效的全景状态。剧情改变了后续画面仍须保留的持续可见状态时，先核对原文与导演：旧态 → 哪个实际事件 → 新态、保持不变的建筑／家具／位置关系、变化的物件及属性、开始生效镜号与后续沿用范围。把这些信息留在现有导演 JSON 的前后态及制作备注、补图请求与引用中，不建立另一份状态台账。摆菜、礼盒开闭或移走、布置和损坏等可触发；只换角度、说话、普通走位而场景持续状态未变不触发，也不为每次手指或表情微动制作新图。来源没有变化事件时，不补戏解释差异；但原文首次出现已经摆满饭菜或已经捧碗，可直接制作并引用该已成立状态图，不为流程先制作空桌／桌上碗，也不虚构上菜／拿碗动作。只有来源确有矛盾或缺失时返回上游核对。

1. **先取得对应新态图。** 按既有 `visual-supplement-request` 写唯一目标状态及 `source_shot_ids`；先查现有已确认图是否完整覆盖，足够则复用，否则登记 `request_supplement`。派生制作保留获准基础来源、固定不变量及剧情已发生的变化；按已有授权生成候选，实际看图并经用户确认后才能作正式输入。缺图、生成失败、未审或用途未核时，明确待制作／待审及受影响镜头，不拿旧图、文件名或假 `@` 占位冒充完成。
2. **沿用新态，退出冲突旧态。** 后续每个适用镜头都继承已发生的状态，直至来源允许下一次变化；按 `source_shots` 找全承载镜头的生成段，不能只核段首。基础图及旧态图保留来源历史；新态生效后，冲突旧图不得再作为该范围的活动全景／布局／状态参考。不能一边上传空桌全景，一边仅补一句“保持桌上的菜”来声称已修好。只负责身份、产品等相容局部职责的其他参考仍按既有用途实看核对，不借改职责名称掩盖可见冲突。
3. **正文与实际输入一起换。** 新态图按准确 artifact、revision、文件 hash、`state_id`、获准镜号及 `quality_evidence.uses` 核验；视频正文写出该状态的可见内容及后续允许的变化，真实有序素材和平台原生引用必须指向同一新态图。只改 `prompt`／`prompt_text` 而 `native_mentions` 或上传映射仍旧，不算完成。程序仅检查声明、字节和范围一致，不能证明画面已经正确或实际生成任务用了哪些输入。
4. **不把状态演变切碎。** 同段内真实发生变化时，明确起态、触发过程、终态及两种参考各自范围；不把结果图冒充动作前态。若平台不能逐镜绑定，必须注明实际只能整段多参考的限制，不把文字职责说成原生逐镜控制；必要时仅在真实叙事变化处提出后续生成段，涉及导演决定则返回确认。保留用户已指定产品开盒、挤料、搅拌同一生成段的限制，不能为补图而逐动作拆段；无法兼容时报告限制，不擅改该选择。

### 同一业务稿内的字段与消费

导演包在对应 `scenes[].scene_states[]` 登记需要沿用的变化后态或原文进入时已成立的状态，每条使用 `state_id`、`entity_id`、`previous_state_id`、`change_event`、`description`、`preserve`、`changes`、`source_shot_ids`。`previous_state_id` 指基础态或上一后态；原文进入时状态已成立且没有此前状态时，用 `previous_state_id: null`，`change_event` 写原文成立事实及定位，不要求虚构变化动作。已有同实体状态链中间不得用 null 重置；后续变化仍是旧态 → 实际事件 → 新态。事件及描述必须来自原剧情／导演，不从缺图倒推新剧情。`preserve` 和 `changes` 分别列持久不变量与实际变化；`source_shot_ids` 列全后续沿用镜头，可包含发生变化的本镜终态。既无待保持的已成立场景状态、也无持久场景变化时省略 `scene_states`，不填空架子；这不是另一份台账。

分镜请求沿用 `target_state`、`must_appear`、`preserve`、`gap` 与 `source_shot_ids` 表达目标及缺口。活动素材沿用 `role`／`roles: state_reference`、`state_id`、`entity_ids`，必要时用引用的 `source_shot_ids` 限定本段内用途；原图登记的 `quality_evidence.uses` 必须覆盖准确状态、职责、实体和镜号。缺字节、错 hash、错状态、错范围或观察失败／未知均不得进入活动输入。

交付消费者回读 `source_artifacts` 指向的准确导演及视频源；其中必须包含视频实际引用的 `source_storyboard`／`source_director` 文件，不能用另一份导演稿或冻结稿自报状态绕过来源。视频已定义 `generation_segments` 时，交付草稿用 `source_segment_id` 绑定原 `segment_id`，草稿的 `source_shot_ids`／`source_shots` 必须逐镜等于该源段映射，不能只报段首或删除变化后的镜头来缩小检查范围。有 `scene_states` 的新提交必须同时携带准确视频源的 `generation_segments` 和草稿 `source_segment_id`，不能删除视频源、降级为仅导演来源来放行；旧包没有这些字段仍可只读，不等于满足新提交准入。

草稿存在 `layout` 引用、来源 `scene_states` 命中，或已有 `scene_state_assessment` 声明时，在原 `quality_evidence.checks.persistent_objects` 的 `observation`／`locator` 中记录具体判断依据，并添加 `scene_state_assessment: changed | unchanged`、`source_shot_ids: [全段镜号]`。`changed` 必须有准确来源 `scene_states` 链；`unchanged` 必须有实际来源依据，不能由省略或删除 `scene_states` 推定。没有判断或判断未覆盖全段时阻止提交。此声明仍只证明所填证据一致，不代替独立阅读剧情、看图或用户终审。 泛用 `state_reference` 也可承担演员动作切点，不能全部视作环境或强制场景判断；这类引用保持原切点合同。场景用途的 `state_reference` 作者必须按本节显式填写场景判断。程序不能从角色／实体 ID 名称自动识别环境，未登记场景状态却假装演员用途的缺漏不在自动识别能力内；须由原文阅读和人工核对揭示，不宣称已被技术检查全面拦截。

一个生成段涉及多个场景状态且没有逐镜或真实起终原生控制证据时，本轮消费者阻止提交；包括前半段沿用前态、后半段切到一个已声明后态的情形，即使只登记了一个变化后态也不能冒充全段同态。可以保留明确起终态的文字候选，待核实平台能力并接入可验证控制，或在不违背导演与用户产品同段限定的前提下修订分段。不会自动切段，也不会把用途文字当成平台能力。

派生场景状态图不是“上一张边界分镜图”。下文新边界图独立取基础参考的规则不变：使用获准且适用的新场景状态来源，不准任取前一边界图递归垫图；失败图不得回灌。状态图也不自动提供平台首尾帧控制、生成授权或用户确认。

## 真实开场状态

本节只约束指定承担开场或切点状态的参考，不规定所有素材上传顺序。身份、服装、产品和环境参考按获准职责使用及跨段复用，不要求每段新增开场图。

下一段要表现某个主体或效果入场时，承担本段动作前开场状态的参考图必须是动作发生前状态：固定场景、角色、机位、光线和材质已经成立，但本段第一个新增事件尚未发生。已经贴合、覆盖、击中、爆炸、冲洗或完成变形的图片只能承担动作或结果职责，不能兼任开场状态。

同一张图兼作前段尾态与后段动作前态时，必须同时符合两侧切点状态；已有同状态不同机位参考组按下节处理。身份、服装、产品和环境参考的跨段复用不受此双职责条件限制。指定承担动作前开场状态的图若已包含本段第一个新增事件，须更换为合格前态参考；缺少该任务确需的前态图时停止相关视频提交，不能仅靠否定词压制冲突，也不因上传序号判定用途。

## 连续事件因时长拆段时的实际衔接参考

只在同一连续事件确因模型时长/承载而分段时执行，不给每段机械补图。先按已确认导演确定可停靠切点；若需要改变导演切点，先返回导演，不自行把过程剪没。

在已有分镜选择记录与提示词制作备注中，用一条跨段记录写明：前段结束/后段开始的准确时刻、人物/道具位置与朝向、持物/接触、动作相位、相机与光线，及明确要变化的项目。文字记录还须绑定具体已确认图的 artifact ID、修订、文件及登记hash和两段各自上传序号，不能只写“保持上一段一致”。

- 同机位直接续接，优先同一张合格切点状态图同时承担前段尾态和后段动作前态；后段第一个新动作尚未发生
- 导演本就要求换机位时，可用同一位置状态的关系图加两侧机位图；两图必须对应同一物理状态/动作相位，不能用不同动作阶段凑成首尾帧。关系展示视角不是新的导演机位
- 原有确认参考确能表达切点就复用；只锁身份、局部抓握或落地后状态的图，不能冒充“起跳前整场状态”。不够时回本阶段建立一个共用目标请求，不为两段重复生产两套无关图
- 选择严格首/尾帧还是多参考输入，按本轮平台与模型实际能力核验：CLI 查当前帮助，网页查原生控制与真实输入职责；只有能力已证实才能声称严格首尾帧控制。当前只能多参考时，把同一状态图真正放入两段输入，并分别说明尾态/动作前态职责；文字中的“首帧”不代表平台提供了该控制

没有可用且已确认的切点参考时，相关视频提交停止；可以按授权试写，但必须保留此缺口。未来实际生成后，前段真实尾态仍需与绑定状态核对；不自动把失败片段抽帧升级为新确认图。

前段返工改变切点状态、人物/道具或相机/参考版本时，后一段的旧绑定一并失效，先重新确认共用参考，再改两段材料顺序与正文并复查。仅修改与切点无关内容时记录不受影响依据，可继续复用原桥图。候选出现不等于正式采用；已确认旧图保留，新采用后旧ART-ID不可继续冒充当前版本。

## 新边界分镜图独立取基础参考

生成每个新的边界分镜图时，独立使用该节点获准的基础场景、人物、服装和道具参考，结合导演已定的该节点动作；禁止把前一张已生成的边界分镜图作为下一张边界图的生图输入，即使前图已确认也不例外。例如，“C02尾／C03首”不作为“C03尾／C04首”的生图参考。所需基础参考缺失时先补齐来源，不以前一边界图替代。

空间连续性由同一基础素材和明确的位置、朝向、持物及动作相位维持，按原有参考记录核对实际输入，不另设一份清单。各节点仍取其完整适用参考集合，不把“独立生成”理解为只能单图参考。

这是不同边界图之间的生图输入规则，不扩大为禁止普通图像编辑或同图局部修正。相邻视频仍可共用同一张已确认的边界图作为前段尾态和后段首态；视频阶段按模型实际能力使用首尾帧或完整多参考输入，并分别标明职责。共用边界图生成视频，与用前一边界图生成下一边界图是两个不同环节。

## 返修参考与固定基准

头像、服装、人物板以及场景、物品等资产图一旦有本轮不接受的瑕疵或用户不满意，失败结果不得作为下一轮生图输入，也不得通过裁切、放大、修色后绕回输入。回到该项原始清晰参考和已确认设计重新生成；原本获准无图设计的，仍用原文本设计重抽。不得把缺失参考伪装成可用：先恢复或重新建立所缺来源，只有既有无参考设计许可适用时才能退回文本；既定身份或指定实物不能靠猜测补齐。

人物 1×4 初次制作、返修或换装都用已确认且清晰的独立大头照与对应独立服装资产重新合成，不输入先前人物板或从板中截出的脸。头像或服装本身不合格，先各自回原始来源重做并确认，再合成；不能用合成板反向修出来源。

分镜图允许按实际需要少量垫图；同一轮返修固定最近已确认、清晰且适用的基准 A，平行生成 B1、B2、B3。B1 失败后仍用 A，不得沿 A→失败 B→失败 C→D 递归叠图；若没有合格 A，就回本镜获准的原资产与镜头设计重建。新结果经实际审图确认后可成为后续正常状态/连续性参考；其中新边界图生图须遵守上节独立基础参考规则，不把已确认边界图递归用作下一边界图输入，也不设机械生成次数门槛。

在现有参考记录中写明本轮固定来源、实际输入及各自职责；失败图可留作问题对照，但不能放入生成输入。验收同时核对实际输入列表，不能只看提示词里的“保持一致”。以下合格 1×4 的下游引用、正常场景派生与低风险人物免制资产规则继续适用。

## 背景母版与单变量派生

背景母版必须锁定固定层，派生图每次只改变一个动作层；字段与确认状态按当前资产清单登记。固定层的专业判断和漂移处理完整读取 knowledge-profile 绑定的 `IMAGE-CONTINUITY-METHOD`（Vault：`projects/Master-Storyboarding/应用知识/图片资产/图片连续性方法.md`），不能把回链当作正文。

涉及固定机位前后状态、同一手的掌背面或共享站位时，验收单元包含直接相关的成对图与受影响镜头：明确哪张锁机位、哪张只提供状态/外观，对照实际像素核对固定层、手面及饰件位置。单图通过不代表两图关系通过；局部改动只复查这组直接依赖，不扩大为全片重跑。引用身份、职责及检查记录通过只能证明绑定过程，不能替代实际视觉检查，也不据未做的单变量实验断言某条提示词是唯一原因。

## 多角度场景参考组

环境一致性优先，按本轮涉及的方向、布局、动线、尺度与光向判断覆盖，并留充分余量。同空间多镜、多机位、长段或空间风险不清时，默认完整四图合理，宁可多生成也不把缺口留到视频。简单单一视向且现有确认图已充分覆盖时可以少补，须说明覆盖依据与余量，不能追求临界最少。30秒只是复查连续性风险的提醒，不是短段禁止多图或长段机械补图的门槛；已有适用四图可完整参考，不因图片数量本身判多余。

采用默认四图时，按顺序建立：场景母图、反向平视回望、45°俯视斜角全景、90°垂直正俯空间总纲。前两张只引用母图，最后一张才组合前三张。每张图的主要职责与适用范围明确；同一图可承担相容的多项职责，冲突状态不可混用。选择较少补图时按实际已确认覆盖确定依赖与顺序，不为凑固定血缘额外上传未使用来源；禁止借转机位重新设计入口、固定资产、人物动线或光向。

## 唯一面部来源

下游分镜、白模外观交接与视频引用时，已有确认的 1×4 人物资产板只要包含清晰、适用的头部特写，就由这张图同时承担人物身份与服装职责，只上传该 1×4，不再额外上传同一人物的独立大头照。用明确的 `AST-ID@OUTPUT-ID` 选择该服装的 1×4；只按 AST 盘点得到的全部确认输出不是上传列表。唯一面部来源指图中指定的头部特写，不指必须另有一个头照文件；按既有图实际的特写所在格标明身份来源，其余身体格只提供服装、比例与方向，不从其中的小脸另取身份。

仅当现有参考没有脸、头部特写模糊或被遮挡，无法承担本次身份控制时，才补充同一人物的已确认头照；服装状态仍取对应确认服装输出。参考互相冲突时先核对来源，不自动换脸或采用新资产。输入记录按实际上传文件列一次，并说明其中的面部与服装职责；来源头照的追溯记录不等于需要再次上传它。

以下是新制作正式身份资产板的构图要求，不把下游复用变成重新制作任务，也不改写既有确认文件：

人物身份资产板必须让高清头部特写成为唯一可信的面部来源。正式资产板以接近 `16:9` 的横向画布为目标，1×4 只表示画布内单行大致四区排布，不要求严格等宽或精确分隔坐标，不得生成 `4:1` 或明显比例失真的超宽画布。最左格必须从头顶构图到颈肩交界，肩部只保留最少边缘，不得出现胸口、上半身、手臂或半身构图；右侧正面、侧面和背面身体视图全部从颈部以下开始，颈部以上留空。不得用遮挡、模糊或低清小脸替代真正不生成头部，避免中远景错误读取身体视图中的小脸。生成后准确记录实际尺寸，允许接近 `16:9` 的少量像素取整差；不因轻微分格宽差或精确坐标未命中返工。身份、服装、唯一清晰脸源与完整无头三视图要求不变。


### 环境后态不替代人物关系

检查同一世界锚点的门窗、桌侧、椅位、地面站位、在场/画外人物、持物者与可达方向。场景持久物的新态图只证明其实际可见内容，不能代替三人站坐与交接的关系参考；反打可换画面左右，不能换世界位置。关系图与上游几何不合时停止该用途，修正/替换为待审候选，不以“仅取关系、眼神不继承”等用途窄化豁免；错误生成尾帧也不能自动升级为下段参考。先核有用且正确的既有图；普通走位、对白或每个手部动作不机械生图，已取消手部过程图仍取消。已发生持续场景变化的后态先生成审查再用于后续的规则不变。

临时护理发型、持物或已布置环境的后态成为当前任务所需状态时，实看整图；明确冲突的整图退出本轮候选活动输入，仅留历史/派生来源，不以“只看身份/忽略背景”或limited-purpose免责，也不把本地计划排除说成远端已解绑。撤图后逐项核原职责由哪份准确相容来源接续；无已取得、实看并适用的来源/版本时继续阻断，不造素材ID。确需局部外观引用时，先核实际可用且相容的准确裁图/版本及用途，不能让原整图借用途改名回到输入；已有失败返修图仍按返修基准规则处理，不借裁切绕回。
