# 视觉补充参考资产契约

本文件的逐图用户确认与用途扩大确认用于兼容人工路径。统一入口按 [Skill SOP](../SKILL.md#本轮执行-sop) 由执行者自查验收，不送网站、不逐图停等；合法来源、范围、字节与观察要求保持，自主验收采用／消费未接通时保留候选，不执行会伪造人审的旧命令。

## 可消费来源

资产清单 1.1 / 2.0 的 `confirmed_outputs` 是同一 AST 的确认图片组：按 purpose、state、view 匹配职责，并核对具体确认引用。`confirmed_asset` 只代表兼容主图，不能代替其他视角。旧清单无图片组时只使用已有主图，不推测隐藏输出。只消费 status=confirmed 的 AST。

| 来源 | 允许用途 | 不允许用途 |
|---|---|---|
| `visual-asset-manifest.json` 中的确认资产 | 锁身份、空间、道具、产品、风格和已登记状态 | 从候选或表外项目推断新资产 |
| 动作参考或已确认视觉补充 | 锁单一动作峰值、起始或结果状态 | 把旧状态机械继承到不适用镜头 |
| 产品实拍 | 锁真实外观、结构、展示面和包装事实 | 用风格图或文字猜产品 |
| `storyboard.package` v4（旧 v1/v2/v3 只读） | 提供来源镜头、镜头目的和静态目标边界 | 重新设计镜头 |
| 用户为本镜选用且已确认的 `reference-handoff.json` 白模包 | 在实际覆盖状态内锁站位、承托、遮挡、构图与摄影机路径 | 锁身份/服装/精细四肢动作；把起幅图当整镜；把场景基座当逐镜确认 |

## 复用优先

参考覆盖判断完整读取 knowledge-profile 绑定的 `VISUAL-SUPPLEMENT-METHOD`。足够时，`decision` 必须为 `reuse_existing`，只登记引用，不生成新图。参考数量受工具限制时先保证实际控制目标、连续性及充分覆盖余量；可去除重复无用来源，不能为临界少图削弱环境一致性。限制下无法保留覆盖时报告缺口，不把压缩数量当作充分性证明。人物 1×4 的面部与服装覆盖按 [唯一面部来源](../../asset-image-assistant/references/02-character-master-guide.md#唯一面部来源) 判断，实际文件只列一次，追溯来源不自动加入上传列表。

## 第三层条件来源（按需）

本轮已确认镜头在 2D/3D 混合媒介或复杂姿势/接触关系上确有参考缺口时，可在仓库内置知识包中选读 `wiki/sources/ai动画制作流程-刺猬星球.md` 的“核心主张”“屏幕证据与可复用部分”“证据缺口”。它是未复现的 candidate 教程来源，不是上表可上传的确认图片。只参考角色、空间与粗草图的信息分工，不替代确认外观；不要求每镜图、固定数量角色板或白模，实际补图仍先判断复用并核授权。原提示词有裁切，不能补成完整模板。未命中或来源缺失时不加载、不阻断独立工作；沿现有选择记录说明实际采用范围，不新建方法或阅读凭据。

## 继承边界

- 按 `VISUAL-SUPPLEMENT-METHOD` 判断当前状态的保留与排除项，写回本次请求；来源镜头与确认资产事实、manifest 的 `must_not_inherit` 仍是不可改写的输入约束。
- 参考互相冲突时停止并报告；不得自行裁改导演镜头或资产事实来消除冲突。

## 连续性

- 分镜画幅继承项目成片要求，不继承场景四视图、人物联系表或产品实拍的画幅。本项目指定竖屏9:16时，实际提示词必须明确9:16；生成后读取像素宽高核对并记录取整差异。竖屏不能靠保留整间房而牺牲指定近景／中景，构图同时核对人物截幅与空间锚点。
- 起身、走近、离场等状态继承前态的位置和通路；先核对每人从哪个坐具／地点开始、朝哪里看或移动，再选择静态瞬间。分镜参考用于锁关系，不把动作直接改成重新集合站队。用户明确改变调度时记录其修订依据，交接同步该改变。
- 人物与环境的尺度按同一空间和可比深度的锚点核对。多人坐具图先确认座位容量与前后层次，再核臀部落在坐面、脚与地面、膝盖与桌边的距离及起身通道。优先用有人与家具同框的真实参考或已核关系图；人物板用于身份、衣装和头身结构。宽窄构图可变，人物与家具的世界关系须稳定；无法看清关键尺度时，先补可核依据再承担空间控制用途。
- 手持产品的尺度优先依据同画面中的真实手掌、身体或其他可核验参照；孤立白底图不能证明实际尺寸，不能自行填写厘米数。抽帧记录视频路径与帧号／时间点，不将非首帧标成首帧。实拍不提供尺度时保留未知，不用猜测尺寸约束生成。
- 用户要求错误图重生时，重写完整提示词，并按 [返修参考与固定基准](image-continuity-hard-rules.md#返修参考与固定基准) 选择实际输入；保留本轮合格基准，不回灌失败结果。移除失效参考时同步当前引用，并保留旧版本退回原因，防止后续误用。

按本镜用途核[场景固定层](../../asset-image-assistant/references/03-scene-master-guide.md#背景母版与单变量派生)、[多机位覆盖](../../asset-image-assistant/references/03-scene-master-guide.md#多角度场景参考组)及下文的开场或切点状态。导演连续性错误沿返工分流返回上游。

## 剧情后的场景状态参考

基础环境图只说明建筑、固定布局及其已核状态，是派生来源，不自动等于视频剧情初态，也不是整场永久有效的全景状态。剧情改变了后续画面仍须保留的持续可见状态时，先核对原文与导演：旧态 → 哪个实际事件 → 新态、保持不变的建筑／家具／位置关系、变化的物件及属性、开始生效镜号与后续沿用范围。把这些信息留在现有导演 JSON 的前后态及制作备注、补图请求与引用中，不建立另一份状态台账。摆菜、礼盒开闭或移走、布置和损坏等可触发；只换角度、说话、普通走位而场景持续状态未变不触发，也不为每次手指或表情微动制作新图。来源没有变化事件时，不补戏解释差异；但原文首次出现已经摆满饭菜或已经捧碗，可直接制作并引用该已成立状态图，不为流程先制作空桌／桌上碗，也不虚构上菜／拿碗动作。只有来源确有矛盾或缺失时返回上游核对。

1. **先取得对应新态图。** 按既有 `visual-supplement-request` 写唯一目标状态及 `source_shot_ids`；先查现有已确认图是否完整覆盖，足够则复用，否则登记 `request_supplement`。派生制作保留获准基础来源、固定不变量及剧情已发生的变化；按已有授权生成候选，实际看图并按本轮适用路径正式采用后才能作正式输入。缺图、生成失败、未审或用途未核时，明确待制作／待审及受影响镜头，不拿旧图、文件名或假 `@` 占位冒充完成。
2. **沿用新态，退出冲突旧态。** 后续每个适用镜头都继承已发生的状态，直至来源允许下一次变化；按 `source_shots` 找全承载镜头的生成段，不能只核段首。基础图及旧态图保留来源历史；新态生效后，冲突旧图不得再作为该范围的活动全景／布局／状态参考。不能一边上传空桌全景，一边仅补一句“保持桌上的菜”来声称已修好。只负责身份、产品等相容局部职责的其他参考仍按既有用途实看核对，不借改职责名称掩盖可见冲突。
3. **正文与实际输入一起换。** 新态图按准确 artifact、revision、文件 hash、`state_id`、获准镜号及 `quality_evidence.uses` 核验；视频正文写出该状态的可见内容及后续允许的变化，真实有序素材和平台原生引用必须指向同一新态图。只改 `prompt`／`prompt_text` 而 `native_mentions` 或上传映射仍旧，不算完成。程序仅检查声明、字节和范围一致，不能证明画面已经正确或实际生成任务用了哪些输入。
4. **不把状态演变切碎。** 同段内真实发生变化时，明确起态、触发过程、终态及两种参考各自范围；不把结果图冒充动作前态。若平台不能逐镜绑定，必须注明实际只能整段多参考的限制，不把文字职责说成原生逐镜控制；必要时仅在真实叙事变化处提出后续生成段，涉及导演决定则返回确认。保留用户已指定产品开盒、挤料、搅拌同一生成段的限制，不能为补图而逐动作拆段；无法兼容时报告限制，不擅改该选择。

### 同一业务稿内的字段与消费

导演包在对应 `scenes[].scene_states[]` 登记需要沿用的变化后态或原文进入时已成立的状态，每条使用 `state_id`、`entity_id`、`previous_state_id`、`change_event`、`description`、`preserve`、`changes`、`source_shot_ids`。`previous_state_id` 指基础态或上一后态；原文进入时状态已成立且没有此前状态时，用 `previous_state_id: null`，`change_event` 写原文成立事实及定位，不要求虚构变化动作。已有同实体状态链中间不得用 null 重置；后续变化仍是旧态 → 实际事件 → 新态。事件及描述必须来自原剧情／导演，不从缺图倒推新剧情。`preserve` 和 `changes` 分别列持久不变量与实际变化；`source_shot_ids` 列全后续沿用镜头，可包含发生变化的本镜终态。既无待保持的已成立场景状态、也无持久场景变化时省略 `scene_states`，不填空架子；这不是另一份台账。

分镜请求沿用 `target_state`、`must_appear`、`preserve`、`gap` 与 `source_shot_ids` 表达目标及缺口。活动素材沿用 `role`／`roles: state_reference`、`state_id`、`entity_ids`，必要时用引用的 `source_shot_ids` 限定本段内用途；原图登记的 `quality_evidence.uses` 必须覆盖准确状态、职责、实体和镜号。缺字节、错 hash、错状态、错范围或观察失败／未知均不得进入活动输入。

派生场景状态图不是“上一张边界分镜图”。下文[新边界图独立取基础参考](#新边界分镜图独立取基础参考)的规则不变：使用获准且适用的新场景状态来源，不准任取前一边界图递归垫图；失败图不得回灌。状态图也不自动提供平台首尾帧控制、生成授权或用户确认。

同镜也需控制人物站坐、持物或交接时，对照[环境后态与人物关系](#环境后态不替代人物关系)。视频草稿的来源、镜号及场景判断按[交付核对](../../../docs/development/delivery-snapshot-checks.md#剧情场景状态的交付核对)。

## 真实开场状态

本节只约束指定承担开场或切点状态的参考，不规定所有素材上传顺序。身份、服装、产品和环境参考按获准职责使用及跨段复用，不要求每段新增开场图。

下一段要表现某个主体或效果入场时，承担本段动作前开场状态的参考图必须是动作发生前状态：固定场景、角色、机位、光线和材质已经成立，但本段第一个新增事件尚未发生。已经贴合、覆盖、击中、爆炸、冲洗或完成变形的图片只能承担动作或结果职责，不能兼任开场状态。

同一张图兼作前段尾态与后段动作前态时，必须同时符合两侧切点状态；已有同状态不同机位参考组按下节处理。身份、服装、产品和环境参考的跨段复用不受此双职责条件限制。指定承担动作前开场状态的图若已包含本段第一个新增事件，须更换为合格前态参考；缺少该任务确需的前态图时停止相关视频提交，不能仅靠否定词压制冲突，也不因上传序号判定用途。

## 连续事件因时长拆段时的实际衔接参考

只在同一连续事件确因模型时长/承载而分段时执行，不给每段机械补图。先按已确认导演确定可停靠切点；若需要改变导演切点，先返回导演，不自行把过程剪没。

在已有分镜选择记录与提示词制作备注中，用一条跨段记录写明：前段结束/后段开始的准确时刻、人物/道具位置与朝向、持物/接触、动作相位、相机与光线，及明确要变化的项目。文字记录还须绑定具体已确认图的 artifact ID、修订、文件及登记hash和两段各自上传序号，不能只写“保持上一段一致”。

- 同机位直接续接，优先同一张合格切点状态图同时承担前段尾态和后段动作前态；后段第一个新动作尚未发生
- 导演本就要求换机位时，可用同一位置状态的关系图加两侧机位图；两图必须对应同一物理状态/动作相位，不能用不同动作阶段凑成首尾帧。关系展示视角不是新的导演机位
- 原有确认参考确能表达切点就复用；只锁身份、局部抓握或落地后状态的图，不能冒充“起跳前整场状态”。不够时回本阶段建立一个共用目标请求，不为两段重复生产两套无关图
- 选择严格首/尾帧还是多参考输入，按本轮平台与模型实际能力核验：CLI 查当前帮助，网页查原生控制与真实输入职责；只有能力已证实才能声称严格首尾帧控制。当前只能多参考时，把同一状态图真正放入两段输入，并分别说明尾态/动作前态职责；文字中的“首帧”不代表平台提供了该控制

没有可用且已确认的切点参考时，相关视频提交停止；可以按授权试写，但必须保留此缺口。未来实际生成后，前段真实尾态仍需与绑定状态核对；不自动把失败片段抽帧升级为新确认图。

前段返工改变切点状态、人物/道具或相机/参考版本时，后一段的旧绑定一并失效，先重新确认共用参考，再改两段材料顺序与正文并复查。仅修改与切点无关内容时记录不受影响依据，可继续复用原桥图。候选出现不等于正式采用；已确认旧图保留，新采用后旧ART-ID不可继续冒充当前版本。

## 新边界分镜图独立取基础参考

生成每个新的边界分镜图时，独立使用该节点获准的基础场景、人物、服装和道具参考，结合导演已定的该节点动作；禁止把前一张已生成的边界分镜图作为下一张边界图的生图输入，即使前图已确认也不例外。例如，“C02尾／C03首”不作为“C03尾／C04首”的生图参考。所需基础参考缺失时先补齐来源，不以前一边界图替代。

空间连续性由同一基础素材和明确的位置、朝向、持物及动作相位维持，按原有参考记录核对实际输入，不另设一份清单。各节点仍取其完整适用参考集合，不把“独立生成”理解为只能单图参考。

这是不同边界图之间的生图输入规则，不扩大为禁止普通图像编辑或同图局部修正。相邻视频仍可共用同一张已确认的边界图作为前段尾态和后段首态；视频阶段按模型实际能力使用首尾帧或完整多参考输入，并分别标明职责。共用边界图生成视频，与用前一边界图生成下一边界图是两个不同环节。

## 分镜返修的固定基准

分镜图允许按实际需要少量垫图；同一轮返修固定最近已确认、清晰且适用的基准 A，平行生成 B1、B2、B3。B1 失败后仍用 A，不得沿 A→失败 B→失败 C→D 递归叠图；若没有合格 A，就回本镜获准的原资产与镜头设计重建。新结果经实际审图确认后可成为后续正常状态/连续性参考；其中新边界图生图须遵守上节独立基础参考规则，不把已确认边界图递归用作下一边界图输入，也不设机械生成次数门槛。

## 环境后态不替代人物关系

检查同一世界锚点的门窗、桌侧、椅位、地面站位、在场/画外人物、持物者与可达方向。场景持久物的新态图只证明其实际可见内容，不能代替三人站坐与交接的关系参考；反打可换画面左右，不能换世界位置。关系图与上游几何不合时停止该用途，修正/替换为待审候选，不以“仅取关系、眼神不继承”等用途窄化豁免；错误生成尾帧也不能自动升级为下段参考。先核有用且正确的既有图；普通走位、对白或每个手部动作不机械生图，已取消手部过程图仍取消。已发生持续场景变化的后态先生成审查再用于后续的规则不变。

## 返工先定位原因，再选择是否回白模

退回一张图不等于重建场景，也不等于只重写提示词。先对照原导演、实际输入图与失败图，写出差异发生在哪一层；返工原因及证据记在已有选择记录/请求中，原确认版本保留。

| 已核实的原因 | 下一步与复用边界 |
|---|---|
| 剧情、镜头目的、拍法或切点本身错误/矛盾 | 返回编导或导演；不能在白模或补图里擅改拍法 |
| 导演意图明确，但已有白模的站位、机位、遮挡、承托、接触或尺度错误 | 请求 return_upstream → blender-previs，沿同一权威场景基座另作逐镜修订、重拍必要静帧并复核。只有固定房间/家具/尺度基座本身错才另建基座修订；不每镜重搭房间 |
| 正确导演已写伴随状态，白模/提示词只实现主动作或默认人物idle | 先核对完整camera/take与前态；白模朝向/粗姿态/支撑错，回同基座逐镜修订；白模正确仅成图/文字漏项，在本阶段返工。不重写正确导演，不逼所有人移动 |
| 缺少足以检查上述空间问题的参考 | 说明具体缺口并按已授权范围选择白模；未选用白模不自动启动。对白模无必要的镜头不制造前置门槛 |
| 白模空间/目标状态已正确，成图却没有遵循它 | 复用有效且已确认的白模及外观母图，重新核对实际参考顺序/职责后另出图候选；不为生图偏差重做正确白模 |
| 身份、服装、表情、材质、光色或真实产品外观错误 | 核对对应母图/实拍和职责；母版本身错回资产阶段，单图表达错在本阶段返工。有效白模可复用，不因外观错误强制渲染 |
| 简单镜头已有确认图完整覆盖，空间没有未决问题 | reuse_existing；无需白模、无需新图 |

回白模的请求仍使用现有 decision / return_upstream.reason，max_images=0；原因写清目标状态与哪项依据不符。白模步骤只调整相应逐镜副本，技术检查、具体白模确认、外部生图授权、成图确认分别处理，不用一次“继续”自动通过全部。

白模交回后先核对当前确切 artifact ID、修订、源场景和文件指纹，再决定生图。分镜新图登记使用按稳定请求/用途区分的 logical_id；depends_on 包含实际使用的导演/资产与准确白模 logical_id。不可用通用 visual-supplement.image 去替换另一用途的图；历史共享逻辑ID只读，返工前先明确本次独立对象。

采用白模新修订或正式返工冻结上游后，相关补图/引用按现有依赖失效处理；候选产生本身不撤销旧确认。新补图采用走现有修订控制，不以直接改 status 或无失效传播的 promote 操作替代。独立图片的 `confirm_candidate(..., usage={"source_shot_ids": ["S01-001"]})` 必须按用户实际获准镜号记录结构化用途，写入同一 hash 绑定确认凭据；`scope_description` 仅是说明，整张图被确认不等于全片可用。镜号不得从 quality_evidence 的观察范围推断，旧凭据没有用途时仍保留但不授予镜号；扩大范围须准确重新确认，不能手补批准。重新消费时对照原问题复查，而不只检查图片存在。

分镜图引用必须用 `python -m scripts.core.asset_refs --project <项目> --require-reference <准确ART-ID...> --for-shots <本次准确Sxx-xxx...>` 核对；白模仅核版本可省略镜号，按本次用途消费时同样传 `--for-shots`；这只证明版本和文件链可用，不证明本图动作相位、用途或画面质量正确。正式消费 AST 母图用 `--require-final-image AST-ID@OUTPUT-ID` 核本次实际选图。该入口沿用普通确认检查，并对已登记的最终人物板核规格；仅制作头照和服装过程图仍走其原入口。

## 放大、缩小剧情的比例来源与适用范围

这类剧情先在现有选择记录中对照已确认故事/导演列出正常、变化中、微缩/放大、恢复的生效范围。只有剧情许可的变身节点可改变体型；未确认的厘米数、白模试验值或不同图中的像素高度不能升级为全片身高。

人物板只负责面容、服装与成人身体结构，不承担角色对世界的尺寸。每个出现微缩/放大主体的生成段，必须能指出实际传入的适用确认图、其中可辨的正常尺度参照，以及两者要继承的相对体量。只有白底人物板、空场景图、孤立产品图或一句“巴掌大”不足以证明共同尺度关系。

优先复用获准范围内的关系图/分镜图，并明确哪些姿态、持物、表情不继承。既有图只批准某些镜号/局部用途时，不因为图已确认就扩大成全片比例母版；要扩大用途先记录候选决定并确认其范围。原已取消的补图不机械恢复，先核对是否能复用图及其比例职责。

跨段继承同一比例依据，机位变化不要求人物像素高度相同；检查世界尺度、相同正常参照物与接触关系，而非对齐像素。局部成图的比例无法由现有确认资料判断，或与其他段相互冲突时，暂停该引用，沿前述返工分流处理。只有确有空间/接触/尺度推演缺口时才回同权威场景白模；白模本身正确时复用有效帧，外观问题不重建房间。

分镜图必须按本次准确用途使用 `--require-reference <ART-ID> --for-shots <Sxx-xxx...>` 核对这次选择有没有超出回执记录的镜号；它不自动识别画面中的微缩状态或尺度锚。新图/新增全局比例用途仍是候选，缺范围或视觉依据不能仅凭程序通过提交。

## 生成记录

如确需生成，记录请求 ID、来源镜头、实际参考路径、工具、模型、用户授权引用、目标尺寸、实际尺寸、技术检查和候选状态。产品出现时，产品实拍必须进入实际参考集合。


## 把缺口推进到可执行返工

发现缺口后，在现有选择记录中给出下一步，不以“缺图”作为工作终点：

1. **已确认且用途覆盖**：列准确 ART-ID、文件/修订和目标镜号，记录复用并以 `--require-reference ... --for-shots ...` 重检；不新增图或白模。
2. **图可用但需扩大用途**：先实际看图，写清仅新增的职责、镜号和不继承内容，作为用途变更候选交用户确认。原确认不扩大；用独立用途 logical_id 和新回执保留旧图/旧范围，可复用完全相同的图片字节，不强制再生图。未获范围确认前仍阻塞该新用途。
3. **确需补一个状态**：建立现有 `request_supplement` 请求，指向精确目标状态与最少候选数；多个视频段共用同一状态时只建一个共用需求。按前述原因分流决定是否回同场景白模，不按视频段数量重搭或重拍。
4. **执行范围已授权**：取当前已确认白模/资产和真实产品参考，按本次工具/额度授权产出候选；没有新增生图授权时保留可直接执行的请求和具体输入，不自动耗图。不能因补充请求而恢复已取消项。
5. **候选与采用**：技术检查、实际看图、来源/状态/范围核对后，记录待审与剩余问题；只在用户明确批准具体文件及其用途后走原登记/修订采用。先重查本次原失败条件，再让前后两个片段重新绑定同一准确版本；只修前段而让后段继续引用旧图仍算未完成。

技术演练可在隔离fixture模拟批准来验证“批准后可消费、返工后失效”，但真实候选必须保持未确认。生产准入检查证明记录/字节/范围有效，不能代替实际画面和最终视频效果验收。
