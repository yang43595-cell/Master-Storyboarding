# 视觉补充参考资产契约

## 可消费来源

资产清单 1.1 / 2.0 的 `confirmed_outputs` 是同一 AST 的确认图片组：按 purpose、state、view 匹配职责，并核对具体确认引用。`confirmed_asset` 只代表兼容主图，不能代替其他视角。旧清单无图片组时只使用已有主图，不推测隐藏输出。只消费 status=confirmed 的 AST。

| 来源 | 允许用途 | 不允许用途 |
|---|---|---|
| `visual-asset-manifest.json` 中的确认资产 | 锁身份、空间、道具、产品、风格和已登记状态 | 从候选或表外项目推断新资产 |
| 动作参考或已确认视觉补充 | 锁单一动作峰值、起始或结果状态 | 把旧状态机械继承到不适用镜头 |
| 产品实拍 | 锁真实外观、结构、展示面和包装事实 | 用风格图或文字猜产品 |
| `storyboard.package` v4（旧 v1/v2/v3 只读） | 提供来源镜头、镜头目的和静态目标边界 | 重新设计镜头 |
| 用户为本镜选用且已确认的 `reference-handoff.json` 白模包 | 在实际覆盖状态内锁站位、承托、遮挡、构图与摄影机路径 | 锁身份/服装/精细四肢动作；把起幅图当整镜；把场景基座当逐镜确认 |

## 复用优先

参考覆盖判断完整读取 knowledge-profile 绑定的 `VISUAL-SUPPLEMENT-METHOD`。足够时，`decision` 必须为 `reuse_existing`，只登记引用，不生成新图。参考数量受工具限制时先保证实际控制目标、连续性及充分覆盖余量；可去除重复无用来源，不能为临界少图削弱环境一致性。限制下无法保留覆盖时报告缺口，不把压缩数量当作充分性证明。人物 1×4 的面部与服装覆盖按 [唯一面部来源](image-continuity-hard-rules.md#唯一面部来源) 判断，实际文件只列一次，追溯来源不自动加入上传列表。

## 继承边界

- 按 `VISUAL-SUPPLEMENT-METHOD` 判断当前状态的保留与排除项，写回本次请求；来源镜头与确认资产事实、manifest 的 `must_not_inherit` 仍是不可改写的输入约束。
- 参考互相冲突时停止并报告；不得自行裁改导演镜头或资产事实来消除冲突。

## 连续性

- 分镜画幅继承项目成片要求，不继承场景四视图、人物联系表或产品实拍的画幅。本项目指定竖屏9:16时，实际提示词必须明确9:16；生成后读取像素宽高核对并记录取整差异。竖屏不能靠保留整间房而牺牲指定近景／中景，构图同时核对人物截幅与空间锚点。
- 起身、走近、离场等状态继承前态的位置和通路；先核对每人从哪个坐具／地点开始、朝哪里看或移动，再选择静态瞬间。分镜参考用于锁关系，不把动作直接改成重新集合站队。用户明确改变调度时记录其修订依据，交接同步该改变。
- 手持产品的尺度优先依据同画面中的真实手掌、身体或其他可核验参照；孤立白底图不能证明实际尺寸，不能自行填写厘米数。抽帧记录视频路径与帧号／时间点，不将非首帧标成首帧。实拍不提供尺度时保留未知，不用猜测尺寸约束生成。
- 用户要求错误图重生时，重写完整提示词，并按 [返修参考与固定基准](image-continuity-hard-rules.md#返修参考与固定基准) 选择实际输入；保留本轮合格基准，不回灌失败结果。移除失效参考时同步当前引用，并保留旧版本退回原因，防止后续误用。

背景母版、真实开场状态、多角度参考组和唯一面部来源的技术规则见 `image-continuity-hard-rules.md`。这些规则用于识别参考是否可靠，不允许本 Skill 把导演连续性错误改写成补图任务。

## 返工先定位原因，再选择是否回白模

退回一张图不等于重建场景，也不等于只重写提示词。先对照原导演、实际输入图与失败图，写出差异发生在哪一层；返工原因及证据记在已有选择记录/请求中，原确认版本保留。

| 已核实的原因 | 下一步与复用边界 |
|---|---|
| 剧情、镜头目的、拍法或切点本身错误/矛盾 | 返回编导或导演；不能在白模或补图里擅改拍法 |
| 导演意图明确，但已有白模的站位、机位、遮挡、承托、接触或尺度错误 | 请求 return_upstream → blender-previs，沿同一权威场景基座另作逐镜修订、重拍必要静帧并复核。只有固定房间/家具/尺度基座本身错才另建基座修订；不每镜重搭房间 |
| 正确导演已写伴随状态，白模/提示词只实现主动作或默认人物idle | 先核对完整camera/take与前态；白模朝向/粗姿态/支撑错，回同基座逐镜修订；白模正确仅成图/文字漏项，在本阶段返工。不重写正确导演，不逼所有人移动 |
| 缺少足以检查上述空间问题的参考 | 说明具体缺口并按已授权范围选择白模；未选用白模不自动启动。对白模无必要的镜头不制造前置门槛 |
| 白模空间/目标状态已正确，成图却没有遵循它 | 复用有效且已确认的白模及外观母图，重新核对实际参考顺序/职责后另出图候选；不为生图偏差重做正确白模 |
| 身份、服装、表情、材质、光色或真实产品外观错误 | 核对对应母图/实拍和职责；母版本身错回资产阶段，单图表达错在本阶段返工。有效白模可复用，不因外观错误强制渲染 |
| 简单镜头已有确认图完整覆盖，空间没有未决问题 | reuse_existing；无需白模、无需新图 |

回白模的请求仍使用现有 decision / return_upstream.reason，max_images=0；原因写清目标状态与哪项依据不符。白模步骤只调整相应逐镜副本，技术检查、具体白模确认、外部生图授权、成图确认分别处理，不用一次“继续”自动通过全部。

白模交回后先核对当前确切 artifact ID、修订、源场景和文件指纹，再决定生图。分镜新图登记使用按稳定请求/用途区分的 logical_id；depends_on 包含实际使用的导演/资产与准确白模 logical_id。不可用通用 visual-supplement.image 去替换另一用途的图；历史共享逻辑ID只读，返工前先明确本次独立对象。

采用白模新修订或正式返工冻结上游后，相关补图/引用按现有依赖失效处理；候选产生本身不撤销旧确认。新补图采用走现有修订控制，不以直接改 status 或无失效传播的 promote 操作替代。重新消费时对照原问题复查，而不只检查图片存在。

分镜图/白模引用用 `python -m scripts.core.asset_refs --project <项目> --require-reference <准确ART-ID...>` 核对；这只证明版本和文件链可用，不证明本图动作相位、用途或画面质量正确。AST母图仍用 --require-image。

## 放大、缩小剧情的比例来源与适用范围

这类剧情先在现有选择记录中对照已确认故事/导演列出正常、变化中、微缩/放大、恢复的生效范围。只有剧情许可的变身节点可改变体型；未确认的厘米数、白模试验值或不同图中的像素高度不能升级为全片身高。

人物板只负责面容、服装与成人身体结构，不承担角色对世界的尺寸。每个出现微缩/放大主体的生成段，必须能指出实际传入的适用确认图、其中可辨的正常尺度参照，以及两者要继承的相对体量。只有白底人物板、空场景图、孤立产品图或一句“巴掌大”不足以证明共同尺度关系。

优先复用获准范围内的关系图/分镜图，并明确哪些姿态、持物、表情不继承。既有图只批准某些镜号/局部用途时，不因为图已确认就扩大成全片比例母版；要扩大用途先记录候选决定并确认其范围。原已取消的补图不机械恢复，先核对是否能复用图及其比例职责。

跨段继承同一比例依据，机位变化不要求人物像素高度相同；检查世界尺度、相同正常参照物与接触关系，而非对齐像素。局部成图的比例无法由现有确认资料判断，或与其他段相互冲突时，暂停该引用，沿前述返工分流处理。只有确有空间/接触/尺度推演缺口时才回同权威场景白模；白模本身正确时复用有效帧，外观问题不重建房间。

按实际用途可用 `--require-reference <ART-ID> --for-shots <Sxx-xxx...>` 核对这次选择有没有超出回执记录的镜号；它不自动识别画面中的微缩状态或尺度锚。新图/新增全局比例用途仍是候选，缺范围或视觉依据不能仅凭程序通过提交。

## 生成记录

如确需生成，记录请求 ID、来源镜头、实际参考路径、工具、模型、用户授权引用、目标尺寸、实际尺寸、技术检查和候选状态。产品出现时，产品实拍必须进入实际参考集合。


## 把缺口推进到可执行返工

发现缺口后，在现有选择记录中给出下一步，不以“缺图”作为工作终点：

1. **已确认且用途覆盖**：列准确 ART-ID、文件/修订和目标镜号，记录复用并以 `--require-reference ... --for-shots ...` 重检；不新增图或白模。
2. **图可用但需扩大用途**：先实际看图，写清仅新增的职责、镜号和不继承内容，作为用途变更候选交用户确认。原确认不扩大；用独立用途 logical_id 和新回执保留旧图/旧范围，可复用完全相同的图片字节，不强制再生图。未获范围确认前仍阻塞该新用途。
3. **确需补一个状态**：建立现有 `request_supplement` 请求，指向精确目标状态与最少候选数；多个视频段共用同一状态时只建一个共用需求。按前述原因分流决定是否回同场景白模，不按视频段数量重搭或重拍。
4. **执行范围已授权**：取当前已确认白模/资产和真实产品参考，按本次工具/额度授权产出候选；没有新增生图授权时保留可直接执行的请求和具体输入，不自动耗图。不能因补充请求而恢复已取消项。
5. **候选与采用**：技术检查、实际看图、来源/状态/范围核对后，记录待审与剩余问题；只在用户明确批准具体文件及其用途后走原登记/修订采用。先重查本次原失败条件，再让前后两个片段重新绑定同一准确版本；只修前段而让后段继续引用旧图仍算未完成。

技术演练可在隔离fixture模拟批准来验证“批准后可消费、返工后失效”，但真实候选必须保持未确认。生产准入检查证明记录/字节/范围有效，不能代替实际画面和最终视频效果验收。
