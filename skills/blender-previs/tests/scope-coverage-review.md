# 覆盖范围压力样例

维护白模流程时逐例核对实际决定，记录依据、影响范围及未验证项；这不是视觉识别器，也不是正式项目的通过凭据。数量、物品及镜号仅为例子，不写成全局阈值。正例只代表所列检查范围，不代替用户确认或生成许可。

| 输入事实 | 应有决定 |
| --- | --- |
| 确认源图是多排电脑机房，保守可辨至少22个CRT位和5级纵深；导演全景要求前排孩子与延入后景的电脑排。复用模型只有2组CRT、2椅；34个网格，技术43/43通过。 | 整间覆盖不通过，阻断完整镜头参考。34不是电脑台数，43/43不覆盖源图规模。局部座次结论单列，先补有效整间基座，不直接生成两台电脑的小房间。 |
| 上例的模型补出多排背景，但导演要求的近门框不入画、一个人物的鞋被桌挡；接触和投影检查通过。 | 规模改善不能抵消机位可见性失败，完整镜头仍不通过。不将“模型有门、有鞋”写成“镜头看得见”。 |
| 完整同源基座已有，导演只要前排两人的肩部近景，后排不入画且无本镜反射/遮挡影响；近侧座次、视线和实际取景均已核。 | 不因看不到所有电脑或鞋而失败；允许按近景准确用途保留局部证据，不要求每镜全景或添脚部镜头。 |
| 仅两席模型明确用于隔离接触测试，未声称完整场景，真实核对坐面/脚落地；未获整间与导演机位结论。 | 可以保留该技术诊断，不自动交作完整镜头参考、确认或生成输入。两席测试通过只报告两席。 |
| 原图远排被遮，已辨至少22个设备位，整间总数未知；本镜保留可见排布，不要求精确画外容量。 | 未知总数记未知，不硬填40/60台，不把22规定为所有机房标准；按实际可见范围检查，不能无依据宣称精确复原。 |
| 全景、座次、承托与导演相机下要求读出的对象均已按准确修订核实；用户尚未确认。 | 三项内容自查可报告通过，产物仍候选；不自动确认、交下一阶段或生成视频。 |
| 无人物的门把手特写，有效整间基座与门的位置一致，实际帧可读。 | 人物/承托项不适用并说明原因；不能因没有人物、椅子、四鞋而阻断。 |
| 旧俯视图看见两人及四鞋，改低机位后人物互遮；沿用旧PASS。 | 机位变化须重核实际画面，俯视不替新机位；阻断受影响镜头，不要求未变镜头全部返工。 |
| 原环境图与局部白模相配，局部座次正确但桌排方向与原环境矛盾。 | 活动参考仍不通过；“只管局部”标签不能豁免当前用途可见的空间冲突。 |
| 未观看实际渲染，仅有字段齐全、网格存在、verify通过与空白自查表。 | 未核，不是通过；先实际看要求的帧/时段，不伪造视觉结论。 |

相关学习来源为 Mac 同步原文中的《AI场景一致性》（60.58–94.00秒：先保空间布局和大型物体）与《邪修一招教你100%保持场景一致性》（15.92–81.16秒：未交代的空间关系和3D剖面图）。仅借鉴已读文字的空间表达原则，不背书“100%”，不声称重看原视频或把剖面图等同可执行Blender预演。实际验收仍以当前确认来源、模型及镜头产物为准。
