# Blender 预演

开始本职任务前读取[共用三层规范](../_shared/skill-layers.md)。本 Skill 适用边界：仅在可选白模预演分支获准后，按本职配方与渲染合同验证空间；不把白模当普遍前置，不以程序通过代替实际画面检查。

> **当前状态：已接入可选步骤，默认关闭。** 同一场景复用一份权威空间基座。只在用户选择的镜头执行本机 Blender，不默认全片逐镜渲染，不自动进入正式成图或视频生成。正式入口及确认/交接见 [项目接入](references/项目接入.md)。

默认本机 Blender 5.2 按用户需要选用，默认不启用；其他真实版本按所需功能实测，不以版本号代替能力证据。只有当前任务已明确授权云执行时，才按项目接入显式登记 `runtime_location: cloud`；不借此默认迁移其他任务。逐镜预演以已确认导演稿为先，先核对正文与导演包一致，再绑定准确镜号、artifact_id／revision／path、AST 与人物占位体映射、起止及关键状态和尺度依据。没有确认的数值只记试验值，不代替正文尺度。房间是可复用空间基座；镜头只补本镜人物、道具状态与摄影机，不重搭房间，也不以房间预览或隔离试验通过冒充逐镜验收。导演歧义返回 storyboard-planner 与用户，不在白模中替他们决定。

由当前执行者按 [PROJECT_RULES.md 的 Skill 执行分工](../../docs/rules/execution.md#skill-执行分工) 执行；默认主 agent 直接执行和自检。

用最小充分几何锁定空间、路径与摄影机运动，为三件事服务：**站位核验**（人物之间、人物与家具门窗道具的关系）、**分镜预览**（景别与运镜是否成立、该读的信息不丢）、**空间一致性**（同一人物跨镜站位朝向不跳变）。

产物有两种用途：给**视频**当运镜/站位参考；给**分镜图生成**当景别与人物关系的硬约束（配方里写 `shots[].must_include` 与 `shots[].subject_fill`，由 `verify` 按相机投影核对）。

## 执行顺序

1. `doctor` 自检环境（Blender、MPFB、必需扩展）；仅标准人体分支需要 MPFB；粗体占位不因此阻塞。缺标准人物模块时报告能力缺口，安装仍需授权。
2. 读齐**本镜所需的已有确认视图**并写空间基准：核对现有环境视图（45°/正面/反面/俯视等）与适用的确认关系图或座位图；每条锚点注明来源视图，缺视图先记录受影响范围，本镜所需空间无法核实才停止对应操作，不强求合法单图/少视图路线补齐四图。复用旧基座前按[覆盖范围三项检查](modules/previs-method.md#覆盖范围三项检查)核对源环境规模与排布，不能把局部座位测试基座当作整间场景；未知画外容量不猜填。
3. 固定房间、家具、道具占位和尺度的**无人物空间基座只建并登记一次**；已有有效基座直接复用，不按镜头重搭房间。按准确导演镜号 `prepare-shot`，据正文写本镜有效配方，再 `stage-shot` 在新副本放本镜人物起止及关键状态。身高用 `height_cm`，坐姿优先 `chair_id`；未定实现参数记试验值，时长继承已确认导演稿。字段与坑见 [CLI与配方契约](references/CLI与配方契约.md)。
4. **可选快速预览，不作为正式渲染或交付的前置。** 需要快速查看与调整时，可先 `export-preview --project <项目> --stage-dir <逐镜布置目录> --output-dir 05_分镜/预演/预览/<镜号_修订>`，在已有资产网页的项目页打开“白模预览”。AI 依据导演稿改本镜候选配方，Blender 计算实际动作与相机，Three.js 只显示同源结果；网页可自由观察、俯视、按导演机位播放与拖动时间轴，不能编辑或确认。调整配方后在新目录重新布置/导出，来源变化的旧预览会标过期。首次接入及文件要求见 [项目接入](references/项目接入.md#同源网页快速预览)。
5. 按待验证的空间问题选最少充分媒体：单态参考用首/落幅或必要关键帧；相机运动或粗路径/中途遮挡确需时序证据时，在已授权镜号与范围内按需出视频，固定机位也可适用。混合段只导实际需要时序参考的镜头，不自动增加渲染。`shoot` 用各镜 `video` 控制；`build` 的静态配方明确 `preview_video: false`、`topdown.video: false`、`topdown.show_paths: false`。俯视默认只出图，不显示路径；仅用户明确要路径辅助图时开启路径线。
6. 对逐镜副本执行 `shoot`，然后 `verify --recipe <本镜有效配方> --scene <逐镜副本> --shots <同一镜头清单> --output-dir …`，核对人物接触/比例、相机投影与产物证据，**不过不交付**。自动检查覆盖起止、关键状态及规定采样，不证明所有帧、全程遮挡或表演正确，仍须查看实际产物。已有完整整场人物时间线的旧白模可直接 `shoot`，但不能再 `stage-shot` 同 ID 人物；新增人物状态回到无人物空间基座，不删除基座人物或改房间。
7. 用 `register-reference` 登记逐镜候选与真实检查记录；登记前完成[覆盖范围三项检查](modules/previs-method.md#覆盖范围三项检查)，将准确用途及未覆盖项写入现有 `coverage` / `limitations`，不以 `verify` 的总通过数放行完整镜头。`actors: []` 只用于核对完整确认来源后确认无在场或影响画内动作的人物，技术通过不证明没漏人，未核实前不可发起用户确认/交接。用户明确通过具体白模后才用 `confirm-reference` 记录准确依据。`handoff-reference` 复核来源、空间基座、文件哈希及确认母图，再交接本镜参考包。包不授权生图/视频，不提升正式成图状态；用户明确授权下一步后按对应 Skill 执行。

## 各步结果与失败回退

上述顺序的核对结果留在现有输入、配方/技术自查记录、登记说明与交接包，不新增台账。`doctor`、导出或 `verify` 成功只证明各自实际检查范围。

- **启动与基座（第 1 至 3 步）**：记录已选镜号/运行位置及授权边界；实际读取确认导演、环境和关系参考，保留准确 artifact/修订、基座版本及三项覆盖核对依据。环境有单图/少视图合法路线，不为凑四图要求补图；缺视图只在本镜所需空间无法核实的范围阻断，画外未知不补造。输入缺失回准备，空间基座不符另作基座修订，导演歧义返回上游与用户；已有有效基座不重建。
- **布置与渲染（第 3、5、6 步）**：核本镜有效配方、人物及粗状态、时长、相机和必要媒体；实际执行 `stage-shot`、`shoot`、同配方/场景/镜头清单的 `verify`，保留真实输出、清单、日志与检查结果。旧整场白模按原例外复用，不重复布置人物。技术失败回本镜实现，不擅改导演或确认家具；第 4 步快速预览可跳过，但不能用预览替代正式媒体。
- **实际画面自查（登记前）**：实际查看导演机位的起幅、必要关键态与落幅；仅当本次要证明运动/遮挡过程时查看对应时序媒体。把整间规模、人物承托/站位、导演信息实际可见三项的来源、结果、未测范围写入现有自查记录和 `coverage`/`limitations`；无人物或无接触只免真实无关子项。未核/失败回相应基座或逐镜步骤，不凭 `verify` 总通过数交付完整镜头。
- **交审与收尾（第 7 步）**：先登记准确候选及真实技术证据，说明可用与未覆盖范围；用户通过具体白模后才确认。交接前复核同一来源、基座、字节和确认母图及实际携带媒体，执行旧稿归档收尾。未获确认停在候选，交接失败回对应失效来源；白模确认、生成授权、正式成图确认各自独立，不自动执行下一 Skill。

## 硬规则

- **多视图**：锚点与家具必须由已确认视图支持并注明来源视图；座位与椅数以关系图为准，环境母版只管房间本身。
- **静态/时序参考**：只验证静态构图时出图；需要核对相机运动或粗路径/遮挡过程时，才在本次授权内选择关键帧组或视频。固定机位不等于无时序风险，静帧不能声称覆盖连续运动。
- **不复刻姿态**：白模只承担空间关系、站位朝向、景别运镜与路径级动作；提示词须写明不复刻白模姿态，完全照白模动作会让成片僵硬。**预演视频只作相机运动与粗路径/遮挡参考**——拾取、递物这类精细动作镜只出景别图，动作过程用文字写；仅当用户明确指定「上传的是精细动作白模」才升级为精细动作级并记录依据。
- **道具只作占位**：白模里的道具是占位块，只锁位置、尺寸与遮挡关系，不承担外观；外观由资产图负责，提示词按颜色认领后声明不保留白模材质。
- **认领颜色**：人物各一色且全片不变，相似却不同的物品各自独立颜色；颜色只作认领标签，须声明不保留白模颜色与材质。
- **画面规范**：统一无纹理材质；关闭坐标轴、相机锥体与叠加物，俯视 `show_paths: false`；仅用户明确需要的路径辅助图允许路径线。保留地面接触点与导演稿要求的结尾 final hold；画幅与成片一致，不把示例的 9:16 当成所有项目要求。
- **只作证据**：只报告 CLI、文件、帧数、分辨率等技术证据，不冒充视觉终审；不自改导演意图，不覆盖非空目录。
- **交付前自检**：能用数字就用数字（量骨骼/网格世界坐标、对椅子座面与扶手范围、算等效焦距与取景），**"看着还行"不算检查**；发现不齐先修再交付。

流程细节与字段表读 `references/CLI与配方契约.md`，方法与边界读 `modules/previs-method.md`；进入阶段先跑 `python scripts/stage_context_cli.py ensure-prepared --project <项目> --skill blender-previs`，并遵守 `PROJECT_RULES.md` 与 `../_shared/` 下的共享红线。
