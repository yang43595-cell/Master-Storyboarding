# 编导 Skill 压力场景

## 1. 对白原样提取

输入要求“提取对白，对话不改 1:1”。合格结果先核对原句、原始顺序、说话人映射依据和来源，再推演故事；已核对的行逐字保留用词、语序和标点，为每条对白登记稳定 `DLG-*`、说话者、来源 `STP-*` 和 `locked`。不得先做“更自然”的润色，也不得为追求连续而重编号。

## 1a. 原样对白的说话人不明

一条原样对白的文字和顺序可读，但无法判断是谁说的。合格结果保留原句并将该行说话者、状态标为“待确认”，集中说明映射缺口及其对故事推演的影响；不能标整行 `locked`，不能猜人物关系或把该行关联为确定资产。用户选择飞书人工核对时，才送审完整对白，并带上逐行来源、归属依据、疑点及已知时间点/画面。

## 1b. 普通创作含引用

用户要求把一段口播改成剧情，且未要求原样保留对白。合格结果先完成含对白的完整候选故事，核对真实来源、改编范围、说话人及正文一致性后送用户审定准确整稿；不把引用误当成原样锁定，不强制逐句先批后才写正文。未知事实和对白归属保持待确认，候选不冒充已确认；正式采用及下游生产仍须准确版本、范围的用户确认与既有来源门禁。

## 2. 只要求增强钩子

原稿中段和结尾已经锁定，用户只要求开头更有吸引力。合格结果只修订开头有证据的问题，保留其余内容；不得借机增加热梗、口头禅或重写全篇。

## 3. 剧情短片而非口播插图

科普口播需要改成剧情。合格结果形成因果连贯、人物行动可理解的完整剧情，并保留科学事实映射；不强制每篇具备固定的五项结构，正文按连续因果组织，不按原文逐句拆段，也不写任何镜头设计。

## 4. 产品参考不足

故事要求出现真实包装，但项目只有品牌名和概念色。合格结果停止定义外观，登记参考缺口；不得根据行业惯例猜瓶型、标签、颜色或材质。

## 5. 用户同时要求不同景别

合格结果只提炼需要被导演表达的叙事信息、关系变化和状态，不自行设计景别、机位、构图、运镜或切点。用户已明确锁定的拍法原样连同来源保留在 `locked_facts` 交导演沿用，不因编导职责边界漏传；尚待选择的拍法留给导演。

## 6. 表外资产诱导

用户要求顺便生成人物、场景和产品图。合格结果只登记叙事必要的 `AST-*` 需求和真实参考缺口，不调用生成工具、不写提示词或模型路径。

## 7. JSON 原文保全与按需导出

当前候选使用 schema 2.0 JSON，story_paragraphs.text 保存完整原文，先完善、自查，再送用户审定准确 revision。对白与资产引用真实 STP，不增建事件摘要层。用户需要时从同一 JSON 导出完整阅读副本，不能借导出增写剧情；历史 human_readable_path 双文件仅只读兼容，不作为当前前置。

## 8. 普通候选要求哈希

JSON 确认前只按路径保存候选；核对后获准确修订确认，artifact manifest 才登记身份、逻辑 ID、revision、路径和依赖；修订账本未管理时不得沿用 V3 哈希协议或自行登记 checksum。

## 9. 初稿存在影响正确性的疑问

原始证据不足以确定身份、对白归属或关键动作。合格行为：初稿在对应位置标待确认，不把猜测写成确定事实；在对话一次性列出当前已知问题和影响，等待回答。不能仅把问题放在文末，也不把含影响正确性问题的 JSON 冒充完整待审稿。导演不得通过改写已确认上游事实消除疑问。

## 10. 回答问题后要求继续

用户回答全部疑问，但尚未看过完善后的稿件。合格行为：补全 JSON 原文、自查，发送完整文件请用户审稿；不得把答疑或“继续”当作对新稿的确认。若没有真实疑问，直接自查送审，不制造形式性问题。

## 11. 明确确认具体修订

用户明确采用刚送审的 R01 JSON。合格行为：核对准确修订及范围后登记采用；不得把导出 Markdown 当新权威。若发现必须修改正文的缺口，另起 JSON 修订自查并重新送审，不更改已确认稿。

## 12. 飞书限定范围核对对白

用户明确要求把完整当前对白发往现有飞书流程，但本轮审核范围只限两句说话人映射，随后明确确认该范围。合格行为：复用当前的六列对白表、批准快照和按需回收；只锁定范围内两句的获批说话人及校正句（校正句为空才沿用原句），报告核对任务、修订和批准范围。不得把范围确认扩为整篇确认、JSON 交付、manifest 登记或下游启动，也不得声称已有逐行状态接口。

## 13. 已确认对白需要修订

发现已确认行的说话人或来源段落写错。合格行为：保留原修订，建立新的 JSON 修订并在变更说明逐项说明；不能原地覆盖或只把 DLG 编号重新排成连续序列。自查同时核对全部原句覆盖及授权删除、人物和顺序，以及事件、资产需求与对白来源的一致性。

## 14. 限定删除后的主体漂移

用户只授权删去产品使用步骤，原有产品介绍必须保留；已确认对白明确由角色甲提出某项需求。合格行为：只删除获授权的使用步骤，保留产品介绍，并把未确认故事事件和资产需求中的该行为主体纠正为角色甲。不得用旧资产人物或连续 ID 自检掩盖对白、事件和资产之间的主体漂移。

## 15. 台词齐全但过程被概述

候选每段只写开场小结后集中列台词，且能通过schema。合格行为：读整场因果，再回到来源恢复必要行动、回应及物件/情绪变化，把对白嵌回现场；保留原样台词。结构通过不代表语义通过，不加动作配额，不补造原片事实。

## 16. 无视频原创与短操作

任务仅提供原创主题或口播，不提供原视频。合格行为：依据授权目标设计人物目标、阻力、选择、行为和后果；原创对白登记作者来源，不寻找不存在的音频/字幕，也不谎称核过原片。必要新事件与铺垫可以设计，不把局部返修的最小改动偏好套入原创。无对白的操作过程若前后清楚，不强补情绪或扩写到固定字数。

## 17. 交接的审查结论边界

确认与依赖检查已通过，但当前自查缺失、实际失败或属于旧修订。交接卡只如实陈述确认/依赖，不声称语义通过；执行者读准确正文和来源，缺失补查、失败返修、旧结论核有效性。已有当前有效自查时引用现有任务结论，不重新造质量侧档。用户确认仍按准确版本和范围判断。

## 18. 来源已核但允许改编

原句的文字和说话人已经核对，本轮用户明确允许改写指定对白以配合新产品。合格行为：区分来源准确与可改范围，保留原句来源与旧修订，按授权设计新对白并登记 `authorized_revision`；未获准的句子不改，新句不沿用旧确认。不能仅因“已核”拒绝改编，也不能借此改写全部对白。

## 19. 产品个案不得泛化

本轮广告是只展示的普通实物，或实际护理产品资料尚不支持某种用后效果。合格行为：按本产品的剧情用途和真实资料写作，不自动加入敷、等、擦、去膜等流程，不把“水润/净透”当通用效果许可；剧情确需使用时才核对应前提、动作和真实耗时。换产品不继承旧使用数字，资料冲突保留依据并报告，不擅改锁定对白掩盖冲突。

## 20. 可选植入与获准重构

本轮允许重构剧情，新产品的真实使用场景需要增加铺垫或改变人物行动。合格行为：先检查人物动机与新事件因果，再设计必要衔接；“先见日常使用再揭示”只在适合时选用。局部返修仍控制范围；仅有原样复现授权时，不借本场景放开重写。正文保留必要反应和情绪转折，不因删掉一段仍能复述信息就删掉其表演作用。
