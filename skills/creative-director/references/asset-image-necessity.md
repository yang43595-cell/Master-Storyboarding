# 资产图需求判断与检查

故事中出现的人物、场景和物品，不自动成为出图任务。列入制作清单前，先判断是否需要独立图片固定外观，以及现有素材是否够用。

| 对象 | 通常需要独立图片 | 通常不必单独制作 |
|---|---|---|
| 人物 | 主要角色、反复出现且需保持同一身份的角色，或外貌有明确要求的人物 | 普通背景人物、一次性路人；一句对白不自动要求完整人物资产 |
| 场景 | 多镜头需保持同一布局，或有特殊空间设计要求 | 一次性普通背景，可在分镜中直接表现 |
| 道具 | 外形必须一致的关键物件；特殊造型、重要细节或交互结构需固定 | 普通陈设、食物、小件，只需表达类别或剧情作用 |
| 产品或指定实物 | 必须准确还原外观，需要可靠图片依据 | 已有真实参考够用时直接复用，不另行生成 |
| 服装、饰物及局部 | 独立展示、取放、交接等需求无法由人物图或场景图支持 | 可以随人物或场景固定的内容，不重复拆项 |

简单一次性配角可以完全不建资产图，在现有判断依据写清由视频提示词描述其外观、在场范围及动作，让模型生成；不虚造图片引用，也不强制单图或1×4。若身份/服装/多镜一致性或交互控制确需固定，再选适用单图、已有综合母图或完整人物板。无需独立图仍保留人物、对白归属和故事事实。

环境一致性优先于少出图；同空间多镜、多机位或长段默认四图合理，可按当前真实覆盖减少补图但必须留充分余量，不以临界最少为目标，不因已有四图就视为浪费。

一次出现也可能需要图，多次出现也可能复用。判断依据是具体制作需要，不是次数、名字或对白。有交互本身也不证明需要独立图。

- 先判断要不要独立图，再决定怎么拆。不同人物、实物在故事中分别记录，不等于分别制作。
- 现有素材够用就复用；能随人物或场景表现的，不重复制作。具体动作、表情和空间关系优先由分镜图承载。
- 只制作当前明确需要的内容，不默认完整表情、服装、多角度组。依赖导演拍法才能判断的暂列待定，不为填表编造镜头。

资产表每项填写“处理结论”和“判断依据”：结论为“无需独立图／复用现有素材／需要制作／待定”；依据简述独立图解决什么问题，或由什么素材、人物图、场景图、分镜图承载。只有“需要制作”进入新制清单；复用项可进入选图，不能直接生成。无需独立图不删除故事事实。

交付前由当前执行者检查每项是否完成上述判断。缺列、空白或只写“出现过、是道具、有对白”的，补齐后交付；已有具体结论与依据的，不再重复详细审查，不增加独立审核流程。

结构化时两列原样映射为 `image_decision` 与 `image_reason`。历史确认包缺字段时保留兼容读取，不改写旧稿、不自动撤销旧图；本轮新稿及实质修订须补齐。用户调整优先，取消项不自动恢复。

新 JSON 稿及实质修订直接填写 asset_requirements 的 image_decision/image_reason，并运行 `python -m scripts.core.story_sources --project <项目> --narrative <叙事包>`。历史 Markdown 候选才沿用原命令并追加 `--check-asset-decisions`：`python -m scripts.core.story_sources --project <项目> --markdown <编导稿> --check-asset-decisions`。程序只检查列、结论和非空依据；依据是否只是“出现过”等空泛表述由当前执行者顺手检查，不再开详细审查。
# 产品动作参考

产品在剧情中出现使用动作时，按 [产品使用参考对接](../../_shared/product-usage-contract.md) 列出具体动作参考及缺口。人物真实使用效果参考需求单列待定；幻想使用画面由分镜处理，不能因此额外生成一张剧情状态资产。
