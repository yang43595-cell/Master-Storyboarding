# 资产图需求判断与检查

故事中出现的人物、场景和物品，不自动成为出图任务。列入制作清单前，先判断是否需要独立图片固定外观，以及现有素材是否够用。

| 对象 | 通常需要独立图片 | 通常不必单独制作 |
|---|---|---|
| 人物 | 主要角色、反复出现且需保持同一身份的角色，或外貌有明确要求的人物 | 普通背景人物、一次性路人；一句对白不自动要求完整人物资产 |
| 场景 | 多镜头需保持同一布局，或有特殊空间设计要求 | 一次性普通背景，可在分镜中直接表现 |
| 道具 | 外形必须一致的关键物件；特殊造型、重要细节或交互结构需固定 | 普通陈设、食物、小件，只需表达类别或剧情作用 |
| 产品或指定实物 | 必须准确还原外观，需要可靠图片依据 | 已有真实参考够用时直接复用，不另行生成 |
| 服装、饰物及局部 | 独立展示、取放、交接等需求无法由人物图或场景图支持 | 可以随人物或场景固定的内容，不重复拆项 |

简单一次性配角可以完全不建资产图，在现有判断依据写清由视频提示词描述其外观、在场范围及动作，让模型生成；无需独立图仍保留人物、对白归属和故事事实。需要跨镜固定同一身份、体型和服装时，优先为每套实际服装选 1×4 身份板。低风险角色确实可用综合单图覆盖时，在判断依据写清单图能支持的身份、服装及出现范围。用户或有效上游明确要求 1×4 时按该规格登记，缺参考图或已有一张肖像时仍保留最终身份板要求。

环境一致性优先于少出图；同空间多镜、多机位或长段默认四图合理，可按当前真实覆盖减少补图但必须留充分余量，不以临界最少为目标，不因已有四图就视为浪费。

一次出现也可能需要图，多次出现也可能复用。判断依据是具体制作需要，不是次数、名字或对白。有交互本身也不证明需要独立图。

- 先判断要不要独立图，再决定怎么拆。不同人物、实物在故事中分别记录，不等于分别制作。
- 现有素材够用就复用；能随人物或场景表现的，不重复制作。具体动作、表情和空间关系优先由分镜图承载。
- 只制作当前明确需要的内容，不默认完整表情、服装、多角度组。依赖导演拍法才能判断的暂列待定，不为填表编造镜头。

在 `asset_requirements` 中为每项直接填写 `image_decision` 和 `image_reason`。结论可选无需独立图、复用现有素材、需要制作或待定。依据简述独立图要解决什么，或由哪项已有素材承载。需要制作的项进入新制清单，复用项进入选图。无需独立图的项仍保留故事事实。

新编导 JSON 中，人类或人形角色的处理结论为“需要制作”或“复用现有素材”时，同时填写 `character_output_kind`（`人物1x4` 或 `人物单图`）。选择 `人物1x4` 时在每项 `wardrobe_states` 写明 `name`、`evidence` 与该套最终板的唯一 `output_id`，单套也登记，例如 `HOME-FINAL`。头照及服装三视图是资产制作的独立过程输出，最终板 ID 保留给对应成图。其他角色类别、无需独立图或待定项沿其出图决定。旧确认包可继续读取，已有规格在返修中沿用稳定 ID 并核对变更范围。

交付前在编导同一次读稿自查中检查出图结论、依据、人物最终规格及服装对应是否齐全。若只写出现过、是道具或有对白，补上具体理由。

本轮新稿和实质修订须填写这两个字段。历史确认包缺字段时按兼容流程读取。用户调整优先，已取消项按现行决定处理。

新 JSON 在编导交付校验中一并检查资产字段。历史 Markdown 候选沿用 `python -m scripts.core.story_sources --project <项目> --markdown <编导稿> --check-asset-decisions`。程序检查字段、结论和依据是否非空，依据是否具体由编导在读稿时核对。
# 产品动作参考

产品在剧情中出现使用动作时，按 [产品使用参考对接](../../_shared/product-usage-contract.md) 列出具体动作参考及缺口。人物真实使用效果参考需求单列待定；幻想使用画面由分镜处理，不能因此额外生成一张剧情状态资产。
