# 对白来源与时间承载契约

## 送审前检查与确认范围

完整 Markdown 每次送审前运行 `python -m scripts.core.story_sources --project <项目> --markdown <候选稿>`，不为检查提前生成交付 JSON。正文中文人物名取自本稿 CHARACTER 资产表，资产 ID 去掉 `AST-` 后对应人物实体（兼容 `CHR-`）；不符合此命名对应时，正文直接使用对白表的 speaker_id，不猜昵称。正文已知人物的独立发言缺少 DLG 时会报错；叙述中转述、陌生称谓及非标准发言仍须自查，不能宣称程序识别了全部自然语言对白。

已有本轮有效的获批对白六列表时，追加 `--dialogue-baseline <对白依据Markdown>`，对照独立依据的 ID、人物、完整原句与顺序；不能传当前候选自身，也不能从当前候选倒抄一份充当批准依据。无新对白修改时沿用原核对稿；用户明确删改时先在现有变更说明列出受影响 ID、原句、新句和授权原话，再更新本轮对白核对稿，保留旧依据。不得把旧版全部冻结来阻止已授权改稿，也不得用空依据跳过核对。首次原样提取还须逐行核对原转写的去向（保留、拆分、授权删除或改写），以及原片的人物发言证据；程序不读取自然语言来源附注证明其真实。

自查动作时，回到原片或用户明确修改，分别核对行动者、对象、先后及结果；局部回答只更新涉及事实，不把“谁谈项目”扩展为“谁最终留下”。未解决的因果和身份疑点在正文对应处保留，不以文件一致性通过宣布语义通过。

仅对白确认需要持久记录时，在既有 `user_confirmations` 中使用 `kind: dialogue-confirmation`、`scope: dialogue`、`dialogue_ids`、`revision`、`approval_ref`，不填整稿 `artifact_ids`，不设置整稿 `user_approved` 或调用候选整稿确认。后续整稿采用另沿现有产物确认流程执行；旧式无范围记录保持兼容，不从旧记录反推新的批准范围。

编导必须以稳定对白事实交付，而不是只提供一段可被下游改写的文本。每条对白至少登记：`dialogue_id`、说话人、原文、来源段落、状态，以及可追溯的来源文件或字段。对白先行核对时，故事尚未产出，来源段落可留空；完整正文完成后再补齐 STP，不提前制造段落或事件。

对于明确的 1:1 / 原样任务，先逐句建立来源清单：原句、原始顺序、说话人映射依据、来源位置和 `source_paragraph_id`。原句必须完整保留；删除、合并或改写只有获得用户授权才能发生，并在变更说明写出依据。普通创作不强制保留输入原句，但同样先交对白供用户核对，核对完成后才产出完整故事正文。

疑点先分清文字与人物。原句听不清或现有转写仍有疑词时，先返回原始资料准备，按已安装的 `video-transcript-correction` Skill 用本轮明确的本地原片和项目资料核对；已有有效结果直接复用，不因人物未知重跑全片，也不把编导任务交给转写 Skill。专用流程的临时证据与清理由其自身约定负责。核对仍不确定或准备不可用时，报告具体疑词与限制，再向用户集中核对。原句清楚而说话人不明时，核对可见发言动作、声画关系、称呼及已知身份；字幕出现在某个人脸上不证明就是此人发言。无法解决的映射继续待确认，不能把推断写成事实。用户明确的改编与确认按其范围保留，不以重新识别结果静默覆盖。

状态为 `locked` 或 `confirmed` 的对白必须逐字保留。用户要求提取且明确“不改”时，只有说话人映射和原始来源均可核对的行才可登记为 `locked`。说话人未知时，Markdown 说话者写“待确认”、状态也保留为待确认；原文不得借整行 `locked` 掩盖映射缺口。`draft` 对白只有在诊断出具体问题且改写未改变锁定事实时才可修订，并在变更说明中列出原文、修订文和理由。

`DLG-*` 是稳定引用，不按版面顺眼反复重编号；删除后的 ID 不复用，新来源行另取非冲突 ID。已确认对白的文字、说话人、顺序或来源段落如需变更，必须新建修订，保留旧修订。

下游只能给对白附加承载方式，不得改写 `text`、`speaker_id` 或 `source_paragraph_id`。删改、合并、换说话人或无法承载时必须显式返回缺口；编导阶段不设计镜头、逐句时间窗或强制口型动作。

结构化后沿用 `python -m scripts.core.story_sources --project <项目> --narrative <叙事包>`，双向核对最终对白六列表、正文和 JSON 的完整文字、人物、顺序及来源段落，拒绝遗漏、重复和未登记对白。正文每次发言单独起行，写作 `人物名（DLG-001）："完整对白"`；也支持中文引号或同一行不加外层引号。人物名须对应 CHARACTER 资产的 `name`，或直接使用 `speaker_id`，不由程序猜昵称；兼容既有 `CHR-LINLIN` 实体对应 `LINLIN` 说话者的写法。动作另起段落，原句内的引号和换行保留，表格内的竖线写为 `\|`；含换行时将原文列表头写为 `原文（换行转义）`，声明该列使用可逆转义；对白单元格内的真实换行写为 `<br>`（也兼容 `<br/>` / `<br />`），正文和 JSON 仍保留真实换行。原句若包含字面 `<br>`，表格写成 `&lt;br&gt;`；字面的该转义串用 `&#38;lt;br&gt;` 表示。仅标明转义的对白列单次解码；未标明的历史表保持原字面值，不改原句、ID 或顺序。格式无法识别时报告具体行，不跳过核对。

该检查证明文件间一致，不证明共同遗漏了原片句子、人物识别正确或外部产品说法属实；这些仍回到原片、获批对白及授权删改逐项核对。候选时的状态文字可因保留已审原文而继续存在；交付时同时给出当前修订和既有采用记录，不从旧 `draft/candidate` 字样重置确认，也不把采用文案说成事实核验。
