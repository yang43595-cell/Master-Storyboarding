# 旧对白交付与核对流程（条件参考）

只有读取历史双文件稿、旧表格，或用户选用飞书核对时，才读对应部分。新生产沿 [对白合同](./dialogue-lineage-contract.md#送审前检查与确认范围) 的 JSON 路径执行；本页不新增 Markdown 或飞书前置。

## 历史 Markdown 与对白基线

历史完整 Markdown 每次送审前运行：

```sh
python -m scripts.core.story_sources --project <项目> --markdown <候选稿>
```

不为此检查提前生成交付 JSON。正文中文人物名取自本稿 CHARACTER 资产表，资产 ID 去掉 `AST-` 后对应人物实体（兼容 `CHR-`）；不符合该对应时，正文直接使用对白表的 `speaker_id`，不猜昵称。已知人物的独立发言缺少 DLG 时会报错；叙述中转述、陌生称谓及非标准发言仍须自查，程序不证明识别了全部自然语言对白。

已有本轮有效的获批对白六列表时，追加 `--dialogue-baseline <对白依据Markdown>`，对照独立依据的 ID、人物、完整原句与顺序。不能传当前候选自身，也不能倒抄候选充当批准依据。无新修改时沿用有效核对稿；用户明确删改时，先记录受影响 ID、原句、新句和授权原话，更新本轮核对稿并保留旧依据。不以旧版冻结阻止获准修改，也不用空依据跳过核对；原样提取仍须核对原转写去向和人物发言证据。

## 旧表格转义

旧表格内的竖线写为 `\|`。含换行时将原文列表头写为 `原文（换行转义）`，声明该列使用可逆转义；对白单元格内的真实换行写为 `<br>`（也兼容 `<br/>` / `<br />`），正文和 JSON 仍保留真实换行。

原句包含字面 `<br>` 时，表格写成 `&lt;br&gt;`；字面的该转义串用 `&#38;lt;br&gt;` 表示。仅标明转义的对白列单次解码；未标明的历史表保持原字面值，不改原句、ID 或顺序。格式无法识别时报告具体行，不跳过核对。

## 飞书核对支路

仅在用户要求，或映射无法确定且用户选择该支路时进入。历史操作入口为 `C:/Users/LIUYANG/Documents/ChatGPT/飞书/workflows/编导包飞书审核.md`；执行前核验当前平台、实际路径与合法工具能力，历史路径不证明本机可用。缺入口时保留具体缺口，继续不依赖它的工作。

送审完整当前对白，保留每行来源证据、归属依据、原始顺序，并在来源证据或审查附注说明疑点和已有时间点/画面。批准快照只作用于明确的审核范围；只批准部分 DLG 行时，只锁定这些行，不扩展为整表、整稿或下一阶段批准。

回收时采用快照中获批的说话人和校正句，校正句为空才沿用当前原句，并保留源原句和顺序追溯。只处理批准范围内的修订与冲突，报告核对任务、所用修订和批准范围；该核对支路不生成叙事包 JSON，也不登记整稿。
