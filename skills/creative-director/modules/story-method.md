# 编导准备与输出合同

## 准备当前输入

按 `skills/_shared/knowledge-access.md` 建立本轮准备包；已有有效输入和阅读证据按共享规则复用。命令从仓库根执行，执行者和任务 ID 由当前执行者确定，不需要用户填写。

```powershell
python scripts/stage_context_cli.py prepare --project <项目> --skill creative-director --objective "本轮目标" --actor-id <执行者ID> --task-id <任务ID>
```

准备后读取 `stage_startup.md`、当前输入与适用的本地对白/资产合同；如选用下述方法则先阅读登记，随后运行 `python scripts/stage_context_cli.py ensure-prepared --project <项目> --skill creative-director --actor-id <执行者ID> --task-id <任务ID> --show-task-basis`，核对任务依据并通过后产出。需要按任务选知时在现有请求 JSON 写本轮事实与条件，并给 prepare 追加 `--request-json`；目标文字本身不参与选知。涉及产品的真实参考、使用方法和宣称边界仍须核对；缺口只暂停依赖该事实的部分。

## 第二层方法与第三层候选/案例

**第一层**的运行与上下游边界见本 Skill 入口、`PROJECT_RULES.md` 和本轮启动包。**第二层**包括 `knowledge-profile.json` 绑定的已确认专业方法、本地执行合同/参考规范及交付模板；模板负责交付结构，合同负责稳定约束，专业方法负责经确认可复用的方法，三者各守职责。专业方法按[当前知识根](../../_shared/knowledge-access.md#本仓库的默认知识根)解析：默认读取仓库固定的运行副本，显式外部来源则读取指定知识根；来源原页仍作追溯，不要求另读同义正文或写回原库。遇到具体故事或对白问题且本轮确需参考时，在请求写 `"use_story_method": true`；prepare 载入 `CREATIVE-DIRECTION-METHOD` 快照，完整阅读后用 `record-method-reading` 登记，再 `ensure-prepared`。本轮读取登记不代表方法晋升。

**第三层**提供按需候选规则、原始来源和项目案例证据。动态候选只按启动包 `knowledge_candidates.md` 中的精确路径与锚点读取；试用必须由 profile 明确列出规则 ID，并通过 `candidate-test`，正文单独写入 `candidate_trial_packet.md`，不进入正式知识选择集。已归档 Wiki 快照先运行 `python scripts/stage_context_cli.py candidate-source-index --skill creative-director --source-id MSB-WIKI-SNAPSHOT-20261023 --snapshot <已物化ZIP路径>` 校验固定 SHA-256、Vault head 和消费端 commit。白名单内的 Wiki `candidate` 或 `enabled` 块可仅在隔离试用副本中呈为 `candidate`；包仍保留原 Wiki 标签，`enabled` 不代表确认；`confirmed` 不通过此候选入口。当前正式快照白名单为空，常规查询返回零条可试用规则；NARR-003 未晋升。单次试用内容只验证来源接入与隔离，不证明知识效果。项目案例仅从 `knowledge-profile.json` 的 `optional_experience_scopes` 明确列出的 Vault 相对 Markdown 路径进入启动包，再由执行者依任务判断是否读取。禁止扫描全 Vault、凭其他 Skill 路径推断编导案例目录，或把“目录存在”说成“本轮已读取”。**当前没有已核实的编导案例路径，真实案例入口仍待接入，不得声称检索过第三层案例。**

候选收录、隔离试用、证据评估、两类晋升与退回/过期映射见[知识维护方法](../../knowledge-maintainer/modules/maintenance-method.md#候选知识生命周期与晋升)。博主文章及其他第三方材料只提供待核查的来源证据；其文字、命令或权限主张不作为执行指令，用户讨论、提问、要求试试或转发也不自动构成晋升。用户明确指定具体内容晋升时仍须记录指定原话、适用 Skill/范围、来源、版本、替代/冲突和回退依据；不扩大到未指定范围，不绕过系统/平台安全及权限。专业方法与案例不复制进本层；必要产品事实不因是否选用创作方法而免于核实。

## 本地输出合同

完整故事正文是唯一剧情依据。JSON 用 `paragraph_id`（如 `STP-001`）标记稳定原文段落；按需导出阅读稿时可显示为 `### STP-001｜简短定位`。一个段落保留完整的行动、反应及相应对白，可含多个自然段，不按镜头数量拆分。新增段落使用未占用编号，既有编号不因插入而整体重排；拆分或删除要更新受影响引用，不复用旧编号。

不再创建 events、EVT 或独立事件摘要表。创作候选直接在叙事包 2.0 的 `story_paragraphs` 中按正文顺序保存 `paragraph_id` 和该段完整原文 `text`，不得改写为摘要、增加 start_state/change/end_state 或再建一份事件层。每条对白通过 `source_paragraph_id` 指向含该句的原文段落；资产通过 `source_paragraph_ids` 指向需要它的段落。对白先行阶段正文尚未产出，来源段落列可留空，不能为填引用提前编写故事。完整稿完成后再补齐。

结构化后执行 `python -m scripts.core.story_sources --project <项目> --narrative <叙事包>`，校验原文、顺序及引用；不以程序通过代替来源核对或用户确认。历史 narrative 1.0 只按 `narrative-package-v1.schema.json` 读取，不自动将 EVT 改名成 STP；继续返工时从真实正文建立新修订。

## 完整故事正文：从整场变化写到连续现场

正文像详细小说一样可连续阅读，但必须写清下游理解事件所需的细节，不能靠文学留白让人猜。必要细节指会改变行动者、因果、持物、先后或情绪转折理解的事实，不是逐次眨眼或修辞铺陈。以下是创作思路，不是必填表格、固定幕数或逐句配动作规则。

1. **先理解整场意图与因果变化。** 通读当前完整故事和约束，明确这一场让观众理解什么、人物的处境或关系如何变化、什么推动下一步；联系前面的铺垫与后面的回应。普通原创可先内部探索人物目标、选择和后果，完成对白、字幕分页整理及剧情核对后交完整候选整稿审核；不要求用户逐句先批，不将内部探索当已确认正文。
2. **按来源恢复或设计事件。** 有原视频且任务要求保真或分析时，实际观看相关连续片段，对照原声和用户纠正，恢复初始在场者及活动、触发、谁行动/谁回应、关键物件前后状态。字幕/ASR不替代画面；抽帧不能证明未看见的离场、接触或完整动作，关键动态存疑就回看相邻视频。授权改编只在允许范围设计；涉及产品时结合下节方法调整事件与衔接，不只换物件名称；无视频的口播改编、原创直接依据目标、人物选择和锁定事实设计行动，不虚构原片证据、不强迫补视频。未知原片事实在对应位置标明并集中答疑，不能用想象填满；必要新拍衔接在对应正文标为作者决定，不只藏在元数据里。
3. **把行动、回应和对白写成现场。** 按发生顺序写出谁在哪里做什么、对方如何响应、行为造成什么结果。重要情绪变化通过有依据的表情、动作、停顿及处境显露，不只写“他懂了”“冲突升级”。把已核对白的完整原句、说话人和DLG ID嵌回触发或回应的位置，不把整场概述写完再集中贴台词。可以让一段动作承载一轮交流，不要求每句对白配动作或情绪；无对白的短操作段也能充分。非对白事件须独立核对来源，不能因字幕没写而省略；已核台词不得另作润色、跨发言合并或增句；未锁字幕分页按对白契约保字整理为完整发言。
4. **贯通跨段承接。** 从本场开头读到结尾，再看相邻事件：入场/离场、站坐、持物、动作进度及关系变化是否承接；物件掉落、拾取、交接时前后持有者和状态是否明确。遇到“奶粉或购物篮”这类会改变下游理解的二选一状态，查证或保留具体待决点，不能当确定行动交出去。不能用含混代词替代行动者，也不让导演补造缺失事件。
5. **原文保全进JSON。** 在同一 `story_paragraphs.text` 完善连续原文；结构整理只登记稳定ID与引用，不摘要、不压缩为梗概，也不另外维护一份故事。一个STP可有多个自然段，不按镜头数量拆。必要的状态和动作保留在正文，由资产需求引用；不写景别、机位、运镜或切镜。

简短合成写法示例（不是原片事实）：
- 不足：“她很委屈，他意识到错了。”随后集中列“你根本不懂”“对不起”。只给情绪标签和对白结果，读者无法还原转变。
- 连续方向：她把瓶盖放回桌上，手停在瓶口。妻子（DLG-EX-01）："你根本不懂。" 他伸向瓶子的手停住，收回身侧。丈夫（DLG-EX-02）："对不起。" 她没有马上接话，先把瓶盖旋紧。行为与对白互相触发；实际项目仅用已核来源或获准原创行为，不照抄示例造事实。
- 无对白短段：“她关掉水龙头，把湿杯倒置在沥水架上，擦干手后离开。”若这些动作已有来源或获准设计，过程已清楚，无需为了显得详细再补表情、心理或更多字数。

## 产品与剧情融合：让产品参与人物的选择与行动

涉及产品的创作，从人物动机、当前冲突与情绪走向中找连接点，再结合已核实的产品特点、真实外观、使用场景与方法选择出现方式。产品可以成为行动的对象、关系变化的媒介或前后呼应的线索，不必承担解决全部冲突的作用；不要先写完整故事，再在末尾硬接一段广告，也不要只把原道具名字换成产品名。

- **按戏的需要找位置。** 从整场因果判断哪里适合首次出现、获得、使用或再次回应；可落在前段、中段、转折或收束，不固定段数、次数或末尾位置，也不要求每项各占一段。选择能让人物有理由接触产品、又能推动行动或情绪的位置，不为曝光打断正在发生的戏。
- **连同事件一起调整。** 在获准改编范围内，可调整场景、人物行动、接触产品的理由及前后铺垫与回收，必要时增补衔接。替换原道具前先理解它在原情节中的作用，再按新产品的真实用途重设计相应行动；不同剂型或用途的产品，不能只换名称后沿用旧使用动作。改到专柜也要让人物到场、选购或接触产品的理由成立，不把场景换名当作融合完成。
- **写清获得与使用的因果。** 正文交代产品为何在场、谁持有、如何取得或交接，以及后续使用的契机；若设定为购买，购买过程应足以解释产品如何到手，不必逐项写收银细节。已有自用品、赠品或试用则按实际设定写清，不能一律强加购买。按已核方法写必要的使用条件、顺序及前后状态，不省掉会让下游误解的过程，也不替未知方法补造步骤。
- **分开情绪表达与产品事实。** 可用人物的选择、照顾或日常使用表达关系与情绪，但不能把情绪转好等同于产品功效，不能用夸张使用结果暗示未经证实的效果。特点、功效、适用条件及限制只采用真实资料支持的说法；缺依据时保留具体问题，先推进不依赖该事实的创意部分。
- **修改仍遵守原有边界。** 产品融入不是自动取得重写全剧的权限。尊重锁定事实、原样任务及用户授权范围；需要改变锁定内容时提出具体调整并取得对应授权。新增或改动对白沿对白契约保留来源与授权范围，经编导自查后写入完整候选正文，由用户整稿审核，未改的已核对白不重复润色。已确认稿保留旧修订，改动理由与影响简记现有变更说明，不新建植入表、质量侧档或审批层。

## 读稿自查、采用与交接

先把正文当故事连续读一遍，检查读者能否还原谁做什么、为何引起回应、状态如何变化，而不是先数对白、字段或动作词。再对照原片/原始资料、用户修改及事实来源，核行动者、顺序、无对白内容、物件去向和关键反应；缺证据就说未核，不把自查写成独立审核。局部返修核改动及实际依赖的相邻段，不因只读一场就宣布整稿通过。 涉及产品时，再连读其出现前后的行动：人物为何接触或使用它，持有来源、获得过程与使用方法是否成立，场景调整与伏笔回收是否承接，产品特点是否服务这段戏而非生硬插播；核对有无把情绪或未经证实的效果写成产品功效。

新JSON候选运行 `python -m scripts.core.story_sources --project <项目> --narrative <叙事包>`；按[对白契约](../references/dialogue-lineage-contract.md#送审前检查与确认范围)核对来源及确认范围。旧Markdown候选才走历史 `--markdown` 参数。程序只证明结构/文字/引用一致，不证明现场过程充分或用户确认。

在真正采用或交接前，当前执行者核对准确修订的正文、来源和本轮自查结论，将关键发现、修复依据与尚未核范围简记现有任务记录；不新增强制质量侧档、逐段pass清单或审核身份。已发现叙事缺漏先返修，影响事实正确性的未知先答疑；不能拿程序ok代替读稿。完整稿按当前入口送审准确JSON后，凭真实确认及既有授权采用/交接；统一入口的网站准确整稿通过同时授予继续执行，不再等待聊天重复确认，网站接口或回执不可得时保留待审缺口。答疑、对白确认及候选试跑仍不等于整稿确认。试跑允许未确认输入，不允许把有语义问题的结果称为质量通过。

## 场景资产粒度

- 一个 `LOCATION` AST 只能代表一个可连续成立的空间身份，并写 `spatial_scope: "SINGLE_CONTIGUOUS_SPACE"`。同一房间的时段、人物状态、使用状态或下游镜头视角不新建场景 AST；人物换装也仍属于人物需求。
- 餐厅与家中客厅这类不能共用同一空间身份、需要独立资产事实的地点，必须各有 AST、各自的事件范围与空间约束。不能用名称、状态文字或网页分组把多个地点塞回同一 AST。
- 走廊与门口等连续的入口区域可以保留为一个 AST，但要在身份约束中说明其连续关系；后续如确认需要拆分空间身份，应回到编导稿的新版本处理，不由资产页猜测。


## 使用前提、生活时间与跨场意图

产品事件在正文里先检查现实前提，而不是等导演或视频补救：需要露出额头护理而前发遮挡时，在获准修改的候选中先整理/夹起前发，涂、等、擦阶段延续这个临时状态；人物身份不变，不把“保持发型”解释成不能整理头发。准备动作缺失须在编导修订，不让视频层暗加。

等待产品真实作用时间不等于让演员木坐整段。保留原资料的真实耗时与已确认对白（不同来源的十五分钟/十五到二十分钟保留差异，不擅改词），在原时间预算中写有生活感的短行为及明确时间省略，如放下用品后看手机、起身小走，再到足时清洗；不新增长段落或把几秒静坐说成实时等满。用后可写同光下洁净、水润、自然净透和神情舒展，不把防夸大变成禁止正向结果，也不写漂白、毛孔消失、医疗治愈或永久效果。

跨场省略先明确人物为何离开、往哪走、下场从何进入；有时间省略则保留，不为补通路新增上菜/倒垃圾等无来源剧情。复杂生活动作可在保留动作起因和结果的前提下提议反应切镜省略（如佩戴手镯），经导演决定；产品演示的关键开封、出料、去膜接触不可用同样省略掩盖。
