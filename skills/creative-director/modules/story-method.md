# 编导准备与输出合同

## 准备当前输入

先确定本轮实际使用的来源和允许改动的范围，沿[知识读取合同](../../_shared/knowledge-access.md)复用仍有效的输入和阅读证据。在现有请求 JSON 的 `source_files` 写入尚未通过项目状态选入的本地原片、基准稿和真实产品依据。由准备包锁定这些文件的版本，`--objective` 只描述任务目标。命令从仓库根执行，执行者和任务 ID 由当前执行者确定。

```powershell
python scripts/stage_context_cli.py prepare --project <项目> --skill creative-director --objective "本轮目标" --request-json <本轮请求> --actor-id <执行者ID> --task-id <任务ID>
```

按 Skill 的执行顺序实读 `stage_startup.md`、实际输入和适用合同。有匹配的必读方法时，读完本轮方法包再用 `record-method-reading` 登记。同一执行者和任务运行以下命令，核验通过后进入场次判断或正文。

```powershell
python scripts/stage_context_cli.py ensure-prepared --project <项目> --skill creative-director --actor-id <执行者ID> --task-id <任务ID> --show-task-basis
```

## 第二层方法与第三层候选/案例

第一层由 Skill 入口与项目总规则确定本轮何时写作、送审和交接。第二层由本地合同和模板规定写法与交付结构，专业方法按 `knowledge-profile.json` 的条件选读。从[仓库固定版本](../../_shared/knowledge-access.md#制作的仓库知识根)读取。

- 遇到具体故事或对白问题且本轮确需参考时，在请求写 `"use_story_method": true`，选读通用编导方法。
- 广告先核准确商品及[本轮展示与使用范围](../../_shared/product-usage-contract.md#广告中的产品展示与使用)。明确选用造物者温泉酸抛光面膜 2.0 时，以 `"product_id": "creator-polishing-mask-2"` 配合 `"product_usage": "display"` 选读纯展示部分，配合 `"product_usage": "real_use"` 选读实际使用部分。单纯提到品牌时省略这两个字段。方法包保留本轮岗位和用途对应的原文，真实实物、步骤和宣称仍以当前来源核对。
- 第三层按本轮启动包和 profile 的精确入口找仓库内的案例与来源。实际采用[候选与案例参考](../references/knowledge-candidates.md)或[旧对白流程](../references/dialogue-legacy-workflows.md)时，将对应仓库相对路径列入 `local_references`。已有资料充分时可直接创作。

## 本地输出合同

完整故事正文是唯一剧情依据。JSON 用 `paragraph_id`（如 `STP-001`）标记稳定原文段落；按需导出阅读稿时可显示为 `### STP-001｜简短定位`。一个段落保留完整的行动、反应及相应对白，可含多个自然段，不按镜头数量拆分。新增段落使用未占用编号，既有编号不因插入而整体重排；拆分或删除要更新受影响引用，不复用旧编号。

人物按 [人物命名与跨阶段身份](../../../PROJECT_RULES.md#人物命名与跨阶段身份)统一：有名字用名字，无名字用固定男女编号，服装只作外观描述。正文行动者、对白说话人与人物资产名称须一致，自查换装前后是否仍指向同一人物；原始对白中的称呼保留原文。

不再创建 events、EVT 或独立事件摘要表。创作候选直接在叙事包 2.0 的 `story_paragraphs` 中按正文顺序保存 `paragraph_id` 和该段完整原文 `text`，不得改写为摘要、增加 start_state/change/end_state 或再建一份事件层。每条对白通过 `source_paragraph_id` 指向含该句的原文段落；资产通过 `source_paragraph_ids` 指向需要它的段落。对白先行阶段正文尚未产出，来源段落列可留空，不能为填引用提前编写故事。完整稿完成后再补齐。

历史 narrative 1.0 只按 `narrative-package-v1.schema.json` 读取。继续返工时从真实正文建立新修订并保留原编号的对应关系。

## 开写前逐场确定保留项

改编或复现已有故事时，读完本轮输入、通过准备核对后，先沿原片或本轮指定基准稿逐场找出：这场让观众理解了什么变化，靠哪个具体动作、反应、对白或物件状态表现，下一场在哪里接上。沿用现有场名或 STP 定位，在本轮任务记录中每场简记一行，区分必须保留的表现、可改的实现及其依据。复现按来源保真；局部返修只核受影响场次及有依赖的前后场。已有锁定事实按原依据保留；从旧稿读出的保留判断写明来源，不记成用户确认。不另建场次表、事件层或逐场审批。

删改前用一个具体反例自查：拿掉这一笔后，观众还能从哪处看懂同样的因果、人物选择、情绪或前后呼应？若找不到，先保留这项作用和必要的可见表现；在获准范围内调整实现，有影响故事方向的取舍待定则原位标明。例如角色先看到对方敷膜，随后才对遗落的盒子好奇；可以改车上的操作展示，但要保住看到敷膜与拾盒之间的因果。两场护理即使操作相近，也先看第二次是否表现了角色主动做出的新选择，再决定如何处理重复展示。

## 完整故事正文：从整场变化写到连续现场

正文应可连续阅读，用必要的动作、回应与对白写清事件、因果和情绪转折，使下游能准确理解并安排表演。必要细节指会改变行动者、因果、持物、先后或情绪转折理解的事实；保留观众所需悬念，同时让执行者理解发生了什么，不用修辞或无效动作扩写代替过程。以下是创作思路，不是必填表格、固定幕数或逐句配动作规则。

1. **先理解整场意图与因果变化。** 通读已有故事或原创需求及约束，明确人物要什么、遇到什么阻力、作何选择并造成什么后果，以及观众应理解的处境或关系变化；联系铺垫与回应。原创和获准重构可以设计必要事件，局部返修只处理具体问题和直接影响。完成适用的对白与剧情自查后交完整候选整稿审核；字幕分页仅在存在该来源时整理，不要求用户逐句先批，不将内部探索当已确认正文。
2. **按来源恢复或设计事件。** 有原视频且任务要求保真或分析时，实际观看相关连续片段，对照原声和用户纠正，恢复初始在场者及活动、触发、谁行动/谁回应、关键物件前后状态。字幕/ASR不替代画面；抽帧不能证明未看见的离场、接触或完整动作，关键动态存疑就回看相邻视频。授权改编只在允许范围设计；涉及产品时结合下节方法调整事件与衔接，不只换物件名称；无视频的口播改编、原创直接依据目标、人物选择和锁定事实设计行动，不虚构原片证据、不强迫补视频。未知原片事实在对应位置标明并集中答疑，不能用想象填满；必要新拍衔接在对应正文标为作者决定，不只藏在元数据里。
3. **把行动、回应和对白写成现场。** 按发生顺序写出谁在哪里做什么、对方如何响应、行为造成什么结果。重要情绪变化通过人物处境与行为所支持的表情、动作和停顿显露，不只写“他懂了”“冲突升级”。把本轮完整对白、说话人和 DLG ID 嵌回触发或回应的位置，不把整场概述写完再集中贴台词。可以让一段动作承载一轮交流，不要求每句对白配动作或情绪；无对白的短操作段也能充分。保真范围内的非对白事件须回到来源核对；原创及获准改编的行动可按剧情设计并保留创作依据。原样任务或明确锁定/已确认的对白按范围保留，本轮获准修改的部分另建修订；已核来源不自动禁止授权改编。未锁字幕分页按对白契约保字整理为完整发言。
4. **贯通跨段承接。** 从本场开头读到结尾，再看相邻事件：入场/离场、站坐、持物、动作进度及关系变化是否承接；物件掉落、拾取、交接时前后持有者和状态是否明确。遇到“奶粉或购物篮”这类会改变下游理解的二选一状态，查证或保留具体待决点，不能当确定行动交出去。不能用含混代词替代行动者，也不让导演补造缺失事件。
5. **原文保全进JSON。** 在同一 `story_paragraphs.text` 完善连续原文；结构整理只登记稳定ID与引用，不摘要、不压缩为梗概，也不另外维护一份故事。一个STP可有多个自然段，不按镜头数量拆。必要的状态和动作保留在正文，由资产需求引用；不写景别、机位、运镜或切镜。

**对白与画面事实分开核对。** 角色的否认、转述、猜测或画外说法只说明角色说了什么。凡会让某件东西入画、改变持物状态或触发道具需求的伴随行动，按原片可见证据或本轮获准的创作决定单独确定。若来源只看得到人物轻触领口，正文就交接这个动作和可见的领口状态，领口内是否有首饰继续留在画外。保留该句原文和戏剧作用，借已核实的动作或反应承接，不为说明说法另造可见证据。

简短合成写法示例（不是原片事实）：
- 不足：“她很委屈，他意识到错了。”随后集中列“你根本不懂”“对不起”。只给情绪标签和对白结果，读者无法还原转变。
- 连续方向：她把瓶盖放回桌上，手停在瓶口。妻子（DLG-EX-01）："你根本不懂。" 他伸向瓶子的手停住，收回身侧。丈夫（DLG-EX-02）："对不起。" 她没有马上接话，先把瓶盖旋紧。行为与对白互相触发；实际项目仅用已核来源或获准原创行为，不照抄示例造事实。
- 无对白短段：“她关掉水龙头，把湿杯倒置在沥水架上，擦干手后离开。”若这些动作已有来源或获准设计，过程已清楚，无需为了显得详细再补表情、心理或更多字数。

## 产品与剧情融合：让产品参与人物的选择与行动

产品承担广告展示或实际使用时，创作前按[广告中的产品展示与使用](../../_shared/product-usage-contract.md#广告中的产品展示与使用)核定可见内容、关键动作和所需参考，并沿现有正文与资产需求交接。

涉及产品的创作，从人物动机、当前冲突与情绪走向中找连接点，再结合已核实的产品特点、真实外观、使用场景与方法选择出现方式。产品可以成为行动的对象、关系变化的媒介或前后呼应的线索，不必承担解决全部冲突的作用；不要先写完整故事，再在末尾硬接一段广告，也不要只把原道具名字换成产品名。

- **按戏的需要找位置。** 从整场因果判断哪里适合首次出现、获得、使用或再次回应；可落在前段、中段、转折或收束，不固定段数、次数或末尾位置，也不要求每项各占一段。选择能让人物有理由接触产品、又能推动行动或情绪的位置，不为曝光打断正在发生的戏。
- **连同事件一起调整。** 在获准改编范围内，可调整场景、人物行动、接触产品的理由及前后铺垫与回收，必要时增补衔接。替换原道具前先理解它在原情节中的作用，再按新产品的真实用途重设计相应行动；不同剂型或用途的产品，不能只换名称后沿用旧使用动作。改到专柜也要让人物到场、选购或接触产品的理由成立，不把场景换名当作融合完成。
- **写清获得与使用的因果。** 正文交代产品为何在场、谁持有、如何取得或交接，以及后续使用的契机；若设定为购买，购买过程应足以解释产品如何到手，不必逐项写收银细节。已有自用品、赠品或试用则按实际设定写清，不能一律强加购买。按已核方法写必要的使用条件、顺序及前后状态，不省掉会让下游误解的过程，也不替未知方法补造步骤。
- **分开情绪表达与产品事实。** 可用人物的选择、照顾或日常使用表达关系与情绪，但不能把情绪转好等同于产品功效，不能用夸张使用结果暗示未经证实的效果。特点、功效、适用条件及限制只采用真实资料支持的说法；缺依据时保留具体问题，先推进不依赖该事实的创意部分。
- **修改仍遵守原有边界。** 产品融入不是自动取得重写全剧的权限。尊重锁定事实、原样任务及用户授权范围；需要改变锁定内容时提出具体调整并取得对应授权。新增或改动对白沿对白契约保留来源与授权范围，经编导自查后写入完整候选正文，由用户整稿审核，未改的已核对白不重复润色。已确认稿保留旧修订，改动理由与影响简记现有变更说明，不新建植入表、质量侧档或审批层。

## 读稿自查、采用与交接

送审前沿实际正文连读一次，在同一次阅读中检查以下三个方面。整稿覆盖全篇，局部返修核改动和实际依赖的场次。遇到具体疑点，回看片段或听原声。

1. **对改动。** 把正文对回开写前的场次判断和依据。保真内容对照原片或原始资料，原创与获准改编对照需求、创作依据和锁定事实。逐场核对原定作用还有哪个可见行动或对白承载，删改是否损伤无对白事件、人物选择、伏笔或回收。段落、对白和引用数量相同不说明作用还在。
2. **读人物。** 顺着相邻场读谁做了什么、对方为什么在此刻这样回应、观众会如何理解、下一步能否接上。继承的旧动作也要复核。若同一个反应可能传达相反的情绪，例如只收到催办消息却笑了一下，先查来源或锁定要求，再在获准范围内补足触发与可见回应；缺证据的事实原位待核。
3. **查交接。** 沿正文追查跨场的物件、消息、人物和时间状态，再核对白、资产需求与交接说明是否都对应当前正文。遇到只从对白推出来的动作或道具，沿对应 STP、DLG、AST 核对画面或创作依据，在正文和资产需求一并纠正。正文已经删除的动作或状态从相关需求中同步清理；只需明确的跨场事实也要前后一致。涉及产品时，检查为何在此处出现或使用、谁持有和如何获得、真实使用前提与步骤、后续去向，以及情绪变化有无被写成未经证实的功效。把问题修回对应正文或引用，复查直接影响。

首次建立原片复现或改编的全稿基线、换用基准，或人物身份、出入及跨场因果的影响无法限界时，在本轮来源范围内核全片画面。核对各场出入、在场人数、全片独立人数、无对白的表演者及独立演示者，在既有事实与范围锁定中记原片身份、出镜依据和获准改编的安排。局部返修沿用有效核对，只查受影响的场次、人物及其对白和交接引用。跨场换装用称呼、行动承接及面部等来源互证，声音归属按对白契约核对。无法区分的人物保留待核，受影响的交付回到本阶段处理。

校验和审核走 Skill 执行入口。网站阅读稿准备会校验同版 JSON。本地待审 JSON 使用 `python -m scripts.core.story_sources --project <项目> --narrative <叙事包> --review-ready`，正式采用前仍按[对白契约](../references/dialogue-lineage-contract.md#送审前检查与确认范围)核查来源及实际确认范围。旧 Markdown 候选沿用历史 `--markdown` 参数。将实际发现、修复位置和未核范围简记在现有任务记录，供复查和交接使用。

## 场景资产粒度

- 一个 `LOCATION` AST 只能代表一个可连续成立的空间身份，并写 `spatial_scope: "SINGLE_CONTIGUOUS_SPACE"`。同一房间的时段、人物状态、使用状态或下游镜头视角不新建场景 AST；人物换装也仍属于人物需求。
- 餐厅与家中客厅这类不能共用同一空间身份、需要独立资产事实的地点，必须各有 AST、各自的事件范围与空间约束。不能用名称、状态文字或网页分组把多个地点塞回同一 AST。
- 走廊与门口等连续的入口区域可以保留为一个 AST，但要在身份约束中说明其连续关系；后续如确认需要拆分空间身份，应回到编导稿的新版本处理，不由资产页猜测。


## 使用前提、生活时间与跨场意图

产品事件先检查本轮真实使用所需的前提。涉及部位、衣物或工具的准备动作，在获准创作范围内写进正文并延续状态；例如护理部位被头发遮住时可先整理前发，人物身份仍保持。仅展示产品不自动补使用流程；已确认正文缺必要动作时另作修订，不让下游暗加剧情。

产品确有等待要求时，核本产品资料中的真实时长、频率和清洁条件；换产品不继承原道具的用法或数字。来源之间有差异或已确认对白与真实用法不符时，保留原依据并提出具体问题，不能自行选一个数字，也不把错误用法交给下游执行。剧情可用有生活感的短行为和明确时间省略承接等待，具体拍法交导演，不把几秒静坐说成实时等满。用后正向状态只在本产品资料支持的范围描述；人物神情须有剧情原因，不当成功效证明。护理产品也不默认获得“水润”“净透”等效果描述许可。

跨场省略先明确离开与到达的意图、人物和物件状态，保留已成立的时间省略；保真任务不能为补通路造事件，原创或获准改编可补必要衔接。本轮确需呈现、且影响正确理解的产品关键步骤，应写清主体、接触、过程与结果；不能用省略掩盖错误或未知。出现产品不自动要求完整开封、使用和清洁教程，镜头与切点仍由导演决定。
