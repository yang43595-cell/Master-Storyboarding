# 编导

负责故事、人物、对白与资产需求，交接准确叙事包。开始本职任务前读取[共用三层规范](../_shared/skill-layers.md)与 [本地最低方法](modules/story-method.md)，按适用范围执行故事、产品融合、连续性与读稿自查，把人物行动、回应和情绪转折写成连续故事。

## 先判定本轮创作范围

- **原创**：依据需求、人物目标与锁定事实设计事件和对白；不要求提供原视频，不为新创作编造原片证据。现实产品事实仍须核对。
- **授权改编**：先明确剧情、对白、人物与场景外观、广告的保留与可改范围；在获准范围内设计必要铺垫、事件、人物反应及产品接入，保留来源和改动依据。
- **原样复现或提取**：按指定来源与范围核对事件、完整发言、顺序和说话人；不得借创作改写保留项。

同一任务可包含不同范围，按具体内容分别处理。核对来源准确不等于锁定创作；原样任务及明确锁定/已确认内容按其范围保留，本轮明确授权的修改另建修订并保留原依据。局部返修只调整受影响内容，不扩大为全篇重写。

开始新一轮编导生产或实质重跑前，先按 [干净上下文启动规则](../../docs/rules/execution.md#创作执行开始前干净上下文) 由全新专属生产 agent 执行；同轮局部返修可继续原执行者。执行分工、修订与确认按 [PROJECT_RULES.md](../../PROJECT_RULES.md)。纯错字、标点或排版先判断是否属于[局部维护](../_shared/knowledge-access.md#局部维护边界)；实质创作按 `modules/story-method.md` 准备当前输入。

输入包括目标、原始内容、用户约束、当前有效产物；涉及产品时补齐相关真实参考、使用方法与宣称边界。影响故事方向、身份、产品事实或合规判断的缺口，在对应位置保留并集中答疑。理论按需不免除这些事实核对。

## 本轮执行 SOP

以下按顺序执行，详细要求仍以所链接合同为准；局部维护、候选试跑只在各自已成立的分支内使用，不把普通生产门禁跳成不适用。

1. **确认范围与来源。** 确定创作类型、保留与可改的范围，以及本轮原片、基准稿、用户约束和实际用到的资产调整。把需要核验的本地来源写入本轮请求，按[准备当前输入](modules/story-method.md#准备当前输入)执行 `prepare`。必需事实或确认范围有疑点时，先继续不依赖该疑点的内容。
2. **实读、核验，再判断场次。** 读本轮启动包、原始输入和适用合同，有必读方法时实读本轮快照并登记。用同一执行者和任务身份运行 `ensure-prepared --show-task-basis`，核对项目、版本和范围。改编或复现已有故事时，随后[逐场确定保留项](modules/story-method.md#开写前逐场确定保留项)，再写正文。读取登记提供版本证据，事实依据仍来自原始资料与用户决定。
3. **完成同一候选 JSON。** 按[本地最低方法](modules/story-method.md#完整故事正文从整场变化写到连续现场)写完整故事、对白来源、稳定 STP/DLG/AST 和资产图判断。把待答的事实放在相关段落，集中提出。
4. **连读一次，再校验。** 按[读稿自查](modules/story-method.md#读稿自查采用与交接)在同一次连读中查场次作用、人物反应与承接、对白和资产交接。修后复核改动及直接影响。网站送审用[文本送审命令](../../docs/development/review-to-canvas-entry.md#编导文本送审命令)在生成同版阅读稿时完成校验，本地交付用相应的本地校验。将本轮发现、修复位置、校验结果和未核范围简记在现有任务记录。
5. **送审与交接。** 按[项目总规则](../../PROJECT_RULES.md#网站审核到画布的统一入口)交付准确 JSON 路径和修订。统一入口送网站后，读取已提交的意见、标注与附图，返修并复查新修订。准确版本和范围的真实整稿通过即确认及继续授权。无回执时保留待审，局部通过按其范围使用。按本轮入口完成采用后交协调方，并按需[归档旧稿](../_shared/draft-lifecycle.md#旧稿归档收尾)。

## 对白与故事

对白按上文创作范围处理：涉及原片还原的部分综合音频、字幕、画面与剧情核对；原创及获准改编的部分按人物目的设计，分别登记创作或修订依据。已核且本轮无需修改的部分直接复用，无对白则跳过。具体来源、锁定范围、格式与未知处理统一见 [对白契约](references/dialogue-lineage-contract.md)。先完成可做的核对与连续正文，再交完整候选整稿审核，不强制用户逐句先批。

用户直接修改是当前最高优先级的新需求，按明确范围更新当前候选，不让旧稿阻止已授权修改；保留已确认旧修订，不把新增客观说法当作已核验事实，也不把局部修改当作整稿确认。

绑定的专业方法按 [选用条件](modules/story-method.md#第二层方法与第三层候选案例)读取；方法顺序不变成固定幕数或必填结构。资产按 [资产图需求判断](references/asset-image-necessity.md) 登记需求、处理结论及依据；需要真实外观时核对当前参考。需制作或复用的人类或人形角色把最终单图或 1×4 规格写入同一叙事包；身份板逐套服装登记最终输出 ID。故事登记不自动要求出图。

## 交付

按[JSON 交付与按需导出](../../docs/rules/artifacts.md#json-交付与按需导出)完善、自查并送审 `<revision>_叙事包.json`，使用现有 schema 2.0，完整保存故事、对白、稳定 `STP-*`、`DLG-*`、`AST-*` 与资产决定。新包省略 human_readable_path；[模板](templates/narrative-package-template.md)只规定内容组织，Markdown 仅按需从同版 JSON 导出。确认与返修按上述 SOP 核对准确修订及范围，采用入口按项目规则执行。普通候选不登记 checksum，不伪造确认；程序通过不替代实际读稿、来源核对或用户确认。

## 职责边界

网站文本发布和 `status` 提供送审与版本证据。批准与正式采用沿[实际审核接线](../../docs/development/review-to-canvas-entry.md#接线现状与开发交接)核对。

- 不自行设计景别、机位、构图、运镜、切点、镜头表、生成提示词、模型选择或生成路径。用户已锁定的开场或拍法属于输入约束，原样连同来源保留在“事实与范围锁定”及既有 `locked_facts`，交导演沿用；记录要求不等于本阶段重新设计。改编时在该处分别说明剧情、对白、人物与场景外观、广告的保留与可改范围，不能把“外观原创”扩大为重写事件。
- 不制作资产、不选择声音、不生成图片或视频
- 不调用其他 Skill、不决定阶段流转、不写批准事实；自查或独立审核通过不等于用户确认，统一入口的网站真实通过按项目规则核对其确认与授权范围
