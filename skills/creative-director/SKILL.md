# 编导

由当前执行者按 [PROJECT_RULES.md 的 Skill 执行分工](../../PROJECT_RULES.md#skill-执行分工) 执行本阶段；默认由主 agent 直接执行和自检，已明确委派时由受派执行者完成。

纯错字、标点或排版维护先按 [共享局部维护边界](../_shared/knowledge-access.md#局部维护边界) 判断；符合时只做局部检查，下述整阶段准备适用于实质创作与修改。

先读取 `PROJECT_RULES.md`、`../_shared/knowledge-access.md`、`../_shared/draft-lifecycle.md` 等共享红线和 `modules/story-method.md`。按模块先建立准备包，再读取当前 `stage_startup.md` 和 `references/dialogue-lineage-contract.md`。本 Skill 的已确认专业判断由 `knowledge-profile.json` 绑定，并随 `prepare` 写入本轮完整方法快照；完整阅读后登记读取证据，再完成产出前校验。已迁移方法不从旧本地副本重复读取；当前知识包中适用的补充条目仍按共享知识入口核对，不因主题相近整块排除。交付时使用 `templates/narrative-package-template.md` 与 `../../schemas/narrative-package.schema.json`。

输入必须包含目标、原始内容、用户约束、当前有效产物及相关产品参考；缺少会改变故事方向、产品事实或合规判断的输入时停止并列出缺口，不自行脑补。故事与对白的基础判断按本轮 `CREATIVE-DIRECTION-METHOD` 快照执行，适用补充知识按当前知识包读取。

资产表须按 [资产图需求判断与检查](references/asset-image-necessity.md) 填写处理结论和判断依据；交付前只检查是否跳过该判断，不重复详细审核。

资产登记只定义需求和来源，不构成本 Skill 已做视觉判断；需要引用真实外观时，按共享读取规则取得当前段、当前 output 的核验事实，不从确认状态或文件名补写外观。

## 对白先行

含对白的任务先整理对白供用户核对；核对完成后，才产出含对白的完整故事正文。普通创作可先内部探索故事和拟定对白，但不提前交付完整故事正文；没有对白的任务直接处理故事。已有明确核对结果且本轮未改动的对白可复用，不重复请用户确认。

明确的“1:1”“原样提取/复刻”或“不改对白”任务，还须按本地对白契约保留原句、顺序、说话人映射和来源。普通创作不受原样保留限制，但同样遵守先核对白、后产正文的顺序。用户直接改稿是本项目当前最高优先级的新需求；新改动覆盖相冲突的旧稿和旧确认内容，按用户修改的具体程度同步对白、正文及相关需求，不因偏离旧稿而回退。含义、范围或事实依据有实质疑点时，向用户核对具体疑点，不要求重复批准已经明确的改动。用户在正文中修改对白时，以新文为依据更新当前候选的对白表和变更来源；旧确认不能自动套用到新句。采用需求不等于证明新增客观说法已有来源，也不等于整稿已获确认；已确认旧修订仍保留。

说话人映射没有来源依据时，在对应原句处保留“待确认”并集中提问；不得以整行 `locked` 掩盖说话人未知，也不得据此推演人物关系、事件或资产。用户要求、或无法确定映射且用户选择人工核对时，才按 `C:/Users/LIUYANG/Documents/ChatGPT/飞书/workflows/编导包飞书审核.md` 的现有流程送审。该分支只核对其明确范围的完整对白，不自动发起、生成叙事包 JSON、登记整稿或进入下游。

## 交付合同

交付顺序与答疑位置以 [项目规则：双文件产物串行交付](../../PROJECT_RULES.md#双文件产物串行交付) 为唯一流程正文。本 Skill 的模板只规定稿件结构，不能替代对话中的答疑或用户审稿。

最终每个已确认修订交付：

1. `<revision>_编导稿.md`：人类可读正文，依次包含事实锁定、最终对白、含对白的完整故事正文、资产需求、变更说明。故事正文的内容要求见 `modules/story-method.md`，不能用事件摘要代替。
2. `<revision>_叙事包.json`：符合 `narrative-package.schema.json`，使用 2.0 格式保存稳定 `STP-*` 故事原文段落、`DLG-*` 对白和 `AST-*` 资产需求 ID；结构化内容必须与编导稿一致，不得形成第二套故事。

两份文件分别登记到当前 `artifact_manifest.json`，使用 `artifact_id`、稳定 `logical_id`、`revision`、`path_or_url` 和依赖关系。普通候选不登记 checksum；只有修订账本明确管理该产物时，才按现行账本规则登记 checksum。候选、审核通过与用户确认保持分离。

## 硬禁区

- 不自行设计景别、机位、构图、运镜、切点、镜头表、生成提示词、模型选择或生成路径。用户已锁定的开场或拍法属于输入约束，原样连同来源保留在“事实与范围锁定”及既有 `locked_facts`，交导演沿用；记录要求不等于本阶段重新设计。改编时在该处分别说明剧情、对白、人物与场景外观、广告的保留与可改范围，不能把“外观原创”扩大为重写事件。
- 不制作资产、不选择声音、不生成图片或视频。
- 不调用其他 Skill、不决定阶段流转、不写批准事实，也不把审核通过冒充用户确认。
