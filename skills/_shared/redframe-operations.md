# 红帧操作

本轮选用红帧并获准平台操作时读取。先核对业务项目登记的渠道、目标和操作范围。

## 连接与登录

- 通过可达内网的本机连接。先读本机 `~/.local/share/codex-headless-browser/README.md`，默认由实际配置为 `gpt-6.1-terra` 的执行者使用 `task_browser(redframe=True)`；用户在本轮明确指定其他执行者时，按其指定执行，并在业务项目记录中登记指定原话与范围（2026-11-13 普拉提 vlog 案例即由用户指定 Muse 本人执行）。登录态失效时走 `redframe_login_browser()`，由用户本人登录，再在新后台会话中验证。会话只保存在本机。
- 页面打不开时先查内网连通性、域名解析及代理分流；权限、节点插件或原生控件缺失时，记录具体缺项并暂停受影响操作。页面卡住或报错先刷新，再核对原项目已保存范围；结果未知先只读确认，避免重复提交。具体按[刷新与重试](../voiceover-to-video-script/references/redframe-canvas-layout.md#卡住或报错先刷新)执行。

## 生图

1. **先上传、当场归位。** 打开已登记的项目画布。按[素材区上传](../voiceover-to-video-script/references/redframe-canvas-usage.md#素材区上传)先把本次的模板图片及已有的对标资产图片放成独立素材卡，同一份可用素材复用现有节点。每个素材卡一落画布就按真实用途命名、排到所属模块的空位，按卡片实际大小留缝，再继续下一项。剧情人物用 Doubao Seedream 5.5；其余按本轮已授权模型和规格。独立资产库、[视频参考直传](#视频画布)及[本地 1×4 拼版](../../PROJECT_RULES.md#人物-14-拼版)分别走各自入口。
2. **建生成节点、接真实端口。** 为本次要出的图建立并命名图片生成节点，当场归位，优先让同模块的素材卡和生成节点按阅读方向可就近对照。从素材卡的实际图片输出端拉线到生成节点的参考输入端口，直到生成节点显示实际参考。共用图片可从同一个源节点接入多项目标；仅需文本或已有明确无对标设计时，按实际适用模板接入灰模等必要参考，无需另找对标图。同批由一个后台会话完成，不为同一目标反复建卡或直传同一参考。
3. **对应提示词，再核输入。** 图片节点主编辑器写本次提示词，用平台原生引用标明每张已接图片的职责及实际对应顺序。人物大头照和服装从本批 `task_basis.json` 取有对标或无对标模板，实际外观参考排在灰模前，只有灰模时从参考图 1 起。灰模只提供主体位置和大小。提交前逐项核实际输入端口、源卡及图片原件、正文里的引用和职责，以及模型、画幅、尺寸与张数。保留编辑器原生引用，编辑后重新核对正文与输入。重开后若只见占位图，先核实际连线和参考是否仍有效。接线后保持画布可读。首次沿本接线方式制作时，先用本来要做的首个目标保存、重开，核线、正文、输入和位置仍一致，再按同样方式铺开。
4. **提交并收口。** 输入、排版和本轮授权核对后，对准确节点提交一次；保存原节点 ID 及可取得的任务 ID。等待同一节点出图，出现超时或未知状态先查原任务，沿原节点处理。成图留在对应节点。取实际原图，核宽高比和可见效果，登记实际模型、准确输出和版本后按现有方式送审或交付。在全景及正常缩放下复看本批位置、标题和连线；发现重叠或遮挡当场修正。

接线用实际画布读回源节点、端口、目标及生成面板参考，不凭截图或本地期望值补齐。若现场无法让原生连线成为有效参考，先保存已排好的素材和可核状态，报告准确缺口，不切换为直传代替。提交前记下该节点已有成图路径（如有），结果等待可复用同一节点的 `wait_for_image_result(node_id, previous_output)`。后台命令有界等待，只回节点 ID、阶段变化、结果路径或失败摘要。

## 视频画布

从[我的画布](https://redframe-ai.xmpaohong.com:28888/#/projects)打开登记的项目，核对项目和子画布。新建按本轮授权执行，并登记实际地址和项目 ID。项目使用 Seedance 2.5，其余参数核对开工记录和当前原生控件。

写入、绑定、认证和重开验收按[红帧交付要求](../voiceover-to-video-script/references/seedance-delivery-package.md#红帧与小云雀的交付边界)执行。右侧对话中的 `@` 用于对话引用，视频草稿使用对应视频节点「生成提示词」主编辑器中的原生 `@`。统一流程交付到草稿；获准提交的生成任务结果未知时，先只读查询原任务。

### 成批写入和整节点回读

新平台操作任务按[执行交接](../../docs/rules/execution.md#画布执行与交接的宿主边界)交干净执行者（默认 Terra，用户本轮明确指定其他执行者时从其指定），沿同一任务后台 Edge 会话完成。已定稿草稿没有本轮修改授权时保持只读。正式写入消费同一份已采用源稿与冻结快照，按[整节点检查](../../docs/development/delivery-snapshot-checks.md#红帧整节点的源连线用途与时间)核原片文件、用途、源节点、端口、入边、槽位、正文引用和逐镜时间。

1. 正式视频草稿执行者在新建或更新草稿节点、上传本批草稿参考和写正文前，对实际目标和本批冻结 JSON 运行 `python scripts/canvas_readback.py --delivery --project <业务项目> --frozen <本批冻结JSON> --preflight --current <写前回读JSON>`。使用同次命令返回的 `ok: true`、目标、段号和 `frozen_sha256` 执行本批。失败时停止受影响段的远端写入，独立合规段以自身范围重跑同一命令后继续。首次上传可按[写前快照合同](../../docs/development/delivery-snapshot-checks.md#操作与采用)只列计划直传槽。更新附最后可信基线及实际写前节点读数，漂移先核影响范围。已有授权的前序生图沿生图入口执行。
2. 按通过的段号和冻结输入新建或更新视频草稿。按[红帧画布使用口径](../voiceover-to-video-script/references/redframe-canvas-usage.md)使用直传参考，或核对要保留的已认证人物源节点连线。核对槽位后写正文原生 `@` 和参数。目标、正文、参数、镜号或引用来源/顺序变化时，重跑预检后再写受影响段。非交互上传、下载和采集由同一个有时限的后台命令执行，日志留原处。使用支持工具内等待的宿主时，把启动和同一会话的有界续等放在一次工具调用中，只将退出状态、阶段变化或异常带回模型。Codex 中 `exec_command` 可先等 30 秒，仍在运行就由该调用对原 `session_id` 用 `write_stdin` 每次等待至多 60 秒，外层按其等待上限续接；不要每秒把空输出交回模型，也不因运行中重开命令。有人工输入、用户询问或实际失败才定向查看。完成后向协调方交一次回执。
3. 新建前用实际节点尺寸检查本批全部预留位置。创建一个节点后先以原节点 ID 读到持久画布，将它移到预留位置并确认落盘，再创建下一节点。以工作区原生模型字段核参数，显示控件空值不作为模型错判。浏览器退出前用准确节点 ID 核已存内容；关闭画布、固定等待或截图不能代替保存回执。节点未读到时保留原 ID，只读回查，按结果决定下一个动作。现有 `redframe_draft.py` 的 `verify_placements`、`verify_saved` 共用这两个检查。
4. 已保存节点沿 `scripts/redframe_draft.py` 读取原生槽位和正文，传给原 `canvas_readback.py` 正式检查。附件从当前节点的真实工作区路径走同页面读取并计算 SHA-256，预览图加载和 HTTP 错误体均不作为素材。按有无实际字节到达判定停滞，保留整批截止时间，只对暂态失败槽重试一次。实际刷新及布局截图沿原交付核验。已有节点同值复测必须使用写前基线和当前读数，只在本次授权内发一次带写前比对的保存。同因连续失败两次保留最后可信快照和最小复现，暂停相关批次。

离线比较只消费实际采集值。原生引用字段、输入槽字节下载、持久化、认证传递和布局均需实际执行者在合法平台通路实测。交回差异、结论、截图及原生数据路径，协调方核当前回执与依赖。统一入口到草稿收口，用户点击生成。

下一次正常红帧生产顺带[计量](../../docs/development/token-budget.md#计量)。分别记录首个新建草稿从写入开始到独立刷新核验，以及全片由批量写入开始到草稿回读完成的未缓存输入 token 和墙钟耗时。两组各保留红帧执行者的实际日志起止和完成段数，包含各自窗口内的失败与恢复，窗口重叠时不相加。《摇钱树》沿用已有复测回执作为历史证据，取数使用下一次本来就要做的项目。

### 画布排版

读取已按用户要求复制的[红帧画布排版](../voiceover-to-video-script/references/redframe-canvas-layout.md)，其模块分类和行列规则为红帧本轮优先；下列检查与共用紧凑原则继续适用。

1. 按红帧副本将人物、场景、物品、分镜、视频生成及视频参考分类成模块，各模块内部保持场景和片段顺序，不按剧情拆成混合资产区。同组卡片对齐，卡片之间只留便于辨认边界和点击的窄缝，组间再留分区间距。节点和连线不得挡住标题或正文。提示词留在视频草稿节点，省去重复文字卡。平台「整理画布」一键排布只作为起点，整理后仍须按模块分类与片段顺序逐项复核调整，不以一键结果为合规排版。
2. 批量铺开前，先选一个代表段按实际卡片尺寸试排。在正常审阅缩放下确认标题可读、素材和草稿便于对照，再按同样方式铺开余段。排版时保留原编号、正文、素材绑定和参数。
3. 保存后重开，检查全景和正常审阅缩放下的关键局部，确认顺序、间距和对应关系都清楚。发现大块留白或遮挡先调整，再重开复核。交付附全景及关键细节截图。
