# 产品使用参考的上下游对接

用户已要求：产品入戏时，剧情中实际出现的产品动作须列在资产需求表，并自动核对、选用资产库里已有的实拍参考。该授权仅包括参考登记、项目副本与需求，不批准新剧情或生图。

- 未选项目参考包的兼容任务从制作资产库读取；`product_reference` 保存稳定产品 ID、动作名、用途、来源。相同内容复用，不按相似名字跨产品选用。网页按实际资产记录取媒体原件，向任务单向复制。
- 编导在确定产品、人物与使用情节后，按当前剧情出现的位置列动作参考。没有写出的动作不补入剧情；只展示产品不当成实际使用。参考没找到时保留空引用，记录缺哪一步和对应段落，按下文处理。
- 网页读取已确认叙事包、用户资产调整及开工锁定的产品参考包。已选包的展示直接取包内外观图，实际使用由 Codex CLI `gpt-6-luna` 按剧情匹配包内分动作。结果保存到 `04_资产/产品使用对接.json`，资产表附录列产品 AST、实际动作、段落、逐字依据、项目副本和缺口。更新剧情或动作库后同步重新核对；失败不自动重试、不声称已匹配。
- 下游统一读取 `core.asset_refs.load_asset_list()` 的 `product_usage` 与产品条目的 `action_references`，按当前段落/镜头取对应动作。整表导出时也携带 `product_usage`。视频只作动作参考，不冒充确认图片母版或成片；不继承手模身份、衣服、环境、声音。魔法操作可参考对应动作或质地，不能把真实使用流程强加给幻想情节。
- 有角色使用产品时，按实际产品、动作、作用部位、已确认剧情及现有参考判断是否需要独立真实使用效果图，可判无需独立图。effects/reference_need 是带来源依据的候选需求判断，不是用户已提出或批准的图片任务；面膜覆盖与质地只适用于本来明确的面膜需求，不套到手机、鞋或其他产品。不得把幻想画面、用后功效想象或无来源效果当成参考事实。
- 需要核对的效果图需求标为 awaiting_reference_review，无需独立图标为 no_independent_reference；generation_route/image_path、工具及生图任务均留空。旧无 reference_need 的记录保守列为待核对，不自动继承面膜要求。用户明确选择范围和实现路径后才准备、复用实际身份与实物参考，另行确认图片；候选判断、图需求确认、生图授权与图片确认彼此分开。具体幻想剧情画面仍属于分镜阶段。

## 广告中的产品展示与使用

已在开工选择产品参考包时，从 `kickoff --project` 的 `product_reference_pack.references` 读取包内说明、图片和动作片段，按用途和镜号明确绑定。先用这套资料核对包装、膜态、工具与动作；既有方法里的旧动作库存、网站案例和查库步骤只用于未选包的兼容任务。包内 `source` 路径和原片时间码用于追溯，实际引用读取清单中的包内文件。包内缺某个步骤时记录到当前镜号并回报，不自行扩到外部知识库检索。

编导和导演准备本轮输入时，先核本 Skill 的 `knowledge-profile.json` 是否有对应产品方法。仅在本轮已明确选择准确商品且确有展示或使用时，直接沿用项目开工记录中的稳定 `product_id`；阶段准备将其带入现有方法选择。用户以「造物者温泉酸面膜」指定商品时，现有开工或阶段输入会把该名称解析到温泉酸抛光面膜 2.0 的同一模板；用户可直接说品名。兼容项目可继续在 `--request-json` 登记。编导选择造物者温泉酸抛光面膜 2.0 时同时填 `product_usage`，纯展示用 `display`，实际使用用 `real_use`。商品未定、同类产品或只是提到品牌时留空。视频沿其现有条件直读，视觉补充按实际状态选择。

- **编导先确定观众要看见什么。** 确认本轮产品、展示目标和入戏位置，在现有叙事正文交代要呈现的包装或实物、实际使用的关键步骤及前后状态，并在既有资产需求登记对应段落和所需参考。仅展示产品时，明确要看清的外观和实物信息；实际使用时，核实本产品的步骤、顺序和条件。已确认选用且有专项方法的产品，按目标 Skill 的第二层入口读取适用内容。
- **按画面任务核参考。** 真实产品图对应实际出镜的包装、实物或工具，动作参考对应观众需要看清的关键动作与顺序，状态参考对应可见的使用前、中、后状态。逐项核对文件、镜号、用途和来源覆盖范围。某张状态图只能说明它拍到的状态，产品图和无关动作视频也不能补证未拍到的动作。参考缺失或无法实际绑定时，记录受影响的步骤及镜号，沿现有资产或导演修订补齐。关键展示或动作缺口未解决时，明确报告并暂停受影响的画布交付。温泉酸的擦除按专项方法只用一段包内手法参考，其他区域和擦净状态由提示词控制；视频默认收在擦除结束。
- **导演给关键展示和使用留足可见时间。** 在现有视听展开和逐镜节奏中，给包装与辨识信息留出清晰停留，给使用动作留出从起手、接触到动作完成及结果可见的时间。逐项核对有效画面时长，区分可并行的对白和必须串行的操作。找物、递物、转身和剧情等待单独计入节拍。需要缩短时，优先压缩重复或非关键信息，并交代省略后的状态；必要过程承载不下时，返修拍法或按现有分段职责调整。
- **写入画布前沿准确镜号复核。** 对照导演稿与实际视频正文，检查关键展示、动作顺序和有效时长仍有承载，当前产品参考按职责进入本段实际输入。素材上传或连线成功只完成绑定检查。关键参考未覆盖、动作路径未定或有效时长不足时，沿现有候选问题及任务记录写清未完成范围和需补事项；解决后再写入受影响段。

导演把本轮确实要靠动作参考支撑的画面写到既有 `shots[].required_visuals`，在对应条目填 `action_reference`（`product_ast_id` 与 `action_key`）。导演用具体动作名登记本轮需求，例如刷涂、湿擦；资产和视频沿用同名。分镜素材检查按当前镜号逐项核对原片覆盖；资产匹配结果只提供候选，`matched` 不代表导演所需动作已覆盖。

视频在实际拟用的项目内动作视频条目保留产品 `asset_id` 和 `source_shot_ids`，用 `action_references` 中的 `shot_id` 与 `action_key` 指明片段具体承担的动作。同一视频可承担多镜，按实际可见范围分别登记。核对动作来源与实物外观分别进行，借用手法的原片只登记其确实覆盖的动作。程序按 [交付快照检查](../../docs/development/delivery-snapshot-checks.md) 对照本轮镜号和素材。

本合同接到原有独立资产表、项目确认和图片生产门禁；不另建生产阶段，不修改已确认叙事原文。
