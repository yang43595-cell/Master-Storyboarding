# 产品使用参考的上下游对接

用户已要求：产品入戏时，剧情中实际出现的产品动作须列在资产需求表，并自动核对、选用知识库已有参考。该授权仅包括参考登记、项目副本与需求，不批准新剧情或生图。

- 真实动作媒体登记在知识库资产库；`product_reference` 保存稳定产品 ID、动作名、用途、来源。相同内容复用，不按相似名字跨产品选用。网页从知识库取原件，向任务单向复制。
- 编导在确定产品、人物与使用情节后，按当前剧情出现的位置列动作参考。没有写出的动作不补入剧情；只展示产品不当成实际使用。参考没找到时空着，交用户解决。
- 网页读取已确认叙事包及用户资产调整，使用 Codex CLI `gpt-6-luna` 核对。结果保存到 `04_资产/产品使用对接.json`，资产表附录列产品 AST、实际动作、段落、逐字依据、项目副本和缺口。更新剧情或动作库后同步重新核对；失败不自动重试、不声称已匹配。
- 下游统一读取 `core.asset_refs.load_asset_list()` 的 `product_usage` 与产品条目的 `action_references`，按当前段落/镜头取对应动作。整表导出时也携带 `product_usage`。视频只作动作参考，不冒充确认图片母版或成片；不继承手模身份、衣服、环境、声音。魔法操作可参考对应动作或质地，不能把真实使用流程强加给幻想情节。
- 有角色使用产品时，按实际产品、动作、作用部位、已确认剧情及现有参考判断是否需要独立真实使用效果图，可判无需独立图。effects/reference_need 是带来源依据的候选需求判断，不是用户已提出或批准的图片任务；面膜覆盖与质地只适用于本来明确的面膜需求，不套到手机、鞋或其他产品。不得把幻想画面、用后功效想象或无来源效果当成参考事实。
- 需要核对的效果图需求标为 awaiting_reference_review，无需独立图标为 no_independent_reference；generation_route/image_path、工具及生图任务均留空。旧无 reference_need 的记录保守列为待核对，不自动继承面膜要求。用户明确选择范围和实现路径后才准备、复用实际身份与实物参考，另行确认图片；候选判断、图需求确认、生图授权与图片确认彼此分开。具体幻想剧情画面仍属于分镜阶段。

本合同接到原有独立资产表、项目确认和图片生产门禁；不另建生产阶段，不修改已确认叙事原文。
