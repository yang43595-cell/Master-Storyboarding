# 未确认稿生命周期

- 同一目标、同一交付对象且尚未确认时，先改原稿，不因结构性大改制造并列版本。
- 用户明确否定，或确认无比较、回滚、依赖、复盘和审计价值时，无价值就删除，并同步清理活跃引用。
- 只有已确认、被下游真实引用、用户要求保留，或存在故障与合规证据需求时，才“有理由才保留”旧稿，并记录具体原因。
- 活跃目录保留当前有效稿及本轮仍在审定的候选；同一交付范围不并列堆积多个废弃候选。已被替代且有保留价值的旧稿及时移入项目 `99_历史与废弃/`，按批次保留原目录层级，并记录旧路径、新路径与归档原因；同步产物清单和当前导航引用。已确认正文、确认依据及提交回执不改写，其中历史路径通过归档清单追溯。仍被生产直接依赖的文件先保留，不能仅凭版本号较小就移动。
- 必要的删除记录只保存文件名、哈希、理由、授权和日期，不保留正文副本；用户要求归档时采用移动，不以删除代替。
- 返工只修改当前候选及其直接派生物，保留用户指定事实和已确认版本；历史设计由 Git 归档承担。

## 旧稿归档收尾

每次旧稿被替代、明确退回废弃，或本轮交付结束时，由当前生产执行者检查本轮涉及的文件；只读审查只报告，不移动。此项属于本轮收尾，不另设审核阶段、不自动扫描或清理全项目。

1. **确定保留与归档。** 对照当前产物清单、确认范围和实际引用，保留当前正式稿、本轮待审稿、用户要求保留的比较稿及生产仍在使用的文件。新候选未确认时，旧正式稿仍有效；场景局部替换不使整份旧稿自动失效。已明确废弃或被替代且无当前生产依赖的旧文件移入 `99_历史与废弃/<日期>_<归档原因>/`，保留原目录层级。同一未确认候选返修继续改原稿，不为归档制造新版本。
2. **移动并保留追溯。** 移动前核对源和目标都在本项目内、目标无同名文件；不得覆盖或删除。归档清单记录旧路径、新路径与原因，同批次沿用一份。正文不重写；相关历史结构化文件和记录按实际依赖一起保存，不因文件名相似自动扩大范围。未知是否仍有效的文件先保留并说明。
3. **处理引用。** 同步产物清单中的归档位置及当前可编辑的导航引用；已确认正文、确认依据、已提交提示词和回执保持原文，其中旧路径通过归档清单追溯。若生产工具仍需直接读取旧路径，先保留源文件，待迁移该实际依赖后再归档；不靠历史映射冒充程序已经支持重定位。
4. **核对收尾。** 检查归档文件存在、移动内容未变、原位置已移出，更新后的路径可读，当前输入和交接未受影响；按实际影响运行已有校验。交付时简报归档数量、目录和因依赖保留的例外。没有可归档项不创建空目录或空报告。
