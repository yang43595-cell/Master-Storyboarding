# Skill 共用三层职责与读取规范

本规范由各 Skill 入口读取；三层按内容职责区分，不按 `modules`、`references`、`templates` 或 Vault 目录硬分层。它不新增生产阶段、知识数据库、审批表或通用专业模板。

## 第一层：启动与运行边界

项目规则、目标 Skill 入口和本轮准确输入决定目标、授权、职责、上游来源、输出、下游交接与停止点。遵守[项目执行分工](../../PROJECT_RULES.md#skill-执行分工)：新一轮编导、导演稿、视频提示词等实质创作由全新专属生产执行者完成；同轮逐段推进与返修续用，不递归为本轮再派生产者。主对话协调和检查；普通问答、只读审计和机械维护不因此新增生产者。生产者自查不是独立审核，独立审核只在用户明确要求后启动。

统一入口的审核范围、自动继续授权及画布停止点以 [网站审核到画布的统一入口](../../PROJECT_RULES.md#网站审核到画布的统一入口) 为准；本 Skill 内旧的逐段／逐稿人工确认与网页送审步骤按该分支解释。先核 [接线现状](../../docs/development/review-to-canvas-entry.md#接线现状与开发交接)，未实现的采用分支不能靠更改人工确认记录冒充跑通。

各入口的真实读取方式保持不变：普通生产准备按 [知识读取合同](knowledge-access.md)；资产 Web 的两个模式由 `library_runtime.py` 组装本次实际输入，不强套普通 prepare；视频直接读来源和适用方法，不建旧准备/阅读/审核包；审核者只消费目标冻结证据，不重建目标包；知识维护不进入生产链；声音和 Blender 仅在其可选分支成立时进入。阶段结束不自动调用下一 Skill。

## 执行与完成核对

各 Skill 按入口 SOP 执行本轮适用步骤。写好流程、列出规范、生成字段或校验通过，都不能替代实际执行；前置未完成时停在受影响步骤，不把后续产物的存在当作前置已完成的证据。

- 开始时确定本轮入口、交付对象、范围和停止点；只写提示词、实际生成、技术交付、内容质检分别判断，不要求执行未获授权的分支。可选或不适用步骤说明原因，不能将缺料、未检查、失败或待用户确认写成“不适用”。
- 执行后保留可核对结果：读取有实际返回的准确原文；程序检查有本轮对象、命令和结果；内容自查能定位实际正文；看图/试听有准确文件、用途、观察与局限。有效证据按共享规则复用，并说明引用来源，不冒称本轮重新执行。
- 交付前按本 Skill 的 `review-profile.json` 中适用产物项核对当前版本，同时检查本轮 SOP 是否实际走完；发现问题回到对应步骤修正，再检查修改及直接影响。修订后不能继续用旧版本的检查结果，未变且仍适用的依据可保留。普通自查不新增独立审核。
- 结果沿用现有候选未决字段、任务/审查记录或本轮交付说明，说明已完成、未执行/阻塞及其原因；适用项无证据就保留未验证，不报整轮完成。无需逐项新建表格、报告、平行状态或同义稿；只读任务不为留证改业务文件。
- 收尾核对交付准确路径、版本与范围，按已有规则处理本轮旧稿；候选、审核通过、用户确认、正式采用和下一步授权分别说明。完成本 Skill 不自动取得下一阶段或外部执行权限。

以上是执行与审查约定。现有 CLI 只强制其已实现的结构、字节、来源和确认门禁；不能强制宿主每次调用顺序，也不能证明执行者已理解、看懂或听核。审查须核实际轨迹和产物，不宣称所有跳步出口已由程序封闭。

## 第二层：当前适用的方法、模板与合同

第二层是已经确认、对本轮范围适用的方法与执行合同，不以存储目录或文件名判断地位。本仓库通过各 profile 选择 `knowledge/runtime/` 的版本化运行副本，属于相同第二层职责；其来源参考仍是第三层。根目录解析、选择清单与刷新边界见[独立仓库说明](../../docs/development/standalone-repository.md)。保留现有正式方法的状态，不因统一三层就把它们降为候选。各 Skill 保留自己的专业方法、schema、模板及目标审核清单，不复制编导的专业写法给其他角色。

适用优先级按职责判断：系统安全和权限不可绕过；当前用户明确决定在其授权范围内优先，项目规则和本地执行合同约束流程、交付与职责；绑定专业方法提供本职方法；知识案例提供其证据覆盖内的参考。模板负责表达组织，不得删去上游已确认事实或覆盖来源语义。历史示例和外部旧模板不得反向替代现行本地交付合同。若同一职责内有未解决冲突，保留双方准确版本与范围，暂停受影响动作并报告，不猜哪版已获批准。

## 第三层：来源、知识、案例与待验证内容

第三层不等于全部候选，也不要求每个 Skill 都有非空专属知识。有效参考、已确认方法的来源证据、条件案例与外来待验证知识必须按真实状态区分；空 profile 或本轮无适用命中不是缺陷。审核者使用目标任务证据，不另绑全部生产理论。

只沿本 Skill 的 `knowledge-profile.json`、现行本地明确引用和本轮所选来源读取精确路径/锚点。来源版本与状态沿既有方法正文维护记录、profile、知识策略与入口登记、固定快照来源清单、任务中真实生成的快照/哈希核对；记录可得的版本、原始来源、准确适用范围和读取入口。路径相同不代表字节相同，用户确认绑定不代表实验有效，存在文件不代表已读或已看/听。缺失版本、原文或来源索引如实标缺，不猜填 hash、墓碑、批准或阅读凭据；固定快照不是实时主库，不写回或覆盖原始来源。

新外来知识先核来源、范围和冲突，未获正式采用前保持候选/待整理；不凭引用、转发、讨论或“试试”改生产状态。长期整理、候选验证、晋升、替代和回退统一复用[知识维护生命周期](../knowledge-maintainer/modules/maintenance-method.md#候选知识生命周期与晋升)及其既有载体，不另造治理表。

两条晋升路径必须分清：实验验证路径需足以支持范围的实际证据、独立证据审查和授权采用；项目验证或历史盲测是按授权选择的方法，不自动执行。用户直接明确指定具体内容正式采用可走 user_directed，免实验前置但不能免来源、内容语义、冲突、范围、安全与权限检查；未实验明确未验证，不标 experiment_validated。两者均保留准确依据、版本、替代关系和回退方式，不把本轮使用升级为长期授权。现有 binding_status 与动态块状态沿用知识维护合同，不新增伪状态或自动迁移其他 profile。

## 生效与验证边界

入口必须实际读到本规范。普通 prepare 已有共享文件依赖收集，资产 Web 显式加入本文件；视频/只读审核/维护沿入口直接读取。链接检查和组装测试只能证明接线、版本与字节，不证明执行者理解、内容效果、视觉质量或用户批准。无真实输入的分支标未运行；不为验证接线制造生产证据或付费生成。
