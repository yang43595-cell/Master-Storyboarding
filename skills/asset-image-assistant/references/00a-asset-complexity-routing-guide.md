# 已登记 AST 的复杂度路由

复杂度只决定如何完成白名单内 AST，不决定需要哪些资产。只生产当前有效资产表中的 AST，用户调整按 PROJECT_RULES.md 的授权分支核对并登记，命中条件只改变实现模块；发现未经授权或尚未登记的表外需要时报告 `GAP-AST-*` 并停止该项。

## 原则

- 只生成能解决一致性风险的资产，并且该风险已属于当前 AST。
- 已有确认资产足够时复用，不重复生成。
- 一张综合母版能稳妥覆盖本次用途时不拆多套资产；环境一致性优先，四图是合理默认，减少视图须保留空间覆盖余量，不追求临界最少。
- 普通一次配角可以单图覆盖；资产表已判断无需独立图时只保留镜内描述，不因角色类别新增图片任务。
- 镜头数量多不等于资产复杂度高。

## 路由

- `L0`：单一综合参考即可满足当前 AST。
- `L1`：综合母版加 1 至 3 个已登记状态、展示面或朝向。
- `L2`：固定人物、复杂空间、关键道具或真实产品需要独立母版与必要验证。
- `L3`：同一 AST 的多状态、多方向或复杂交互确有高一致性风险，使用完整验证组。

多个 AST 各自选择等级，不得用一个 L3 判定扩张整个项目资产范围。

## 强制考虑项

| 当前 AST 已登记条件 | 实现模块 |
|---|---|
| 广告产品或明确要求还原的包装、工具 | 产品真实参考与所需展示面 |
| 固定人物身份、体型、发型或服装 | 人物身份母版 |
| 多方向空间关系 | 场景母版和已登记方向 |
| 道具承担交互或状态变化 | 道具母版和已登记状态 |
| 风格本身是已登记 AST | 风格母版 |

## 路由记录

每项 AST 登记：复杂度、判断依据、已有资产是否足够、启用模块、跳过原因、所需候选数量，以及是否存在表外缺口。扩大高成本验证前必须取得用户授权。

### 5.1 按预算执行稳定性压力测试

短视频、单一广告或预算受限项目只测试当前 AST 的真实高风险项，不以压力测试为理由扩张白名单、增加未登记状态或建立冗余母版。扩大候选数量、方向、状态或高成本验证范围前，必须说明风险证据并取得用户授权。

压力测试用于验证当前覆盖方案是否稳定，不用于机械消耗预算；不得默认连续生成十次，也不得把重复生成当作通过标准。已有确认资产、真实参考或少量候选已经足够证明稳定时，应停止继续生成并进入技术核对或用户确认。
