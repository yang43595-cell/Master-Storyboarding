# 视觉资产清单合同

项目使用 `visual-asset-manifest.json`，结构遵循 `schemas/visual-asset-manifest.schema.json`。该清单是候选、确认状态和下游引用的唯一资产事实，不使用文件名或目录猜状态。图片批次执行者只写独占分配的候选与现有制作/观察记录；共享 manifest、当前资产清单、网站确认及阶段状态由阶段负责人核对后统一更新，不让多个批次各写整份清单。

## 来源白名单

导出入口只记录实际文件技术检查和准确用户选图确认，不按 REAL_PRODUCT 类别写产品事实 `passed`；没有单独结果时省略可选 `product_fact_check`，表示未记录，不能解释为已通过。历史清单里的 `passed` 也不单独证明 Agent 实际核对过产品事实，须回查准确图片及真实观察依据；不补造证据、不原地改写已确认清单。

- `source_narrative` 指向有效采用的准确叙事包。canonical JSON（schema_version=2.0 且省略 human_readable_path）直接使用包内 `asset_requirements`，登记依赖 `narrative.package`，不要求独立资产表。仅历史合同实际使用独立资产表时，保留其 artifact、revision、路径和校验值于原确认记录的 `source_asset_table`，并增加 `narrative.assets` 依赖；来源变化须重新核对受影响交接，不删除历史字段绕过差异。
- `source_asset_requirement_ids` 是本轮有效 AST 白名单，由已采用叙事包的资产需求和按项目规则登记的用户调整共同生成；保留原始来源与调整依据，不把新增项伪称为原叙事包事实。
- `assets[].asset_id` 必须属于该白名单；未经授权或尚未核对登记的表外请求写入 `scope_gaps`，不得先创建资产条目；取消项按需求调整记录排除，不列作缺图。

## 每项资产

必须登记：

- `asset_id`、类别、名称和状态；
- 事件适用范围与可选镜头范围；
- 交互、展示面、朝向和所需状态；
- 必须继承与不可继承内容；
- 真实参考路径；普通剧情物品无参考时记录无参考及设计依据，不编造路径或实物核验结论；
- 独立候选、技术检查和可选生成授权记录；
- 用户确认后才存在的 `confirmed_asset`。

`must_not_inherit` 用于排除不应进入母版或其他镜头的剧情状态，例如特定表情、动作、污损、强剧情布光、临时构图、背景人物或文字。

## 状态规则

- `missing`：登记需求尚无可用候选。
- `candidate` / `awaiting_user_review`：未获用户确认。
- `confirmed`：必须同时存在确认候选、真实路径和 `user_confirmation_ref`。
- `stale` / `rejected` / `blocked`：不得作为当前下游输入。

生成成功、技术检查通过、Agent 自查／独立审核通过、文件位于母版目录，均不能单独构成 `confirmed`。按项目已定通道登记真实人审依据，覆盖准确 AST、输出 ID、修订或图片字节及用途。普通对话使用用户对该图和用途的明确通过，记录在项目现有的逐图确认与清单中。工作台通道使用真实网站回执，沿[网站决定与交接](../../../docs/development/review-workbench-operations.md#资产网站决定与交接)登记。无真实回执或登记条件不满足时保持待审。

## 技术检查与用户终审

执行者检查路径、格式、尺寸和参考来源。用户查看实际成品，决定是否符合本轮用途。

对话及批次交付只包含文件夹绝对路径、准确文件名、对应 AST/output、修订/字节依据、实际参考、用途及用户修改意见，不嵌入图片载荷。证据沿现有制作项与审核备注保存，不新建平行 QA 账本；共用记录文件由阶段负责人统一写入。选用工作台送审时，候选媒体按[资产图送审](../../../docs/development/review-workbench-operations.md#资产图送审)执行；聊天路径说明不代替网站可见图片。

## 下游读取

下游只能引用 confirmed 状态资产的 `confirmed_asset.path` 或 `confirmed_outputs[].path`，并遵守适用范围、必须继承和不可继承内容。先按登记 AST/output、准确修订与用途定位，再到交付目录读取准确文件；批次文件夹用于定位，不代表其中全部图片已确认或可用。不得从候选目录随机挑图，也不得绕过清单重建人物、场景、产品或道具事实。

1.1 清单保留 `confirmed_asset` 作为兼容主图入口，`confirmed_outputs` 为同一 AST 的必要独立图片组，每项含 output_id、purpose、state、view 及具体用户确认引用。下游需要某状态或视角时按这些字段匹配，不能把主图冒充未提供的视角。旧 1.0 清单没有此字段时只提供原有主图，不推测有其他图片。

旧道具复用输出若误录为四视图，工作台和 `python -m scripts.core.asset_refs --project <项目> --scope AST-ID@OUTPUT-ID` 在读取时按原确认显示「原图视角」。沿用原确认、路径及交接版，不为更正这处显示标签重新选图。换图、用途变化或确认撤回仍走原流程。

用户明确新增、删除和恢复资产需求时，执行 [用户调整资产图需求](../../../docs/rules/visual-production.md#用户调整资产图需求)。该授权分支允许按已核对出现位置加入需求表，不适用“表外一律停止”的自动推断限制；未授权的新物件仍须停止。下游读取 asset_requirement_decisions，取消项不是缺图，新增项须沿用其出现范围。

## 交付版本核对

导出前从当前登记记录定位实际选定的 AST、output_id、来源修订、用途/状态/视角及文件，实看交付文件与已检查结果一致；旧兼容主图只按其已登记范围使用。不能按“最新文件”或文件名猜选，也不能把中间验证图、少一张的组图、已替换版本冒充最终输出。文件或版本有变化时重新核对受影响结果，旧审核结论不自动沿用；已有合用的人物四格图按原确认复用。新四格按[人物 1×4 拼版](../../../PROJECT_RULES.md#人物-14-拼版)制作，在现有登记中关联两张已确认源图的输出 ID、文件字节及确认引用，记录成品字节与技术自查。机械拼版须展示成品并取得同版用户确认。

未完成、未验证和阻塞项写在现有记录及交付说明中，区分已就绪范围与缺口，不报整项完成。交给下游的是准确文件与职责，不是笼统“素材已齐”。本 Skill 不操作画布；实际上传后的原生引用、保存和刷新回读由承担上传的阶段核对，未执行时不得宣称已上传验证。

## 普通对话整轮交审

按有效编导稿和已登记的需求调整列出角色造型、场景、产品及道具的全部需求，标明可复用的准确原图和用途。本轮需人审的源图列在项目请求的 `asset_review_targets`，人审后机械拼成的人物板单列为交付结果。每批沿用原实看回执，记录准确路径、字节、候选身份、用途及用户反馈。汇总委派批次时运行 `python scripts/chat_asset_review.py --project <项目> show-round --context-id <批次一> --context-id <批次二>`。主对话直接制作的批次使用可重复的 `--receipt <项目内实看回执.json>`，可与委派批次一起汇总。缺图时继续处理所列缺口；齐备时把返回的准确图片、用途、偏差及适用范围一起展示，保留这份展示编号。用户明确要求提前看某批时才用 `show --context-id <批次>`。

用户说“全部通过”时，协调方将实际消息记为 JSON（scope 为 all_shown，quote 为原话，at 为带时区时间，review_ref 指向真实消息），运行 `python scripts/chat_asset_review.py --project <项目> confirm --shown <实际展示编号> --confirmation-json <消息文件>`。整轮展示只传一个编号。兼容历史分批展示时可重复 `--shown`，仅传本次通过的准确范围。用户仅通过部分时，确认文件用 `scope: selected` 及 `targets` 准确列出此次展示中通过的输出，同时保留原话、时间和消息引用。命令写母版、逐图回执和当前资产清单，可用原参数重试。用户退回时用同样的展示编号和实际消息执行 `return --shown <编号> --feedback-json <消息文件>`。把返回的意见和候选身份交给资产 Skill，保留原图，另存新版本再展示。用户未回应时保持待审。返修沿用其余已确认项，只展示需重新决定的新版本。

普通对话确认头照和服装后，在仓库根运行 `python scripts/chat_asset_review.py --project <项目> compose-boards`。命令按当前角色、服装交审时绑定的最终输出及已确认源图制作就绪的板，返回候选文件、待补项和展示编号。来源不唯一时用 `--board AST-ID@最终输出ID 头照输出ID 服装输出ID` 指定同一角色的准确来源，可重复指定。展示返回的成品，用户通过后按上段 `confirm --shown` 登记此次拼版。重复执行沿用同版；换一套衣服只重拼对应板，共用头照换版时重拼引用它的板。
