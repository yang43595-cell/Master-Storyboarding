# 项目资产网页入口

涉及产品动作参考或真实人物使用效果参考时，执行 [产品使用参考对接](../../_shared/product-usage-contract.md)。参考视频与待定效果需求单独列示，不加入已确认图片母版数量；生成路径未指定时不创建生图任务。

这是资产 Skill 项目模式的交互界面，不是独立资产库模式，也不是另一个生产阶段。

## 输入与盘点

项目核心代码统一判断产物登记与用户采用状态；网页不重复解释正文生命周期。canonical JSON（schema_version=2.0 且无 human_readable_path）从已采用叙事包读取结构化 AST 与原文背景，不要求独立 narrative.assets 或 Markdown。历史包保留 human_readable_path 时沿原双文件及适用独立资产表合同只读检查，一致性在上游交付审查完成，不得删字段绕过差异。网页按选中 AST 限定原文范围；保留确认来源和文件校验值。缺少有效来源则停止，不自行填表。

所有写词和审查使用同一个任务输入：当前制作项、适用项目事实、参考图、模板原文、Skill/知识库规范及审查项。模板原文独立于已写提示词，返工不能用旧提示词替代模板。没有独立模板的类型使用分类指南。资料入口统一按 [Web 受限读取合同](web-input-contract.md) 执行，默认当前对话自查并返修；不保留试点与普通两套输入路径。

日常同步按资产需求内容及制作背景判断失效；变更来源路径或格式不增加新的确认阶段。首次目录或交付格式迁移作为一次性数据操作记录，不建立专用网页接口。旧图与原确认历史保留。

网页制作格属于一个 AST；用途、状态和视角是它的实现信息，不能派生表外 AST，也不能把一个合并场景 AST 在网页按名称或状态拆成多个地点。遇到多个独立空间被登记在同一 AST 时，保留旧图片和记录、停止该项制作，并回到编导稿新版本拆分真实 AST。库存元数据仅帮助筛选，未实际看图不能声称视觉匹配。用户选用现有图后仍需项目内逐项确认。

模板仅在匹配输出时使用：大头照、服装、人物1×4和环境使用知识库既有模板；物品、产品、风格按分类指南编写，明确展示“依据分类指南编写”。不把独立库的默认比例当成所有项目需求的规范。

## 生成与确认

- 网格每项生成独立图片；多选写提示词与多选生成是两次操作。提示词由当前对话编写、自查并修改；按 production_artifact_checks 全部核对。修改提示词或参考后复核受影响结论。独立审核仅在用户明确要求时启动。
- 大头照 3:4，完整头顶到锁骨，下边界到锁骨下缘，不出现衣服、领口、肩带；服装和人物1×4使用各自既有模板。
- 环境输入参考接受任意视角，包括俯视、平视、侧视；输入参考不冒充某张交付图，也不计入四张输出。环境一致性优先，默认四图是合理起点。用户明确选择四图后，按 45°、正面、反面、俯视分别制作和确认；状态是否需要另一组由实际可见变化和覆盖余量决定，不把每个剧情状态机械乘四。已确认母图加少量必要视角足够时，可按盘点的用途、视角、理由与实际依赖制作两图或其他充分集合；说明覆盖、盲区和相机余量，不追求临界最少。先依据输入参考制作母图，再派生其余视角。添加输入参考与选择交付数量分开，已有两图/单图计划不因添加参考自动变为四图。保留已展示的空间布局，未展示部分作为待确认设计补全。此网页入口的视角顺序覆盖场景指南的默认排列。单母版需求不强加四视图。
- 人物1×4初次、返修及换装均引用清晰的独立确认服装和原独立确认脸，不使用旧板或板内裁脸；依赖图必须先完成项目确认。头像、服装及其他资产返修统一执行共享“返修参考与固定基准”。
- 网页人物新制作路径中，大头照与服装三视图均经用户确认后，最终1×4自动在本地拼版并回填：左格使用确认大头照，后三格依次取确认服装图的正面、左侧、背面，画布16:9。不再调用模型或要求单独视觉确认；记录为已确认来源的派生图，保留来源图片与确认引用。换脸、换服装须重新确认来源并生成新版本，旧图不覆盖。直接选用已有1×4仍需用户确认。
- 用户对本批最终提示词、工具、模型和上传/额度消耗明确授权后逐项提交。失败或重启不自动再次生成；查询已提交结果不等于重新生图。
- 成功生成图全部本地保存并分类备份知识库；未确认不等于废弃。垃圾桶三十天可恢复。库内确认和项目确认分别登记。

## 输出与交接

逐项视觉确认后才允许整表导出；图片、清单和确认凭据保存到项目资产母版的新版本目录。1.1 清单的 confirmed_asset 保留主图，confirmed_outputs 列出全部必要独立图片的用途、状态、视角及确认引用。下游按职责选择，不能只取主图替代整组。

复用项目产物登记、确认和交接机制；资产可与导演规划并行，不改写其他阶段的 current_stage 或 next_stage。“继续项目”只提供交接文件和 Codex 继续指令；不执行其他 Skill。

## 人物需求的选择优先流程

人物需求进入网页后，先按当前用途选择“人物单图／综合参考”或“身份与服装1×4”路线，再选择已有图或新制作。普通一次配角可以单图覆盖，不因缺少服装套数而阻塞此路线；显式上游状态仍须覆盖。已登记无需独立图的角色不进入图片任务，保留故事事实与镜内文字。身份板路线沿用已有最终人物1×4或重新制作；不要求先运行全表盘点。制作路径登记仅建立工作台任务，不等于完成 Skill 的准备、提示词或图片生产。

网页以需求卡片呈现，点击后在悬浮窗内选择。两套服装各交付一张1×4，可分别选用两张已有图，也可共用一个大头照、两套服装制作。脸和服装可上传或从库中选择；留空步骤由右下“补充生成”入口按依赖顺序编写、审查提示词，用户核对后另行授权生图。虚构人物未上传照片时以已确认 AST 描述为依据，未知项仍交审查；服装生成携带确认大头照。真实产品和实物参考门禁不变。场景与物品使用同一组卡片/悬浮窗入口，复用路径不混入批量生成。

选择身份板新制作路线时，同一人物共用一张大头照，每套上游要求的服装分别有服装三视图和最终1×4。单图路线不套用这组中间图要求；按其实际用途与确认输出交接。套数与名称由当前 AST 原文确定，网页不让用户另设套数或名称；来源缺失或冲突回上游解决，不把情绪或皮肤状态算作新服装。直接复用某套1×4不要求补齐该套脸/服装过程图，仍须项目视觉确认。新制作路径中脸与服装均可选择已有资产并确认；生成服装前确认共用脸，生成1×4时必须绑定该人物确认脸及对应套的确认服装，上传仍按服装、脸顺序。

人物路径中的写词和审查仍走本 Skill 的 Web 受限读取合同、Skill 模板、知识库语言约束及当前对话自查；不通过直接任务登记规避生产规则。上游未知项保留在人物卡与审核上下文中，不能由固定流程假设解决。

换脸使依赖它的新制作1×4待重新核对；改单套服装仅影响该套及其合成图。切换复用/新制作或服装标注变化保留旧图与历史确认。交接只要求当前路径实际需要的步骤，直接复用的最终1×4可单独交接；新制作路径的脸、服装及最终图都纳入确认图片组。

### 新制作角色的提示词审查

选择新制作且大头照留空，允许依据当前 AST 和生成方向设计虚构角色的身份候选。未锁定的面部、发型等外观须写成具体、单一的候选供用户审核，不声称来自参考照片；已有确认身份必须继承。空参考列表本身不构成失败理由，不要求用户先生成一张参考脸才能制作首张大头照。明确要求还原真人或已有角色时仍须身份参考。请求的 allow_unreferenced_design 只许可未锁定外观设计，不许可改动已确认剧情、身份或真实产品。

选择新制作且服装留空，表示依据已确认 AST 设计该套服装，不表示还原大头照中的衣服。大头照只锁人物身份；款式、颜色、体型和配饰遵守上游已锁定信息。未锁定且不影响剧情的裤装、鞋履、面料和普通结构可提出具体、单一的设计方案，注明为待用户审核的设计选择，不声称来自参考照片。不得同时给互斥选项。仅缺少目标服装照片不构成失败理由。明确指定实物还原、真实产品、关键剧情结构缺失或已确认约束冲突时，仍须参考或上游澄清；同批同类步骤使用相同标准。

用户明确新增、删除和恢复资产需求时，执行 PROJECT_RULES.md 的“用户调整资产图需求”。该授权分支允许按已核对出现位置加入需求表，不适用“表外一律停止”的自动推断限制；未授权的新物件仍须停止。下游读取 asset_requirement_decisions，取消项不是缺图，新增项须沿用其出现范围。


外部工具已获授权并实际生成的图片，按 [现有导入与溯源入口](../../../scripts/visual_asset_ui/README.md#外部已生成候选的接入不替换原生生成) 接为候选。原生成服务失败不授权切换工具；导入来源、提示词/参考指纹、项目视觉确认和服务接通是不同事实，不能互相代替。
