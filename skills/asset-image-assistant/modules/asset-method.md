# 资产方法

完整流程见 [Skill 六步 SOP](../SKILL.md#本轮执行-sop)。本文件只补充方法适用条件与成图自查；Web 两种模式按 `Web 受限读取合同` 准备资料。

## 本 Skill 产出须命中的规范（缺即停）

委派、并行或跨执行者交接的普通图片批次按[隔离准备入口](../../_shared/knowledge-access.md#图片批次的隔离准备)执行；产出前运行 `python scripts/stage_context_cli.py ensure-prepared --project <项目> --skill asset-image-assistant --context-id <本批ID> --actor-id <本批实际执行者> --task-id <本批任务>`，与本批 prepare／阅读登记保持一致。主对话直做批次沿用本阶段 `task_basis`，不传 `--context-id`，但仍须冻结 `image_targets` 并写回现有回执。普通准备沿本轮启动包读取并登记现有方法。Web 只核本次 task-package，背景固定层的专业方法随场景制作项加载。两种入口均核对下列适用规范；真实缺项按当前普通准备或 Web 入口补齐或报告受影响范围，动态知识与本地规范分开核对：

- **色卡统一风格**（锁整片跨镜头配色）：见 `references/01-style-master-guide.md` 的"整片色彩统一（色卡）"工作流；有 `STYLE_REFERENCE` 或需锁整片配色时必做，它是与背景母版、多角度参考组并列的第三种一致性路线。
- **图片连续性**：核[共用检查](../../storyboard-director/references/image-continuity-hard-rules.md#共用检查)。人物只读对应输出规格和适用的身份引用；做场景时按[背景母版](../references/03-scene-master-guide.md#背景母版与单变量派生)及[多角度覆盖](../references/03-scene-master-guide.md#多角度场景参考组)核固定层和空间。
- **对应类别 master-guide**：按当前 AST 类别必读 `references/01-style-master-guide.md`（风格/色卡）、`references/02-character-master-guide.md`（人类/人形角色）或 `references/02a-body-character-master-guide.md`（动物/非人形/PET）、`references/03-scene-master-guide.md`（场景）、`references/04-prop-product-master-guide.md`（道具/产品）的对应部分（非可选），把抽象词落成可观察的拍摄/材质/光线条件。
- **提示词语言合规**：写提示词必读 `../voiceover-to-video-script/references/prompt-language-hard-rules.md` 并以其为准；禁用 影视级/8K/唯美/高级 等炫技含糊词。人物/空间/产品/光线四项连续性分别检查。

在 SOP 已核定的需求范围内，为候选记录来源参考、指定变化、必须继承与不可继承内容。人物、空间、产品与光线连续性分别检查；首次、返修和换装均执行图片连续性规则的“返修参考与固定基准”，不把失败图滚动继承为输入。

母版按对应类别指南构建：人物先选综合单图或身份板；身份板按[人物 1×4 拼版](../../../PROJECT_RULES.md#人物-14-拼版)用确认头照和对应无头服装三视图直接拼接。普通对话的场景机位在母图通过空间自查后接续，与母图一起交审。Web 依赖按本次任务包执行。普通物品按四视图短模板，真实产品按所需展示面与状态制作。不得把可选验证组变成每项必做任务。

环境母图在现有 `ASSET-FORMAT` 检查中按[取景与补全](../references/03-scene-master-guide.md#可复用环境母图的取景与补全)核对。提示词阶段核实际正文的机位、覆盖区域与补全内容。成图按[本地交付验收](../references/03-scene-master-guide.md#十四本地交付验收)指认可见空间，把覆盖不足及其影响写回现有实看记录。

## 身份替换与年龄版本

替换人物面容时，定向核对受影响的既有年龄/状态版本、确认输出及下游引用；同一人物身份不等于同一年龄状态。多个年龄条目共用一张新照片时，说明它只锁身份，年龄由提示词表现，不能据此判定年龄已经被图片覆盖或取消原年龄要求。旧年龄图若属于旧面容，不直接混入新身份。

已有适用年龄图就按获准职责复用；只有身份图但本段允许通过提示词表达年龄时，明确职责和未验证效果即可，不把同一路径自动判成缺图或阻塞。确需补图时仍由用户决定需求与生成，不自动恢复旧版本、新增AST或生成各年龄一套图片。年龄来源用当前剧情的明确节点，不自行补算未知年龄。

## 角色类型与身体外观

CHARACTER 是叙事角色类别。先按 character_type 选择：人类及人形角色沿用人物身份与服装方法；动物和非人形角色读取 references/02a-body-character-master-guide.md，使用角色外观母版，不套用人类脸部、无头人台及服装拆分要求。普通 prepare 与 Web 均支持 body：按本轮已明确角色类型填写 `asset_method_scopes`，纯非人形启用 body 且不启用 character，只读取非人形指南及共同连续性方法；人类/人形用 character，混合角色两键均启用。普通请求已启用 character 时，显式 `body: false` 排除非人形指南；旧请求仅 `character: true` 继续兼容两类指南，类型未知不凭名称猜测或缩小范围。普通 prepare 不自动扫描 AST，执行者须覆盖当前完整需求；这些条件不改变角色类别或出图授权。所有路线仍执行图片连续性方法、动态提示词规则与用户审图确认。旧版未登记类型保持旧路线；已明确的类型更正写入项目资产需求调整，不改已确认剧情。

## 候选交付

人物灰模的用法和规格统一见[人物构图](../references/02-character-master-guide.md#九image2-提示词结构)。项目使用[大头照和服装各两版生图模板](../references/character-layout-prompts.md)作为正文。普通对话和红帧从本批 `task_basis.json` 取对应的 `character_prompt_templates` 正文和 `character_layout_references`。资产网页用同一正文和灰模。原参考在前、灰模在最后。按实际参考槽位补充本轮需求，避免另写整篇通用提示词。灰模只用于生成构图，不登记为已确认资产或下游素材。

图片执行者只写本批分配的候选文件。开始、恢复执行及交付前，核对当前有效用户要求、资产需求调整、所用规范版本和授权；上下文摘要只作定位线索，不能替代原文。新执行者、上下文压缩后依据不完整，或要求、用途、版本发生变化时，重读相关持久原文及适用规范（Web 使用当前完整任务包）；同一有效上下文内未变化的材料按共享读取规则复用。不完整或相互冲突的关键依据只阻塞受影响项，不猜填、不报完成。用户最新明确调整按原登记流程生效，优先于通用默认，不取消安全、确认或生成授权门槛。

先把本轮实际要求对应到制作路线和最终交付：人物是单张综合参考还是身份板，场景是哪些机位、规模及状态，道具/产品是哪些结构、展示面及使用状态。复杂度默认不能覆盖用户明确要求；也不能反过来把所有人物硬套 1×4、所有场景硬套四图。普通物品继续轻量检查名称、明确要求和对应布局。制作前按目标平台、模型和实际用途核对已知图片限制，生成或拼版后用最终交接文件复核，在现有制作项记录实测尺寸。新做服装三视图默认 4:3，生成参数、提示词和灰模画幅统一，按成图实际像素验收。拟用于红帧人脸认证的人物板按[人物板导出尺寸](../references/02-character-master-guide.md#人物板导出尺寸)制作。

新叙事包中的 `character_output_kind` 随已采用资产需求传入制作。人物1×4按 `wardrobe_states[].output_id` 绑定每套服装；普通批次与 Web 都沿用这些输出 ID 派单、送审和导出。多套服装按实际造型绑定有效身份来源和对应已确认服装，逐套核对拼版成品后交接。明确单图的角色沿单图路线；取消、无需独立图或待定的角色不进入制作。

历史叙事包没有人物输出字段且已有明确 1×4 要求时，仍可在现有 `04_资产/资产需求调整.json` 登记 `character_output_requirements`。每项以 AST 为键，记录 `source_revision`、`evidence` 和 `outputs`（准确最终 output_id 到 `人物1x4` 的映射）。多套服装没有现成绑定时，在同一记录用 `outfit_output_ids` 对应上游服装名与输出 ID，例如 `{"居家服":"HOME-FINAL","外出服":"OUT-FINAL"}`。新确认的结构化规格优先，历史包的原记录可继续作为依据核对。

普通批次在请求的 `image_output_kinds` 中声明最终目标，如 `"AST-001@HOME-FINAL":"人物1x4"`，由 `prepare` / `ensure-prepared` 核对。头照和服装三视图用各自中间输出 ID。最终交付运行 `python -m scripts.core.asset_refs --project <项目> --require-final-image AST-ID@OUTPUT-ID`，可传裸 AST-ID 核该角色全部最终输出。入口检查确认、文件、最终类型以及人物板实际格式及横版构图。网页整表导出核同样的最终规格。复用合格1×4时沿用准确用途和确认依据。缺某套只影响相关交付。

候选保存后展示实际文件、用途及版本。用户退回时记录原话和对应版本，按意见另存新文件。用户通过后沿用该文件及其确认记录，任何格式或内容变化都作为新候选。
