# 资产方法

完整流程见 [Skill 六步 SOP](../SKILL.md#本轮执行-sop)。本文件只补充方法适用条件与成图自查；Web 两种模式按 [Web 受限读取合同](web-input-contract.md) 准备资料。

## 本 Skill 产出须命中的规范（缺即停）

普通对话产出前运行 `python scripts/stage_context_cli.py ensure-prepared --project <项目> --skill asset-image-assistant`；Web 只核本次 task-package，不运行该命令。两种入口均核对下列适用规范；真实缺项按 `skills/_shared/knowledge-access.md` 补齐或报告受影响范围，动态知识与本地规范分开核对：

- **色卡统一风格**（锁整片跨镜头配色）：见 `references/01-style-master-guide.md` 的"整片色彩统一（色卡）"工作流；有 `STYLE_REFERENCE` 或需锁整片配色时必做，它是与背景母版、多角度参考组并列的第三种一致性路线。
- **图片连续性规则（背景母版 + 多角度参考图组）**：必读 `../storyboard-director/references/image-continuity-hard-rules.md`，不再视为"涉风险才读"；按需用背景母版锁固定层、用多角度参考组锁场景空间。
- **对应类别 master-guide**：按当前 AST 类别必读 `references/01-style-master-guide.md`（风格/色卡）、`references/02-character-master-guide.md`（人类/人形角色）或 `references/02a-body-character-master-guide.md`（动物/非人形/PET）、`references/03-scene-master-guide.md`（场景）、`references/04-prop-product-master-guide.md`（道具/产品）的对应部分（非可选），把抽象词落成可观察的拍摄/材质/光线条件。
- **提示词语言合规**：写提示词必读 `../voiceover-to-video-script/references/prompt-language-hard-rules.md` 并以其为准；禁用 影视级/8K/唯美/高级 等炫技含糊词。人物/空间/产品/光线四项连续性分别检查。

在 SOP 已核定的需求范围内，为候选记录来源参考、指定变化、必须继承与不可继承内容。人物、空间、产品与光线连续性分别检查；首次、返修和换装均执行图片连续性规则的“返修参考与固定基准”，不把失败图滚动继承为输入。

母版按对应类别指南构建：人物先选综合单图或身份板；身份板统一由 AI 使用确认头照与对应无头服装三视图生成。场景先确认母图再派生机位；普通物品按四视图短模板，真实产品按所需展示面与状态制作。不得把可选验证组变成每项必做任务。

## 身份替换与年龄版本

替换人物面容时，定向核对受影响的既有年龄/状态版本、确认输出及下游引用；同一人物身份不等于同一年龄状态。多个年龄条目共用一张新照片时，说明它只锁身份，年龄由提示词表现，不能据此判定年龄已经被图片覆盖或取消原年龄要求。旧年龄图若属于旧面容，不直接混入新身份。

已有适用年龄图就按获准职责复用；只有身份图但本段允许通过提示词表达年龄时，明确职责和未验证效果即可，不把同一路径自动判成缺图或阻塞。确需补图时仍由用户决定需求与生成，不自动恢复旧版本、新增AST或生成各年龄一套图片。年龄来源用当前剧情的明确节点，不自行补算未知年龄。

## 角色类型与身体外观

CHARACTER 是叙事角色类别。先按 character_type 选择：人类及人形角色沿用人物身份与服装方法；动物和非人形角色读取 references/02a-body-character-master-guide.md，使用角色外观母版，不套用人类脸部、无头人台及服装拆分要求。普通 prepare 与 Web 均支持 body：按本轮已明确角色类型填写 `asset_method_scopes`，纯非人形启用 body 且不启用 character，只读取非人形指南及共同连续性方法；人类/人形用 character，混合角色两键均启用。普通请求已启用 character 时，显式 `body: false` 排除非人形指南；旧请求仅 `character: true` 继续兼容两类指南，类型未知不凭名称猜测或缩小范围。普通 prepare 不自动扫描 AST，执行者须覆盖当前完整需求；这些条件不改变角色类别或出图授权。所有路线仍执行图片连续性方法、动态提示词规则与用户审图确认。旧版未登记类型保持旧路线；已明确的类型更正写入项目资产需求调整，不改已确认剧情。

## 本轮要求到实际成图的自查

沿用现有制作项、候选和审核记录，不另建平行清单。开始、恢复执行及交付前，核对当前有效用户要求、资产需求调整、所用规范版本和授权；上下文摘要只作定位线索，不能替代原文。新执行者、上下文压缩后依据不完整，或要求、用途、版本发生变化时，重读相关持久原文及适用规范（Web 使用当前完整任务包）；同一有效上下文内未变化的材料按共享读取规则复用。不完整或相互冲突的关键依据只阻塞受影响项，不猜填、不报完成。用户最新明确调整按原登记流程生效，优先于通用默认，不取消安全、确认或生成授权门槛。

先把本轮实际要求对应到制作路线和最终交付：人物是单张综合参考还是身份板，场景是哪些机位、规模及状态，道具/产品是哪些结构、展示面及使用状态。复杂度默认不能覆盖用户明确要求；也不能反过来把所有人物硬套 1×4、所有场景硬套四图。普通物品继续轻量检查名称、明确要求和对应布局，不补造尺寸、实物参考或全套状态字段。

提示词自查只证明计划；生成后、复用换用途后及导出前，须实际查看本轮选定图片，将可观察内容对照当前要求及类别指南，不能用文件存在、尺寸、数量、审核 ID 或“已确认”代替看图。重点核对：人物板的区域内容与视角（不是四个随意景别）、场景实际规模/布局/需保留的变化、产品可见结构和当前开合/使用状态、身份及服装等明确不变量。静态图不能证明动作时序或视频连续性；不可见、看不清或工具无法读取的部分记为未验证。图片里已经可见的冲突不得以“后续提示词会修正”放过。

在现有审核备注中简记重要要求的来源定位、实际 output/文件及观察结果、结论和未满足处理。缺件、错内容、错版本为未通过；未读取或无法判断为未验证/阻塞，不填 PASS。通过仅为本轮客观要求自查，不等于用户视觉确认。中间验证图不顶替最终交付；人物四格图须实看本轮 AI 生成的最终文件，确认头照和服装不自动确认该成图。实际图仍有问题可列为待修候选供用户查看，但不得宣称整项已完成或交接为合格素材。

Web 审查版本由 `library-profile.json` 的现有 version 管理；本轮升级后，旧版审查记录保留，但不代表新版检查已完成，应沿原入口重新审查。不得只改旧记录的版本号冒充重审；版本升级不撤销既有图片的用户确认，也不要求重生成。普通物品重审仍只走原有轻量检查。
