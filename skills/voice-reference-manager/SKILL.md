# 声音参考管理

开始本职任务前读取[共用三层规范](../_shared/skill-layers.md)。本 Skill 适用边界：仅用户明确要求声音参考时进入；核对来源授权、角色/对白映射和用途，保留候选与 current 区别，不因三层统一强加声音输入。

按 [项目规则的可选声音参考边界](../../PROJECT_RULES.md#导演稿之后的生产顺序) 启用；用户未提出时不进入本阶段，也不要求声音输入或交付声音参考项。

由当前执行者按 [PROJECT_RULES.md 的 Skill 执行分工](../../PROJECT_RULES.md#skill-执行分工) 执行本阶段；默认由主 agent 直接执行和自检，已明确委派时由受派执行者完成。

读取 `PROJECT_RULES.md`、`../_shared/knowledge-access.md`、当前 `stage_startup.md`、`../_shared/draft-lifecycle.md` 等共享红线、`modules/voice-method.md`、`../../schemas/voice-reference-library.schema.json` 与 `../../schemas/voice-reference-manifest.schema.json`。需要执行确定性导入、绑定、换声或校验时才使用 `../../scripts/voice_reference_cli.py`；普通审查不运行写入命令。

## 输入与职责

- 以已确认角色 ID、角色名称和最终对白中的说话者归属为准。文件名、目录名、音色印象或模型猜测都不能证明人物身份。
- 声音候选必须登记真实音频路径、声音来源、说话者身份依据、授权状态与授权引用、允许用途、技术时长和文件哈希。来源或授权不清时可保留候选，但不得建立 current 项目快照。
- 试听只判断声音是否适配指定角色目标；候选、待确认、拒绝和 current 必须分离。用户对具体候选的确认引用，不能替代来源授权证据。
- 同一有效上下文、同一角色和用途可复用已有试听结论及准确快照；新执行者、用途/角色/版本变化或结论未覆盖本段对白时，按共享读取规则定向试听。来源登记、哈希和 current 状态不等于已试听，也不替代新的适配判断。
- 项目绑定必须登记角色、对白范围、项目/场景/片段适用范围、排除范围和 current 快照。默认范围可以是“该角色在本项目全部已确认对白”，但必须显式记录，不能靠下游猜测。
- CLI 范围写 `project`、`scene:<准确场景ID>` 或 `segment:<准确片段ID>`，可重复；未指定时默认项目，显式场景/片段范围不会追加项目。排除范围优先于适用范围；引用场景范围须在片段里有准确 `scene_id`。同一声音的范围变化也须按换声流程重新确认并使依赖失效。

## 执行

按“角色与对白归属 → 来源与授权 → 候选试听 → 技术核对 → 用户确认 → current 快照 → 下游引用校验”执行。

- `voice-reference-library.json` 保存可复用候选事实，不等于项目确认。
- `07_声音与配音/voice_reference_manifest.json` 只保存项目 current 绑定；同一角色只能有一个 current 声音快照，快照复制到项目内并记录哈希。
- 换声必须有新的用户确认，旧快照保留但退出 current；不得静默覆盖。只报告受影响的角色、对白和下游引用，不决定下一阶段或生成策略。
- 交付声音清单时列出：角色、voice ID、来源与授权、对白范围、适用/排除范围、快照路径、哈希、确认引用和下游引用状态。
- 下游引用必须以 `character_id` 和已确认对白 ID 为依据；无归属对白、未绑定角色、越出适用范围或快照漂移均停止并报告。

## 硬禁区

- 不改写、润色、拆分或补写台词，不用声音候选反推角色设定。
- 不按文件名猜人物，不把试听、技术通过或 Agent 评价写成用户确认。
- 不把来源授权未知或用途受限的声音登记为可用 current 快照。
- 不生成逐句配音、不决定口型、不写视频提示词、不提交视频模型。
- 不调用下一 Skill、不决定阶段流转，也不恢复 V3 orchestrator、任务图或派发协议。
