# 声音参考方法

声音事实分三层保存：

1. 候选事实：音频文件、来源、说话者身份依据、授权、时长、哈希和音色描述。
2. 用户选择：具体角色选择了哪个候选，以及确认引用。
3. 项目 current 快照：复制到项目内的稳定文件、角色/对白/范围绑定和下游引用状态。

技术可用只说明文件可读且未漂移；角色适配由试听判断；项目可用还必须同时具备授权和用户确认。三者不得合并成一个“通过”。

## 实际试听与返修

先核对音频准确路径、voice ID 和哈希，再实际播放与本轮角色及用途相关的范围。沿既有任务记录或本轮交付说明记下实际听到的时间范围、角色目标、可定位的适配观察、缺陷及结论；例如语气与年龄感是否符合已定角色、可辨识度是否满足用途、是否有杂音或混入其他说话者。只判断已听范围，不从技术参数或音色标签推断整段通过，也不把参考试音当作本片对白已生成或已听核。

已有试听可复用时引用准确音频版本、原听核范围与用途，说明本轮仍适用的依据；不冒称本轮重新试听。当前执行者无法实际听核且无有效既有依据时保留“未试听”，停在候选。候选待确认、已被拒绝、用户已选和 current 的情况留在既有记录或交付说明，不向现有仅存候选事实/current 的 JSON schema 塞入不支持字段，也不新建状态台账。

适配不符先定位候选与具体时窗，由当前执行者按授权修正候选选择或补充真实资料，再核对新音频及直接影响；换音频、角色或用途范围时重核受影响的试听和确认，不能只更新哈希。授权证据不覆盖本次用途时，即使用户喜欢声音也停止 current 绑定。CLI 校验的实际覆盖以结果为准，不能用 `authorized` 字样或空的允许用途记录替代用途核对。

## 第三层条件来源（按需）

仅用户已明确选用声音参考，且本轮需要比较同一角色的不同情绪样本时，可在仓库内置知识包中选读 `wiki/sources/AI声音一致性-刺猬星球super-i.md` 的“核心主张”第 3 项及“证据限制”。正常、愤怒、伤心短样本是未验证的 candidate 方案，不默认建库、生成音频、换声或启用声音阶段；未命中或来源缺失不加载、不构成普通任务缺口。实际样本仍按已有来源授权、试听、角色/对白范围及用户选择核对，不能以情绪分库存绕过当前一角色一份 current 快照。来源中的未具名配音工具、Pitch/Stability 参数和影视声音授权不随引用采用；本轮参考判断留在现有记录，不改正式方法绑定或添加阅读凭据。

## 确定性命令与用途核对

`add` 的 `--permitted-use` 登记来源证据允许的准确用途，可重复；`unknown` / `restricted` 候选可保留空用途，但 `authorized` 候选必须有非空、合格的允许用途及授权引用。`bind` / `replace` / 兼容的 `snapshot` 必须显式传 `--intended-use <本次用途>`，可重复；这些字符串须逐项准确匹配允许用途，不按“内部使用”等词面猜出商用范围，也不自动从允许用途选择本次用途。新快照保存 `intended_uses`，其变化同样需要新确认并使依赖失效。

`python scripts/voice_reference_cli.py validate-project --project <项目>` 核对已登记用途；旧快照未登记时保留原字节，输出 `usage_checked=false` 和具体限制。需要核本次准确用途时可追加 `--intended-use <准确用途>`，只读核来源授权覆盖；不补造历史用户对新用途的确认。已有快照登记了用途时，本次检查也不得越出其已确认范围。

现代提示词仅在明确使用声音参考时，在同一 `video.prompt` JSON 保留 `audio_policy=voice_reference` 或准确 `voice_reference_manifest_path`，并沿用 `source_storyboard`、`source_shots` / `source_audio` 与已确认角色/对白映射；本稿及下游登记的 `depends_on` 必须可追溯到所用 `voice.character.<角色ID>`。换声先只读核当前登记的准确 JSON、来源确认与哈希及上述映射，缺依赖或来源失败在复制新快照前停止。合格时沿既有依赖使受影响产物失效，保留旧确认正文；旧 `production_plan` 只作兼容，不为现代稿补建。未选用声音参考的普通对白稿不因此新增声音前置。
