# 素材与提交交付

交付一份包含完整分段提示词的 JSON 业务稿，Markdown 按需导出，不依赖 production_plan、打包器或请求 schema。候选每段列拟上传文件顺序、准确选中版本、引用标记、主要职责与相容用途；平台操作后核同一映射的实际上传和原生身份，不把拟定顺序写成已执行。素材 ID 或文件夹不能代替实际文件。核对文件真实存在、非空且属于本次确认参考，涉及真实外观时按现有复用边界实际看图。

给用户文档的可点击路径，以及图片文件夹、准确文件名和段内顺序；遵守项目图片交付约定，不嵌入大图或 Base64。共用素材可列统一清单，每段仍明确自己的输入顺序及当前是拟定还是实传，生成模型不能依赖其他段正文。

局部返修需要换图或槽位不足时，先将上一版和本版的有序引用按实际镜号与职责对照。核被移除图承担的每项仍有效职责在本版由哪张适用图承接，尤其是开场状态和前后段共用切点。优先移除重复证明同一布局的图。无合格替代时，在现有未决项记录缺哪一镜的什么状态，并按候选或正式交付原有门禁处理。改完按新顺序重核正文中的编号和实际原生槽位。

画布中提示词直接保存在对应视频节点，后续交付不再额外放置同内容的提示词阅读副本或重复文字节点。2026-11-05 用户明确要求“副本下次不用放到画布，没用”；本条不授权删除既有副本，也不影响实际参考素材、视频草稿、生成结果及必要总览。

实际提交需要时才保存对应 UTF-8 TXT，内容与确认稿一致。参数及图片/视频/音频输入以所选模型当前能力为准。声音母版仅在用户明确采用声音参考时核对，不把试听候选当作确认声音；未选用时按[项目可选边界](../../../docs/rules/visual-production.md#导演稿之后的生产顺序)省略该项。

实际执行获授权的生成时，在原有交付或任务记录按[草稿、提交与结果的取证边界](../../../docs/development/delivery-snapshot-checks.md#草稿提交与结果不混用)保全当次输入和任务标识。草稿保存和原生回读继续作为草稿证据。用户自行提交且平台未提供可查的历史输入时，将实际提交关联标为未知。

交付不等于授权上传或付费，素材和参数检查不证明生成效果。来源、授权或文件缺口直接报告；复用现有交付 JSON 和修订记录，不创建平行预检账本或退役机器计划模拟授权。有广告产品时，写入画布前核对[广告中的产品展示与使用](../../_shared/product-usage-contract.md#广告中的产品展示与使用)所要求的参考覆盖和有效时长。

每次画布写入（含已授权的私有候选预览）前，按[提示词内容合规审查](../modules/video-method.md#提示词内容合规审查)完成或核对仍有效的本轮结论；未完成或不通过先修复，不以写后回读替代。同稿内容结论的复用不免除当前版本、引用、授权和目标检查。每次正式交付或提交生成前，实际运行现有版本及引用检查；AST 输出和补图按 SKILL 的 asset_refs 入口核对。正式画布交付使用现有快照的 `--delivery` 模式；明确授权的私有候选预览仅按 PROJECT_RULES 的限定例外使用 `--private-preview`，不升级确认或允许生成。按[交付快照校验](../../../docs/development/delivery-snapshot-checks.md)补齐参考职责与准确版本，先 preflight 核当前登记和文件，再比较实际刷新后的原生读数；JSON、图边或旧 PASS 不能替代本修订回读。中断先只读确认已保存范围，不自动重写或重复生成；返修、重提或上游变化后重跑受影响检查及实际回读。缺 manifest、有效采用依据或原生映射时报告缺口，不能填造登记或宣称正式交付。采用及唯一自查报告按[Skill 记录分界](../SKILL.md#自查记录与正式采用)，不另建账本或冒充人审。

叠加文字与剧情内实体文字按[对白与时长](../modules/video-method.md#对白与时长)核对；小云雀参数按[平台合同](seedance-platform-contract.md#小云雀网页写入选择2026-10-23-用户要求)显式冻结为 480p，并实际读回。`canvas_readback.py` preflight 对小云雀核 480p，并对已知叠字与时间保护语作有限文本检查，不替代来源、屏内执行方案或内容判断，不自动改正文、历史快照和用户时长，也不证明模型服从。历史普通比较不冒充新写入许可。

小云雀画布交付必须完成排版、复核与截图，不以节点已上传或正文已写入作为完成。按本轮场景和片段顺序整理，参考素材、生成草稿与结果清晰分组，同组节点对齐、间距一致，避免遮挡和交叉混杂；沿用现有编号及准确对应关系，不为排版改动已确认正文、素材引用、生成参数或采用状态。排版后实际刷新并复核布局是否保存，同时完成上文原生字段回读；截图不能代替字段检查。交付画布全景与关键细节截图，分别展示整体顺序及可辨认的节点标题、素材对应和片段关系；沿用现有交付记录说明实际检查范围和缺失证据，不另建账本。未实际刷新、未查看截图或仍有遮挡混乱时，不宣称画布交付完成。

## 画布紧凑排版

本条同时适用于红帧和小云雀。同一阶段的节点紧凑排列、对齐，相邻节点之间只留一条便于辨认边界和点击的缝，不采用大面积留白的网格间距。不同阶段再分区，不把阶段之间的间距套用到同一阶段的每个节点。对应图片、提示词和视频草稿便于就近对照；在正常审阅缩放下实际检查间距，不以缩小全画布代替紧凑排版。节点不得重叠或遮挡，不为排版改动正文、素材引用和参数；保存后刷新核对布局并截图。

小云雀批量摆放前先在一个有代表性的片段按实际卡片尺寸试排，确认标题可读、素材和草稿可就近对照，再沿片段顺序铺开。红帧试排并入下文的[代表段验收](#红帧代表段验收)。整批重开后实际查看全景和正常审阅缩放的局部，确认组内没有大块留白、节点和连线没有挡住阅读、主审阅区没有新增重复提示词卡。只有零重叠或位置已保存时，布局仍未验收；发现问题先调整，再重开查看。

## 红帧与小云雀的交付边界

红帧排版先读取[红帧专用副本](redframe-canvas-layout.md)：按 2026-11-12 用户要求沿用小云雀原模块分类与行列，不以就近对照改成混合资产区。下文保存、回读及可读性验收继续执行。

本节沿用户对本项目的直接要求执行，不新增平台能力或通用授权。红帧与小云雀分别核对准确项目/画布、当前模型控件、上传方式和原生引用；小云雀的 480p 选择、实体类型、参数名称或布局操作不直接作为红帧能力事实。红帧参数采用用户本轮明确选择，并以该入口实际支持为准；缺能力或证据先报告，不擅改模型、时长或分辨率求通过。

红帧上传并绑定素材后，对每份含写实人脸的素材，先通过原生入口点一遍“人脸认证”，再生成视频。交付给用户自行生成的画布，也在交付前执行这个动作；只交草稿的任务做完后仍不点击生成。不另设单独检查、核验报告或逐项确认环节。

红帧额度无限不等于允许自动生成：每次实际生成前须取得用户对本次明确范围的同意，明确批次可覆盖其中列明的片段，不把写稿、上传、排版或保存草稿授权当作生成授权。失败后的重新提交、追加生成也须先得到用户同意；结果未知先只读查原任务，不能当作失败重提。此为本项目红帧的当前限制，不以一般的“原范围授权可复用”覆盖；不改变其他入口的既有授权边界。

红帧画布也按本轮片段顺序组织参考素材与草稿，并区分已有结果；依据该入口实际布局能力完成清晰分组、对应和可读排版，不复制另一平台的操作方法，不为排版改正文、引用或参数，不要求为截图生成结果。完成后实际刷新，查看全景及关键细节截图，同时核对本次准确节点的原生正文、参数、有序媒体身份及适用的引用实体。平台不支持某项操作或无法取证时明确具体缺口与已完成范围，不能用截图、图边或同名标签补成字段回读，也不能因此擅自超出本次授权新建替代平台或适配器。

### 红帧代表段验收

红帧首次写入、写入方式变化或批量排版时，先用本轮一个正式段试验，优先选正文较长、引用较多的段。在「生成提示词」主编辑器写入原稿，在相应动作处插入原生 `@`，设好参数，并按实际卡片尺寸紧凑试排。正文可沿用本项目实测的原生纯文本粘贴方式。通过原生机制保存后，从「我的画布」按准确项目重开，在同一次验收中逐行比对正文，核对参数及原生 `@` 的实际素材身份、出现顺序和对应动作，并在正常审阅缩放下查看代表段的标题、素材与草稿是否便于对照。独立文本节点、图边和同名标签均不能代替主编辑器及原生引用回读，素材字节身份缺证时标为未核。

试段发现缺口时先修正，再重开核对。适用项通过后自行完成余段，整批交付前重开回读各段并检查全景和关键局部。沿用已验证写法的局部修订只复核受影响项及直接依赖。

平台专用采集能力须来自实际核验；本仓库离线比较器及旧 RHTV 工具本身不证明红帧或小云雀采集器已实现。无法真实采集某字段时保留未核，不手填期望值充当读数，不把 `after_refresh` 标签当刷新证据。沿同一交付记录分别报告：准确目标与本轮范围、写前内容结论、实际保存/上传和绑定、刷新后字段回读、布局截图、生成是否获准及是否执行；只完成其中部分就报告部分完成。候选预览仍保持候选，正式交付仍走现有检查，均不升级为用户确认或视频效果通过。

## 跨目录恢复与文件包传递

只在需要文件包时检查：完成打包后、发送前运行 `python -m scripts.core.product_refs --project <项目> --package <实际成品.zip> [--package <另一成品> ...]`；画布交付也可在原有 `canvas_readback.py --delivery` 命令追加同样的 `--package` 参数。检查读取每份实际成品（含压缩/目录开销），输出 bytes 与 SHA-256；默认每包必须严格小于 19,000,000 bytes，这是本轮 ChatGPT 传递的保守预算，不是所有平台的通用上限。渠道预算已另行核实时可显式传 `--max-package-bytes <独占上界>`，不能为通过检查随意调高。超限拒绝并提示重新准备较小、自包含的包后复检；不自动删素材、拆包或改相对链接。需要拆分时先核对各包独立可打开及链接依赖，保留原件。此为交付检查点，不是后台上传拦截器；没有传包路径不能声称包大小已检查，检查后包字节变化必须重跑。

在独立临时目录解压自己生成的包，核对本次声明文件、相对链接、原始字节和已有准确 revision/hash；不要改真实项目或已确认正文。人工自制 ZIP 的恢复试验不等于支持安全导入未知 ZIP；未知归档不直接 extractall，先检查越界成员及链接。绝对路径不会因解压自动修好，须按已有明确迁移映射或另做阅读副本，不能篡改确认凭据。

文件可读不代表恢复运行授权。候选测试状态绑定准确项目目录，复制到新目录仍会拒绝运行；不得删标记、伪造确认或自动改路径以求通过。当前没有自动重绑候选运行身份的恢复命令，需要另行明确处理授权和运行身份。恢复检查不推进采用、上传、生成或发布。


### 生成前检查的证据边界

- `--preflight` 只核本地输入，不读取平台实际绑定；不得同时传 `--readback`。要比较真实回读，单独运行不带 `--preflight` 的 `--readback` 流程。
- `native_refresh_binding=selected_fields_match` 仅表示所选回读字段匹配，须结合 `native_reference_checks` 判断是否覆盖原生实体。它不证明未暴露的媒体 ID / 原件哈希，也不是生成授权；`production_ready=false` 不得解释为可以生成。
- 只读富文本采集支持已观察到的 `P/richGrid`、`SPAN/richMark`、`SPAN/richWrite` 结构，保留结构、空白与 FEFF，不把序列化 token 回写正文。未知结构继续未检查；离线 HTML 回放不能代替当前平台刷新后的实际采集。

红帧若无公开稳定 `media_id`，只可按[明确的 node/port/输入槽下载分支](../../../docs/development/delivery-snapshot-checks.md#红帧-node--输出-port--实际输入槽下载显式分支)核实际字节；不得把 port 或 blob URL 填成媒体 ID。完整输入槽证据未取得时仍未核；已有证据通过也不代替持久状态、包装用途、内容审查或生成授权。
