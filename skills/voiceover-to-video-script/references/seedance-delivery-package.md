# 素材与提交交付

## 草稿参考与交付

交付一份包含完整分段提示词的 JSON 业务稿，Markdown 按需导出，不依赖 production_plan、打包器或请求 schema。候选每段列拟上传文件顺序、准确选中版本、引用标记、主要职责与相容用途；平台操作后核同一映射的实际上传和原生身份，不把拟定顺序写成已执行。素材 ID 或文件夹不能代替实际文件。核对文件真实存在、非空且属于本次确认参考，涉及真实外观时按现有复用边界实际看图。

给用户文档的可点击路径，以及图片文件夹、准确文件名和段内顺序；遵守项目图片交付约定，不嵌入大图或 Base64。共用素材可列统一清单，每段仍明确自己的输入顺序及当前是拟定还是实传，生成模型不能依赖其他段正文。

局部返修需要换图或槽位不足时，先将上一版和本版的有序引用按实际镜号与职责对照。核被移除图承担的每项仍有效职责在本版由哪张适用图承接，尤其是开场状态和前后段共用切点。优先移除重复证明同一布局的图。无合格替代时，在现有未决项记录缺哪一镜的什么状态，并按候选或正式交付原有门禁处理。改完按新顺序重核正文中的编号和实际原生槽位。

画布中提示词直接保存在对应视频节点，后续交付不再额外放置同内容的提示词阅读副本或重复文字节点。2026-11-05 用户明确要求“副本下次不用放到画布，没用”；本条不授权删除既有副本，也不影响实际参考素材、视频草稿、生成结果及必要总览。

交付不等于授权上传或付费，素材和参数检查不证明生成效果。来源、授权或文件缺口直接报告；复用现有交付 JSON 和修订记录，不创建平行预检账本或退役机器计划模拟授权。有广告产品时，写入画布前核对[广告中的产品展示与使用](../../_shared/product-usage-contract.md#广告中的产品展示与使用)所要求的参考覆盖和有效时长。动作素材默认保留原画幅。确需裁切时，核对手、工具和作用部位仍可完整辨认，并记录选用版本及依据。

## 正式草稿写前检查

本轮单段还需首次采用或自主修订提交时，使用[单段采用与写前预检](../../../docs/development/artifact-adoption.md#单段采用与写前预检)的 `accept-artifact --preflight-json`；自主修订加原 `--change-id`。同一入口完成采用登记、准确回读和本地预检，不手工补 state，也不把预检失败当成需要再次采用。已登记完整且无采用动作的单纯检查仍用原只读预检。

先核当前内容结论的适用范围。同一执行者、同一任务内，准确修订、正文和有序素材字节、用途、要求及来源均未变且可核时，复用本轮已完成的结论。缺少有效结论或正文、引用等变化时，按[提示词内容合规审查](../modules/video-method.md#提示词内容合规审查)核当前稿及受影响内容，未完成或不通过的范围暂不写入。

保存前核当前采用版本、引用授权和实际目标，沿实际 AST 输出与补图做资产引用检查。按[草稿身份与回读](#草稿身份与回读)冻结并取得本轮原生证据。缺 manifest、有效采用依据或真实原生映射时报告缺口。中断先只读核已保存范围。

正式 `--delivery` 默认读取这五节：[同一份 JSON](../../../docs/development/delivery-snapshot-checks.md#同一份-json)、[操作与采用](../../../docs/development/delivery-snapshot-checks.md#操作与采用)、[来源映射](../../../docs/development/delivery-snapshot-checks.md#来源映射)、[正式交付的文件依赖](../../../docs/development/delivery-snapshot-checks.md#正式交付的文件依赖)、[本轮观察证据与输入版本](../../../docs/development/delivery-snapshot-checks.md#本轮观察证据与输入版本)。

- 红帧核[分段参数](../../../docs/development/delivery-snapshot-checks.md#分段参数)，再进入[成批写入和整节点回读](../../_shared/redframe-operations.md#成批写入和整节点回读)。已有实际连线时核[既有连线草稿](../../_shared/redframe-operations.md#既有连线草稿)；包含布局引用、场景后态或既有场景判断时读[场景状态的交付核对](../../../docs/development/delivery-snapshot-checks.md#剧情场景状态的交付核对)。
- 分批沿用前段时核[已有前驱与分批范围](../../../docs/development/delivery-snapshot-checks.md#已有前驱与分批范围)。使用不同机位的共用切点时核[同状态参考组](../../../docs/development/delivery-snapshot-checks.md#同状态参考组)。
- 导演登记了必保镜头、最低时长或动作参考时核[必保画面与产品动作参考](../../../docs/development/delivery-snapshot-checks.md#必保画面与产品动作参考)。现稿声明已回读或本轮接手旧回执时，核[当前修订的回读证据](../../../docs/development/delivery-snapshot-checks.md#新稿不得继承旧回读通过)。

只有明确授权的私有候选才读[私有预览快照](../../../docs/rules/experiments.md#私有候选预览)。生成取证、跨目录传包和采集器接线分别按实际动作读取。

## 草稿身份与回读

写入前核开工记录 `kickoff.canvas` 的实际画布、模型和参数，再冻结本轮的画布 URL、准确 `node_id`、当前提交正文、原生参数及有序输入的 node/media ID。新建按红帧直传计划暂列计划身份，取得真实节点后再绑定。每段写入显式传入该段冻结数据，避免上一段正文或参数被误写。替换前只读定位目标，确认活动节点、富文本编辑器、焦点及选区均属于它。仅点击编辑区不足以执行全局全选或清空。出现整画布删除提示立即取消并核节点未变。参数弹层分开读当前值、修改、确认和读回。异常先查真实停点，再恢复受影响操作。

保存后按本轮用户决定刷新，只读本轮准确节点，逐项核正文、参数、全部输入槽及原生引用。槽位顺序由 `ordered_media` 保留，正文出现顺序、重复引用及实际 `media_id` 与不可编辑实体由 `native_mentions` 单独核。静态标签、图边和保存提示都不足以证明绑定或持久化。按[快照字段和只读比较](../../../docs/development/delivery-snapshot-checks.md#操作与采用)保存本轮证据。缺可读字段或未实际刷新时标明未核范围；最终回复从现有回执带出已知报错、认证及可生成性未核项，不能只报告草稿保存和字段匹配。历史普通比较保留其兼容范围，不用于本轮正式采用。草稿交付与视频提交分别执行。

对照分镜图选择记录，逐段回读应有的**人物位置关系参考**，含单段样片。图片须进入该视频节点实际素材槽，正文用平台原生引用指向同一图，并说明继承的人物相对位置与固定锚点。按准确图版、字节、槽位和引用逐项核实。只在本地留图或画布上有一张独立素材卡，均记为该段缺绑定。所需关系图缺失、用途冲突或未接入时，先补齐受影响段再提交，用户明确同意只用提示词控制的具体关系和镜号沿原决定执行。桌面状态的文字控制决定只覆盖其原范围。

## 小云雀网页草稿

叠加文字与剧情内实体文字按[对白与时长](../modules/video-method.md#叠加文字与实物文字)核对；小云雀参数按[平台合同](seedance-platform-contract.md#小云雀网页写入选择2026-10-23-用户要求)显式冻结为 480p，并实际读回。`canvas_readback.py` preflight 对小云雀核 480p，并对已知叠字与时间保护语作有限文本检查，不替代来源、屏内执行方案或内容判断，不自动改正文、历史快照和用户时长，也不证明模型服从。历史普通比较不冒充新写入许可。

快照按实采显式包含 `edges` 或 `source_nodes` 时，补读[整节点字段](../../_shared/redframe-operations.md#红帧整节点的源连线用途与时间)和[连线槽位](../../_shared/redframe-operations.md#既有连线草稿)。

小云雀画布交付必须完成排版、复核与截图，不以节点已上传或正文已写入作为完成。按本轮场景和片段顺序整理，参考素材、生成草稿与结果清晰分组，同组节点对齐、间距一致，避免遮挡和交叉混杂；沿用现有编号及准确对应关系，不为排版改动已确认正文、素材引用、生成参数或采用状态。排版后实际刷新并复核布局是否保存，同时完成上文原生字段回读；截图不能代替字段检查。交付画布全景与关键细节截图，分别展示整体顺序及可辨认的节点标题、素材对应和片段关系；沿用现有交付记录说明实际检查范围和缺失证据，不另建账本。未实际刷新、未查看截图或仍有遮挡混乱时，不宣称画布交付完成。

## 画布紧凑排版

本条同时适用于红帧和小云雀。同一阶段的节点紧凑排列、对齐，相邻节点之间只留一条便于辨认边界和点击的缝，不采用大面积留白的网格间距。不同阶段再分区，不把阶段之间的间距套用到同一阶段的每个节点。对应图片、提示词和视频草稿便于就近对照；在正常审阅缩放下实际检查间距，不以缩小全画布代替紧凑排版。节点不得重叠或遮挡，不为排版改动正文、素材引用和参数；保存后按本轮用户决定刷新核对布局并截图；用户明确不刷新时保留未核范围。

小云雀批量摆放前先在一个有代表性的片段按实际卡片尺寸试排，确认标题可读、素材和草稿可就近对照，再沿片段顺序铺开。红帧试排并入下文的[代表段验收](#红帧代表段验收)。整批重开后实际查看全景和正常审阅缩放的局部，确认组内没有大块留白、节点和连线没有挡住阅读、主审阅区没有新增重复提示词卡。只有零重叠或位置已保存时，布局仍未验收；发现问题先调整，再重开查看。

## 平台保存与回读依据

批量制作依赖画布能力的素材或提示词前，先找同平台、同模型和同引用方式的保存及重开回读依据。缺依据时，按已授权范围做一次不生成的最小试接，确认原生引用和参数能保存及回读。缺可用样段或授权时，继续原片核对、编导及其他独立工作。

## 红帧与小云雀的交付边界

红帧排版读取[阶段、模块与验收规范](redframe-canvas-layout.md)：沿用分类与行列习惯，区分当前成果、制作来源、待确认候选和历史版本，并覆盖相关素材与完整草稿区。下文保存、回读及可读性验收继续执行；纯排版按该规范比较变动范围，用户明确不刷新时按其决定记录未核范围。

本节沿用户对本项目的直接要求执行，不新增平台能力或通用授权。红帧与小云雀分别核对准确项目/画布、当前模型控件、上传方式和原生引用；小云雀的 480p 选择、实体类型、参数名称或布局操作不直接作为红帧能力事实。红帧参数采用用户本轮明确选择，并以该入口实际支持为准；缺能力或证据先报告，不擅改模型、时长或分辨率求通过。

红帧画布也按本轮片段顺序组织参考素材与草稿，并区分已有结果；依据该入口实际布局能力完成清晰分组、对应和可读排版，不复制另一平台的操作方法，不为排版改正文、引用或参数，不要求为截图生成结果。完成后按本轮用户决定刷新，查看全景及关键细节截图，同时核对本次准确节点的原生正文、参数、有序媒体身份及适用的引用实体。平台不支持某项操作或无法取证时明确具体缺口与已完成范围，不能用截图、图边或同名标签补成字段回读，也不能因此擅自超出本次授权新建替代平台或适配器。

### 红帧草稿的人脸认证

对每份含写实人脸的素材，按[原生人脸认证与接线](redframe-canvas-usage.md#写实人脸认证)核对应来源及输入方式。交付给用户自行生成的草稿，也在交付前完成认证并核实所需的源卡连线及正文原生引用。仅交草稿时停在保存与回读。不另设核验报告或逐项确认环节。

### 红帧代表段验收

红帧首次写入、写入方式变化或批量排版时，先用本轮一个正式段试验，优先选正文较长、引用较多的段。在「生成提示词」主编辑器写入原稿，在相应动作处插入原生 `@`，设好参数，并按实际卡片尺寸紧凑试排。正文可沿用本项目实测的原生纯文本粘贴方式。通过原生机制保存后，从「我的画布」按准确项目重开，在同一次验收中逐行比对正文，核对参数及原生 `@` 的实际素材身份、出现顺序和对应动作，并在正常审阅缩放下查看代表段的标题、素材与草稿是否便于对照。独立文本节点、图边和同名标签均不能代替主编辑器及原生引用回读，素材字节身份缺证时标为未核。

试段发现缺口时先修正，再重开核对。适用项通过后自行完成余段，整批交付前重开回读各段并检查全景和关键局部。沿用已验证写法的局部修订只复核受影响项及直接依赖。

平台专用采集能力须来自实际核验；本仓库离线比较器及旧 RHTV 工具本身不证明红帧或小云雀采集器已实现。无法真实采集某字段时保留未核，不手填期望值充当读数，不把 `after_refresh` 标签当刷新证据。沿同一交付记录分别报告：准确目标与本轮范围、写前内容结论、实际保存/上传和绑定、刷新后字段回读、布局截图、生成是否获准及是否执行；只完成其中部分就报告部分完成。候选预览仍保持候选，正式交付仍走现有检查，均不升级为用户确认或视频效果通过。

## 跨目录恢复与文件包传递

只在需要文件包时检查：完成打包后、发送前运行 `python -m scripts.core.product_refs --project <项目> --package <实际成品.zip> [--package <另一成品> ...]`；画布交付也可在原有 `canvas_readback.py --delivery` 命令追加同样的 `--package` 参数。检查读取每份实际成品（含压缩/目录开销），输出 bytes 与 SHA-256；默认每包必须严格小于 19,000,000 bytes，这是本轮 ChatGPT 传递的保守预算，不是所有平台的通用上限。渠道预算已另行核实时可显式传 `--max-package-bytes <独占上界>`，不能为通过检查随意调高。超限拒绝并提示重新准备较小、自包含的包后复检；不自动删素材、拆包或改相对链接。需要拆分时先核对各包独立可打开及链接依赖，保留原件。此为交付检查点，不是后台上传拦截器；没有传包路径不能声称包大小已检查，检查后包字节变化必须重跑。

在独立临时目录解压自己生成的包，核对本次声明文件、相对链接、原始字节和已有准确 revision/hash；不要改真实项目或已确认正文。人工自制 ZIP 的恢复试验不等于支持安全导入未知 ZIP；未知归档不直接 extractall，先检查越界成员及链接。绝对路径不会因解压自动修好，须按已有明确迁移映射或另做阅读副本，不能篡改确认凭据。

文件可读不代表恢复运行授权。候选测试状态绑定准确项目目录，复制到新目录仍会拒绝运行；不得删标记、伪造确认或自动改路径以求通过。当前没有自动重绑候选运行身份的恢复命令，需要另行明确处理授权和运行身份。恢复检查不推进采用、上传、生成或发布。

`product_refs --discover-dependencies`会输出独立JSON报告行，追加`--package`时另有packages JSON行，错误还有普通文本且退出码非零。调用者先核退出码，再逐行解析明确JSON报告并保留错误原文；不能对混合多行stdout直接json.loads，也不能取最后一行当总PASS。程序输出协议保持不变。

## 已授权生成的取证

默认交草稿。用户明确要求执行者为可准确定位的片段生成视频时，同一条请求即可授权该范围的首次提交。已有有效授权时，直接沿原用户消息核对项目、目标画布、片段和提交范围，并把消息引用记入原任务或交付记录。批次授权覆盖其中列明片段的首次提交，可分批执行，无须逐段、逐批再次询问。只在授权缺失、范围无法确定或本次动作超出原授权时补确认。写稿、上传、排版、保存草稿及查询结果的许可各按原范围使用。

提交前按[写前检查](#正式草稿写前检查)核当前内容结论、来源版本和引用，核准确节点的保存后回读、实际参数与适用的[人脸认证](#红帧草稿的人脸认证)，再提交该段一次。

实际提交需要时才保存对应 UTF-8 TXT，内容与确认稿一致。参数及图片/视频/音频输入以所选模型当前能力为准。声音母版仅在用户明确采用声音参考时核对，不把试听候选当作确认声音；未选用时按[项目可选边界](../../../docs/rules/visual-production.md#导演稿之后的生产顺序)省略该项。

实际执行获授权的生成时，在原有交付或任务记录按[草稿、提交与结果的取证边界](../../../docs/development/delivery-snapshot-checks.md#草稿提交与结果不混用)保全当次输入和任务标识。草稿保存和原生回读继续作为草稿证据。用户自行提交且平台未提供可查的历史输入时，将实际提交关联标为未知。

提交结果未知时，先按原任务 ID 查询。还没取得任务 ID 时，按准确原节点只读核本次任务记录，红帧沿[同一会话续查](../../_shared/redframe-operations.md#视频提交结果未知时续查)。仍无法确定时保留未知，不重新点击。确认失败后拟重新提交，或要追加生成，先核用户是否已明确同意这次重提或追加。仅有首次提交授权时须补授权。平台额度、草稿验收和技术检查通过均不能授权生成。

### 生成前检查的证据边界

- `--preflight` 只核本地输入，不读取平台实际绑定；不得同时传 `--readback`。要比较真实回读，单独运行不带 `--preflight` 的 `--readback` 流程。
- `native_refresh_binding=selected_fields_match` 仅表示所选回读字段匹配，须结合 `native_reference_checks` 判断是否覆盖原生实体。它不证明未暴露的媒体 ID / 原件哈希，也不是生成授权；`production_ready=false` 不得解释为可以生成。

红帧若无公开稳定 `media_id`，只可按[明确的 node/port/输入槽下载分支](../../_shared/redframe-operations.md#红帧-node--输出-port--实际输入槽下载显式分支)核实际字节；不得把 port 或 blob URL 填成媒体 ID。完整输入槽证据未取得时仍未核；已有证据通过也不代替持久状态、包装用途、内容审查或生成授权。
