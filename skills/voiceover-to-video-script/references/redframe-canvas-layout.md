# 红帧画布排版

本文件是红帧各制作阶段共用的排版正文。2026-11-12 按用户要求从小云雀版本 2 引入分类模块与行列习惯；2026-11-18 结合包含源图、灰模、人物板、产品参考、生成候选和视频草稿的实际画布补充阶段与版本关系。小云雀原文不改。平台操作与输入绑定仍按[红帧共用入口](../../_shared/redframe-operations.md)执行，排版不改变采用状态或生成授权。

## 先识别阶段与当前用途

排版前查看整张画布及现有项目记录，识别当前阶段、各节点实际用途和有效版本。不能仅凭图片／视频节点类型、名称中的“候选”或所在位置判断是否可用；同一张视频可能是动作参考，也可能是生成结果。以准确版本及既有确认／采用记录为准。

画布按用途分为三类区域；只建立实际需要的区域，不预留整片空白：

- **当前工作区**：本轮正在制作的任务及其候选、当前已确认且会用于下游的人物板、场景母图、状态图、产品与动作参考、分镜、视频草稿和已有结果。待用户审图的候选放在对应任务旁，标明待确认，不提前归入已确认素材。
- **制作来源区**：身份照片、服装参考、灰模、头像与服装三视图等中间素材，以及真实产品原件、动作视频等来源。仍直接服务本轮任务的来源就近保留在对应模块内；已完成制作但需追溯的中间过程集中到该模块下方，不因不在视频上传清单就称为废弃。
- **历史候选区**：被替代、明确取消或未采用的版本，保留版本与原有问题记录；放在当前工作区下方或外侧，和当前可用版本清楚分开。用户仅接受局部用途的图仍按获准用途使用，不能排成完整状态参考。未经授权不删除、不重传、不重新生成。

区域可以通过已有标题、模块位置或平台分组辨认；必要时增加简短组标题，不要求为每个区域新建说明卡。排版位置不成为新的业务台账，准确状态仍留在现有项目记录。

## 模块与总体方向

当前工作区内按用途集中为人物、场景、物品／产品、分镜、视频参考、视频草稿与结果等模块。先看用户现有模块顺序，沿原顺序横向展开；新增类别接在相关模块旁，不为采用本规范强行重排另一套顺序，也不按每段剧情复制一套混合资产区。来源和历史区域可在对应模块下方续排，不强迫所有时期、所有元素挤在同一排。

区内紧凑、对齐，区间留可辨认边界，避免过远或大面积空白。按实际卡片宽高和标题占用留距，不设固定像素数；宽人物板、竖幅图片、横幅产品图和视频卡不能套统一占位尺寸。

| 元素 | 摆放与关联 |
| --- | --- |
| 人物身份、服装、灰模及图片生成节点 | 同一角色和造型的源图、灰模与对应生成节点靠近，保留真实接线；已完成的过程素材可下移到制作来源区。不得把灰模或未确认候选排成已确认人物板。 |
| 已确认人物板与膜态等状态图 | 人物板在人物模块集中，按角色排列；状态图邻近对应角色或场景，标明状态及用途。已确认头像与服装三视图仍是拼版来源，不因人物板完成而删除。 |
| 场景母图与分镜 | 场景图按场景集中；分镜另成模块并按场景／镜号排序。同一母图的不同状态、视角与有限用途关系图明确区分，不能把空场母图视为所有后续状态已验证。 |
| 产品实拍、普通道具与动作视频 | 产品成套参考保留产品 ID、版本及职责；普通道具与产品分组辨认。动作视频放视频参考模块，按产品使用顺序排列，与生成视频结果区分。已在草稿内直传的参考不为排版再上传一套素材卡。 |
| 图片生成节点与候选输出 | 留在所属人物、场景或分镜模块；当前待确认候选靠近原任务，返修就近对照。原节点自带的多次输出不为排版重复导出建卡。被取消的版本转历史区，保留来源关系。 |
| 视频草稿、补改节点与已有结果 | 草稿按片段顺序排，补改节点紧邻对应原段；平台独立显示的生成结果靠近对应草稿，标明版本与状态。结果不混入动作参考，不因有草稿便创建空结果卡。 |
| 声音参考与文字 | 仅已选用声音参考时设置对应小组，按角色／用途区分。提示词留在对应生成节点主编辑器，避免同内容文字副本；必要分区标题不等于提示词卡。 |

按[红帧生图 SOP](../../_shared/redframe-operations.md#生图)，素材上传后、图片生成节点新建后立即归位，再继续下一项。图片生成保留源卡与真实端口关系；视频草稿参考沿既定直传和原生引用方式，不为视觉对齐改成连线输入。素材与任务便于对照不要求每段复制共享资产。

## 各模块行列

沿用以下排法作为常规行容量，按实际卡片尺寸铺开；不是统一像素网格，也不要求每行填满：

- 人物图：每行 4 张；宽人物板占实际宽度，不压缩图片凑格。
- 场景图：每行 4 张，同一场景放同一行，超出后在相邻下一行续排。
- 物品图／产品图：每行 3 张，成套产品保持相邻，动作视频在视频参考模块内按顺序续排。
- 分镜图：每行 8 张，按场景换行，同一场景超出容量时相邻续排。
- 视频草稿：每行最多 5 个，按场景或剧情分行，同一行顶边对齐；下一行从该行最高卡片及标题的实际底部之后开始。
- 补生成／返修节点：紧接被补原节点的对应组，超过一行容量时在相邻下一行续排，保持编号和关系可辨。

上述数量用于同类成果卡。源图、灰模与生成任务组成的制作小组按关系排，不机械拆散以凑行数；模块内部仍保持角色、场景和片段顺序。间距以正常审阅缩放实看为准。

## 随制作阶段维护

- **资产制作时**：本轮任务、直接来源、生成节点和待确认候选就近对照；已确认人物板、场景母图等集中在当前成果位置，旧过程移到下方保留。
- **分镜补图时**：复用已确认资产区，分镜模块按场景与镜号扩展；返修候选靠近原任务，明确取消的补图留历史区。未选择补图的镜头不建占位卡。
- **视频草稿交付时**：复看整张画布，整理本轮仍使用的资产、产品／动作参考及分镜，再排完整草稿区。不能只将新增视频节点排齐，就声称全画布完成排版。共享素材保留一处，通过标题和实际原生引用核对应关系。
- **后续返修或集数**：新增内容在所属模块相邻位置或下方续排，复用有效素材。旧版移入历史区前核其是否仍被使用；移动不解除引用，也不因排版撤回确认。

只调整本轮涉及的工作区及影响阅读的直接关联节点，不顺带清理其他项目或无关区域。

## 执行与验收

每次写入、补充与交付当轮完成归位，不等用户另说“排版”。图片按[红帧生图 SOP](../../_shared/redframe-operations.md#生图)核首个实际节点，视频新增或写法变化按[代表段验收](seedance-delivery-package.md#红帧代表段验收)核写入；纯布局调整不为验收重写提示词、重传素材或重新认证。

每段提示词交用户验收前，先把该段草稿、实际引用的分镜或关系图及已有结果排到便于就近对照的位置，再做保存回读和提示词验收。适用范围包括旧段返修、只补一张参考图、单段样片与批量交付。共享参考保留一张，通过邻近分组和原生引用对应适用段。获准清理时，只移除有明确废弃依据且任何保留节点都不依赖的卡片。先备份画布并核图边与正文原生引用，已采用成果、仍在使用的来源及结果未知的任务继续按其实际状态归位。

1. **先看全局，再试排。** 核当前成果、制作来源、候选及历史版本，按代表卡片实际尺寸试排，再铺开同类节点。平台一键整理只能作起点，不能替代上述分类和对应关系检查。
2. **核整个交付范围。** 全景确认模块顺序、阶段关系和历史区边界；正常审阅缩放逐区看标题、端口、行距与对应关系，尤其检查宽人物板、混合横竖图、第二排草稿和补改节点。小比例全景看似分开，不能证明正常缩放无重叠；离屏占位尺寸也不能作为实测尺寸。
3. **保留内容与引用。** 移动前后核节点 ID、数量、真实连线及本轮受影响节点的非位置数据，保留正文、素材、原生引用、参数、结果和用户修改。连线端点坐标可随移动改变，不能为阅读删线；可用平台显示开关辅助查看，但隐藏线不等于解绑。纯排版复用有效素材字节证据，不重复下载全部附件。
4. **保存与取证。** 默认保存后重开／刷新核布局；用户明确要求本轮不刷新时遵从，在同会话核实际保存坐标及全景、正常缩放局部，清楚标注未验证刷新后保持。按用户当前决定操作，不为取得截图触发生成。
5. **如实交付。** 原有交付记录写准确范围、变动与检查结果，附全景和关键局部，不另建平行台账。只有节点数量相同、坐标保存或矩形零重叠仍不足以通过；标题遮挡、候选混用、对应关系不清或大块无效留白应先修。平台错误提示等既有缺口按实际记录，不以排版成功冒充认证、素材采用或生成效果通过。

本规范不额外规定资产总数、图片尺寸、审核／生成流程，也不要求为满足模块分类新增素材或空节点。

## 卡住或报错先刷新

红帧卡住或报错时先保留准确目标、节点 ID、待写文本和最后可信读数；保存或提交结果不确定时先只读查原节点/原任务，再按原要求刷新。刷新后核已保存范围及原生引用/连线，只处理已经确认尚未成功的步骤。缩略图加载失败不等于未上传，不重复上传、建节点、认证或提交生成，不擅自删除已有内容。恢复动作必须针对具体原因；仅重复相同点击、缩放或刷新且没有新的可核信息时，保留现场并暂停受影响步骤，不按固定失败次数继续试。刷新不扩大任何授权。

图片操作沿[图片页面共用入口](../../_shared/redframe-operations.md#图片页面共用入口)：本任务使用独立大视口，先用准确节点定位；已知对话遮罩仅关闭准确的“关闭对话”控件。节点/端口不在可操作范围时，最多一次“适应视图”后再核位置，仍不可达则返回实际坐标、视口和阻碍，由执行者实看调整本批布局，不在循环中猜缩放与屏幕坐标。页面驱动失联时退出本任务会话，按同一原节点恢复；已有提交回执只查原结果。
