# 红帧画布使用口径

本轮选用红帧后按操作读取对应小节。[连接、登录和草稿交付](../../_shared/redframe-operations.md#连接与登录)及[阶段、模块与行列](redframe-canvas-layout.md)沿仓库现有入口。

## 素材区上传

需要在画布素材区放独立素材卡时，走右键画布 →「上传」→ 选文件（视频为 remote-videoNode，图片为 remote-imageNode）。产品参考包等成套参考独立成区，命名带产品 ID 与版本（如 `产品参考·R04-…`）。红帧生图从图片素材卡[接入图片生成节点](../../_shared/redframe-operations.md#生图)。视频草稿的实际输入按[成批写入和整节点回读](../../_shared/redframe-operations.md#成批写入和整节点回读)直传。

图片上传、建生成节点、原生接线及引用写入统一用[图片页面共用入口](../../_shared/redframe-operations.md#图片页面共用入口)。上传和创建均单次执行，用实际持久画布的新增节点 ID 找回结果；异常不等于未创建，不自动再上传或再建一张。素材卡已有准确版本时复用其节点；最终接线、原生引用及源图原件字节仍须一致。入口不代替实际布局查看、人脸认证、图像审查或平台授权。

## 命名与排版

先按[阶段与当前用途](redframe-canvas-layout.md#先识别阶段与当前用途)区分当前成果、制作来源、待确认候选及历史版本；具体模块、行列和整张画布验收以该文件为唯一正文。以下仅说明节点命名和实际尺寸，不另定布局。

新建、上传、生成节点后当场排到所属模块的空位。交付前逐区做一次重叠检查，发现叠放先移开再验收。纯资产节点（右键上传生成的 remote-imageNode／remote-videoNode）尺寸由内容比例决定、宽高都变（实测：4:3 图 338×330、9:16 视频 198×392），网格列距与行距都必须大于实测尺寸上限；后台无头通道里离屏图片不渲染、量到的是统一占位尺寸（220×174／220×152），不能据此判无重叠，须以视口内实测或内容比例推算为准。

节点在创建当下起正式名，不留「图片 N」「视频 N」默认名。视频段用段号前缀（如 `W14 礼盒亮相及活动口播`），分镜图用「分镜图·段号-镜号 拍点」，素材按类型前缀（人物·／场景·／物品·／产品·）。各案例画布的分区原点与当前状态记在各业务项目的交付记录里，不在本文件复述。

## 批量修改节点

成批改名、移动及已获准的无生成记录节点清理，沿工作区的 `画布1.json` 执行。用 `RedframeWorkspace.write_canvas(写前原图, 仅含本批变更的画布)`，适配器在真实持久画布与写前原图一致时保存一次，并保护视频生成记录。移除节点前先备份整张画布，并核对保留节点的图边和正文引用。按明确节点 ID 核写前差异，写后立即在同一后台 Edge 会话刷新，核受影响节点和未修改节点的数量、原生连线、正文及媒体。用户自己的浏览器若开着同一画布，其操作可能回写旧状态，大批量改动前知会、改完提醒刷新。

重建视频节点时用「视频」菜单创建新节点，把旧段及成片留在历史区域。用户明确授权移除具体旧视频节点时，再读取旧节点的 `videoTask`、`outputs`、`draft` 与 `draftHistory`，沿现有交付记录保全任务身份和需保留的媒体。成片须落盘并能读出后才移除对应节点。另有结果未知的任务先沿原节点查清。实际移除按已授权的准确节点在平台操作，再刷新核保留范围。常规批量存档入口保护视频节点及其生成记录，带生成记录的节点仍可改名、移动。

工作区读写使用 `GET /api/workspaces/files/read` 和带 `x-toonflow-workspace: 1` 与 `Content-Type: application/octet-stream` 的 `PUT /api/workspaces/files/write?exclusive=false`。上传文件仍用[素材区上传](#素材区上传)。存档接口对 `assets/` 路径返回 404（2026-11-16 实测）。

## 写实人脸认证

拟认证的源图在资产制作时按[人物板导出尺寸](../../asset-image-assistant/references/02-character-master-guide.md#人物板导出尺寸)核对像素边长与宽高比。

上传前实看本批有序视觉参考。遇首个写实人脸槽，先只读定位实际画布、模型、参考模式和目标输入槽，核认证由哪个节点携带。红帧 Seedance 2.5 的已验证图片路径是认证源卡 `image → in`。在同画布、同模型与参考模式下，同媒体类型和同槽位能力复用首次核得的路径，同一原件可复用仍有效的认证卡。更换原件时核该卡的字节和认证，目标、模型、参考模式、媒体类型或槽能力变化时重核路径。缺证据时暂缓受影响槽，继续独立范围。按[上传前计划](../../_shared/redframe-operations.md#新建直传计划和回读)冻结槽位，再开始上传或接线。

1. 产品包的图片和视频同样可以使用平台的人脸认证。核对源卡对应的原件版本和字节，在浏览器中确认卡片显示「人脸已认证」，并回读源节点的 `data.faceCertification`。更换原件后重新核验。
2. 图片认证使用源卡 `image` 输出接入视频节点 `in`。视频认证沿本轮实际核实的源输出和目标输入接线。将正文中的原生 `@` 绑定到同一源卡。有对应直传副本时替换该副本，核对该段其他素材的顺序及绑定。图片生成按[生图接线](../../_shared/redframe-operations.md#生图)接认证卡。
3. 按[既有连线草稿](../../_shared/redframe-operations.md#既有连线草稿)保存并回读源卡认证、源节点与端口、目标槽、素材字节及正文原生引用。核对同一张图在该段只占实际需要的槽。交付草稿到保存与核对为止。已有生成报错时先查原任务，再按实际授权处理重试。

机场开场 V01 的 Seedance 2.5 试跑中，原直传提交返回缺真人认证。直传槽 `localReferences` 保存地址和类型，认证保存在源卡上。复用同图的已认证源卡，以 `image → in` 和指向该卡的原生引用提交后成功得到 6.08 秒视频。认证后的直传尚未单独试跑。

## 单会话与异常

同一画布只允许单个会话写入，多会话并行会互相覆盖已建节点。画布卡住、保存报错或生成结果不明时，按[卡住或报错先刷新](redframe-canvas-layout.md#卡住或报错先刷新)核对原节点和原任务。

## 视频节点时长

视频节点的时长在生成面板用**拖动轨道**设置，不是只能选固定档位；4/8/13/17/21/26/30 秒等只是轨道上的快捷档或显示值。按稿内准确秒数拖动轨道后，以节点原生持久化字段回读核验，不能把 6/7/9 秒四舍五入成固定档。（2026-11-21 用户更正）
