# 提示词正文、生产约束与模型负面通道硬规则

本规则适用于当前 `asset-image-assistant`、`storyboard-director` 与 `voiceover-to-video-script`；`storyboard-preview`、`storyboard-formal`、`video-plan` 仅为历史名称。目标不是删除所有否定表达，而是把不同职责放回正确通道，避免通用负面词包污染正文或误伤必要控制。

## 一、三通道职责

1. **内容与动作正文**：优先写模型应当生成的可见结果。主体、状态、动作、空间、表情、材质、光线、摄影机和声音均使用肯定、具体、可观察的描述。
2. **生产约束**：只写本镜真实风险、用户明确要求、安全合规、产品准确性、声音边界或交付可用性。不得把同一组“无文字、无水印、无 UI、无畸形手、无风格漂移”无条件复制到每个镜头。
3. **模型专用负面通道**：仅当当前工具和具体模型实际提供 Negative Prompt 或等价独立字段时使用。负面通道中的内容不重复塞入正文；模型不支持独立通道时，必要排除项放在正文末尾的“专项排除约束”，并保持少而具体。

## 二、正向优先规则

- 抽象词必须落成可见证据：不用“高级感、电影感、松弛感”独立承担控制，改写为光线、色彩、材质、构图、空间、动作和表情。
- 正文中的“不要 X”优先改写为目标状态。例如“不要夸张表情”改为“嘴唇自然闭合，眼神放松，面部肌肉只有轻微变化”。
- 时序、运镜和声音不得为了避开否定词而变模糊。“全段不切镜”“禁止背景音乐”等若承担明确生产职责，可以保留。
- 参考图、导演预演或产品实拍与目标冲突时，先修输入或调度，不用更长的排除词包压制源冲突。

## 三、允许保留排除项的条件

满足任一条件即可保留，但必须能说明对应风险：

- 用户明确要求成片不出现某元素；
- 安全、合规、品牌、产品用法或产品外观红线；
- 声音策略，如禁止 BGM、歌曲、随机旁白，或避免“禁止人声”误伤角色对白；
- 当前镜头已知的模型失败模式，如随机字幕、额外人物、重复肢体、错误 UI；
- 当前工具提供独立负面字段，且该具体模型确实支持该字段。

没有真实风险时不写专项排除项；文档字段可以记录“无额外排除约束”，但这句话不复制进提交给模型的提示词。

## 四、模型能力边界

- 模型能力优先于通用模板。调用前以实时 CLI 帮助或官方模型文档确认是否存在独立负面字段。
- 2026-08-26 的 `dreamina multimodal2video -h` 仅提供单一 `--prompt`，没有独立 Negative Prompt 参数；Seedance 视频的必要排除项因此属于正文末尾的生产约束，不得假装存在独立通道。
- Google Imagen 官方文档显示，部分旧版 Imagen 支持独立 `negativePrompt`，后续模型可能不再支持；这证明负面通道必须按模型分支处理，不能写成全项目固定能力。
- Diffusers 等 CFG 管线的 `negative_prompt` 是独立条件输入，与自然语言正文中的“不要 X”不是同一机制。

## 五、交付与检查

- 图片：每镜正文正向描述；反向提示词可选。存在时只含本镜真实风险，并记录风险依据和实际使用通道。
- 视频：提交正文只写本段可生成的声画和必要专项约束。内部完成条件、验收清单、对白/镜头/资产编号、本地路径及与其他任务比较的说明留在正文外的制作备注；不能把整份工作文档上传。动作先后、对白归属、连续运镜和结束状态仍用具体声画描述保留，不因隔离内部说明而删掉必要控制。不得默认补齐固定六项负面词包。
- 自动检查只阻断已知旧通用词包、跨段复制和缺少模型能力分支，不按“不要/禁止/无”的简单数量判断质量。
- 真实效果必须通过同模型、同素材、同参数的 A/B 生成验证；未验证前不得把“token 会把每个词当独立视觉任务”写成已证实机制。

## 六、来源与限制

- Google Cloud Imagen 官方负面提示词说明：`https://docs.cloud.google.com/vertex-ai/generative-ai/docs/image/omit-content-using-a-negative-prompt`
- Dreamina Seedance 2.5 官方负面提示词指南：`https://dreamina.capcut.com/seedance/seedance-2-5-negative-prompts`
- Hugging Face Diffusers 官方 API：`negative_prompt` 只在相应 guidance 管线中生效。
- 本规则确认的是生产写法和模型能力分支；“提示词污染”的 token 机制解释仍属于教学性简化，尚未被本项目实测证明。
