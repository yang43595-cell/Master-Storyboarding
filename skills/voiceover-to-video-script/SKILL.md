# 视频提示词与生成

开始本职任务前读取[共用三层规范](../_shared/skill-layers.md)。本 Skill 适用边界：承接准确导演稿、对白和真实素材，直接读取本职视频方法及模板；不恢复 prepare，不改导演镜头，上传与生成仍依授权。

遵守 [项目规则](../../PROJECT_RULES.md)。直接读取原始资料，读取复用与回传按[共享读取开销规则](../_shared/knowledge-access.md#读取与执行开销)执行；不采用其中准备包、阅读登记或计量门禁。不建立准备包、任务索引、阅读凭据或审核包，新轮实质创作先按项目干净上下文规则交全新专属生产执行者，同轮返修续用；本轮执行者不递归派生产子 agent，也不自动派独立审核者；用户明确要求独立审核时，按 [审核方法](../stage-reviewer/modules/review-method.md#视频提示词的直接审核分支) 交当前准确候选与来源，不恢复旧包。旧逐块任务和编码格式已退役，不恢复旧进度链；历史产物不修改。

## 执行顺序与停止点

压缩或会话恢复后，先按 [主动恢复核对](../_shared/knowledge-access.md#压缩后的主动恢复核对)逐项核本轮状态、可选分支与 9:16、平台参数及采用路径；未核范围明确保留，不等用户追问。本 Skill 继续直接读取，不建 prepare 或阅读凭据。

先按[网站审核到画布的统一入口](../../PROJECT_RULES.md#网站审核到画布的统一入口)确定采用分支：统一入口逐段自查后继续并完成全片检查，不送网站、不停等逐段人审，保存并核对指定画布草稿后停止。只有未采用统一入口的兼容路径才逐段等用户确认，取得准确整稿确认后沿人审采用入口交接。正式采用或下游消费前核[接线现状](../../docs/development/review-to-canvas-entry.md#接线现状与开发交接)，缺项保持候选，不补造通过。

再按实际任务选择步骤；同一请求可以在授权范围内组合操作，不为查询或下载先重走创作流程。

| 本轮任务 | 执行范围与读取 |
| --- | --- |
| 写／改提示词 | 执行步骤 1–3，读取下节本轮来源及适用方法；候选不要求先上传或生成 |
| 保存／更新画布草稿 | 执行步骤 4，使用准确现稿；写入前必读[画布紧凑排版](references/seedance-delivery-package.md#画布紧凑排版)和对应平台交付要求。只有本轮同时要求改稿时才进入步骤 1–3 |
| 生成新视频 | 按实际入口执行必要提交检查及步骤 5，读取平台合同、交付说明和执行说明；生成仍须另有覆盖本次范围的明确授权 |
| 查询／下载已有任务 | 直接执行步骤 5，读执行说明的查询下载部分、真实任务 ID、原提交记录与结果；不重写提示词、不重新选择模型、不重做全片创作审查 |

本轮操作红帧时，另读[红帧操作](../_shared/redframe-operations.md#视频画布)，按其中的连接与登录入口执行。

1. 仅写／改稿时：记录准确来源修订、创作段落与停止点，按下节读取来源、方法和前序素材检查结论，运行适用的 `knowledge_runtime` / `product_refs` 检查。真实缺料阻止相关正式产出；经明确授权的试写只交带缺口候选。
2. 仅写／改稿时：按原镜头理解完整连续事件，在同一 JSON 写完整的本轮创作段落。分段时先对照导演的持久状态及其镜号范围，检查拟用素材是否覆盖各段，尤其是段内跨状态、沿用变化前底图、参考只覆盖部分镜号三种情况。段内控制依赖尚未核实的平台能力时，在现有稿件未决项写清影响范围，再决定是否补状态图、在真实动作边界重划分段或保留审阅稿；已核实且适用的段继续。交付前运行 `generation_boundaries`，按[内容合规审查](modules/video-method.md#提示词内容合规审查)与[动作链自查](modules/video-method.md#自查与修改)核正文及跨段依赖，记录实际范围和修复依据。源分段检查和平台状态覆盖检查分别记录。
3. 交付本轮准确 JSON 及完成范围，按上文采用分支推进。全部段落写完后另做全片覆盖、节奏和接续复核；正式采用按下文“自查记录与正式采用”执行，不直改确认或 manifest。

运行 `python -m scripts.core.generation_boundaries --project <项目> --prompt <视频稿> --storyboard <导演稿>` 时，`scene_state_plan.segments` 只列导演已声明持久状态的段。逐段处理 `needs_review`，顶层 `ok` 仍表示源分段校验通过。计划覆盖结论用于写前定位，不能代替实看或画布原生回读。
4. 仅本轮获准平台操作时，按[素材与提交交付](references/seedance-delivery-package.md)核引用和版本、完成写前内容审查，写入并整理画布。新建、复制或局部更新都要验收布局。保存后刷新，回读原生字段，并在正常审阅缩放下按[画布紧凑排版](references/seedance-delivery-package.md#画布紧凑排版)复核布局，查看全景和关键细节截图。有排版缺口先修正再交付。记录准确目标、节点、实际保存范围与缺口。统一入口完成草稿交付即停止，另行获准生成才进入下一步。
5. 仅本轮获准生成、查询或下载时，按实际入口操作并保留真实任务 ID、提交参数、结果与输出路径；结果未知先查原任务。授权包含接缝验证时，按[关键接缝试剪](references/video-qc-checklist.md#关键接缝试剪)从风险最高的相邻段起步。交付媒体前检查实际落盘文件及 `ffprobe` 结果，未落盘或技术检查失败先处理，不能以平台成功替代文件通过。明确要求结果内容质检时再实际看/听，按[质检清单](references/video-qc-checklist.md)记录范围、问题时窗与结论；普通下载不自动扩成全片内容验收。
6. 收尾按本轮实际交付对象分别说明：提示词自查、平台保存/提交、媒体技术检查、已授权的听看质检和用户采用。未执行、阻塞、不适用分别说明；修订、重新提交或媒体换版后只复核受影响项与直接依赖，不能把文字修好说成旧任务输入或旧成片已修好。完成本 Skill 后停止，不自动进入下阶段。

## 输入与读取

本节适用于写／改提示词；其他操作按入口表读取其直接依据，任务查询不因历史稿未重新审查而被要求重写。

导演稿和资产图确认后的默认前序是 `storyboard-director` 的按需分镜图检查：先读取本轮复用结论及已确认补图，再编写视频提示词。无需补图可直接使用现有素材；已决定补图但尚未确认的相关镜头先完成前序，不把首次动作、表情与空间控制检查推迟到本阶段。此处核对已有结论，不调用其他 Skill，也不要求每镜都有分镜图。

存在 `分镜图选择记录.md` 时同时读取其中的共用状态和适用镜头。每段按其涉及镜头引用已确认的场景关系图，保留位置关系与画外人物位置，说明本段明确变化；不把参考展示视角或画面左右当作固定机位。超出适用状态时按前序选择记录处理，不能把“已选择补图”当作“图片已确认”。

核对范围、导演包及其叙事包的准确版本、最终对白和所用素材。写改提示词及保存画布时，从项目需求的 `kickoff.canvas` 读取平台、模型、画幅、分辨率和目标画布，可用 `python scripts/stage_context_cli.py kickoff --project <业务项目>` 只读核对。范围未变时沿用开工决定。正式产出使用已确认来源；仅在用户明确授权试写时使用候选来源并标出阻塞，不能据此提交生成。

先读[视频方法](modules/video-method.md)、[语言规范](references/prompt-language-hard-rules.md)及相关原始资料。候选返修遵守[未确认稿生命周期](../_shared/draft-lifecycle.md)；使用图片控制开场与衔接时读取[图片连续性](../storyboard-director/references/image-continuity-hard-rules.md)，涉及灯光表达时读取[灯光提示词规范](../storyboard-planner/references/lighting-prompt-standard.md)的适用小节。涉及真实外观时实际查看本段选中的确认输出，不从文件名推断；已核验且用途未变的图片复用既有结论，只在新用途、版本变化或结论不足时补看。声音参考仅在用户明确提出或选用时读取，按[项目可选边界](../../docs/rules/visual-production.md#导演稿之后的生产顺序)处理；视觉补充只在使用时读取。Blender、白模和正式分镜图不是必需输入。

已在开工选择本地产品参考包时，通过同一 `kickoff --project` 输出读取 `product_reference_pack`，把本段所选包内文件作为实际输入。按[产品参考对接](../_shared/product-usage-contract.md#广告中的产品展示与使用)核参考职责和缺口。

专项方法按 [knowledge-profile.json](knowledge-profile.json) 的 `direct_read_when` 和明确路径直接读取。知识根固定为本仓库 `knowledge/runtime/`，先运行 `python -m scripts.core.knowledge_runtime` 核验所选文件与字节，再读取本 Skill 适用的内置方法和第三层资料。业务原片、产品实物和动作素材按本轮已核实的来源读取。基础和素材职责方法用于匹配任务；Seedance 2.5 方法仅在选择该模型时读；产品专项方法只在本轮已确认准确产品且有对应展示或真实使用时按 profile 读取。缺失或状态冲突报告具体缺口，不以模板替代，不全库搜索或复制方法正文。同任务同版本已读内容复用；长资料按自然章节补读，不生成事件包。

本轮登记了适用历史案例时，按当前输入范围使用其原件，区分已核实事实、推断与待验证处理。放大或缩小的通用核对沿下文比例来源执行。

在开始写本轮提示词前，先按上述明确路径列出本轮适用方法、真实产品资料与实际动作参考，使用现有只读入口逐项检查：`python -m scripts.core.product_refs --project <项目> --input-root <本仓库knowledge/runtime的绝对路径> --input-root <实际产品参考根> --discover-dependencies --require-file <本轮上游或交付JSON> --require-file <准确方法文件> [--require-file <准确文件> ...]`。项目内文件用项目相对路径；外置文件用绝对路径并显式允许其实际根目录，不以磁盘根目录放宽范围。缺文件、空文件或越界先停止受影响产出，恢复真实来源后重跑；未适用的方法、未选用的声音等不加入清单。这里不新增清单文件、不重启 prepare；检查从所选 JSON 递归发现已支持的结构化文件引用和 manifest 依赖，报告实际覆盖、缺失/越界及无法本地检查的远端引用；自动补查未手列的这些依赖。它不推断任意自然语言缺料、不解析 Markdown 链接、不证明内容/版本正确、已阅读或已确认；未编码的适用方法与业务必要性仍按上述原始资料判断，后续准确修订与 hash 检查仍须执行。

持续可见场景已因剧情改变时，按[剧情后的场景状态参考](../storyboard-director/references/image-continuity-hard-rules.md#剧情后的场景状态参考)读取准确新态图及适用镜号；通过 `source_shots` 覆盖段内所有镜头，正文与真实有序引用一起切到新态。缺图、失败、未核或错范围只可列待制作／待审文字候选，阻止相关提交；不靠旧空场景图加一句“保持”放行，也不将普通走位或切镜变为补图任务。

## 创作、自查与交付

按原镜头顺序理解连续事件，再决定生成分段；普通切镜不是独立生成的理由。按[逐场创作与确认](../../docs/rules/execution.md#逐场创作与全片复核)完成当前创作段落，由本轮专属生产执行者自查并直接修改，不模拟生产/审核角色。普通写稿不要求问题 ID、逐块登记或另建机器报告；正式采用所需报告见下文，不据此省略。

默认在完整导演包确认、全片复核及前序素材检查完成后，按创作段落逐段完善同一 JSON 业务稿，采用[正文模板与交付结构](templates/video-script-template.md)。内置绑定方法提供知识与约束，本地模板负责组织方式，不改写其原文；没有真实素材时省略素材区。每个创作段落可含多个生成片段，推进按入口已选分支执行。沿用同一稿件及确认记录，标明范围与完成情况；用户明确要求整稿交付时可一次完成。局部返修只改相关段与直接影响，已确认稿另存新版本。对白直接使用原文，不编码、不另抄登记表。按项目 JSON 唯一业务源规则保存完整来源、范围、分段正文、参数、素材职责与真实未决事项；Markdown 仅按需导出，不维护同义稿、逐段副本、CSV 或退役 production_plan。

交付前检查当前范围及跨段依赖，全部完成后另做全片复核。按[视频方法](modules/video-method.md#自查与修改)核来源动作、对白、时间范围的完整唯一覆盖、说话者、时长、素材与接续；未生成时检查文字安排是否漏写／重播，只有实际听核后才报告播放结果。

### 自查记录与正式采用

普通写稿把实际范围、正文位置、检查结果、修复依据和未决事项简记在同一业务 JSON。统一入口正式采用时，另按既有[本地流程授权与自主采用](../../docs/development/review-to-canvas-entry.md#本地流程授权与自主采用)整理一份绑定准确稿件／上游／检查 profile 字节的结构化自查报告，业务稿不重复抄整份报告；报告不放进被绑定正文中填自身 hash，自查也不等于人审或生成效果验证。

- 统一入口：完整稿及全片复核通过后登记准确候选和上述报告；首次采用用 `accept-artifact`，已有正式版本返修走该页自主修订入口。
- 兼容人审：准确整稿经用户确认后按项目规则首次 `adopt-package`；已有正式版本仍走修订控制，不用它覆盖旧稿。

缺授权、仍有未决或验收失效时保持候选；不得冒用 `adopt-package` 的人审字段。采用不上传、不生成、不发布，也不选择渠道。

内容审查的触发与同稿结论复用统一见[提示词内容合规审查](modules/video-method.md#提示词内容合规审查)；写入前仍核当前版本、引用和目标，写后回读单独报告。叠加文字与实物／屏内文字按[对白与时长](modules/video-method.md#对白与时长)处理，模板保留每段必要约束。小云雀参数按[平台合同](references/seedance-platform-contract.md#小云雀网页写入选择2026-10-23-用户要求)执行，不套用其他平台。

关键摄影决定的按需转写与精简检查见[视频方法](modules/video-method.md#正文与素材)：保留影响拍法的信息，常规细节留给模型，不以逐镜参数齐全作为验收目标。

连续事件因时长拆段时，执行[具体切点参考](../storyboard-director/references/image-continuity-hard-rules.md#连续事件因时长拆段时的实际衔接参考)：前段尾态/后段动作前态绑定可核验的共用图或同状态参考组，缺图/缺确认则阻止相关提交。返工导致切点参考换版，后一段旧绑定也须重查。记录留在现有选择记录和本修订 JSON，不新建逐段计划。

剧情涉及放大/缩小时，按[比例来源](../storyboard-director/references/reference-asset-contract.md#放大缩小剧情的比例来源与适用范围)核对唯一的剧情尺寸状态与适用图。每个有关生成段都须实际上传含正常尺度参照的适用确认图；人物板仅管身份/服饰，不能重置角色对世界的比例。缺图、越界复用或跨段比例冲突先处理真实缺口，不把多写“微缩”当作修复。已取消补图不机械重开，能复用则先核对新增用途范围。

## 按需执行

本轮明确选用声音参考时，按[声音用途与现代稿引用](../voice-reference-manager/modules/voice-method.md#确定性命令与用途核对)核实际用途与确认范围，在同一 `video.prompt` JSON 保留 `audio_policy: voice_reference` 或准确 `voice_reference_manifest_path`，并使登记依赖可追溯到所用 `voice.character.<角色ID>`；沿导演/叙事的准确对白映射引用，不用自然语言说明替代机器可核的选择。未选用时不新增这些字段或声音前置。

- 确定分段与模型参数：按实际入口读[平台合同](references/seedance-platform-contract.md)：CLI 核当前帮助，小云雀网页核当前原生控件及允许输入，不把某个入口的历史参数套到另一个入口。
- 产品出镜：按已绑定的产品方法与本轮项目登记的商品资料、包装和动作参考核对，只写已确认的使用动作。需要商品 brief 时读项目内实际文件。
- 上传交付：读[素材与提交交付](references/seedance-delivery-package.md)。
- 用户要求生成、查询或下载：网页按实际平台和原提交入口操作；使用 CLI 时读[CLI 执行](references/seedance-cli-notes.md)，必要时保存 UTF-8 TXT，不依赖机器计划。

素材清单只放 `04_资产/当前资产清单.json` 里状态为“要出图”且有已确认母版图片的资产；被取消或被拆分的父项不放进素材、也不写进正文引用，无图人物或物件只写在镜内过程或动作文字里，保留外观描述、在场状态与对白归属，不虚造图片引用。候选逐项列选中的准确 output ID 和拟上传顺序；平台操作后核同一清单的实际上传与原生绑定，不把计划写成已执行。提交前用 `python -m scripts.core.asset_refs --project <项目> --require-final-image <AST-ID@OUTPUT-ID...>` 核对本段实际选择。已登记最终人物板的造型须选对应板。首尾帧模式按该平台槽位核对准确端点及其制作时实际采用的人物板，并由端点继承身份、服装和空间尺度。裸 `AST-ID` 只可做资产可用性检查，不能证明某个具体版本已核验；无图、输出不存在或已取消的项直接阻塞。
分镜补图与白模按准确ART-ID用同一入口 `--require-reference` 核对，补图同时传 `--for-shots <本次镜号...>` 并按[观察证据准入](../storyboard-director/references/image-evidence-admission.md)核对登记中的本用途观察；可与 `--require-final-image` 同次检查。文件/确认通过不等于切点状态正确，仍须实际看图并核对获准用途。旧ID失效时返回相应返工步骤，不按同名文件自动换新版。
