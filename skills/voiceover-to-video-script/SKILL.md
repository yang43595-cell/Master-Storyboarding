# 视频提示词与生成

开始本职任务前读取[共用三层规范](../_shared/skill-layers.md)。本 Skill 适用边界：承接准确导演稿、对白和真实素材，直接读取本职视频方法及模板；不恢复 prepare，不改导演镜头，上传与生成仍依授权。

遵守 [项目规则](../../PROJECT_RULES.md)。直接读取原始资料，读取复用与回传按[共享读取开销规则](../_shared/knowledge-access.md#读取与执行开销)执行；不采用其中准备包、阅读登记或计量门禁。不建立准备包、任务索引、阅读凭据或审核包，新轮实质创作先按项目干净上下文规则交全新专属生产执行者，同轮返修续用；本轮执行者不递归派生产子 agent，也不自动派独立审核者；用户明确要求独立审核时，按 [审核方法](../stage-reviewer/modules/review-method.md#视频提示词的直接审核分支) 交当前准确候选与来源，不恢复旧包。旧逐块任务和编码格式已退役，不恢复旧进度链；历史产物不修改。

## 输入与读取

导演稿和资产图确认后的默认前序是 `storyboard-director` 的按需分镜图检查：先读取本轮复用结论及已确认补图，再编写视频提示词。无需补图可直接使用现有素材；已决定补图但尚未确认的相关镜头先完成前序，不把首次动作、表情与空间控制检查推迟到本阶段。此处核对已有结论，不调用其他 Skill，也不要求每镜都有分镜图。

存在 `分镜图选择记录.md` 时同时读取其中的共用状态和适用镜头。每段按其涉及镜头引用已确认的场景关系图，保留位置关系与画外人物位置，说明本段明确变化；不把参考展示视角或画面左右当作固定机位。超出适用状态时按前序选择记录处理，不能把“已选择补图”当作“图片已确认”。

确认范围、导演包及其叙事包的准确版本、最终对白、所用素材和用户选择的模型/平台。已有明确选择在范围未变时复用，不让用户填写内部请求 JSON。正式产出使用已确认来源；仅在用户明确授权试写时使用候选来源并标出阻塞，不能据此提交生成。

先读[视频方法](modules/video-method.md)、[语言规范](references/prompt-language-hard-rules.md)及相关原始资料。候选返修遵守[未确认稿生命周期](../_shared/draft-lifecycle.md)；使用图片控制开场与衔接时读取[图片连续性](../storyboard-director/references/image-continuity-hard-rules.md)，涉及灯光表达时读取[灯光提示词规范](../storyboard-planner/references/lighting-prompt-standard.md)的适用小节。涉及真实外观时实际查看本段选中的确认输出，不从文件名推断；已核验且用途未变的图片复用既有结论，只在新用途、版本变化或结论不足时补看。声音参考仅在用户明确提出或选用时读取，按[项目可选边界](../../PROJECT_RULES.md#导演稿之后的生产顺序)处理；视觉补充只在使用时读取。Blender、白模和正式分镜图不是必需输入。

专项方法按 [knowledge-profile.json](knowledge-profile.json) 的 `direct_read_when` 和明确路径直接读取 Vault 原文，根使用本轮明确指定的 Vault；未指定时读取环境变量 `MSB_VAULT_ROOT`，再缺省为当前用户目录下的 `Documents/Obsidian Vault`。基础和素材职责方法用于匹配任务；Seedance 2.5 方法仅在选择该模型时读；造物者方法仅在对应产品且确有使用过程时读。缺失或状态冲突报告具体缺口，不以模板替代，不全库搜索或复制方法正文。同任务同版本已读内容复用；长资料按自然章节补读，不生成事件包。

经验只按 `knowledge-profile.json` 的 `conditional_experiences` / `direct_read_when` 触发条件定位经验索引并按需直读；未命中不加载，不加入专业方法必读包。区分已核实事实、推断与待验证处理，不把一次试验参数或未验证方案当通则；检索到经验也不等于本次素材已确认。

在开始写本轮提示词前，先按上述明确路径列出本轮适用方法、真实产品资料与实际动作参考，使用现有只读入口逐项检查：`python -m scripts.core.product_refs --project <项目> --input-root <本轮Vault根> --input-root <实际产品参考根> --discover-dependencies --require-file <本轮上游或交付JSON> --require-file <准确方法文件> [--require-file <准确文件> ...]`。项目内文件用项目相对路径；外置文件用绝对路径并显式允许其实际根目录，不以磁盘根目录放宽范围。缺文件、空文件或越界先停止受影响产出，恢复真实来源后重跑；未适用的方法、未选用的声音等不加入清单。这里不新增清单文件、不重启 prepare；检查从所选 JSON 递归发现已支持的结构化文件引用和 manifest 依赖，报告实际覆盖、缺失/越界及无法本地检查的远端引用；自动补查未手列的这些依赖。它不推断任意自然语言缺料、不解析 Markdown 链接、不证明内容/版本正确、已阅读或已确认；未编码的适用方法与业务必要性仍按上述原始资料判断，后续准确修订与 hash 检查仍须执行。

持续可见场景已因剧情改变时，按[剧情后的场景状态参考](../storyboard-director/references/image-continuity-hard-rules.md#剧情后的场景状态参考)读取准确新态图及适用镜号；通过 `source_shots` 覆盖段内所有镜头，正文与真实有序引用一起切到新态。缺图、失败、未核或错范围只可列待制作／待审文字候选，阻止相关提交；不靠旧空场景图加一句“保持”放行，也不将普通走位或切镜变为补图任务。

## 创作、自查与交付

按原镜头顺序理解连续事件，再决定生成分段；普通切镜不是独立生成的理由。按[逐场创作与确认](../../PROJECT_RULES.md#逐场创作与确认)完成当前创作段落，由本轮专属生产执行者自查并直接修改，不模拟生产/审核角色，不要求问题 ID、逐块登记或机器报告。

默认在完整导演包确认、全片复核及前序素材检查完成后，按创作段落逐段完善同一 JSON 业务稿，采用[正文模板与交付结构](templates/video-script-template.md)：按素材职责、公共条件、连续视听正文组织，模板中的八项只作完整性核对，不强制八标题或逐项顺序。外部绑定方法继续提供知识与约束，本地模板负责组织方式，不改写其原文；没有真实素材时省略素材区。当前创作段落确认后再写下一段；每个创作段落内部可包含多个生成片段。沿用同一稿件及确认记录，标明本轮范围与完成情况；全部段落完成后核对完整稿。用户明确要求整稿交付时可一次完成。局部返修只改相关段与直接影响，已确认稿另存新版本。对白直接使用原文，不编码、不另抄登记表。按项目 JSON 唯一业务源规则保存完整来源、范围、分段正文、参数、素材职责与真实未决事项；Markdown 仅按需导出，不再维护同义稿。不创建逐段副本、CSV 或退役 production_plan。

每轮交付前检查本轮范围及跨段依赖，全部完成后复核全片；核对原镜头顺序及来源动作、对白、时间范围的完整唯一覆盖（同镜连续子范围见视频方法）、对白文字与说话者、实际播放是否漏播/重复、时长能否容纳内容、素材引用与跨段状态。真实未决问题与自查结论简记在同一文档；自查不代表用户确认或生成效果验证。首次采用平台无关完整视频提示词 JSON 时，用户确认后按项目规则运行 `stage_context_cli.py adopt-package`；此操作不上传、不生成、不发布，也不选择渠道。

生成画面不生成字幕、片尾文字、说明字卡、时间描述等可叠加文字，全部交后期；原文和出现时机留同一 JSON 的制作备注，不进提交正文。秒数和切镜时间仅控制动作/剪辑，不渲染为文字。真实包装和商标仍按参考保真，不擅自去字。小云雀新写入草稿显式选择 480p 并读回确认，不沿用 720p，不改用户时长；详见模板和平台合同。

每轮交付及画布写入前，必须先通过[提示词内容合规审查](modules/video-method.md#提示词内容合规审查)，未审或未修复不得写入；同次自查执行[动作链自查](modules/video-method.md#自查与修改)，技术版本与引用检查执行[素材与提交交付](references/seedance-delivery-package.md)的现有入口；两者分开说明结论，不以保存成功替代动作判断。

关键摄影决定的按需转写与精简检查见[视频方法](modules/video-method.md#正文与素材)：保留影响拍法的信息，常规细节留给模型，不以逐镜参数齐全作为验收目标。

连续事件因时长拆段时，执行[具体切点参考](../storyboard-director/references/image-continuity-hard-rules.md#连续事件因时长拆段时的实际衔接参考)：前段尾态/后段动作前态绑定可核验的共用图或同状态参考组，缺图/缺确认则阻止相关提交。返工导致切点参考换版，后一段旧绑定也须重查。记录留在现有选择记录和本修订 JSON，不新建逐段计划。

剧情涉及放大/缩小时，按[比例来源](../storyboard-director/references/reference-asset-contract.md#放大缩小剧情的比例来源与适用范围)核对唯一的剧情尺寸状态与适用图。每个有关生成段都须实际上传含正常尺度参照的适用确认图；人物板仅管身份/服饰，不能重置角色对世界的比例。缺图、越界复用或跨段比例冲突先处理真实缺口，不把多写“微缩”当作修复。已取消补图不机械重开，能复用则先核对新增用途范围。

## 按需执行

- 确定分段与模型参数：按实际入口读[平台合同](references/seedance-platform-contract.md)：CLI 核当前帮助，小云雀网页核当前原生控件及允许输入，不把某个入口的历史参数套到另一个入口。
- 产品出镜：读真实产品目录 PRODUCT_BRIEF.md 及其指向的参考清单，不新增上游没有的使用动作。
- 上传交付：读[素材与提交交付](references/seedance-delivery-package.md)。
- 用户要求生成、查询或下载：读[CLI 执行](references/seedance-cli-notes.md)，必要时保存 UTF-8 TXT，不依赖机器计划。
- 生成异常读[排错](references/troubleshooting.md)；明确要求内容质检时读[质检清单](references/video-qc-checklist.md)。

模型选择不等于上传、付费或提交授权；已有授权仅在原范围内有效，缺实质参数才询问。来源或授权冲突阻塞相关动作，不改对白、不猜素材、不改导演决定、不进入其他 Skill。

素材清单只放 `04_资产/当前资产清单.json` 里状态为“要出图”且有已确认母版图片的资产；被取消或被拆分的父项不放进素材、也不写进正文引用，无图人物或物件只写在镜内过程或动作文字里，保留外观描述、在场状态与对白归属，不虚造图片引用。素材清单逐项写实际上传的 output ID；提交前用 `python -m scripts.core.asset_refs --project <项目> --require-image <AST-ID@OUTPUT-ID...>` 核对。裸 `AST-ID` 只可做资产可用性检查，不能证明某个具体版本已核验；无图、输出不存在或已取消的项直接阻塞。
分镜补图与白模按准确ART-ID用同一入口 `--require-reference` 核对，补图同时传 `--for-shots <本次镜号...>` 并按[观察证据准入](../storyboard-director/references/image-evidence-admission.md)核对登记中的本用途观察；可与 `--require-image` 同次检查。文件/确认通过不等于切点状态正确，仍须实际看图并核对获准用途。旧ID失效时返回相应返工步骤，不按同名文件自动换新版。

涉及产品使用动作时，按 [产品使用参考对接](../_shared/product-usage-contract.md) 读取当前资产清单的 `product_usage` / `action_references`，只取本轮镜头实际对应的动作，缺口留空。不将参考视频冒充角色身份资产、已确认成片或现实约束对幻想剧情的改写。
