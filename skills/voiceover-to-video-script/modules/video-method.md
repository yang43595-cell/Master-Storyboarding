# 视频方法

## 承接已审定拍法

导演阶段的职责见 [导演 Skill](../../storyboard-planner/SKILL.md#承上启下的职责)。本阶段把按本轮入口有效审定的视听分镜转成所选模型适用的提示词，负责素材引用、生成分段与实现参数。生成分段可以不同于摄影镜头划分，但须保留已确认的观看顺序、动作与反应、声画关系、切点及连续状态。

原稿的拍法含糊、自相矛盾，或模型/素材限制使其无法忠实实现时，说明具体来源镜头、限制和受影响的导演决定，返回导演阶段修订；不自行删反应、换机位、改戏剧顺序或改变节奏意图。需要修改已确认拍法时，使用按本轮入口重新审定的准确导演修订后继续；统一入口由导演执行者自查，不把本阶段返修变为网站导演人审，正式采用仍受现有接线限制。

## 分段与依据

按场景、连续事件和原镜头顺序理解内容。同一事件、状态可衔接且所选模型一次能忠实承载时合为一段；景别变化或普通切镜不自动拆段。单镜独立成段须有独立事件或真实能力限制的理由，不默认全片一镜一段，也不为减少段数强行合并。来源动作、对白与时间范围按原顺序完整且恰好覆盖一次，不改变导演的机位、调度、切点与剧情。同一连续长镜头确受模型承载限制时，可由多个生成段分别承载连续子范围，在现有制作备注写清动作前后态和各段所含原文；同一来源镜号再次出现本身不算重复。不得为平台任务另造 Shot 或新增剪辑意图；无法保持拍法与接缝状态时返回导演。

先依据自然对白和必要动作估算待承载内容，按导演明确的同时关系扣除重叠；以所选模型当前单段时长上限判断是否需要拆分，上限从平台合同及提交前帮助核验，不在通用方法固定为30秒。预计不超过上限且能完整承载时，优先不拆；确有素材或执行限制需要提前拆分，说明具体限制，不以笼统的“更稳妥”为由切碎。

超过上限时，在本段可容纳的范围内，按以下优先级寻找原导演已有的边界；不为了等待高优先级边界超时，也不为了填满时长跨过合适的结束点：

| 优先级 | 分段边界 |
|---|---|
| 第一 | 场景或时空转换 |
| 第二 | 一个剧情事件完成，或明确的时间省略；仅换话题、换表情不自动构成事件结束 |
| 第三 | 一轮交流完成；容量不足时再选完整句末。问答、邀请与回应、讥讽与反应优先共同承载 |

每个候选边界都核对上一段结束状态、下一段开场状态及现有素材能否衔接，包括人物位置、站坐、持物和动作进度。优先保留取物、掉落、拾取等连续动作链；单条对白或连续动作本身超限、且没有可用边界时，明确返回所需拆分及其影响，由导演处理会改变拍法的部分，不删对白、不加速、不截断关键动作来凑时长。分段理由简记在现有段落说明，不另建分级表或审核阶段。

直接核对原始导演包、叙事包和实际素材，保留准确版本及确认事实。明确授权的试写可列缺口交候选，不能冒充正式确认。

### 现行生成段的只读检查

分段仍由本轮执行者按上面的方法判断，不运行固定秒数分组器。交付本轮候选前，用同一 JSON 与准确导演原稿运行 `python -m scripts.core.generation_boundaries --project <项目> --prompt <提示词JSON> --storyboard <导演JSON>`。缺依据的候选可以保留并明确阻塞，但不能把检查失败写成分段已核、正式采用或画布可提交。正式采用与画布 preflight 已调用同一检查；历史只读比较不改写旧稿，不恢复 production_plan。

每段沿用 `source_shot_ids` / `source_shots` 映射，场景取自导演，不按片段标题猜。相邻段的边界落在同一来源场景时，在后段现有 JSON 内记 `same_scene_split`：`from_segment_id`、`reason`、具体 `evidence`，以及 `source_boundary` 的准确 `shot_id`、`field`、`quote`。字段可定位动作、节奏、切点或对白（如 `audio.dialogue.0.text`），不得为了填字段改导演。

- `model_duration_exceeded`：填连续待承载内容的 `estimated_scene_duration_seconds` 与 `timing_basis`。沿用 `selected_video_model`，记录用户已选 `id`、`confirmed_by_user`、实际 `platform` / `entry_point` / `reference_mode`、本轮核实的 `max_duration_seconds`；`capability_evidence` 指向项目内保留的真实帮助/原生控件取证文件，写 `path` / `sha256` / `locator` / `checked_at`。两侧模型与参考模式均须匹配该能力依据；每段自己的生成时长字段须与该段参数相符，且各自不超过已核上限，不要求前后两段等长。未知能力不得填经验值。
- `execution_limit`：限有具体素材或执行限制，`limitation_evidence` 用同样四字段定位真实证据，不以“更稳妥”代替限制。它不豁免当前入口的模型/参数检查。
- `event_complete` / `time_ellipsis`：仅限导演原文已有的完整事件或明确时间省略，不把普通切镜、话题变化或同镜对白中途当成新事件。程序只核原文定位，不判定语义成立。

前两类连续事件拆段同时记录后段 `continuity.previous_segment_id` 及 `boundary` 的 `state_id`、具体 `description`、`previous_sha256s` / `current_sha256s`。所列图必须真实进入两侧 `materials` / `candidate_upload_order`，标同一 `state_id` 和 `state_reference` 职责；已核严格控制时也可分别使用 `end_frame` / `start_frame`。这只是准确尾态/动作前态引用，不声称多参考就是硬首尾帧控制。合格旧图可复用，同状态不同机位图仍走现有组别与视觉核验；基础环境图、人物身份图不能仅因复用就算切点。画布检查还核这些源图确在本次 `reference_checks` 中，原生字节、实际图片、用途确认与状态组继续按既有门禁验收。

先按导演动作和切点判断哪些状态实际继承。普通跨场硬切在正文或现有接续备注交代仍需保持的穿搭、随身物等，新场自行建立站位和空间。带调度设定（`space_rules`）的同场接续仍须在后段写 `physical_continuity`。跨场若继续同一动作、继承关键物理状态有风险或已有漂移，也在后段用同一字段登记。用 `from_segment_id`、`permitted_change` 定前驱和允许的变化，从 `positions`（人与锚点及彼此位置）、`props`（持物组合、持有人与落点）、`visibility`（关键物件或服装的可见状态）中只写实际继承的项，每项写 `previous_state`、`current_state`、`basis`。例如等待后湿擦只核必须接上的膜态、人物姿态和仍在场的相关物件，已重置或与动作无关的项省略。

有高风险继承或已见漂移时用 `status: visual_reference`，逐侧填写 `previous_sha256s`／`current_sha256s` 和对应 `previous_observation`／`current_observation`，把实际图和准确镜号绑入两侧素材清单及交付 `reference_checks`，在引用 `physical_scope` 标明该图实看能承担的项。标为 `end_frame` 的图承担前段落幅，标为 `start_frame` 的图承担后段起幅。确实可跨侧使用的图按实际范围登记状态、布局或外观职责。可靠实拍、既有参考或动作已足以说明相应状态且无需图像证据时，写依据并标 `no_visual_needed`。同场换话题或省略时间后仍继承的项继续核对。图中没有演员，不能用于证明座次。单品白底图不能证明在手的袋盒组合。未看见的服装内状态不写为可见。先看相邻两侧成片，再采用合格实际尾帧。

检查通过只说明所填来源、能力证据字节和引用职责一致，不证明证据内容正确/仍适用、估时真实、图片已确认、视觉接缝合格或用户批准。未知项不猜填；同一镜号跨段的连续子范围仍可保留，完整动作、对白与时间覆盖继续按现行自查及音频来源检查执行。未拆段的中立稿不因此强制选择模型，不自动生成或修改素材。

实际交付的模型、参考模式和生成时长须逐段匹配准确源稿及已核上限，不让自填时长范围覆盖能力。只交付后段时保留真实前驱，按[交付快照检查](../../../docs/development/delivery-snapshot-checks.md)引用已有准确前次节点证据；不删除前驱另起事件、不重传前段或补造批准。

## 正文与素材

入口负责读取与执行顺序，现行模板负责正文组织，适用知识参考负责具体判断。历史案例专用脚本（例如旧 build_case2_prompts.py）不是通用转写入口；不得将 framing/movement 的选择性拼接当成完整继承。局部试写的成功也不自动确认模板能覆盖全片。

按已绑定且实际适用的知识库方法创作，不复制第二套专业方法正文。正文组织取[现行模板](../templates/video-script-template.md)，八项只用于完整性核对。提示词写模型应当看见、听见的动作、镜头与状态变化，不用内部路径、镜号或“见导演包”代替。候选按拟上传顺序列准确文件，平台操作后核对实际有序引用；同一素材明确一个主要职责，可附带相容用途并合写一处，只有串用风险或继承边界不清时补充说明，不为形式强拆素材或重复解释。冲突状态不可混用，血缘来源不自动进入上传集合，正文引用与清单一致，不要求上传整个素材库。

按[语言规范](../references/prompt-language-hard-rules.md#五交付与检查)隔离提交正文与制作备注。自然切换地点和承接同段上一镜的描述可以保留；不能用“另一地点”等词本身判断污染。可用 `python scripts/check_video_prompt_focal_intent.py <本轮提示词JSON或按需MD或提交TXT>` 检查定性焦段及已知内部说明泄漏；它只核对已识别的提交正文，不要求为了检查另导出 Markdown；0段或正文缺失不通过，不替代空间、动作和素材用途判断，也不构成新的准备包门禁。

素材可用与用途匹配分别判断：核对本段需要的身份、年龄状态、服装、空间、产品外观或动作是否在各参考的获准职责内。涉及人物面容替换或年龄版本时，沿用[资产方法的对应检查](../../asset-image-assistant/modules/asset-method.md#身份替换与年龄版本)，不把路径和确认状态通过写成年龄效果已验证。

同一场既要交代人物和物件的位置，又要让观众读清真实包装时，分别检查关系镜和产品镜能否承担各自任务。若广角分镜只能核对位置和尺寸，不能拿其中重绘的盒面当真品依据。可在关系镜用取景或有动机的遮挡只交代物件状态，把可读包装交给有真实来源的独立镜头；采用原件像素做后期插镜时，在制作备注保留准确来源、时机及声音衔接，生成正文只写该时刻实际要生成的画面。遮挡前后仍须能解释同一件东西在哪里、谁拿着、何时放下。

同一人物换服装参考或换生成段，不等于发型、衣袖、妆面和持物自动重置。对实际会影响接续的状态，核对来源与相邻段：哪些持续、哪些有动作改变、哪张图只负责局部外观。来源图一致但成片漂移时，先记录为执行偏离，不反推成“参考图冲突”；必要时把已有的持续状态明确写出，不补绑发、收手机等新动作来解释错误。用户已明确自行调整的时长或其他选择以其当前决定为准，不作为待修缺陷，也不据此推断其余偏差的原因。

转写时按镜头的表达任务保留关键摄影决定，如机位关系、运镜、落幅和焦段。**当有依据的光学选择影响本段观看效果时，提交正文保留定性焦段倾向（广角、标准或中长焦；段内切镜可分别说明）及其可观察光学目的；二维图形等无摄影光学需要的内容可省略，不补无依据占位句**，例如用广角保留空间纵深、用标准焦段保持人物关系自然、用中长焦压缩背景并把人物或物件从环境中分离。这是对适用光学决定的转写，不把未知设备参数伪装成控制；精确焦距只在导演包或可核验拍摄证据已经给出时照原值写入，不能从景别、机位或经验推测毫米数。景深和背景层次仍按实际需要简短说明，不逐镜填参数表。上游明确的清晰对象、景深层次、转焦起止及触发、光线变化、运镜起幅路径落幅、段内切点和声音表演必须随连续正文保留；焦段不替代焦点，参考职责也不替代动态过程。精简只去重复与无关信息，不能删已有摄影决定。参考图已说明的环境与位置通过职责引用，正文着重当前状态和变化；必要的素材读取方式直接进入提交正文。

声音、灯光、产品及必要排除项服务当前内容，不逐段复制通用词包。对白、环境声与后期配音职责明确；后期对白不要再要求模型同时生成同一句人声。

对伴随状态的转写按[完整镜头的同刻状态](../../_shared/prompt-language.md#完整镜头的同刻状态转译)：来源明写、未变前态继承以及已有结果所需的朝向/观看/接触可以落实；不得借“更自然”新加动机、情绪转折、离场或抓放物。前态继承不属于新增剧情，场景 overrides 的局部性也不重置持物、支撑或站坐状态。该范围说明适用于本 Skill 对绑定方法的理解，不改写知识库发布正文。

## 对白与时长

ON_SCREEN_TEXT 沿用导演的无声画面文字决定，但字幕、片头/片尾文字、说明字卡、时间描述及其他可叠加文字全部交后期：在同一 JSON 的既有制作备注中逐字、按序保留原 DLG 内容、take/rhythm 的显示时机和阅读停留，禁止将这些文字或显示指令放入生成正文。它们不是角色对白、旁白、配音或口型任务；speaker_id 仅作上游归属，不计入有声语速。模型只生成承载后期的底画面，必要的构图留白与动作可保留；不因此删除上游文字、改剧情或改用户时长。

每个生成段正文明确不生成可叠加文字；正文中的秒数、区间与切镜时间仅为动作/剪辑指令，不能渲染为字幕、时间码、倒计时或说明字卡。真实参考中的包装、商标、道具和场景实物固有字样不属于后期叠加文字，不擅自抹字、换字或改造品牌。剧情内手机、电脑等实体屏幕按已有来源和已定执行方案呈现内容，不因含字就一概转后期；“手机屏幕显示通话中”与画外浮现说明字卡分别判断，泛称“屏幕显示”本身不能证明是剧情内实物。真实外观继续按参考保真，冲突先说明，不以“无字”重造产品。

逐字保留最终对白和说话者。跨镜头一句对白可连续播放，不因切镜重复整句；确需跨生成段拆句时保留原文顺序和衔接。反应镜头提及某句话不表示重播。不填写槽位、字符位置或另一份对白登记表。

用户明确自行改过台词时，以其当前修改为准；与旧叙事包不同只用于定位变化，不能自动恢复旧句。核对说话人、漏播/重复及直接关联的小字，记录采用事实但不覆盖已确认上游。改词或改序后，同时核对受影响段的观看承诺：当前画面是否仍表现新句让观众期待的行动、信息或关系，前后动作状态及素材职责是否仍适用；不能只换文字便沿用原拍法。只检查变化及实际依赖，需要改变已确认拍法时返回导演修订；未变化范围不重复确认。

生成时长与目标剪辑时长分别说明。按自然语速和实际动作估时，不套字数公式，不强制五项分解。连续对白用时不能只取最长一句；只有导演依据支持同时发生时才扣除重叠，复杂情况用一句话解释。实测音频与估算区分。时长不足应合理分段或报告上游缺口，不删台词、不加速塞入、不低报时长。

## 提示词内容合规审查

每轮提示词交付、画布新写入或替换前，生产执行者须对准确提交正文及有序素材引用完成以下审查；仅查询／下载既有任务不触发重新创作审查。首次适用或依据不足时实际通读；同一执行者、同一任务内，准确修订、正文及有序素材字节、来源、用途、要求和检查依据均未变且仍可核对时，可引用已完成的本轮内容结论，不重复全文审。写入前仍重核当前版本、授权、目标和实际绑定，写后仍实际刷新回读；任一内容或适用条件变化时复核改动及直接影响，不拿历史 PASS 放行。用户明确要求独立审核时沿现有入口交当前准确稿；审查未完成或不通过先停止受影响写入。

- **本轮要求落点**：从本轮有效用户要求、准确导演修订及适用方法核对实际提交正文、参数和素材职责中的对应内容；简记要求来源、落实位置和未满足处理，不能用制作备注中的“已保留”替代模型实际收到的指令。情绪表演、切点、动作时间与取景取舍按已有来源核对，不为补齐检查而新设计拍法。上下文不完整或要求发生变化时回读相关原文；核对无变可复用有效依据，实际变更才修订受影响内容，不以摘要或旧 PASS 代替本轮核对。仅操作者需要的来源、后期安排及授权依据仍留正文外。
- **入口适用性**：核对当前实际平台、模型及用户参数选择；CLI 历史能力、小云雀网页选择不能直接套到红帧或其他入口。仅用本轮已核支持的引用/控制方式，不能虚设专用槽位或通过换模型、分辨率、时长绕过缺口。未知能力列未核，阻止依赖该能力的提交；不阻塞不依赖它的提示词候选交付。

- **组织与去重**：按模板核完整性，不要求固定字数或八标题；同一素材的主要职责和相容用途合写一处，将真实原生引用放在对应职责处，不在正文首尾重复整套职责。公共条件已交代的开场不再同义复述，正文接第一个动作或镜头变化；必要约束、引用和导演决定仍保留。
- **状态与动作**：公共条件只含持续条件和真实开场，逐句核对其与后续动作及结束状态。稍后才坐下、端碗或换手，不能提前写成开场已完成；素材中间相位也不能替代动作过程。
- **执行归属**：正文只给模型本段可生成的声画与必要约束。按已确定方案明确模型和后期各做什么，不留“模型生成或后期合成”的未定选择。剧情内屏幕及真实道具字样不能一概当叠加字幕删除；后期文字原文、时机仍留制作备注，必要底画构图与阅读停留可留正文。
- **生成声音**：逐段检查实际提交正文明确要求不生成背景音乐（BGM），并按本段安排保留对白、环境声和动作音效。核对正文与参考素材的声音职责，避免同时指示生成或沿用背景音乐。已安排的后期配音及配乐留在制作备注。
- **素材与正文一致**：对照本轮实际图片、视频及已选音频、获准用途、当前状态与真实有序引用，核身份、衣装、空间、动作相位和声音职责。视频/音频核准确文件及实际使用片段，注明本次实际看/听范围；已有核验且版本、范围及用途未变可复用，不把摘要当观看或听验。只借动作的视频不继承原角色、环境或原音，无原音用途时明确排除其声音；深度图视频可按用户选择作为普通视频参考，说明其动作/空间用途，不假设专用 Depth 槽、外观依据或 1:1 复现。参考片段及其取用方式须符合本轮实际入口，不能仅靠文字裁切声明冒充已受控的素材。原生实体自身的标题/版本标签不是手写伪引用，但标签不能证明真实媒体身份、模型接收内容或素材已确认。缺件、未核、用途冲突仍按既有门禁处理。

普通写稿将准确修订、范围、具体依据、发现及修复、结论简记在业务 JSON 的既有自查／未决字段；写入前核这些依据仍适用，没有依据不能只填“通过”。统一入口正式采用时按[Skill 的记录分界](../SKILL.md#自查记录与正式采用)整理既有结构化报告，不把“不新增平行台账”误读为免交采用凭据。正则只能发现有限已知模式，不能证明职责去重、状态逻辑、视觉用途或执行归属正确；语义判断须实际读稿，必要时看图。写后持久化回读单独报告，不能代替写前审查；两者通过也不等于用户确认或生成效果验证。维护规则时用[内容审查压力样例](../tests/prompt-content-review.md)核边界。

## 自查与修改

对导演决定的具体核验沿[状态与节拍步骤](../../storyboard-planner/modules/shot-planning.md#把创作决定落实为可验证的状态与节拍)执行：仅承接该节检查步骤，不采用该文的导演prepare入口或导演权限；本阶段由source_shots派生受影响生成段及直接接口，核职责继承与实际实现；发现导演拍法本身缺口返回上游，不在视频层暗补。

导演镜号有 `required_visuals` 时，将每条 `prompt_clause` 原样独占一行放进实际连续声画正文的对应动作位置，去掉原有同义句，保留其前后触发和承接。有 `min_seconds` 时，视频源段及实际交付都用 `shot_durations` 按 `source_shots` 的顺序逐镜列时长，至少一个承载该指令的镜头满足最低时长。落稿时同时实看对应参考的姿态、光线、在场人与产品相位。措辞或拍法需改，回到准确导演修订再同步。校验覆盖文字和分配，模型执行仍按成片质检判断。

同稿观察如何绑定本修订并由真实交付入口检查，见[观察证据与输入版本](../../../docs/development/delivery-snapshot-checks.md#本轮观察证据与输入版本)。记录的是可定位事实而不是勾选保证；候选保存、正式交付和实际生成/动态验收分别判断。

动作链自查并入以下同次提交前自查：实际查看适用首尾图和参考，贯通前态→拿取/握持→关键接触→脱离/放回→后态，核对持物、可达侧、动作相位及全部实际参考职责；只检查本段确有的动作，不按此顺序补造剧情。边界换图时读取直接受影响的相邻两段全文，检查首图已开始的动作是否被重复起手、旧约束是否强迫回姿，以及尾态能否自然到达。按上述对白与时长方法区分估计和实测、可重叠与必顺序动作，不以固定字数公式证明容纳。结论沿用同一稿件的自查备注，明确未检查、发现问题或已人工看图的具体范围与依据；勾选、关键词命中或技术 PASS 均不证明动作事实。影响已确认拍法的冲突返回相应上游，不改定稿来凑通过。

按项目逐场流程，先对照本轮创作段落的原始镜头、原文对白及真实素材，检查涉及的跨段依赖和相邻段衔接；全部创作段落完成后检查全片覆盖与整体节奏。当前范围之外尚未写出的提示词不冒充已检查。核对正文实际描述与时长、声音策略、素材决定是否一致，不以字段齐全代替质量判断。必要修正直接写回当前候选并检查直接影响，结论和缺口简记在现有交付文档，不生成审核包。

对导演已设的关键剪辑接口，按成片预期顺序连读前段落幅和后段第一个要保留的画面，核动作或声桥触发、听者反应和时间提示在实际正文或制作备注的落点。可供模型定位的公共空间条件、参考图起幅和剪辑实际入点分别核对，防止空间已经交代后被转写成另一次建立镜头。后期才加的时间提示需核到既有 `postproduction_text` 与底片可用位置。同一参考换用剪裁区域时，检查实际提供的裁取范围，画外职责不能靠整图中相冲突的人物或物件来表达。若需要改变导演选定的切点或拍法，按本方法返回上游。

摄影表达按[正文与素材](#正文与素材)核适用的导演决定、可见光学目的及参数来源，再查有无遗漏、重复、无依据或与参考冲突的控制，不将产品尺寸当焦距。可选检查器仅查已识别提交正文，`--require-focal-intent` 用于已核实的关键光学要求；未识别 Markdown 时可改查实际提交 TXT，不为检查重建格式。沿用正文说明，无须另建逐镜参数表；导演与实际素材实质冲突时报告影响并返回上游。

不能只因“原稿也这样写”就判定合理：检查动作为什么发生、是否引入无依据的行为，公共设定与单镜站位是否冲突，物件由谁持有且能否触及，景别与机位能否看见要求的信息，切镜后的动作进度是否承接。全脸涂抹/擦净等终态须有能覆盖所需区域的过程，状态图不替代动作路径。发现影响已审定拍法的冲突按本方法返回上游，不默默补戏或自行增加资产。

转写后的正文还应保留上游决定中的取舍条件，例如“脸和握带手必须同框、袋体只需一部分”。只留下景别名或主要动作会改变观看结果；若视听正文与逐镜字段对取景范围相互冲突，先返回导演收口，不择一个字段凑通过。技术检查分别报告实际覆盖：正文解析、来源/对白覆盖、原生素材绑定都不能证明构图、状态和转场执行正确。复盘时先核生成任务实际输入；只有当前草稿而无提交时快照时，明确这一缺口，不把单次成片偏差断言为唯一模板或模型根因。

报告分别注明文字自查、素材绑定、平台生成结果及用户采用，技术检查不升级为视觉确认。用户已明确采用最终剪辑时，不将历史生成瑕疵继续列为该成片的生产阻塞，不据复盘自动重跑；确认范围和本次明确排除的检查事项沿现有记录保存。

首次理解本轮连续事件及整段拍法；局部返修复用仍可用的原文，按实际依赖补读，不固定为前后若干镜。除下述公共设定外，追溯跨镜对白、站坐与持物的来源、远处铺垫和后续回应，以及实际已生成素材的版本；依赖不清时扩大到完整相关场景。对白或动作移到另一生成段时，核对该段实际提交词和已有成片承载，不能用新版文稿代替旧视频已经实现。全片覆盖检查在全部创作段落完成后仍须执行，不以分批交付或少读为由省略。

导演包 v4 使用场景公共设定与单镜例外：取任何镜头时同时读取全片 director_rules、所属场景 space_rules/defaults、camera、take 和 cut/rhythm。overrides 仅覆盖出现的字段，空列表表示关闭，省略表示继承；覆盖不自动延续到下一镜。对白按 audio.dialogue 中的准确片段、说话人和呈现方式衔接，不按同一 DLG 编号重复播放整句。旧导演包按其原版本解释，不补造新决定。

### 场景真实感的本轮核对

转写后按[四类场景核对](../../../docs/development/scene-realism-checks.md)回看具体正文：旁人感知与合理不同反应、物件数量/取得/交接因果、环境声源与事件影响、相邻镜状态与动作相位。近处能察觉冲突却毫无依据地继续活动不能只当背景略过；远处未察觉者、克制和有动因的同步反应不强行改戏。缺上游拍法时返回准确来源，不自行添加剧情。

高风险候选可在同一 JSON 的制作信息中补 `scene_realism`，用既有文字检查器的 `--check-scene-realism` 做有限声明对照。它不理解全部自然语言，不发现漏写的人物，不读像素或声音；未提供记录明确未核，不能用它替代实际正文自查、生成结果听看或获得采用授权。普通创作不要求为此另建稿件、计划或准备包。

## 平台草稿的目标与持久化证据

小云雀新写入草稿默认并显式选择 480p；不能从旧快照或平台默认继承 720p。原生控件无 480p 或保存后不一致时，报告该项阻塞，不自动升分辨率，不改用户时长、模型、画幅或历史草稿。

操作前冻结准确画布 URL、草稿节点 ID、提交正文、实际参数和有序引用的 node/media ID；名称相同不证明素材身份相同。草稿写入授权与生成授权分开，写入成功不自动执行生成。

每段写入显式传入该段冻结数据，不能沿用上一段的闭包或全局正文。替换内容前确认真实活动节点、可见富文本编辑器及其焦点/选区都属于当前草稿；仅“点击过编辑区”不能授权全局全选或清空。出现整画布删除提示立即取消并核节点未变，不能把它当编辑器清空。参数弹层分开完成打开、读当前输入值、修改、原生确认及读回，不把一批连续点击/键入当作参数已保存；失败先确认停点，不重写已正确正文或擅改目标参数。

旧 RHTV 工具必须显式设置 `RHTV_CANVAS_URL` 或 `RHTV_TARGET_ID`，两者同时给时须同时匹配；无匹配、多匹配或导航离开均停止。`rhtv_cdp.js` 不再执行任意 JS stdin，而只接受结构化单步 JSON：`operation` 为 `read`、`click` 或 `set-value`，给准确 `selector`；`set-value` 另给字符串 `value`，只支持普通 input、textarea、select。`read` 可用 `attributes` 列所需原生属性，`all: true` 只用于明确多项只读。可给 `wait_ms`（0至10000）等待元素；每次等待后重验目标并重新定位，最终同步作用及每次事件派发前再核对 URL/文档身份。零匹配、多匹配或导航时停止，不通过正则猜任意代码是否读写。需要平台原生chip等复杂写入时先实现专用已验证适配器，不回退任意JS。调用失败不能证明尚未写入，已提交操作可能部分生效，不自动重试；事后报错不撤销已有作用。旧任意表达式调用须迁移至上述受限入口，导航后另起一次操作。旧 RHTV 地址不是小云雀的后台合同。

需要承诺全字段持久化时，最后一次刷新后只读本轮准确草稿的原生编辑器字段，与冻结提交逐项比较正文、参数及有序媒体身份（保留重复引用）。节点/标题/边的图读回只能证明图结构，不能补成正文持久化。适配平台的只读收集器负责真实刷新和字段提取；`python -m scripts.canvas_readback --frozen <冻结.json> --readback <刷新后字段.json>` 只比较提供的证据，不访问远程服务，也不凭 `after_refresh` 字段证明刷新真的发生。缺任何字段或真实读回能力时明确列缺证，不宣称完整验收。

比较输入使用 `target_url` 和 `drafts`；每稿包括 `node_id`、`prompt` 字符串、`parameters` 参数名到原生值的对象、`ordered_media` 按正文出现次序排列的 `{node_id, media_id}`。读回另带 `phase: after_refresh` 和冻结对象的规范 JSON SHA256（工具 `digest`）。只读回目标稿，不重传全部画布和素材。平台原生字段到此结构的映射必须经实测，不能拿可见标签推测 media ID。

平台要求正文原生素材引用时，冻结稿另写准确 `native_entity_type`，读回在同一草稿的 `native_mentions` 中按出现顺序提供实体的 `node_id`、`media_id`、`entity_type` 和 `native_noneditable_entity: true`；收集器必须从原生编辑器实体取得，不能由正文标签或图连线生成。比较器核对实体类型、身份、次序及重复引用；缺实体证据不通过该范围。历史输入未声明此项仍可核普通字段，但结果明确原生引用未检查，不能据此声称 @ 已验证。生成记录、实际媒体和声画检查另依真实结果判断，不从草稿比较通过推出已经生成。


## 跨段声画游标与动作阶段

每段从准确 `source_shots` 和导演 `audio.dialogue` 的片段续接，不按DLG编号回取整句。现有 `source_audio` 保留准确片段和说话人，正式采用及画布检查共用逐镜回放。按源ID与片段推进游标（可计算字符区间，不另写槽位表），平铺片段仍须带准确镜号，且按源镜顺序提供。同句跨镜只续说一次；相同文字但不同源ID的两次回应/告别均保留，不能全文字符串去重。上一段已说内容只以不含原句的制作备注摘要说明，不把整句原话再抄进可发声正文或素材说明；参考音轨不承担本段对白时排除其声音。`quality_evidence` 的检查是声明/版本一致性，不证明实际音轨。

电话的剧情状态与生成段结束分开：在现有入态/尾态中继承同一通话 active/ended、当前说话人及已说到的准确片段。离耳看屏不等于挂断；仍接通时不可点击结束、收机或重拨，回耳接触点需可读。真正结束只有源事件授权才写 ended。原文两次告别不文本去重；UNKNOWN说话人继续保留未核。

产品动作从导演前态续做，不重演已完成步骤；接触、承托和合理兼持按[导演承托边界](../../storyboard-planner/modules/shot-planning.md#连续现场的重点反例)核可见依据，不凭空补步骤、人或支架。核当前参考的实际动作范围与阶段重叠：同次动作的多视角不等于要求做多次；文字声明裁切不证明入口真的只接收该片段，慢放也不代表真实动作工时。已明确的合段要求继续保留，能力冲突返回上游。产品专用案例按本轮适用的第二层方法选择。

局部修订后必须回放完整正文和有序引用变化，不只检查新增片段是否出现：对照旧句检查同一动作是否重复、已完成相位是否回退，逐项写明触发来源、方法、准确改前/改后及未核范围。范围由局部扩大为整段时，同步恢复完整来源的全部适用参考职责及直接边界，不让完整正文沿用仅尾段的引用计划；来源未恢复或职责不相容仍留缺口，不继承旧确认。空间与护理缺口按上游职责返回修订；此回放可以是无图视频生成的候选测试，不构成正式采用。分开 source_text、delivered_candidate、active_binding、job_input；文字曾写对不证明旧job收到了它，更不证明模型遵守。

公共条件写持续条件和真实开场；稍后变化写在正文对应位置，不能提前写成已完成。每个独立段说明已成立的前态，同段正文直接接动作，不同义复述公共开场或重演已完成步骤。`cut.exit/trigger` 是剪辑触发点，不可直接复制成 `exit_state`：按本段正文最后实际动作归纳完成态，再对照本段尾态、下段入态及公共开场、下段正文第一动作；下一段才执行的动作在前段写尚未，不只改标签而保留正文重播。连续动作中途切点保留准确进行相位，不强制全部完成；跨场、明确时间省略和新一轮事件按来源区分，不脑补省略事件或机械强求同一首尾态。人物自身左右手与画面左右分开，反打只改变投影，门窗／桌边锚点和持物状态继承。
