# 深度图视频复刻执行方法

## 开工与原片

先沿共用编导入口还原原片剧情、对白、说话人和动作，交整稿采用。采用后沿现有 [kickoff](../../../docs/rules/project-layout.md#开工确认单) 登记 `creation.workflow: "depth-guided-recreation"`，在 `creation.reference_scope` 记原片窗和两类参考用途：用于核镜头的原片范围，以及获准用于制作资产或生成节点的素材范围。在同一份开工决定记录只换人物、只换场景或都换，写明角色、场景、服装、动作道具及声音文字的保留或变化。续做保留其他有效决定，顶层 `source_files` 按既有合同登记原始文件。

连看原片并按实际切点定位。按编导段登记源窗和动作落点，已有段内切点随深度片沿用。相同机位一镜内的推拉摇移保留在同镜。提取外观参考时取能看清所需特征的帧，实看静帧和连续片段以区分固定结构、瞬时遮挡和原片剪辑。

## 人物和场景参考

需要结构复刻的剧情镜头用深度视频提供结构，以本项目选用的资产图提供外观，重新生成完整画面。

| 本镜选择 | 人物参考 | 场景参考 |
| --- | --- | --- |
| 只换人物 | 指定角色用新人物资产，其他角色保留本轮确定的身份和外观，服装按已定范围设置。 | 从原片取能看清场地、固定陈设和光向的画面，生成或复用该场的确认场景参考。保留可辨识的场所和动作相关布局，允许非关键纹理与布置差异。 |
| 只换场景 | 从原片取能看清原角色面容、发型和服装的画面，整理、生成或复用同一角色的确认资产，连续镜沿用同一身份和造型。 | 用新场景资产提供地点和外观。对照原片动作，核新空间的入口、通道、站位、遮挡与接触表面能承接原拍法。 |
| 人景都换 | 将源角色逐一映射到新人物资产。 | 以新场景资产复核原镜头的景深层次、行动位置与道具接触条件。 |

用原片不同机位补充同场可见布局。场景参考图若带原人物，只选择能独立承担空间外观的范围或准备干净的场景图，以免旧角色进入身份参考。原人物资产以看清身份和造型为准，背景交给场景素材。只换人物时沿用对标场景的已确认布局，新制母图按[环境母图取景与补全](../../asset-image-assistant/references/03-scene-master-guide.md#可复用环境母图的取景与补全)留足跨镜空间，区分原片实见与补全设计，并沿用[场景图确认与派生](../../asset-image-assistant/references/03-scene-master-guide.md)。相应深度参考沿用该镜在原片上的走位、动作落点和构图。

多镜复用同一确认人物和场景资产。若外观参考中的家具高度、门的位置或人物尺度与动作冲突，先补合用资产。必须动已锁拍法时，定位镜号并交协调方核对变动范围。广告产品和实物继续从准确的真实参考取外观与操作依据。

跨段或反复出镜的人物若依赖稳定服装与造型，核人物板是否清楚覆盖实际可见的衣身及相应造型，写入其前后段的原生引用和开场画面。人物板锁脸、发型、服装和首饰，专用状态参考只管对应细节，例如上脸膜的透明度、厚薄、光泽与眼唇留空。给深度视频标注采用的景别、机位、运镜、站位与动作节拍，明确排除原片的脸、发型、服装、首饰、膜型或材质等冲突信息。普通参考模式中的文字约束需以成片验证。深度轮廓冲突持续出现时，先收窄该视频承担的镜头与动作范围，再对照生成结果判断。

换景先保原片的空间骨架：门洞、通道、桌椅承托面、景深层次、入画路径、停步区、接触点和遮挡顺序。材质、颜色、灯饰和陈设风格可换。用起幅、动作落点和尾幅核固定地标的相对位置与尺度，跨镜沿用同一场景母图和动作锚点。

## 原片产品核对与制作分流

实看原片，核对每款商品是否为自家产品，并分别登记使用和展示的镜段及时间。展示包括包装入画、拿放和外观特写；使用核实际操作及可见结果。普通剧情道具按实际用途辨认。归属或款式未核清时保留待核事实，先推进已明确的剧情段。

- **原片是自家产品。** 若本轮尚无明确决定，先问用户「要不要延续原片里的这款产品及使用方式？」将用户决定、准确商品、覆盖镜段和消息依据记入现有开工记录，参考用途写入 `creation.reference_scope`，沿用同版已有明确决定。
- **自家产品且用户确认延续。** 按原视频 1:1 复刻，范围包括正常剧情和原片的产品使用、展示段。沿用产品段的切点、动作顺序、节奏和前后状态。同款官方或已确认实物参考承担包装、料体及外观核对。
- **自家产品但用户选择不延续，或原片是非自家产品。** 前后无关剧情仍沿原片结构复刻。受影响的产品段交视频提示词，按本轮确定的内容写明实际画面、动作顺序、时长和接缝。若改为拍目标产品，按其真实外观、实操和状态参考写词；本轮无产品时，按已确认的剧情处理相应镜头。

## 深度参考职责与排除项

- **连续产品段整段从深度源片切除。** 从产品首次入画、取出、展示或使用开始，直到该次产品动作、展示及其接续镜头结束。自家产品确认延续时，原片产品段的镜头、动作和节奏仍按 1:1 复刻，由提示词与已确认的实物或实操参考承接。
- **同一产品段断续入画时，夹在中间的无产品画面也整段排除。** 短暂遮挡、离画和几刀插镜都随同一次产品动作或展示保留在提示词里。深度参考只取与该产品段分开的完整无产品剧情段，按各自的原片连续范围使用。成片仍按本轮产品拍法和原镜头结构交付。
- 需要转深度的源片先按需处理字幕、贴纸、界面文字、水印，并移除音轨，再到[同一红帧画布转深度](../references/depth-video.md)。转换结果直接引用。每条原生引用说明它负责的景别、机位、运镜、站位、动作节拍及准确时段；需要排除的原片人物、服装、配饰或场景外观按实际冲突说明。

有深度输入组在正文写明参考约束：**深度视频只参考构图、机位、运镜、站位和动作节拍。忽略其中的字幕、贴纸、界面文字、水印，不沿用参考原声。** 按本轮产品分流核镜头的商品外观。延续自家产品时写清已确认的同款实物依据。原商品排除时，目标商品的外观、实操和状态按本轮已选参考表达。

## 分段交接

协调方运行普通 handoff。复刻 Skill 在项目的 `01_原始资料/复刻分段.json` 写一份输入清单。顶层填已采用编导的 narrative_id、narrative_sha256、fps、first_frame、end_frame、references 与有序 segments。帧界均左闭右开。references 以正文引用名索引，逐项写项目相对 path、sha256、role；产品动作视频另写实际帧数 frame_count。深度参考的 frame_count 与 source_start_frame 按转换输入覆盖的原片窗登记。人物、地点、物件用本项目当前确认的准确用途和版本，产品外观可取真实实物资料。

新分段将该镜实际出画的人物和场景 AST 编号列入 `visible_asset_ids`。同一剧情段拆多镜时逐镜填写，画外发声的人物不列入。按当前有效资产决定，只把须有独立图的对象绑定到已确认外观；每项引用用 `asset_id`、`output_id`、文件路径和字节摘要定位具体造型。旧计划的确认母版可按准确路径和字节沿用。

每段写 id、frames、paragraph_ids、dialogue_ids、mode、motion、reference_frames、appearance；列明剧情动作、谁说话及需要继承的状态。depth 模式使用同窗深度，product 使用目标产品的真实实操；只展示、拿取或放回商品时用 `product-display`，引用同款包装图。无合用视频参考的纯剧情段可用 `text`，靠正文与确认外观图交代镜头。这两种模式的 `motion` 填 null，`reference_frames` 填空数组。包装图不能充当操作依据。同镜混合时按原片实见时间登记剧情、产品使用与展示范围，参考职责按本轮产品分流决定。原片只供其获准用途。需要改写戏剧动作时 mode 填 rewrite，change 写具体冲突。原动作参考已不适合新工序时同时设 requires_new_motion 为 true，回传须选择不同字节的实际动作视频。导演通过下面的回传命令落实本段改法、进出状态和对应参考。其余段并行继续。分段或参考换版后重新核对受影响段。

新写或改写红帧草稿前，在既有分段记录里用原片时基确定各连续产品段的起止，并在计划顶层的 `product_visible_frames` 登记整段深度排除窗。每窗为半开区间 `[起帧, 止帧]`，包含同一产品段内的短暂无产品画面。分属不同产品段时分别登记，之间独立的无产品剧情可用深度。红帧预检按转换输入的 `source_start_frame` 与 `frame_count` 拦截覆盖排除窗的深度参考。即使本批没有深度输入，也保留排除窗。

有产品的分段计划登记 `product_pack.product_id`，对应开工时用户确认的商品，`packaging` 和 `operations` 列出 `references` 内同款包装和实操的键。目录内商品按开工锁定的参考包核对字节及用途；目录外同款实物包在 `product_pack.source` 登记项目内来源文件 `path` 和 `sha256`。产品段缺任一实际依赖时在交接中列出缺口，使齐备的剧情段继续。

### 按段读取写词输入

从仓库运行以下只读命令。取单段或局部批次时只传实际负责的段号，合并组为本批目标时逐个传实际子段。既有提示词的局部修订也用此入口。

```sh
python scripts/stage_context_cli.py recreation-prompt-input --project "<业务项目>" --segment-id SEG-01
```

使用回包中的本段剧情、对白、参考窗和外观素材。对白标有 `text_in_paragraph` 时，逐字取对应原文中的带编号台词，状态和说话人看同条记录。多个分段共用的剧情段还有本轮范围外内容时，取各目标段登记的 `event` 和各自对白。有 `story_needs_source_review` 时，沿该目标段帧窗核原片或已绑定参考，缺证如实保留。接缝取实际相邻段的进出状态，旧分段缺状态时以相邻事件和切点定位，有具体衔接疑点再看片。已核的同版输入直接复用；旧提示词和新增证据按实际段号或用途定向取用。编导阅读稿供人审，写词上下文沿这一份回包取源事实。正式交接、采用及画布预检继续走原有校验。

## 局部导演回传

普通 handoff 在导演交接卡标出每个段的任务文件，内含 job_sha256、段内对白、有效资产、当前参考和相邻段。协调方或本段导演在项目内准备回传 JSON。填 segment_id、派单中的 job_sha256、decision（具体改法）、entry_state、exit_state、reference_use（参考覆盖什么及为何适配新动作），以及 mode、motion、reference_frames、appearance。引用键必须来自当前计划；新实操片先登记其准确路径、哈希与时窗。产品或手法更换时实看新参考；文字说明不能使旧刷敷视频变成喷雾示范。
运行 `python scripts/return_director_segment.py --project <项目> --result <回传JSON>`。成功后按普通 handoff 接续，仅本段需更新提示词；不手改模式放行。来源或相邻接缝变化时重发该段任务。

## 接入既有制作入口

实际提交前分别核生成时长、参考视频长度和素材数量。每段写词只用这一段的参考；平台需要更短的参考时，按已登记的帧窗先裁转换输入，再到红帧转换。碗、刷子和余料只沿用下一段可见的状态。首轮交稿后局部返修可凭稿段 segment_sha256 复用其他段。其计算为项目 sha256_json 对 [编导文件哈希, fps, 本段对象, 主参考及各外观参考对象的有序列表] 的摘要。稿包与全计划同版时使用 plan_sha256。

有专用深度控制的交付以当前平台实际支持和取证为准。只有普通视频输入时，按[视频方法](../../voiceover-to-video-script/modules/video-method.md#提示词内容合规审查)作为动作和空间参考，核素材身份、原生引用及参数是否保存。对白和字幕等依项目声画安排交原环节处理。

### 用户要求在生成前检查

先完成已授权的补图、素材核对、分段和提示词修订。审查画布时直接打开已配置的正式视频节点，提示词只写入该节点的「生成提示词」主编辑器。正文预览留在本地源稿。前置缺项只影响依赖它的镜段，已就绪部分继续准备。

写入本轮完整草稿，按[红帧排版验收](../../voiceover-to-video-script/references/redframe-canvas-layout.md#执行与验收)先整理正式草稿和直接关联素材，再保存刷新。按[画布交付入口](../../../docs/development/review-to-canvas-entry.md)核正文、实际输入槽与原生引用、模型、模式、画幅、时长、接缝以及适用认证，同时检查全景和正常审阅缩放的关键局部。原有交付回执记录本轮字段核对和实际布局结论，确认原镜头覆盖及复刻段与产品段的输入分工。两项检查完成后交准确画布链接和段号，停在原生视频节点的「生成」按钮之前，收到用户确认后再提交。

有产品时，按 `product-canvas` 交接把登记的实物包装参考集中放在画布素材区，按本段实际需要把实操、包装或状态素材绑定到视频草稿。关闭写入会话后重新打开画布，回读图片卡和关联输入的字节与原生身份；续作或提交前检查同一画布的当前状态。实物图仅供外观核对时留在素材区。沿用 `06_视频/画布交付回执.json` 或在计划的 `product_pack.canvas_receipt` 指向已有回执。保留 `target_url`、`target_project_id`、`plan_sha256`、`phase: "after_refresh"`，以及 `product_pack.product_id` 和按包装参考键索引的 `product_pack.packaging`，每项记实际 `node_id` 与 `sha256`。对应段落在 `segments` 中记录 `reference_identities` 和按实际引用键索引的 `verified_product_inputs`（SHA-256）。提示词交稿与产品包画布交付各自显示状态。

## 样片核对

用有运镜、人物调度、固定地标或道具接触的代表段验证新入口。同时间窗对照原片和样片，按[现有成片质检](../../voiceover-to-video-script/references/video-qc-checklist.md)记录镜号、时间点和偏差。

复盘只要求修正制作前置时，先查该次生成实际提交的正文和素材。把已表达清楚且参考覆盖一致、成片仍未实现的要求留在成片质检记录，修正范围只包含可确认的前置遗漏、参考缺口或接缝状态冲突。实际提交内容无法确认时记为未核。

- 结构与时间：切点、景别、运镜方向与落幅、人物进出画、动作顺序、停顿与接触时点是否对应。关注飞手、穿模、遮挡反转和拼接跳变。
- 外观：被换对象在关键镜头中清楚可辨，保留项在相邻镜稳定，人物、服装和场景都能追溯到选用的素材。场景细节允许合理生成差异。
- 声画：按已定用途核对白、原声和字幕是否覆盖、是否与画面动作和切点对齐。

需要区分深度参考的实际收益时，可在已有生成授权范围内固定人物图、场景图、正文和可锁参数，对照加深度参考与仅用外观资产的结果。发现结构问题先核原片切点、转换输入的登记窗和草稿引用，发现外观漂移先核对应参考图、实传引用和冲突。把实际观察与可接受偏差归到使用该结果的镜段，供后续采用和返修。
