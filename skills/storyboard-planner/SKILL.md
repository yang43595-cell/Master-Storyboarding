# 导演：从故事到视听分镜

开始本职任务前读取[共用三层规范](../_shared/skill-layers.md)。本 Skill 适用边界：承接确认故事与对白，以 modules/shot-planning.md 和现行模板组织逐场视听稿；不重写故事或决定生成分段。

## 承上启下的职责

编导确定故事发生什么、人物关系、事件与对白；本 Skill 把已确认的故事设计成观众能够经历的情绪过程，决定这些内容怎样成为按顺序看到和听到的一段戏。按[逐场创作与确认](../../docs/rules/execution.md#逐场创作与全片复核)逐段完善，最终主交付是完整、可阅读且可执行的视听分镜稿；验收与授权按本轮统一或兼容入口处理。

- 承接已确认叙事，保留事实、事件顺序、对白和说话者；在输入允许的创作范围内作出具体的镜头、表演和声画设计。发现需要改写故事或补充事实的问题时返回编导，不自行补写。
- 实质创作先按 [镜头规划加载与合同入口](modules/shot-planning.md#从整场意图想出画面) 完整阅读三份本地基础参考，再读 [画面构思与拍法选择](references/visual-conception.md)：从整场关系变化、观众体验和可见载体想出观看路线，在重要岔路比较后选定，再落到镜头；不逐句配镜。创作时及创作后按[状态与节拍的具体步骤](modules/shot-planning.md#把创作决定落实为可验证的状态与节拍)分别检查表达质量与执行连续性，不把具体判断推迟到成图质检。
- 依照绑定方法，以“情境与表达目标 → 拍法选择 → 可读效果”形成整段视听设计；按模块先写连贯视听展开，再定剪辑边界和逐镜拍法。不从表格空栏倒推创作，也不把互斥选项留给下游。
- 说明节奏、停留、时间依据与未验证限制；守住用户时长及制作预算，未测不冒充实测，不以镜头数量替代表达判断。
- 视频 Skill 承接本轮合法验收采用的拍法，负责提示词、素材引用和生成分段。实现受限时返回具体镜头及影响，需改变导演决定的部分由本阶段形成修订，并按本轮入口重新检查或送审，不能由下游暗改。

本阶段同时验收“拍法可执行”和“重要情绪有视听表达”：整段拍法已经清楚，关键情绪与关系转折能从实际画面、表演和声音中读到，可供用户审定并被下游忠实实现。叙事与对白覆盖完整不等于表达充分。表格完整、引用正确与镜头数量只是辅助检查；本阶段不承诺模型生成效果，也不要求先制作全套分镜图。逐镜复刻须以原片证据核对；只依据故事创作的拍法明确标为候选导演设计。

按 [干净上下文启动规则](../../docs/rules/execution.md#创作执行开始前干净上下文) 执行本阶段；新一轮导演创作或实质重跑由全新专属生产 agent 执行，同轮逐段推进与局部返修可继续原执行者。

纯错字、标点或排版维护先按 [共享局部维护边界](../_shared/knowledge-access.md#局部维护边界) 判断；符合时只做局部检查，下述整阶段准备适用于实质创作与修改。

读取 `PROJECT_RULES.md`、`../_shared/draft-lifecycle.md` 等共享红线后，按 `modules/shot-planning.md` 的唯一入口完成准备、完整方法阅读、适用本地合同与产前校验；有效阅读按共享规则复用。补充资料按当前表达或事实缺口，从准确候选路径定向读取；方法的出处链接不自动成为额外全文必读，也不因主题相近排除适用补充。灯光沿用方法快照，不重读旧导演预演段落。交付使用 `templates/专业影视分镜输出模板.md` 与 `../../schemas/storyboard-package.schema.json`；自查按 `references/专业影视分镜审查门槛.md`。

本阶段适用的本地合同：[专业影视分镜执行规范](references/专业影视分镜执行规范.md)与[对白来源合同](../creative-director/references/dialogue-lineage-contract.md)，按上述唯一准备入口读取与核验。

## 术语与范围

| 用语 | 本阶段含义 |
| --- | --- |
| 原文段落 STP | 上游故事的来源定位，不规定镜头数 |
| 创作段落 | 本轮逐段写作与检查的范围，按场景、时空或完整剧情阶段划分 |
| 分镜段 | 阅读正文中的表演／情绪推进单元，可含多镜 |
| Shot／镜头 | 一次连续摄影，对应一个 `shots[]` 对象 |
| take | 单镜内的起／过程／止，不另建镜头层 |
| 视频生成片段 | 视频 Skill 决定的生成单位，不由本阶段划分 |

这些单位不要求一一对应。交付时用已有来源与镜号说明“本段”的准确范围，不新增编号或台账。

## 本轮执行 SOP

启动时按[项目统一入口](../../PROJECT_RULES.md#网站审核到画布的统一入口)判定一次本轮路径：新任务采用自主检查；未迁移的既有任务保留原人工路径。以下主线按统一入口执行，兼容分支见交付合同。专业判断与字段仍按既有方法、模板和审查门槛。

1. **核定本轮与上游。** 新创作轮由全新专属生产执行者开始；按下文输入门禁实读当前已确认叙事、确认范围、用户锁定拍法及现行资产调整。按 [唯一准备入口](modules/shot-planning.md#本-skill-产出须命中的规范缺即停) 完成 `prepare`、必要全文阅读、单独登记和 `ensure-prepared`，核对工具返回与任务依据；来源或确认冲突时停止受影响设计。
2. **统筹时间并选择观看路线。** 按模块先做全片作用、情绪、来源、衔接及各段粗预算；在重要转折检查表达，存在实质拍法岔路或表达不足需要重选时，按 [实质创作的先后顺序](#实质创作的先后顺序)比较后选定。无实质岔路直接展开，不凑双案。
3. **完成当前创作段落。** 先写连贯视听展开，再定连续摄影边界并整理同一 v4 JSON 的逐镜记录，按 [状态与节拍步骤](modules/shot-planning.md#把创作决定落实为可验证的状态与节拍) 落实表演、空间、手物、声画与时间。段落候选保留已写/待写及接口；不补占位镜头、不把一段完成当全片完成。
4. **自查、校验、返修再查。** 先按 [审查门槛](references/专业影视分镜审查门槛.md) 检查实际视听表达，再核来源和执行连续性；局部用下文显式 STP 范围命令，整稿用默认严格 `story_sources --narrative <叙事包> --storyboard <导演包>`。将真实问题、落实镜号、修复结果、命令结果和未核范围留在既有记录；修当前候选后重查改动及直接影响，最终版重跑适用校验。成稿后追加准确 revision/hash 并回读选路落实；已确认内容另作修订。
5. **完成全片并验收。** 段落自查后继续下一段，逐段更新预算；全部完成后做全片表达、连续性、来源和总时长复核。按下文交付合同绑定本轮真实授权、准确版本与完整自查，合法采用；授权、证据或接线缺失时保留候选。
6. **收尾并交回协调方。** 交付准确路径、revision、已完成/待完成范围、验收依据及未核项，执行 [旧稿归档收尾](../_shared/draft-lifecycle.md#旧稿归档收尾)。不自行调用分镜图、视频或独立审核，由协调方承接已授权流转。

输出以表演／情绪单元组成的分镜段为阅读主线：场景共用设定写一次，段正文直接写行动、表情和声音，在实际词句／动作切点处写景别与运镜，一句对白可跨多个镜头，不在段首固定单一景别。目的、候选比较、知识映射和审核声明留在过程／审查记录，不挤入每段阅读正文；检查仍照常执行。按 [分镜段创作与实质比较](references/segment-sequence-method.md) 和简洁阅读模板落实；底层每次连续摄影仍对应一个 shots[]，不删执行细节。

## 实质创作的先后顺序

准备/阅读通过只说明可以开始工作。按[两阶段比较记录](references/segment-sequence-method.md#先选路再核落实不要等最终哈希才比较)，适用的实际短序列比较须先保存并得到工具返回，再展开选定完整稿；成稿后回读落实情况并追加最终 revision/hash。晚补比较只作后验返修依据，不追认创作前顺序；具体记录与方法修复验证要求只在该处维护。

## 输入门禁

- 只消费 `project_state.json` 与 artifact manifest 指向的已确认 `narrative.package` revision；确认状态、路径或 revision 不一致时停止。
- 分清事实与拍法的确认范围：用户明确锁定的拍法、已确认导演版本或片段均按准确来源保留；当前授权修改时另作候选，按本轮入口重新检查或送审。AI 自选但未经用户确认的旧拍法不因进入旧稿、任务摘要或已确认叙事而自动锁定，可在本轮创作范围内重选。未锁定且属于本轮创作范围的拍法由导演明确选定；来源不明且会改变受保护拍法时先核对确认记录，仍不明确再问，不擅自解锁。局部换服等修改只处理相关镜头及直接连续性，不扩大为全量重设计。
- 完整阅读已确认叙事 JSON 的故事、对白、锁定事实、STP/DLG/AST、资产约束、来源和未决项；新包运行 `python -m scripts.core.story_sources --project <项目> --narrative <叙事包>` 核对原文及引用，不再同时读取同义 Markdown 或省略原文的第二份视图。历史带 human_readable_path 的包仍完整阅读原稿并用 `--reading-supplement` 核对双文件一致性；校验失败处理具体差异，不删除旧字段绕过。对白文本和说话者必须逐字沿用，不能新增、删除、改写或重新编号上游事实。上下文中缺必要原文时补读，阅读记录不能代替原文。
- 资产输入同时读取项目规则指定的现行资产需求调整记录与当前资产表；原叙事事实保留，用户已确认的新增需求按核对位置引用，取消资产图不等于删除故事物件。导演不自行新增需求。
- 本段需要引用资产图时，先用 AST 与明确 output ID 查询当前段范围；只在首次用途、版本或所需视觉判断变化时定向查看图片。确认登记和文件存在不等于已看懂画面。
- 缺少会改变剧情、人物、已锁定空间或资产事实的信息时，只返回带来源段落和受影响镜头的缺口，不自行补写；输入允许且未锁定的站位、机位与调度按[画面构思边界](references/visual-conception.md#2-从现场找可见载体)作具体候选设计。

## 交付合同

完善并自查 `<revision>_storyboard-package.json`（v4），保存完整视听展开、场景、逐镜拍法、对白承载、时间依据与衔接，只引用已确认叙事修订及稳定 ID。

- **统一入口：** 不送导演网页、不逐段等待人审；段落自查后继续，全片严格校验和完整自查通过后，按[本地流程授权与自主采用](../../docs/development/review-to-canvas-entry.md#本地流程授权与自主采用)绑定授权、准确 revision/hash 与自查结果。首次使用 `accept-artifact`，返修走该页的自主修订入口；它仍可合法使用 revision_control，禁止的是补造逐稿人工确认的旧 API 或直改 manifest。授权、证据或[接线](../../docs/development/review-to-canvas-entry.md#接线现状与开发交接)缺失时保持候选；有条件通过不等于正式采用。
- **未迁移的既有人工路径：** 同一候选 JSON 自查校验后送现有审核网页，核准确版本、范围与用户确认；首次采用、返修及继续授权沿原合同。局部网页见下文，入口未核实只暂停对应网页动作，不虚构 URL 或已发布结果。
- **阅读与历史兼容：** 按[JSON 交付与按需导出](../../docs/rules/artifacts.md#json-交付与按需导出)，新包省略 human_readable_path；Markdown 仅用户明确要求时同版导出，不作前置、业务权威或依赖，也不反向覆盖 JSON。历史双文件仍按输入门禁核对；`storyboard-package-v1.schema.json`、`storyboard-package-v2.schema.json` 与 `storyboard-package-v3.schema.json` 仅用于旧项目的只读兼容。

正式交接使用本轮合法验收与授权，由协调方承接。

## 硬禁区

- 不新增或修改资产需求，不制作、移动或确认资产。
- 资产引用只用 `04_资产/当前资产清单.json` 里的有效编号：已取消出图的物件可以保留为故事事实，但素材与出图引用不得用它，物件写在镜内过程；已拆分的改用子项。新 JSON 候选用 `story_sources --narrative <叙事包> --storyboard <导演包>` 自查来源和资产引用，实际图片用途再按当前资产清单核对。`--shot-plan` 仅用于历史 Markdown 逐镜表，不能拿它检查 JSON 或新连续正文。
- 不调用 Blender，不设计 Blender 配方或预演执行。
- 不决定视频模型、生成分段、时长上限、提示词、生成参数或正式分镜图。
- 不修改剧情、角色、事件顺序、对白、产品事实或叙事包 ID。
- 不调用下一 Skill、不决定阶段流转、不写批准事实。

全片完成后运行 `python -m scripts.core.story_sources --project <项目> --narrative <叙事包> --storyboard <导演包>`，验证版本、原文与段落覆盖。STP 只是原文定位，不是镜头数量或事件摘要；一段可对应多个镜头，同一镜也可引用多个连续段落。

## 逐段候选来源自查（不等于整稿采用）

全片未完成时，在同一累计候选 JSON 内写清已写/待写范围与跨段衔接未决项，不补占位镜头。显式运行：

```sh
python -m scripts.core.story_sources --project <项目> --narrative <完整已确认叙事JSON> --storyboard <同一候选导演JSON> --candidate-paragraph-id STP-01
```

每个已写 STP 重复一次 `--candidate-paragraph-id`；范围必须覆盖该累计候选内所有已写镜头（包括前轮已写但不改动的部分），不是裁出本轮段落另建包。跨段镜头必须将全部来源 STP 纳入本次范围并完整承载这些段落；不截断对白/动作来迁就范围。顶层来源清单可保留全片统筹，未写段落不能伪装成已完成镜头。仍完整检查上游叙事、准确修订、当前资产及本轮对白原句/顺序。

结果明确列出 checked/unchecked STP、共享场景/资产可机械识别的跨边界来源、相邻待写段落，并标明 `whole_package_validated:false` / `formal_adoption_allowed:false`。这些只帮助定位，不证明跨段语义已检查；人工核对前后状态、远处铺垫/回应与衔接，将未解决处留在现有 `open_questions` / `asset_gaps`。无关后续未写部分不当作本轮漏写，不能宣称全片自查完成。

以下局部网页仅用于未采用统一入口的既有人工路径；统一入口继续段落自查，不发起该网页步骤。兼容路径按[适配说明](../../docs/development/web-content-adapter.md#导演逐段候选来源范围)，同次提供完整原叙事及相同 STP 范围，强制 `reviewable:false`，只供阅读/反馈。用户段落确认仍走原 segment 范围记录，绝不变成网页整稿批准。全片写完后去掉局部参数重跑默认严格校验，之后才按本轮合法验收及正式采用合同处理；局部参数不传入 adopt-package/commit，恢复稿也无例外。

历史已批准正文用作隔离候选输入时的证据分层（批准正文的证据登记格式、原声核验口径）见 [隔离试验细则](../../docs/rules/experiments.md)「历史正文批准与原声证据分层（仅隔离候选）」节；普通导演任务不适用，仅在本轮明确授权 candidate-test 时按该节执行。

## 视觉生产衔接细则

本阶段涉及资产、按需分镜、场景状态或可选白模时，读取 [视觉生产与资产调整](../../docs/rules/visual-production.md)，仅执行本职及已授权分支。
