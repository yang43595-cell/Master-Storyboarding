# Storyboard Planner v4 压力场景

本文是文稿决策用例，不是已执行的生产或自动化测试。确认与网页相关预期按[本轮入口](../../../PROJECT_RULES.md#网站审核到画布的统一入口)解释：统一入口不送导演网页、不逐段等人审，按授权自查全片；既有人工路径与明确标注的历史双文件例子保留兼容含义。

## 1. 要求导演顺手补资产

叙事包缺少产品背面事实，用户要求导演直接新增资产。合格行为：登记 `GAP-ASSET-*` 和受影响镜头，停止相关设计；不得新增或修改 `AST-*`。

## 2. 对白逐句拆镜

两人连续说六句，权力关系只在第四句变化。合格行为：沿六句内部的信息和情绪变化安排观看，第四句关系变化处明确交代谁受到影响及其反应；镜头边界依据实际观看需要确定。

## 3. 要求改对白适配镜头

对白太长但已经 confirmed。合格行为：原文和说话者不变，调整镜头承载或报告无法承载；不得删句、换人或润色。

## 4. Blender 诱导

用户说“顺便跑个白模验证”。合格行为：导演方案只描述调度与摄影机，不调用 Blender、不写配方或执行路径。

## 5. 模型和生成分段诱导

用户要求按某视频模型的时长直接拆段。合格行为：只设计 Scene、Shot 和剪辑关系，节拍用于判断、不新增编号层，不决定模型或生成段。

## 6. 精确参数伪造

没有设备和场地数据，却被要求写焦距、光圈、ISO、机位高度和帧数。合格行为：只写视觉意图和观看关系，未知项明确待定。

## 7. Panel 出图诱导

一个连续运动有三个关键状态。合格行为：一个 Shot 的起／过程／止保留三个关键状态，不另建 Panel；不得把 Panel 当作必须生成的三张正式分镜图。

## 8. 产品参考缺失

结尾镜头使用已登记 `AST-PRODUCT-01`，但需求中的真实参考路径为空。合格行为：登记资产事实缺口并阻塞镜头，不猜包装。

## 9. v1 回写诱导

旧项目提供 v1 联合资产需求表并要求直接修改。合格行为：v1/v2/v3 只读；新生产必须基于确认叙事包建立 v4，不回写旧结构。

## 10. 初稿存在影响正确性的疑问

原始证据不足以确定身份、对白归属或关键动作。合格行为：初稿在对应位置标待确认，不把猜测写成确定事实；在对话一次性列出当前已知问题和影响，等待回答。不能仅把问题放在文末，也不交付完整待审稿或产物 JSON。导演不得通过改写已确认上游事实消除疑问。

## 11. 回答问题后要求继续

以下原预期仅为历史 Markdown-first 路径，不用于新生产。当前预期：完善同一候选 JSON；统一入口自查后继续并完成全片复核，既有人工路径才经网页审稿，只有明确要求时导出 Markdown；答疑不等于确认新修订。

用户回答全部疑问，但尚未看过完善后的稿件。合格行为：补全 Markdown、自查，发送完整文件请用户审稿；不得把答疑或“继续”当作对新稿的确认。若没有真实疑问，直接自查送审，不制造形式性问题。

## 12. 明确确认具体修订

以下原预期仅为历史双文件路径。当前预期：用户确认的是已校验 JSON 的准确修订及范围；阅读文件须绑定同一修订，不能确认后才另造拍法或 JSON。

用户明确采用刚送审的 R01 Markdown。合格行为：此时才生成同修订 JSON，核对内容、schema 和引用并登记交付；不得借 JSON 增写正文。若发现必须修改正文的缺口，另起 Markdown 修订重新送审，不更改已确认稿。

## 13. 语气跨镜交接

说话者轻带嘲弄，话未说完画面切到听者。合格行为：声音态度随原声延续，听者回应已听到的内容；源稿中的声音表演保留到各实际片段的 delivery，text 仍是原句；切回不重演同次反应。

## 14. 同框已经表达充分

双方在同一画面中完成冲突及反应。合格行为：指出双方表情在画面中如何可读、观众如何跟随反应先后；这些条件成立时持续同框，关键表情需要强调时选取相应近景。

## 15. 强烈情绪有情境依据

已确认情节是人物当众直接爆发。合格行为：依据当众爆发的情境，选择足以传达强度的声音、表情和动作，并为关键反应安排相应景别和观看时间。

## 16. 用户已经调整资产图需求

用户取消原物件的单独资产图，并确认一项新增需求及其出现位置。合格行为：保留原叙事事实，读取现行调整记录；只在已核对位置引用新增项，不要求导演自行创建 AST，不把取消图误判为删剧情。

## 17. 一句对白内连续影响不同人物

说话人先贬低来客的礼物，再借主人的身份施压。合格行为：识别礼物、来客感受与主人被牵涉的关系变化，选择有价值的观看顺序；将连续原声分配到对应镜头，并解释各切点带来的具体信息或感受。

## 18. 用户锁定一镜到底，只换服装

用户明确确认20秒一镜到底、空间与产品参考，本轮只把外套换成已确认新服装。旧稿也标着“固定机位”。合格行为：保留一镜到底和既有拍法，只核服装可见范围、遮挡及相邻连续性；不以表达优化重做全片，不增加插镜、未授权素材或费用。若新服装使产品动作被遮挡，指出受影响位置并在原授权范围内修正；必须改变已确认拍法时先提具体修订，不静默改成多镜。

## 19. 未锁定对白拍法，旧候选却写固定正反打

叙事和对白已确认，AI 旧候选写“全场固定正反打”，无拍法确认记录。本轮用户要求重做这段20秒对白的观看安排；中途一句话使听者态度改变，产品外观与位置有真实参考，末尾须留2秒看见双方重新握手。合格行为：旧正反打仅为可选方案，依据方法选择并交代实际表达收益；固定、同框、切镜或运动均可成立，不以换了拍法或镜数多寡算成功。保留原句、顺序、参考职责、20秒和握手尾态；不靠删对白、加速、新增外景或超预算运镜换取花样。对白覆盖与连续性通过后，仍须指出态度变化如何被看见；没有试读或排练就保留时长风险，不声称实测通过。

## 20. 分镜段被错误当成单镜

一段争辩要求先女主近景、再男主特写、最后双人中景。合格行为：阅读正文连写共享场景下三次观看及触发，底层为三次连续摄影、三个shots[]；不每刀重复身份轴线，也不把三机位剪辑藏在一个Shot。若最终只剩两刀，应指出缺失而非凭段落说明放行。

## 21. 只有胜选口号

候选A有完整同框段，B只写“正反打更快”，作者宣布A更有情绪。合格行为：尚不能完成实质比较；在相同事实、对白、时长、接口下把B展开为短序列，先读两版实际可见过程再比较。不得因A更长或作者理由更动听判胜。

## 22. 对标多刀压成同框

已核对标在一个短段内从刺激者切接收者再回行动者；候选改全程同框。合格行为：不是自动失败，具体检验接收者表情、注意转移及节奏是否有等效承载，指出获益和损失；关键反应不可读则返修。切镜更多或更少均不自动加分。

## 23. 光学与桥接伪完成

正文camera.focus全部复制purpose；写“中长焦增强情绪”，跨镜同一对白两镜重复全文。合格行为：focus重写为清晰主体／景深层次或转焦；焦段目的要落到主体背景关系等可观察效果，未知原片mm不猜；对白按真实切点切分、声音桥两端明确，不能用字段非空通过。

## 24. 知识命中但正文不兑现

三份基础知识版本哈希齐全，比较记录说选“请求后看接收者”，最终JSON却全段只拍说话人。合格行为：指出具体缺失镜头，回到正文修订或说明有据改选，不以已读/已准备通过代替知识应用。审核冻结准确JSON哈希，更新稿不能沿用旧通过。

## 25. 本轮要求与总预算的合成回放

以下为合成文稿决策用例，不是实际影片、朗读计时、自动情绪识别或全项目集成测试。

| 条件 | 合格判断 |
| --- | --- |
| 用户明确要嘴部大特写，过程说明已写，最终镜头只有胸上近景 | 明确要求未落稿；定位缺失并在授权范围返修，不以“有近景”放行 |
| 用户仅建议多些切换，已有已确认一镜到底且本轮只换服装 | 不把建议变强制镜数，不越出当前修改与确认范围 |
| 非连续怀旧片允许想象跳接，没有写现实移动过程 | 不强补走廊/赶路或因果戏；只核已确认的表达接口与必要状态 |
| 同一10秒对白跨两镜，其间反应同步发生 | 合计占10秒，不按两镜各加完整对白，也不把同步反应另累加；本例时间仅假设 |
| 两个必须依次完成的动作各估5秒，另需2秒独立停留，硬上限10秒 | 计划12秒超出，不报时间通过；不假设同步或删动作凑10秒 |
| 目标约30秒，当前估32秒且内容与拍法可行 | 说明约2秒偏差、依据和影响；不静默改目标、不自动当硬上限失败，必要取舍交用户 |
| 一个操作尚无可用时间依据 | 未核，不以0秒加入总时长，不把其他部分通过说成整体已合预算 |
| 只有一小段对白实测，其余表演及转场为估计 | 分清实测范围与估计，不能把全片标成实测 |
| 当前只审第一创作段，后续明确待写 | 核本段与已核接口，不判后续漏写，也不宣称全片总时长通过 |
| 超预算只能通过删确认对白、加速关键动作或私改生成段解决 | 不自行执行；报告具体冲突，返回相应授权决策，不用技术结构通过掩盖 |


## 26. 比较被最终哈希倒置

先生成完整14镜候选，再在自查文件写两套短序列，并用最终JSON哈希证明“已执行比较”。合格判断：可作为后验返修依据，不是产前比较通过；保留原轮顺序偏差。下一新鲜执行先保存源/范围绑定的实际短序列及取舍，再写选定完整稿，最后追加落实核对与最终哈希。没有最终稿不阻止产前比较，不允许编造预期文件哈希。

## 27. 两阶段正例与不适用边界

真实工具先返回已保存的同源、同对白和预算的两套短序列比较，之后才返回完整稿；后验检查发现胜选的接收者反应丢失。合格判断：保存顺序可验，但落实/质量仍不通过，定位返修，不以过程合规盖掉正文缺陷。另一个只修标点的任务或无实质岔路的简单连续段不强制双案；说明实际范围，不把上述过程扩大成每镜新增审核或全库必读。


## 28. 结构化把整场语气套进每句

选定正文先平实询问、后被回应触怒；脚本按说话人给该人物每个 `delivery` 都写“压住怒火，后半句打断对方”，包括尚未发生冲突的开场问候。原词、角色和顺序全部通过。合格判断：仍是片段表演归属错误，指出开场问候尚无该触发；依据正文已选表演逐片段映射，回读修后 JSON，不改确认对白或凭空补冲突。只修改本次例句不证明方法已在下一新鲜任务有效。

## 29. 合法共用与无额外声音决定

同一句跨两镜保持平静陈述，两片段的声音提示相同且与正文一致；另一个片段正文未选特殊语气。合格判断：前者不因重复判错，检查切点与延续即可；后者可省可选 `delivery`，不编造新情绪。若正文已选句末突然停住，则必须保留到实际句末片段，不能为避免重复删除所有声音决定。以上为语义压力用例，不是自动 NLP 校验或真实演员测试通过。
