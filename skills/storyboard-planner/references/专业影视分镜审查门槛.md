# 导演镜头方案 v4 审查门槛

本文用于候选 storyboard-package v4 JSON 的内容与执行自查；统一入口逐段自查后继续并做全片复核，不送导演网页、不等待逐稿人审。仅未迁移的既有人工路径使用网页审查及用户准确版本范围确认。JSON 为业务权威；Markdown 仅明确要求时同版导出，不作为前置、不反向覆盖 JSON。网页入口、自主采用接线及版本缺口按项目根规则处理，不把离线校验冒充已发布或补造人审。历史带 human_readable_path 的包继续双文件一致性只读兼容，不删除字段绕过差异。

审查对象是 [导演 Skill](../SKILL.md#承上启下的职责) 定义的整段拍法。先按播放顺序检查画面、表演、声音、节奏与衔接能否组成清楚的视听安排，再核对字段和来源；不能把后者通过扩大为前者已经成立。

整段表现按本轮方法快照的“拍法选择与整段表现”核对：先指出重要变化由哪些实际画面承载，再检查尚未获得清楚表达的情绪、物件和关系，最后检查重复观看。对每个关键位置，依据实际景别、可见表演、原声覆盖和停留，判断观众能否读懂；保留同框和拆为近景都需给出具体表达依据。

重要态度与情绪按方法快照的“人物态度与表演承载”检查触发、声音、可见变化及跨镜延续；以情境需要确定表演强度和观看距离。

旁观者按“旁观者反应与叙事铺垫”检查：找出话语与行动对在场其他人的影响，将有意义的反应落实到观看顺序，并核对其后续承接。关键对白按[反应镜与大特写](visual-conception.md#对白中的反应镜与大特写)回读：切给谁、在哪个词或动作上切、观众能多读到什么；用了大特写时，检查实际入画的细节和切出后的关系是否清楚。

按[逐场创作与确认](../../../docs/rules/execution.md#逐场创作与全片复核)限定审查结论：逐段送审检查本轮完整范围及跨段依赖，不将明确待写的其他段落判为本轮漏写，也不将本轮通过扩大为全片通过。全片完成时再检查全部来源覆盖、对白顺序、铺垫回应、情绪、道具状态与整体节奏；同场景分段须继承共用设定，跨段对白和动作不漏播、不重复或断裂。修改已确认部分须有对应修订和重新确认。

## 不通过

- 叙事包未确认，或 artifact、revision、路径不一致；
- Scene、Shot 无法回指来源 `STP-*`；
- 新增、删减、换人或改写 `DLG-*`；
- 导演自行新增、修改或重新编号 `AST-*`，或把缺口写成新资产需求；用户已确认调整按项目规则读取并核对出现位置；
- 缺少会改变剧情、已锁定空间、人物、产品或交互的事实却自行脑补；已授权且未锁定的机位与调度可作明确候选设计，但不能覆盖真实参考的固定布局或伪称原片事实；
- 镜头按台词、段落、时长或图片数量机械切分；
- 起幅、镜内过程、落幅实际需要多个剪辑镜头才能成立，却合在一个 Shot 条目；剪辑目标没有对应的独立镜头记录；
- 镜头目的、观众信息、调度、摄影机、声音、切点或连续性缺失；
- 本稿声称的重要情绪或关系转折只有文字标签，实际观看对象、表演、构图或声音不足以承载，却以对白覆盖或人物在场判为表达完成；
- 影响拍法的选择仍互斥或含糊，需要视频 Skill 重新导演才能执行；
- Shot 与 Panel 混淆，或把 Panel 当成正式分镜图要求；
- 设备未知却伪造精确摄影参数；
- 包含 Blender、视频模型、生成分段、提示词、生成参数或正式出图决定；
- 把机器检查或审核结论冒充用户确认。

## 有条件通过

仅用于不改变导演合同、不影响正确性与执行的已知非阻塞限制，并写明范围和影响。统一入口不因此逐稿停等用户；兼容人工路径中确需用户接受的取舍，仍按准确版本和范围处理。资产事实、对白、来源追溯、空间可执行性或连续性缺口不得降级为有条件通过。

“有条件通过”不能直接用于正式自主采用；须完成相应处理并重新自查，整稿结论真实达到 `pass`，且没有真实未决、失败或生产阻塞。不得仅把结论改成 `pass`，或把真实问题从 `open_questions` 移到限制说明中掩盖；合理估计且已说明未实测范围，不自动构成真实未决。采用条件沿用[本地流程授权与自主采用](../../../docs/development/review-to-canvas-entry.md#本地流程授权与自主采用)。

## 通过

- 来源 revision 正确，STP/DLG/AST 覆盖可追溯；
- 每镜能回答“拍什么、观众得到什么、人物如何行动、摄影机为何如此、为什么在此结束或继续停留；有切镜时怎样承接”；
- 声画与空间连续性可执行；
- 整场与逐镜的视听安排明确，重要情绪和关系转折有可读的视听承载，可供用户审定拍法；时间依据与未验证限制如实说明，没有把结构通过写成实测节奏通过；
- 资产缺口只报告、不新增需求；
- JSON 中事件、对白、镜头与资产引用内部一致；修订后重新检查修改及直接影响，最终版绑定准确 revision/hash。仅兼容人工路径核对同版网页并在改版后重审；若明确要求 Markdown 检查稿，从同版 JSON 导出，历史双文件检查保留；
- 验收依据与本轮入口相符：统一入口保留真实流程授权、准确字节与自查结果，采用未接通保持候选；兼容人工路径仍等待准确范围的用户确认。自查通过不冒充独立审核或逐稿人工确认。

审查结论只允许“通过”“有条件通过”“不通过”。

## 紧凑合同检查

场景公共设定可被每镜明确继承；单镜例外不隐式传播。起／过程／止、状态交接、准确对白片段和声音切点仍完整。没有 Beat、Panel、删除测试独立表不构成缺项。不得在结构化或阅读视图中补造 JSON 没有的拍法。

候选 JSON 自查及网页审查时，逐场核对空间字段与 defaults，逐镜核对 camera、take 与切点：各字段按其语义提取，不把整段共用设定复制为轴线、方向、站位，也不把人物动作当摄影机运动或把整段摄影文字复制为 framing／movement／focus。正文未规定运镜或焦点转移时如实注明，不据此补造固定机位、移动或拉焦；重复文字先作语义检查，不机械去重。来源与对白脚本通过只证明对应技术范围，不能代替拍法对照。

对白表演另按[片段绑定方法](../modules/shot-planning.md#声音表演随片段绑定不按角色批量填充)逐项回读：原词与说话人正确，仍可能把后句的打断或另一个人的反应挂错当前片段。定位实际 `dialogue_id`、提示与上下文冲突；准确的持续语气允许重复，不以重复字符串自动判失败。

同一镜若从面部近景转到手部特写，而落幅或切点仍要求读到眼神，须核对回到面部的观看过程是否已明确。连续运镜与切镜含糊、但拍法未锁定且在本轮授权内时，由导演选定、按真实连续摄影边界整理 Shot 并自查；涉及用户已锁定拍法、事实缺口或授权变化时，才提出具体问题和受影响位置。不得把互斥拍法留给下游。

## 分镜段实质验收

按[分镜段创作与实质比较](segment-sequence-method.md)检查实际 JSON，而非作者摘要。重要关系转折先核表达；有实质拍法岔路，或表达不足需要重选时才比较实际短序列，不因转折重要就硬凑双案。比较须按该方法先保存并获得工具返回，再写选定完整稿；后补不能追认产前顺序。冻结 revision、路径和哈希后核落实，正文变化则重查。只有选A理由无可比短序列、知识判断未落镜头、focus复制purpose、对标注意转移无等效承载或损失说明，均返修对应段；参考不足如实限制结论，不伪造切点。

连续性按[状态与节拍步骤](../modules/shot-planning.md#把创作决定落实为可验证的状态与节拍)核原叙事视觉事件、在场物与必要状态交接。普通动作写清关键先后和结果；复杂交互、产品关键工序及易穿帮处才细核接触、承托、释放与终态。产品个案只在[条件连续性案例](conditional-continuity-cases.md)的适用条件成立时读取，并以本轮真实来源为准。首次导演创作无下游时只核当前镜头与前后接口；已有下游时再反查 `source_shots` 及受影响片段，不把切镜或生成段当作状态重置。

## 本轮明确要求与总预算收口

按 [交付前核对](../modules/shot-planning.md#交付前本轮要求与整体时间核对) 检查实际冻结稿：重要明确要求须能定位最终镜头/正文及实现结果，不以启动时已登记、过程说明或检查 ID 齐全替代。未满足给出具体位置和处理，无法核实保留未核结论；不能声明本轮要求全部完成。方向建议不硬化为配额，已锁定拍法与允许自由设计分开，非连续叙事不被强补因果。

全片统筹先粗估各段及合计，逐段完成后更新已用时间与剩余预算，整稿完成再精核全片；沿现有字段记录估计，不新增时间台账。按实际顺序核累计时间，同步声画与跨镜连续原声不重复计时，独立动作/停留/转场不漏计。明确硬上限已被计划超过，或必需步骤与预算冲突未解决，时间项不通过；未知不算零、不冒实测。目标时长偏差如实交待，不自动判成硬上限，也不自改目标。无测量但有合理估计的候选不因此一律阻塞，仍明确未验证风险；“时间项未验证/待决策”不能被总评写成“全部实测通过”。沿现有三种总评及范围说明记录，不新增状态或批准机制。
