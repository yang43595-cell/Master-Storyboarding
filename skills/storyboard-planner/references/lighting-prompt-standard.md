# 灯光提示词物理与连续性执行标准

本文件是 `lighting.prompt-physical-logic` 的仓库权威执行载体，适用于资产图、视觉锚点和视频生成段。它只约束灯光信息如何被写成可观察、可继承、可审查的生产合同，不改变各 Skill 的职责边界。导演预演的灯光判断以 `STORYBOARD-PLANNING-METHOD` 为唯一正文。

## 最小灯光合同

每个需要正式表达灯光的场景、资产、锚点或视频段，至少写清：

1. **灯光目的**：灯光服务于叙事、身份辨识、产品展示或空间可读性中的哪一项。
2. **可解释光源或方向**：例如窗外日光、顶灯、台灯、屏幕光，以及主光从画面哪一侧进入；不得只写“电影感”“高级光影”。
3. **作用对象或可见结果**：说明人物面部、产品材质、空间层次或阴影关系发生什么可观察变化。
4. **继承或变化逻辑**：同场景默认继承既有灯光基线；需要变化时写明触发事件、变化路径和结束状态。

阴影反差、材质响应、色温和环境光只在镜头职责需要时补充，不要求每镜机械填满全部字段。

## 分阶段执行

### 资产图

- 人物身份资产使用中性、均匀、可辨识的基准光，不继承具体剧情布光。
- 场景母版记录主光来源、方向、时间和天气，派生机位继承同一灯光基线。
- 产品和关键道具按真实材质控制高光、反射与透明度；不得用过曝高光掩盖结构或标签。

### 视觉锚点

- 锚点继承已确认场景母版的光源方向、色温和材质响应，只改变镜头职责要求的状态。
- 体积光或丁达尔光必须有雾、烟、尘、水汽等可见参与介质。
- 身份、产品结构或空间关系是主要职责时，灯光不得牺牲可辨识性。

### 视频生成段

- 段首继承输入资产、场景母版或上一段 exit 的灯光状态。
- 变光必须写明触发、变化路径和结束状态，并在下一段 entry 中继续锁定。
- 提示词需要同时覆盖可解释光源、作用对象或结果，以及保持或变化逻辑；灯法名称不能替代这些条件。

## 审查与阻断

出现以下任一情况时结论为 `changes_required`：

- 只有抽象风格词，没有可解释光源、方向或可见结果；
- 同场景相邻镜头主光无理由换边、色温跳变或阴影逻辑冲突；
- 视频变光没有触发、变化路径或结束状态；
- 体积光缺少参与介质；
- 身份资产带入强剧情光，影响后续复用；
- 产品高光、死黑或反射遮蔽真实结构和关键标签。

结构化字段和静态检查只能证明灯光合同存在，不能证明生成画面已经正确。实际过曝、死黑、塑料皮肤、产品材质和跨片段光线连续性仍由用户审片；只有用户明确要求时才增加自动视觉 QC。
