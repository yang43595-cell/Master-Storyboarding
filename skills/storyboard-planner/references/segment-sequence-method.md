# 分镜段创作与实质比较

用于实质导演创作或拍法返修，承接已绑定专业方法，不替代事实、确认与阶段边界。分镜段是一次表演／情绪推进单元，可含多刀；不是视频生成片段，也不是新的业务ID层。短段可一镜到底，长场景可多段。先通读整场和远处铺垫，再逐段细写。

## 一段怎么写

用户正文与创作过程分开：创作目的、候选比较、知识映射、审核结论保留在既有过程/审查记录，不在每段正文重复。它们仍须执行，不是删掉质量检查。场景身份、服装、空间轴线、屏幕方向、公共光线和声音写一次，段内只写发生的事和必要变化。

段正文直接按时间写“谁在哪里做什么、怎样反应”，在故事发生的过程中写景别和运镜，不在段首为整段固定一个景别。每次切镜明确：说到哪个准确词句，或哪个动作发生时，切向谁、什么景别、看见什么变化。可在一句对白中切多次，听者反应不必等说话者说完。连续动作、固定镜、空镜和物件停留仍按表达需要选择。

完整对白在正文出现一次，可由切点拆成连续原文片段；注明声音继续及画内/画外变化，不在每次换画面时重写整句。底层 audio.dialogue 的片段按镜头顺序拼回原句；准确说话人、动作、轴线、时间和切点不能因阅读简化消失。需要的停留直接写入过程，段尾给时长或预算；全稿统一说明估时边界，不每段重复声明。

光线优先交代实际光源、方向与人物明暗关系，共用光线写场景，变化才写段内。焦段/焦距随镜头光学目的选择，可在段内改变；写清机位距离、主体背景关系或清晰层次，不把未知原片参数说成事实。前景、背景、构图在影响观看时写，设备品牌、镜头型号、风格标签可选，不要求每镜填设备清单。

完整的一句跨三镜示例见[用户阅读模板](../templates/专业影视分镜输出模板.md)。示例是写法演示，不是项目剧情或固定切镜公式。

业务阅读正文放 scene.audiovisual_flow，正文必须含本段实际对白原文、说话者与声画切点，不能用“DLG001–005”“按原文说完”或故事编号摘要替代。整理 shots[] 后回读正文，检查没有只剩摘要或混入自查声明；不靠网页额外展开卡片补齐缺失正文。镜号贴在实际切点，来源定位与共用设定沿用现字段；底层 shots[] 仍一次连续摄影一个对象。space_rules/defaults 保存共享条件，每镜保留其完整决定，不添加 v4 不支持的字段，也不将多次剪辑藏在一个 take.process。用户阅读版不重复逐镜卡和机器元数据；只有执行需核细节时再展开。具体排版见同版模板。

## 用知识作选择，不只登记读过

三份基础参考分别进入本段决策：

1. [分镜与剪辑组织](foundations/01_分镜与剪辑组织.md)：何时把注意从刺激者交给接收者，何时留余波，哪些变化不能省略。
2. [景别与构图](foundations/02_景别与构图.md)：读表情还是手物关系，画幅与遮挡是否容纳，景别和光学意图如何服务观看。
3. [运镜与人物调度](foundations/03_运镜与人物调度.md)：人物行动是否已改变关系，固定／切镜／移动各得到和失去什么。

当前准备包绑定的导演规划方法全文继续适用，尤其人物态度、旁观者反应、声画与切点、遗漏→比较→删除测试。其它已恢复知识只按 stage_startup 的准确候选路径、适用范围定向取用，沿共享 knowledge-access 记录实际采用；不是全库灌入，也不把图片/产品方法变成导演越权指令。

已恢复且当前可解析时，按任务缺口读取以下准确 Wiki 路径的相关章节，使用本轮知识快照解析，不把这次工作目录写死到 Skill：

- `wiki/concepts/02-镜头与剪辑/专业影视分镜设计与执行方法.md`：推荐决策链、信息接力切镜、先证明镜头为什么动、摄影机位移／变焦／焦点转移分判、画面占比与停留时间、叙事性声音的具体声源与时间关系。
- `wiki/concepts/02-镜头与剪辑/景别理论.md`：完整读取“景别 × 焦距：拍摄距离决定透视”和“景深 × 光圈：清晰范围的深浅”。这两节可能位于注册知识块之外，只读命中规则块不能替代全文相关章节。迁移机位距离、主体背景关系和清晰层次，不照抄示例毫米数、光圈值或设备套餐。

当本段确有相应问题时，再读取以下精确路径的适用章节；不把它们全部变为每段必读：

- `wiki/concepts/02-镜头与剪辑/连续性剪辑.md`：“动作切的阶段对齐”“先选跨镜载体，再选转场形式”，落实动作中点、视线或声音的两端，而非只写转场名称。
- `wiki/concepts/02-镜头与剪辑/图片连续性规则.md`：“跨段共用帧：真实开场状态”，只用于导演起止状态和控制职责，不在本阶段决定出图或共用素材。
- `wiki/concepts/03-AI生成与视频/ai分镜设计.md`：“空间地图”“动作写物理行为”，落实既有空间关系及动作路径，不引入生成分段规则。
- `wiki/concepts/03-AI生成与视频/ai人物活人感.md`：“核心方法”，按动作动因、过程与可见结果设计表演，不堆微表情形容词。
- 本段确有主次人物注意竞争，或视线/面部表演显得机械且需要比较拍法时，可选读 `wiki/sources/超真实AI电影六技巧拆解-刺猬星球super-i.md` 的“核心主张”“屏幕核对”“未决与限制”。这是 candidate 二次拆解、未实测的第三层来源，按当前知识根解析；只提供细微视线、自然不对称与群像主次的诊断线索。“反应同步”指同一人左右脸，不是多人动作；不默认随机眨眼、降低配角信息、删反应或要求群体错开动作。仍按本段既定观看任务比较，来源缺失仅跳过该可选参考，不改变正式方法绑定。
- `wiki/concepts/03-AI生成与视频/ai人物反向表演.md`：“三个技巧”，仅人物确有隐藏情绪动因时考虑；时间过程可用，不能让所有角色克制、表里不一或凭空新增动机。
- `wiki/concepts/01-叙事与对白/短剧电影叙事法则.md`：“角色意图、场景因果与对白推进”“创意选择与克制修订”，识别既定场景任务，不据此重写已确认故事和对白。

知识页生命周期 `needs_review` 与页内已登记项目块状态分开核对，不能一概否决全部内容，也不能将整页升级为已验证方法；适用经验注明来源与限制。关联的 `wiki/sources` 可追溯原意，但不自动全文读取或全部执行。教程里的2–6秒、多人开场必1秒全景、30秒四图或182毫秒等示例数字不作导演硬约束；优先遵守本项目画幅、观看任务、事实与时间预算。

它们是已恢复知识的精确可选经验入口，不新增已确认专业方法绑定。实际采用时沿共享读取合同保存来源路径、版本/哈希与范围，运行快照未提供或状态未知则标范围限制，不扫描全库补猜、不声称已同步最新全库。读到“固定为基线”是比较起点而非优胜规则；“只在信息改变时切”应结合情绪距离、关系、节奏等观看收益，不用它删掉有表达作用的反应或停留。

在本轮现有核对记录中保留少量关键映射：“来源路径/章节 → 本段触发条件 → 采用或不采用的判断 → 候选具体镜头 → 最终镜号及实际效果”。同一判断可覆盖多个段，不每镜重复写知识说明。哈希、阅读声明、术语出现不能替代这条映射。三文件中的《我的妹妹不可爱》仅为有界采样案例，不能当已完整观片；迁移条件与注意顺序，不照搬剧情、秒数或未知运镜。

## 重要岔路必须有实际短序列

关键关系转折先检查表达是否充分，不因转折重要就强制双案。存在影响观看体验的实质拍法岔路，或表达不足需要重新比较拍法时，写两套真正不同的短镜头序列；必要才增加第三套。没有实质岔路则说明直接展开或返修的依据，不凑陪跑候选。共同固定事实、对白、资产条件、画幅、段落时长预算和前后接口。候选均须有可读动作、观看顺序、镜头范围、声画切点和大致时间，不能一套写完整、另一套只用标签陪跑。

先看候选正文推断观众会经历什么，再读作者理由。先排除事实/对白/时间/空间不成立的方案；再比较关键表情可读性、注意转移时机、关系表现、节奏留白和邻段衔接。指出具体镜头的收益与代价，再决定取舍；局部高分但接前后不自然的方案需修或放弃。可用简短优劣或粗等级辅助，不制造精确客观分，不以切镜数、运镜数、空镜数、焦距数字加分。不把同一执行者的自查叫独立盲评；独立审核仍按项目授权，不固定增加角色。

删镜测试在遗漏检查之后进行：若改为同框或删掉此刀，会丢什么已明确的表情、关系或节奏；若固定镜已经成立，运动是否真的另有收益。不是默认越稳越好，也不是越复杂越好。

### 先选路再核落实，不要等最终哈希才比较

比较仍留在项目现有审查/任务记录，不新建业务权威、任务表或审批。分清两次不同工作：

- **创作前选路**：绑定已读源文件的准确 revision/hash、当前段落范围与共同事实/对白/预算/接口；保留实际短序列文本及其内容哈希，先读候选正文再写收益、代价与选择。记录真实保存并获得工具返回后，再展开选定完整视听稿/逐镜表。这时可写计划修订名，但最终 JSON 尚未产生，不要求或编造最终文件哈希。两套短序列本身是比较材料，不要求先生成整份导演包来充候选。
- **成稿后核落实**：读取已写的完整候选，逐处核选择是否落实到具体镜头、对白和切点；如有改选记录准确原因，必要时回到新一轮比较。随后追加最终 JSON revision/hash 和落实镜号；只有选定拍法进入业务正文。旧的创作前记录保留，不覆盖成一个看似一直完整的记录。

晚补比较必须标作后验自查/返修依据，不能改变该轮产前顺序未遵循的事实。不得靠文件mtime、手写“已比较”或自动生成两份标签判合规；结合实际工具返回顺序与方案内容核对。记录只能支持可追溯性，不能自动证明理解/情绪效果。需要验证方法修复时使用新冻结基线和全新执行者，不在旧稿旁补一张表就报循环通过。没有实质岔路不强凑两案；纯技术维护仍不重做整场构思。

写脚本仅做结构化时不得硬编码“选A”充当比较，不以通用purpose自动填focus或cut。审查时冻结候选文件，修改后重新绑定，不边覆盖同名稿边沿用旧结论。

## 有原片对标时

先区分用户锁定拍法、节奏参照、自由改编。只对实际看过的范围记录观看对象顺序、切点精度、可确认景别／运动、反应停留和已听验声画；观察与目的推断分开。稀疏抽帧不等于精确逐镜表，未知原片焦距、音轨和连续运镜不编。

改编不强制复制切镜数量，但需要对照原有注意结构：保留在哪里；改写后由什么等效机制承担；损失什么、为什么符合本轮目标。尤其检查把多镜压成同框是否吞掉反应与节奏，而不是仅以“劳动同框更完整”等作者解释放行。新增产品段按独立预算处理，不用放慢全部剧情给它让位。

## 落到现有 JSON 的底线

- camera.framing：观看范围、机位角度、构图／视线；光学作用重要时明确广角／标准／中长焦倾向及目的。它是候选设计，不是假装知道原片毫米数。
- camera.focus：清晰主体与景深层次；转焦写起点、触发和落点。没有转焦可固定焦点，但不能复制purpose当焦点设计。
- camera.movement：固定或连续移动；移动有起幅、触发、路径和落幅。真实剪辑另开Shot。
- take：起／过程／止的可见表演与持物状态；情绪标签不能替代行为。
- cut：入口、出口、动作／词句触发及下一镜承接的信息；视线关系明确，不全镜只写“承上启下”。
- audio与rhythm：准确对白片段、声画桥两端和停留预算；估时不冒充实测。

最终验收读取冻结 JSON 的 actual shots[]，逐项核对段落观看路线、胜选镜头、知识映射、焦段/焦点意图、声画桥和邻段状态是否仍在。schema和来源通过只证明相应技术项；没有生成视频时结论限于文稿表达与执行可行性，不保证成片。
