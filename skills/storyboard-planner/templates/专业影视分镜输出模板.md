# 简洁阅读模板

最终阅读稿只呈现“这场戏怎样发生、镜头怎样看”。不重复创作目的、候选比较、知识映射、审核声明和逐镜字段表；这些仍保留在既有过程/审查记录和完整 JSON 中。新生产仍以 v4 JSON 为业务权威，Markdown 仅用户要求时从同版导出，不能反向改稿。

## 排版

文件头只给项目、修订、候选/确认状态、范围及估时说明。场景按顺序排，每场共用条件一次，然后直接读分镜段。短模板或短示例以约2–3页可读为宜，不为页数删对白、动作或切点；全片长度依内容，不强压页数。

### 场景｜时间、地点

共用设定：谁在哪、相互朝向、重要物件位置；主要光源方向与明暗；必要环境声。身份、服装、轴线已共用时不在每刀复述，单镜例外明确写出。摄影机保持哪一侧在此说明。

### 段名｜估时

直接写谁正在做什么。随行动写“女主近景”“男主特写”“双人中景”等，不在标题或段首另设一个统管全段的景别字段。

完整台词随过程出现一次。在说到准确词句或动作发生时写“切向谁／什么景别，看见什么反应”；原声可继续，画面换到听者、手、物件或空间。一句可跨多镜，不必一句一个特写。运镜有触发和落幅；关键停留直接写在发生的位置。段末状态自然接下一段。

光线有变化才补。需要特定光学效果时写焦段/焦距设计及目的、机位距离与空间关系；景深和焦点按观看需要写。构图、前景背景按需，设备/镜头型号和风格可选，不堆清单。未知原片参数不冒充实测。

## 完整示例：一句话跨三镜

以下为虚构写法示例，非项目台词，不可直接写入实际故事。这里只示范一句话连续跨镜，不把词尾作为默认切点；正式创作先找动作停顿、视线、信息或情绪变化带来的观看收益，再把已选切点定位到实际词句或动作相位。没有切换收益时保持当前画面，不为套示例切三次。

### 客厅｜傍晚

女主站餐桌左侧，男主坐右侧，面向她；账单平放桌面，女主右手扶桌。摄影机始终在二人交流轴线靠窗这一侧。左侧窗光照亮女主侧脸，男主背后的墙面较暗，人物眼睛可读；远处只有轻微钟表声。

### 争辩｜约7秒，未朗读实测

（S01-001）女主胸上近景，视线朝画右。她压着气，把目光从账单抬向男主，说：“你说这些钱花得太快，”

“快”字落下即切（S01-002）男主面部特写。他原本要开口，嘴微张后又闭住，目光从她脸上落到桌面。女主声音不中断，转为画外继续：“可你有没有想过，” 此镜选中长焦倾向、稍远机位，让背景墙弱化但仍保留窗边位置关系，焦点落在男主眼睛，不用虚化掩掉表情。

“想过”说完即切（S01-003）双人中景，重新看清她站着、他坐着的距离。女主扶桌的手慢慢松开，目光仍停在他脸上，接完同一句：“这个家每天都需要什么？” 男主没有立即回答；保留半拍可见沉默后接下一段。

这句台词按三片段顺序合并为：“你说这些钱花得太快，可你有没有想过，这个家每天都需要什么？” 真实交付不另附这行复写；本行仅用于说明跨镜不会重复或遗漏对白。估时包含说话与同步反应，不把每次切镜另加停顿。

## 执行信息保留在哪里

- 同场分多轮创作仍只有一个唯一 scene_id 场景对象，在其中追加分镜段与连续镜号；不能复制同 ID 场景对象，否则来源核验与网页锚点均拒绝。局部候选范围通过入口的现有 STP 参数声明，已写/待写及跨段未决保留在现有字段，不另造分段业务包。
- scene.audiovisual_flow 保存上述按过程展开的分镜段；space_rules/defaults 保存场景共用条件。
- 每次连续摄影仍分别存入 shots[]。camera、take、cut、audio、rhythm 等 v4 必需字段完整保留，用户阅读版不重复展开全部卡片。
- 同一句跨镜使用同一 DLG 的实际连续片段、准确说话人和画内/画外方式，按顺序拼回原文；不以镜号代替台词，不重复整句。静默文字按现合同明确不发声。
- STP/DLG/AST 来源、候选比较、知识应用、状态和时长检查保留在现有 JSON 及对应过程/审查记录，不另建业务权威。不把隐藏阅读细节当作取消检查。仅核对白或结构时，过程记录中的表达审查如实记未完成，不在用户段正文反复列审查声明。
- 下游读取单镜时同时读取场景共用条件和全片总则；例外不会自动传播。阅读导出不能补造 JSON 中没有的拍法或移动已确认切点。

创作与自查时按[状态与节拍步骤](../modules/shot-planning.md#把创作决定落实为可验证的状态与节拍)核对；结果放回上述视听展开、场景设定、take和原自查备注，不新建同义状态表。
