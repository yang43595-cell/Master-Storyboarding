# 阶段审核

仅在用户明确要求独立审核时启动；普通“检查/审查/修改”在当前对话自查，不自动派发。审核者保持独立，只读执行并遵守 [PROJECT_RULES.md 的 Skill 执行分工](../../PROJECT_RULES.md#skill-执行分工)。已获独立审核授权时，首次才另派不继承生产对话的子 agent；返修复审回原审核子 agent，不新建。不得由产物执行者自审冒充独立审核；已是审核执行者时直接审核，不递归转派。

只读取 `PROJECT_RULES.md`、当前 `review_packet.md` 及其明确列出的本轮文件（视频提示词直接审核用下述准确候选与来源，不要求此包）、`../_shared/draft-lifecycle.md` 等共享红线和 `modules/review-method.md`。不得读取生产对话、全部历史版本或完整项目树。检查清单、文件格式及复审要求统一按该方法，不重复加载另一份清单说明。

本次已获用户明确独立审核授权时，默认按审核方法的轻量交接执行；仅用户明确要求正式留档时启用 `--formal-archive`。沿用生产时建立的唯一 `task_basis.json`：使用准备包的阶段由prepare建立。视频提示词新流程不生成此依据或审核包，不通过此旧打包接口恢复；其默认自查由当前对话完成；用户明确要求视频独立审核时按 [直接审核分支](modules/review-method.md#视频提示词的直接审核分支)，不以缺少 task_basis 或 review_scope 阻塞。`production` 审核核对候选、冻结必检项、硬红线和已接受问题；`skill_contract` 使用同一profile的合同清单，不与产物审核混用。适用专业方法须列出完整同版快照及已有读取证据；快照存在不证明已读。采用准备包的阶段以任务依据和审核包限定范围；视频直接审核以获准的准确候选、来源和范围限定，不新增验收要求。

同一任务复审回原审核者，只核对修订项、原阻塞项及直接影响；原审核者无法恢复时报告限制，不自动替换。阶段或修订号变化不构成新建审核者的授权。

问题与结论按 `modules/review-method.md` 记录，保留准确证据，不以无新证据的审美偏好新增阻塞或改变标准。

审核通过不等于用户确认；不得修改被审文件、决定下一阶段、生成批准事实或替用户做图片视觉终审。
