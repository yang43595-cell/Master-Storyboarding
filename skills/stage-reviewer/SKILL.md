# 阶段审核

开始本职任务前读取[共用三层规范](../_shared/skill-layers.md)。本 Skill 适用边界：仅在用户明确要求独立审核后，只读准确候选和目标已冻结证据；不刷新准备包、不修改候选、不授予批准；专属知识为空可成立。

只在用户明确要求独立审核后启动。整稿交付、重大改动或反复出错时，可以建议用户安排独立复核；建议本身不是授权，不自动派发或阻塞生产。日常小改仍由本轮生产执行者自查。

审核依据是目标 Skill 的现行 `review-profile.json`、冻结范围、准确候选及其指定来源。不得复制或另造生产业务标准。产物审核与 Skill 合同审核分开；视频提示词按 [直接审核分支](modules/review-method.md#视频提示词的直接审核分支) 使用准确候选和来源，不恢复旧审核包流程。

审核者应保持独立：首次审核不继承生产对话；修订复查回原审核者，只核原问题、修订及直接影响。方法、证据范围、交接格式和留档选项统一见 [审核方法](modules/review-method.md)。这是执行要求，仓库没有自动隔离审核者或自动派发机制。

只读报告事实和证据；不修改候选、不生成批准事实、不代表用户确认、不决定阶段流转，也不替用户做图片视觉终审。通过结论不等于批准。

## 执行 SOP

1. 核对明确独审授权、目标 Skill、本次审合同还是产物、准确路径/修订及范围。首审由独立上下文执行；缺目标或来源则报告具体缺口，不自行刷新或补造冻结证据。
2. 读取目标入口、对应清单和准确候选/来源；采用准备包的阶段只消费现有冻结包，视频走上述直接分支。核对本轮实际交付对象，排除有依据的不适用项，不把未生成的图片/视频判为质量通过。
3. 先读实际产物，再按清单核内容、来源及本次适用 SOP 的执行证据。报告已核范围、未验证项和不适用原因，不能只列发现后把其余默认为通过；证据不足项保持无法确认。
4. 按审核方法给出可定位发现和限定范围的结论。必需证据缺失时，不得对该要求判通过；有条件通过明确等待用户接受的限制，审核者不代为接受。
5. 有返修时回原审核者，逐条核上轮未决、实际修改及直接影响；用当前版本证据关闭问题。来源或范围变化按方法处理，遗漏项不自动解决。结果留在本次对话或既有审核记录，交回后停止，不修改生产稿或推进阶段。
